2025 年年中，开发者圈被一条消息刷屏：据 36kr 等媒体报道，字节跳动旗下 AI Agent 搭建平台「扣子」（Coze）逐步停止独立运营，团队与能力并入火山引擎。戏剧性在于，就在退场前，它还在多家第三方机构的智能体平台份额榜上排第一。份额第一的产品被自家公司主动收掉，这不是输给竞品，而是被技术路线本身「格式化」了。这篇拆三个问题：扣子当年赢在哪？字节为什么算不过账？以及最关键的——大模型到底抹平了低代码的哪一层。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-10/aee751a115ba6685.png)

## 扣子赢过什么：把 Agent 做成拼积木

先交代背景。扣子是字节的低代码/无代码 Agent 平台：海外版 2023 年底上线，国内版 2024 年初发布，正好踩中大模型应用落地最猛的窗口期。

它的产品逻辑很清晰：把搭 bot 的脏活全部封装成可视化节点。

- **工作流编排**：拖拽节点连线，替代手写调用链。比如一个「每日晨报 bot」，定时触发器 → 新闻插件 → LLM 摘要节点 → 推送到飞书群，半小时搭完，一行代码不用写
- **插件与知识库**：内置 RAG，上传文档就能让 bot 带上私有知识，长记忆、定时任务开箱即用
- **分发渠道**：一键发布到飞书、微信客服、抖音等，这是它相对独立开发者的最大吸引力

结果就是第三方统计里，它的智能体数量和活跃用户规模长期位居第一梯队乃至第一。**赢的本质是：把「调 API、管上下文、接渠道」的工程摩擦降到接近零。**

## 份额第一，字节为什么还是收了

看三本账，就明白这事并不矛盾。

1. **商业账**：C 端和中小开发者基本免费，模型推理的 token 是真金白银的成本；而低代码工具本身收不上钱——愿意付费的企业要的是私有化部署和确定性，不是公有云上的一块拖拽画布
2. **战略账**：字节的 AI 版图三条主线——豆包管 C 端应用，火山引擎/方舟管 B 端基础设施，Seed 管模型。扣子卡在中间层，定位重叠，能力被火山引擎的 Agent 产品线吸收是更顺的路径
3. **技术账**：这是下一段的重点——它所在的那层抽象，正在被模型本身替代

一句话总结：**面向「人人都能搭应用」的这层，账算不过来；面向企业的确定性编排，换个载体继续做。**收编不等于放弃，是资产搬家。

## 真正的杀手：大模型抹平了「抽象层」

低代码这门生意，本质是赚**抽象层**的钱。理解这一点，就理解它为什么危险。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-10/f9ec128766101dee.png)

1. **低代码的护城河 = 预制积木**。表单、审批流、数据看板这些高频软件模式，被做成可视化组件，用复用替代手写。积木库越厚，护城河理论上越深
2. **大模型干的事，是绕过积木直接编译**：自然语言 → 可运行代码。Cursor、v0、bolt.new 这类产品已经验证了「描述需求 → 拿到能跑的应用」这条路径的可行性
3. **决定性的变量是边际成本**。维护可视化编辑器 + 组件市场 + 兼容性矩阵，是线性的人力投入；而模型生成代码的成本随推理降价一路下探——一年多里主流模型 API 价格普遍降了一个数量级。「现场生成」越来越便宜，「预制积木」的复用价值随之贬值
4. **编排范式本身也在换代**。Agent 框架正从「人画流程图」走向 model-driven control flow：调用哪个工具、循环几次、何时终止，交给模型自己决定。「流程图即程序」正在被「自然语言即程序」取代

打个比方：低代码像汇编时代的宏汇编器，大模型是高级语言编译器。宏汇编器不是做得不好，而是它所在的抽象层级被整体抬高了——**上层建筑跟着整个平移**。这种死法在软件史上有固定剧本：4GL、CASE 工具、可视化建站都喊过「消灭代码」，结果代码只是换了写法，这次换成的写法叫自然语言。

## 低代码没死，死的是「积木生意」

要精确一点，别把婴儿和洗澡水一起倒掉：

- **概率性 vs 确定性**：大模型的输出是概率的，而金融风控、审批合规这类流程要求每一步可审计、可回放。显式工作流在这类场景仍是刚需
- 所以真正退出的是 **C 端与轻量场景**那一层；企业侧的编排会换壳继续存在——私有化 Agent 平台、模型网关、流程引擎，只是不再以「拖拽积木」作为核心卖点
- **中间层最危险**：夹在模型厂商和企业之间的纯工具平台，两头都可能被绕过——模型厂商自己做 Agent 平台，企业直接调 API。扣子就是这个位置的前车之鉴

## 三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-10/a4db59e1c764ad95.png)

1. **学「写规格」，别学「点节点」**。把模糊需求翻译成输入、输出、边界、异常都清晰的需求文档（spec），是这个时代迁移成本最低的技能。工具会死，需求工程不会
2. **开发者往价值链上游走**。胶水代码和编排能力在贬值；评估（evals）、数据管道、权限护栏、成本观测在升值。Agent 时代的工程难点，已经从「怎么把它串起来」变成「怎么知道它没出错」
3. **押注「模型原生」，先设计退出机制**。选平台时问三个问题：模型变强时，这个平台是受益者还是受损者？我的知识库、数据、流程资产能不能迁走？它靠什么活着？扣子的用户资产一夜之间整体搬进火山引擎，就是教科书级案例——**在别人的地基上盖房，迁移成本要提前算**

低代码没有输给任何一个竞品，它输给了「下一代抽象」。用工程师的话说：不是被 deprecated，是被 include 进了更大的系统——编译器换了一层，你的积木就成了标准库。
