2024 年底，Anthropic 放出 Claude 的 computer use 演示，画面里 AI 对着一枚"I'm not a robot"复选框自言自语了句“这还挺讽刺”，然后伸手点了下去。2025 年，OpenAI 的 Operator 在浏览器里被验证码拦住时，官方策略是——停下来，转交人类。36kr 这条“验证码拦不住个人 Agent 了”的热搜，讲的不是一个新漏洞，而是一道维持了二十多年的人机边界，正在被重新定价。这篇文章拆三件事：验证码为什么曾经有效，现在为什么失效，以及防线搬到了哪里。

## 验证码的本质：一道“反向图灵测试”

- CAPTCHA 全称 Completely Automated Public Turing test to tell Computers and Humans Apart——机器自动出题、自动判卷，赌的是“只有人类做得出来”。
- 这套东西诞生于 2000 年前后的 CMU，主创是 Luis von Ahn。2009 年 reCAPTCHA 被 Google 收购，把亿万次人工点击变成了古籍数字化和街景门牌识别——换句话说，人类每点一次验证码，都在免费给系统做数据标注。
- 形态一路演进：扭曲字符 → 九宫格选红绿灯 → 2014 年的"No CAPTCHA"复选框 → 2017 年 reCAPTCHA v3 的无感评分 → Cloudflare Turnstile 的 proof-of-work。鼎盛时期，全球每天要被解掉数亿次验证码。
- 关键真相：那个复选框根本不考核你的点击技术，它考核的是鼠标轨迹、Cookie、IP 信誉、设备指纹。验证码从来不是一道题，而是后端风控系统的前台表演。

## 为什么失守：考题撞上了“刷过题库”的考生

- 2023 年，苏黎世联邦理工学院的研究者用微调过的目标检测模型（YOLO 系）攻破 reCAPTCHA v2 的图片挑战，在高置信度样本上报告准确率接近 100%。
- 2024 年以来多项测试显示，GPT-4o 这类多模态大模型对扭曲文字、简单图形验证码的破解成功率普遍在 90% 上下，部分类型和速度甚至超过人类平均水平。
- 失效原因可以拆成三层：
  1. **语料即题库**：训练数据里本来就有海量验证码样本——你在网上看到它，模型也在网上“看到”过它；
  2. **OCR 时代的防御打错了靶子**：扭曲变形防的是字符识别算法，而多模态模型做的是语义理解——扭曲对 OCR 是天堑，对一个见过一万个斑马线的视觉模型只是滤镜；
  3. **边际成本归零**：过去要买“人肉打码服务”，现在个人 Agent 自带视觉能力，解题成本趋近于免费。
- 一句话总结：验证码考察的是“是否拥有类人感知”，而这恰恰是多模态模型的核心能力。考点没变，考生的物种变了。

## 能过 ≠ 该过：个人 Agent 的真实处境

- 各家厂商的策略并不一致：Operator 遇到 CAPTCHA 会停下来转交人类；Claude computer use 能自己点复选框；一些浏览器厂商甚至替用户自动点过，引发过公开争议。
- 这件事上其实站着三方，各有各的账：
  - **用户**：Agent 是效率工具，订机票、填表单、比价下单，凭什么最后一步让我人肉过闸？
  - **站点方**：流量、广告和反欺诈是生意底盘，把门禁交给访客定义等于自拆防线；
  - **模型厂商**：夹在中间，既要能力又要合规，普遍策略是“遇到验证码就交还人类”。
- 真正的技术难题在更深处：一个订机票的个人 Agent，和一个抢票的黑产脚本，在验证码眼里长得一模一样。验证码本来就没打算区分“你是谁”，它只赌“你是不是人”——而这个赌注已经输了。

## 防线搬家：从“考题”到“信任链”

- **无感风控加深**：TLS/JA3 指纹、行为生物特征、IP 信誉、限流策略——判断发生在协议层，不再依赖前台考题。你以为你没做题，其实每秒都在被评分。
- **硬件与密码学背书**：passkey / WebAuthn、设备证明（attestation）、以及 proof-of-personhood 的相关讨论——思路从“证明你足够聪明”转向“证明你被某个可信方担保”。
- **陷阱与蜜罐**：Cloudflare 在 2025 年上线了 Labyrinth，为爬虫生成大量看起来真实、但人类永远不会见到的假链接迷宫——Agent 分不清真假，一脚踏进去就暴露身份。
- **给 Agent 修正门**：官方 API、MCP（Model Context Protocol）、llms.txt 这类“给机器看的站点说明”，加上支付行业的 Agent 专用凭证——Visa、Mastercard、以及 Stripe 与 OpenAI 合作的商业协议，都在尝试给 AI 发一张带额度的“数字工牌”。
- 趋势一句话：与其在门口出题刁难所有访客，不如给真人发通行证、给可信 Agent 发工牌、给恶意流量设闸门——三扇门分开管理，成本反而更低。

## 收尾：三条冷思考

1. **个人用户**：让 Agent 优先走官方 API 和带授权的通道，遇到验证码交还给自己，别装破解插件——省下的三十秒，可能赔上一个账号和一堆风控记录。
2. **站点开发者**：别再给前端验证码无限续费了。预算挪到行为风控、设备指纹和 passkey 上，把目标从“挡住所有机器人”换成“识别出真人和可信 Agent”，再按身份分层放行。
3. **长期视角**：验证码二十多年的历史证明，任何“内容型”的人机边界都会被更强的模型追平。边界不会消失，只会搬家——搬进密码学、硬件和商业协议里。给人和给 Agent 各修一条路，往往比互相拦截便宜得多。
