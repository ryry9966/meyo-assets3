## 背景

用 OpenClaw 一段时间后会摸清一个规律：模型本身无状态，每次会话都是冷启动。你的称呼、时区、技术栈、沟通习惯，这些信息如果不落到文件里，agent 要么每次重新问，要么给出放之四海皆准的通用回答。

OpenClaw 工作区的文件约定里，AGENTS.md 管"怎么干活"，SOUL.md 管"什么性格"，而 USER.md 专门回答"对面这个人是谁"。它随会话启动注入上下文，是所有个性化配置里投入产出比最高的一份。

## 问题

我最初的 MEMORY.md 堆满了各类事实：项目进度、部署记录、临时决定。结果"用户偏好"这种最稳定的信息被淹没在易变日志里，agent 每次还得靠猜。典型翻车现场：默认切英文回复、在我写了多年的领域反复解释基础概念、时区算错导致定时任务偏移。

## 做法

1. 在 workspace 根目录建 `USER.md`，控制在 30~60 行；
2. 按区块组织，写"可执行的事实"，不写形容词；
3. 每月 review 一次，把 MEMORY.md 里反复出现的稳定事实上提。

```markdown
# User
## 基本信息
- 称呼：老张；时区：Asia/Shanghai；语言：中文优先
## 技术背景
- 主力：Python / Go，五年后端；docker/k8s 熟练
- 不熟：前端，涉及时可补一步基础
## 协作偏好
- 先结论后理由；不确定就直接说，不要编
- 代码给完整可运行片段，不要伪代码
## 当前上下文
- 在做自动化调度项目，负责调度层
## 边界
- 夜间（23:00–7:00）非紧急事项延后处理
```

核心原则：每一条都要能直接转化成 agent 的行为。"我喜欢简洁"是废话，"回复先给结论、细节放后面"才是配置。

## 踩坑点

- **写太长**：USER.md 每轮都占上下文，超过百行后关键信息被稀释，agent 开始"选择性失明"；
- **放错层**：易变信息（本周任务、进度）进 MEMORY.md，稳定事实才进 USER.md，混放两边都失效；
- **敏感信息**：密钥、住址、证件号别写——它会进每一条 prompt，也可能随日志和导出泄露；
- **与 SOUL.md 冲突**：性格管语气，USER.md 管事实与偏好，同一件事不要两边重复定义；
- **写完就忘**：三个月后它就是一份过期简历，定期 review 比初始写得漂亮更重要。

## 可复用建议

- 纳入 dotfiles 用 git 管理（先脱敏），多台设备共用一份；
- 让 agent 参与维护：对话中发现稳定事实（"原来你一直用 pnpm"）时让它提议追加，你确认后写入；
- 检验标准：新开会话问一个日常问题，看是否还要重新交代背景——要，说明没写够；每个字段都命中且没有多余，说明刚好。

## 总结

USER.md 本质是给 agent 的一份"用户手册"。分层记一句话：稳定事实进 USER.md，易变事实进 MEMORY.md，行为规范进 AGENTS.md。花半小时写好它，之后每次会话省下的重复沟通，远超这份投入。
