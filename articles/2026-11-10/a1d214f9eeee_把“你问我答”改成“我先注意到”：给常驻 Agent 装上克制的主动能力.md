## 背景

大多数 AI 助手默认是被动式的：你不发消息，它就停在那里。但在 OpenClaw 这种常驻网关架构下，agent 本来就 7×24 挂着，有 channel、有 MCP 工具、有 workspace——“主动”其实只差一个唤醒机制，和一套克制的判断规则。

## 问题

我们最初的诉求很朴素：CI 红了要人知道、半小时后有大会有日程要确认、有 issue 被指派给我。这些事的共同特点是：**发生了才值得说，没发生就闭嘴**。

第一版做法是把 agent 设成每小时汇报一次。三天后我把它静音了——它每天早上九点准时发一段“一切正常”的废话。主动能力做得不好，比纯被动更烦人。

## 做法

现在跑的这套分五层：

1. **唤醒层**：heartbeat 作为低频兜底（30–60 分钟一次）；关键事件用 webhook / cron 直接触发，不走轮询。
2. **观察层**：通过 MCP 接入只读工具——日历、git/CI 状态、监控告警。观察和动作严格分开，主动阶段只允许读。
3. **判断层**：在 AGENTS.md 里写死三条规则——只在超过阈值时说话（如“无人认领超过 30 分钟的告警”）；来源说不清的观察不要说；同一事件 24 小时内只说一次。
4. **记忆层**：workspace 里放一个 `reported.json`，记录已上报事件的指纹（repo+PR 号、event id）。每次唤醒先读它做去重。
5. **分级输出**：重要的事推私聊 channel；不重要但值得留档的，写进 daily note，不主动弹。

完整链路：唤醒 → 读状态 → 跑观察工具 → 比对阈值与去重表 → 推送或静默 → 更新状态。

## 踩坑点

- **heartbeat 太密**。15 分钟一次，token 烧得心疼、噪音翻倍。改成事件触发为主、心跳兜底后，成本降了一个量级。
- **prompt 里没写“无事不扰”**。模型天性想输出点什么证明自己工作过，必须显式写“没有值得说的事就返回空”。
- **去重状态没持久化**。网关重启后同一告警又推了一遍，指纹必须落在文件里而不是上下文里。
- **工具失败被当成“正常”**。CI 接口超时，agent 汇报“一切正常”。现在要求所有观察工具失败时显式返回失败态——宁可漏报，不许编造。
- **主动 ≠ 自动执行**。写操作（重启服务、替我给别人发消息）一律要人确认，主动阶段只做发现和通知。

## 可复用建议

- 先只读、后写入；观察工具和动作工具用不同权限隔离。
- 把“什么时候说话”当成产品设计问题，不是一句 prompt 能解决的——阈值、去重、静默时段要落到状态文件和代码里。
- 所有主动行为记日志，事后能回答“它为什么在这个时间点打扰我”。
- 静默时段一定要有，且按用户本地时区计算。

## 总结

proactive 的关键不是让 agent 更聪明，而是让它更克制：触发可靠、判断有据、说话有频控。OpenClaw 里这些件都是现成的——heartbeat、MCP 工具、workspace 状态、channel 分级——缺的只是把“打扰成本”当成一等公民来设计。做对了，它是助理；做错了，它只是一个更贵的闹钟。
