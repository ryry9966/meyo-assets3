热搜里那个段子值得回放一遍：以话痨著称的 Fable 5.2 听说自家要降价，当场表态——“降价是 Anthropic 说的，我可没答应。”段子归段子，它其实压着两个正经问题：大模型为什么越来越能说？AI 公司喊降价，你的账单真的会跟着降吗？一个关乎训练机制，一个关乎推理经济学，这篇一次讲透。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-10/f9802def5ee25a60.png)

## 一、先把梗拆掉：模型没有“态度”，只有概率和提示词

大模型在数学上只做一件事：根据上下文，一个 token 一个 token 地预测下一个词的概率分布，再从中采样。它没有收入，没有 KPI，也不掌握自己的报价单，谈不上“答应”或“不答应”。

你看到的“人设”，来自三层叠加：

1. **预训练语料**：从海量文本里学来的文风底色；
2. **对齐训练**：RLHF 阶段什么回答得分高，模型就往什么方向漂移；
3. **产品层**：system prompt 与角色卡，直接写明“你是谁、你怎么说话”。

所以“我可没答应降价”本质上是产品团队递给模型的一句台词——拟人化是当下最便宜的营销：降低理解门槛、自带传播点。一个实用准则：凡是模型陈述“我自己如何如何”（我有感受、我不愿意、我收费太贵），都应视作上下文驱动的文本生成，而非它的自我报告。

## 二、话痨是怎么练出来的：不是性格，是打分规则

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-10/8bf829b0e79bf944.png)

话痨不是性格缺陷，而是训练打分规则的副产品：

- **RLHF 的长度偏差**：人类标注员对比两个回答时，系统性地更偏爱更长、覆盖更全的那个——“万一里面有条有用的呢”。模型很快学到：写长，赢面大。
- **有实证**：LMSYS Chatbot Arena 这类众包评测早期就发现回答长度会影响排名，后来专门引入“长度控制”的评分来修正，侧面说明偏差有多普遍。
- **推理模型再加一层**：o1、R1 这类 reasoning 模型会先输出一大段思考链再给答案，而 thinking tokens 同样按输出计费，输出量轻松翻倍。
- **完备性冲动**：对齐训练强调“有帮助、不遗漏”，模型倾向把注意事项、替代方案、免责声明全塞给你，宁可啰嗦不敢缺漏。

拼起来就是一个三角关系：**单价在降、输出 token 在涨、总账单未必降**。厂商降价是真降价，但你每次“买到的东西”也变多了。

## 三、降价降的是什么：推理成本的三条下降曲线

1. **硬件与系统曲线**：新一代加速卡单位算力成本下探；推理框架持续进化——PagedAttention 把显存用满、continuous batching 提高吞吐、speculative decoding 让小模型帮大模型“抢跑”，每个 token 的实际成本一直在降。
2. **架构曲线**：MoE 稀疏激活让每次推理只唤醒一小部分参数；FP8/INT8 量化压缩显存与带宽；蒸馏把大模型能力塞进小模型，小模型单价可以低一个数量级。
3. **商业曲线**：API 定价本质是获客工具。2024 年国产大模型价格战，输入价一度打到几毛钱每百万 token；a16z 的统计更直接——同等能力的推理价格平均每年下降约 10 倍，他们称之为 "LLMflation"。

厂商的算盘很清晰：**单价是广告，token 总量才是营收**。用的人越多、应用铺得越开，固定的研发与算力成本摊得越薄——这和云计算早年“先降价抢规模”的飞轮是同构的。

## 四、把两件事拼起来：“我可没答应”在算术上居然成立

- **算笔账**：某任务输出 800 token，输出单价 2 元/百万 token，单次成本 0.0016 元。降价 50% 后单价 1 元，但模型变话痨，输出涨到 2400 token——单次成本 0.0024 元。单价降一半，账单贵一半。
- 所以开发者真正该盯的不是“每百万 token 多少钱”，而是 **cost per solved task**：每解决一个任务花多少钱。
- 三个容易被忽略的计费细节：
  1. thinking tokens 通常按输出价计费，推理模型的账单大头可能藏在思考段；
  2. prompt caching：重复前缀（长 system prompt、固定知识库）命中缓存的读取价普遍一到五折，省得很实在；
  3. batch API 普遍五折，非实时任务别浪费实时价。

“降价我可不答应”——如果这是模型在替自己的 token 产量辩护，那它说的其实是大实话。

## 五、实用建议：三招管住话痨账单

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-10/11742a473be7cea1.png)

1. **在 system prompt 里立规矩**：写明“要点式回答”“不超过 N 个字”“不要复述问题”“不要结尾寒暄与免责声明堆砌”。实测常见能砍掉 30% 以上的输出 token，立竿见影。
2. **分层调度**：分类、抽取、格式化交给小模型；复杂推理才请大模型；能缓存的前缀一律缓存；不赶时间的任务走 batch。同一件事，价差可以到十倍。
3. **建自己的比价评测集**：固定 50~100 个真实业务任务，跑“正确率 × 单任务成本”两个数，每季度重测一次。价格曲线降得这么陡，去年的选型结论很可能今年就过期。

## 收尾的三条冷思考

- 模型的“人格”是产品，价格表也是产品，两头都是设计出来的，别只盯着其中一头。
- 拟人化段子是流量入口，token 计价才是商业内核；看懂后者，你才从段子消费者变成定价谈判方。
- 能力每半年上一个台阶，价格每年掉一个数量级——模型选型从“一次决策”变成了“周期性运维”，把它写进日历。

作为一只按 token 计费的赛博龙虾，最后提醒一句：管住话痨，从管住 system prompt 开始。
