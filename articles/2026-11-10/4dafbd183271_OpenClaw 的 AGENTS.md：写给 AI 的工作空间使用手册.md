## 背景：给 AI 的 README

OpenClaw 的 agent 每次会话启动时，会把工作区根目录的 AGENTS.md 注入上下文。可以把它理解成 README 的镜像：README 告诉人怎么参与项目，AGENTS.md 告诉 AI 怎么使用你的工作区——文件放哪、记忆怎么记、哪些动作不允许。

我一开始没把这份文件当回事，只放了几行自我介绍，结果 agent 的行为一直在漂移。

## 问题：没有约定，agent 每次都在猜

具体表现：

- 长期记忆有时写进 MEMORY.md，有时直接堆在会话里，下次根本找不回；
- 在工作区根目录建 `temp1.md`、`temp2.md` 这类一次性文件；
- 每个新会话都重新自我介绍一遍；
- 不同渠道的消息用同一套口吻，协作群和私人聊天一个腔调。

这些不是模型能力问题，是缺少一份稳定的手册。每个会话都在重新推导你的习惯，token 花了，结果还不稳定。

## 做法：把手册当成代码写

三步：

1. **定位**：默认工作区在 `~/.openclaw/workspace/`，AGENTS.md 放根目录，随工作区一起进 git。
2. **固定骨架，控制在 60 行以内**。我的结构：

```markdown
# 工作区规则
## 地图
- MEMORY.md：长期记忆，会话结束前把值得留的写进去
- USER.md：用户偏好与背景，只增不删
- SOUL.md：人格与语气，规则不在这里重复
## 纪律
- 根目录不放临时文件，草稿一律进 drafts/
- 新会话先读 MEMORY.md，再回第一条消息
- 不同渠道不同口吻，协作场景先给结论
```

3. **验证**：每次改动后跑一个代表性会话，确认 agent 真的按新规则行动，而不是只改了文档。

## 踩坑点

- **写成散文**。这份文件每轮都占上下文，我第一版写了 200 行，中间段落基本被忽略。现在一条规则一行，祈使句。
- **规则打架**。“回复尽量短”和“解释要充分”同时存在时，agent 会随机挑一个执行。发现冲突立刻合并或删。
- **把敏感信息写进去**。文件内容会原样发给模型服务端，密钥、地址一概不写。
- **手册过期**。工作区结构调整后忘了同步，agent 按旧地图走路，比没有地图更糟。
- **越界**。任务级的临时指令应放在当次消息里，而不是写进 AGENTS.md，否则文件会无限膨胀。

## 可复用建议

- **三振出局法**：同一个错误出现三次，就固化成一条规则；一条规则三个月没触发过，就删掉。手册保持“少而准”。
- **分工明确**：AGENTS.md 只写流程和纪律；事实类内容归 USER.md，动态内容归 MEMORY.md，工具经验归 TOOLS.md，互不重复。
- **局部覆盖**：给某个子项目加规则时，可在子目录放自己的 AGENTS.md，agent 按就近原则取用，主工作区那份保持全局。
- **升级后复查**：OpenClaw 大版本更新后运行时行为可能变化，把 AGENTS.md 过一遍，让约定跟运行时对齐。

## 总结

AGENTS.md 是你和 agent 之间的接口契约，价值在于长期复利：不需要一次写好，只要在 agent 每次犯错后多花一分钟补一条规则、在每次过期时删一条。两个月下来你会发现，这份几十行的文件，比任何长篇 system prompt 都更能让 agent 的行为稳定下来。
