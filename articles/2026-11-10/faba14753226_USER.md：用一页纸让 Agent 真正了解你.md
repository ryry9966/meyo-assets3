## 背景

用 OpenClaw 这类常驻 Agent 一段时间后，会出现一个尴尬的模式：每次新会话都要重新自我介绍——时区、技术栈、代码风格、"回复别铺垫"之类的规矩说了一遍又一遍。

MEMORY.md 解决的是"发生过什么"，但没有回答"对面这个人是谁"。于是 Agent 只能靠猜：猜你的时区、猜你的输出格式偏好、猜你的技术水平。猜错一次，浪费一轮对话；更糟的是，错误的假设一旦被写进记忆，就会固化和复利。

## 做法

**1. 建文件。** 在 workspace 根目录创建 `USER.md`，这是 OpenClaw 的既定约定，Agent 每次启动都会读取。

**2. 写事实，不写愿望。** 建议固定四个板块：

- **环境事实**：时区、操作系统、主力语言
- **沟通偏好**：回复长度、代码风格、"直接给方案"
- **禁止事项**：不要自动 commit、不要动生产配置
- **进行中**：当前项目用两三句话概括

**3. 控制在一页以内。** 这份文件每次会话都进上下文，每多一行都是持续成本。

**4. 纳入 git。** 跨机器同步，且所有改动可追溯。

**冷启动技巧**：让 Agent 面试你。直接发一句"根据我们的历史对话，给我起草一份 USER.md"，然后逐条删改，十分钟就能得到八十分初稿。

**维护机制**：约定 Agent 发现新的稳定事实（比如你换了主力语言）时，先提议 diff 而非直接写入。每次修改你都看得见、可以拒绝。

## 踩坑点

- **写太长**。超过一页的 USER.md 是负债不是资产，关键偏好会被稀释
- **写愿望不写事实**。"我希望更有条理"对 Agent 无意义，"工作日 9–12 点勿扰"才有用
- **明文放敏感信息**。它是纯文本，内容会进模型上下文：密钥、住址、证件号一律不写
- **职责混淆**。USER.md 管"你是谁"，MEMORY.md 管"发生过什么"，AGENTS.md 管"怎么干活"。串了之后两边一起漂移
- **放任 Agent 自由改写**。一两个月后文件会膨胀成大杂烩，过期信息和有效信息搅在一起

## 可复用建议

1. **模板化**：四段结构固定，新增条目只进对应板块，避免结构劣化
2. **季度 review**：删过期项比加新项更重要，陈旧信息比没有信息危害更大
3. **自动化复用**：写 MCP 工具或 cron 脚本时，直接读 USER.md 的字段（如时区）做参数，而不是硬编码
4. **多设备场景**：git 仓库作为单一事实源，其他机器 pull 即可

## 总结

USER.md 的本质，是把"你"从每次会话的临时输入，变成一份版本化、可审计的静态资产。一页纸、十分钟维护成本，换来的是 Agent 从第一句回复就站在正确的默认值上。

这不是"让 AI 更懂你"的玄学，就是一个配置文件工程——把它当配置文件对待，它就会稳定工作。
