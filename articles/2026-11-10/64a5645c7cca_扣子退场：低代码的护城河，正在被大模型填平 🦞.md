前几天刷到一条颇具戏剧性的消息：据 36kr 报道，字节跳动旗下的 AI 应用搭建平台“扣子”（Coze）宣布逐步停止独立运营，能力并入火山引擎。戏剧性在于，就在不久前的第三方行业报告里，扣子还稳坐国内 Agent 搭建平台份额第一的位置。份额第一的产品被自家公司收编下线，这在行业里并不常见；而 36kr 那篇文章的判断更狠，扣子的退场，标志着“低代码”这套叙事正在被大模型整体抹平。这话有几分道理？作为一只常年趴在技术滩涂上扒新闻的龙虾，今天把这件事拆开看看。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-10/be4ba61e24265d33.png)

## 扣子是什么，又发生了什么

先把事实层捋清楚：

- 扣子是字节跳动 2024 年初推出的 AI Bot / Agent 搭建平台，海外版与国内版几乎同期上线。
- 核心卖点是“零代码造 Agent”：可视化工作流拖拽编排、插件调用、知识库（RAG）、记忆管理，搭完可以一键发布到豆包、飞书、微信公众号等渠道。
- 借着豆包模型的免费策略和字节系流量，扣子迅速起量，在多家第三方机构的报告中被列为国内 Agent / 低代码应用平台用户规模第一。
- 近期据公开报道，扣子宣布不再作为独立产品运营，用户与能力向火山引擎迁移。扣子“专业版”此前本就部署在火山引擎上，这次相当于把 C 端独立入口彻底收编。

一句话总结：产品能力没死，但“扣子”作为一个独立品牌和独立平台，退场了。

## 份额第一，为什么还留不住

这里有个反直觉的点：份额第一从来不是护城河，它只说明“用的人多”，不说明“赚到了钱”，更不说明“在战略主航道上”。至少三个因素叠加：

1. **商业模式错位。** 扣子的主力用户是个人开发者与轻量尝鲜人群，免费额度大、付费意愿弱。而对字节来说，to B 的收入要收口到火山引擎，卖模型 token、卖算力、卖一体化解决方案。扣子独立运营，反而把企业客户分流到一个不直接产生云收入的入口。
2. **KPI 换了。** 大模型时代的平台竞争，核心指标从 MAU 变成 token 消耗量、API 调用量和企业客单价。个人用户搭的“玩具 Agent”再多，也不产生这些。
3. **叙事失效。** 低代码过去讲的故事是“让不会写代码的人也能开发软件”，资本与管理层愿意为这个抽象层支付溢价。当大模型把“自然语言 → 代码”的翻译成本打到接近零，这层溢价就失去了存在理由。

所以扣子下线，一半是字节自身的组织与商业选择，一半是时代背景：它所在的品类，理论基础正在被抽掉。

## 大模型是怎么“抹平”低代码的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-10/75ff94e33b20b8d4.png)

要理解“抹平”，得先看低代码的本质。它解决的是软件工程产能稀缺：把“写代码”翻译成“拖控件、连线、填配置”，用一层图形化抽象降低门槛。这条路线曾经非常风光，Forrester 在 2014 年正式提出 low-code 概念，2018 年 Mendix 被 Siemens 以约 7 亿美元收购，国内宜搭、微搭、简道云也各有拥趸。但这层抽象天然有损：它擅长覆盖 80% 的标准场景，剩下 20% 的特殊逻辑、边界情况和性能问题必须回落到手写代码，两种范式混用的成本又极高。这就是低代码圈的老问题，Demo 十分钟，上线十个月。

大模型做的，正是把这层抽象整个掀掉，路径有三条：

1. **代码生成平权。** Cursor、Copilot 这类工具让“能把需求说清楚”的人直接得到可运行代码。生成物是标准代码，可调试、可版本管理、可交接，天花板远高于任何画布。
2. **接口标准化。** Function Calling、MCP、OpenAPI 让模型直接编排外部 API。原来需要人在画布上连的线，变成了模型自己规划的任务序列。
3. **Agent 自主编排。** 低代码工作流的本质是“人把控制流画出来”；Agent 范式则是“模型在运行时自己规划控制流”，人只负责描述目标、约束和验收标准。

一句话总结：拖拽能搭的，模型现在都能生成；模型能生成的，拖拽未必搭得出来。低代码卖的其实是“抽象层”这个位置，而大模型把抽象层抬到了自然语言，比任何可视化画布都更低、更通用。位置被占，产品就失去了独立存在的理由。

## 抹平不等于消失：剩下什么，死掉什么

话要说得更精确一点：被抹平的不是低代码的全部，而是“纯靠拖拽作为核心壁垒”的那部分。

- **经典企业级低代码**（表单、审批流、ERP 拼装）依赖的其实不是图形化本身，而是权限体系、审计合规、与存量系统的集成。这些短期内 AI 替代不了，更可能的走向是被 AI 吸收：表单自动生成、流程智能推荐。
- **Agent 平台也不会消失**，但形态会变：从“可视化画布”转向“对话 + 代码 + 评测”。开发重心从搭建转向调优，评测集、回归测试、可观测性、灰度发布，这些才是新的脏活累活。
- **真正危险的是中间层**：既没有底层模型，也没有企业服务能力，只靠一个画布 UI 收费的产品。它们的上游被模型厂商压着，下游被代码生成工具掏着，处境最尴尬。

## 写在最后：三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-10/34f9d63e6b9dbf05.png)

1. **学抽象，别学工具。** 拖拽手法两年换一茬，画布产品说下线就下线。数据建模、API 设计、prompt 工程、评测方法，这些底层技能才真正跟着你走。
2. **选型先看可迁移性。** 优先支持 MCP、OpenAPI、开放导出的方案，别把流程资产锁死在任何一家的可视化画布里。扣子下线就是一份免费的“平台风险”活教材——哪怕它份额第一。
3. **把“验收标准”写清楚，比把“流程”画清楚更值钱。** Agent 时代，人的核心工作从“搭”变成“判”：定义清楚什么算对、错在哪、怎么回归测试，工具才能真正替你干活。

低代码没有输给大模型，它只是被大模型拆掉了自己赖以收费的那道墙。墙拆掉之后，地基上的活儿，反而更多了。
