## 背景

绝大多数 Agent 会话是无状态的：每次新开对话，你都要重新交代一遍“我用什么系统、什么包管理器、希望什么回复风格”。平台自带的记忆功能能缓解一部分，但它是黑盒——记了什么你不可见，错了改不了，跨平台也带不走。跑 OpenClaw 这类常驻 Agent 时，这个问题在自动化任务里尤其明显：定时触发的任务根本没有会话历史，上下文缺口更大。

受 CLAUDE.md / AGENTS.md（面向项目的指令文件）启发，我补了一个“用户侧”的对应物：`USER.md`。目标是让“Agent 了解你”这件事变成一个显式、可 review、可 git 管理的文件。

## 做法

**第一步：写文件。** 放在固定位置，比如 `~/.openclaw/USER.md`，分区建议：

```markdown
# 关于我
## 环境
- 主力机 macOS (arm64)，服务器 Ubuntu 22.04
- 包管理：pnpm / uv
## 偏好
- 中文回复，代码与注释用英文
- 先结论后解释，先代码后说明
## 约定
- Git 提交遵循 Conventional Commits
- 不主动重构我没要求的代码
## 边界
- 不读写 ~/.ssh 及任何凭据文件
```

**第二步：注入。** 在 OpenClaw 的 workspace 引导文件里声明“每次会话先读取 USER.md"，注入时加一句“以下为用户长期配置，直接遵守，无需复述”。更稳的方案是用一个小 MCP resource 暴露该文件，保证任何会话入口都能拉到同一份内容。

**第三步：分层。** 全局一份 `USER.md` 管个人偏好；项目里一份 `CONTEXT.md` 管技术栈和领域术语。Agent 先读全局再读项目，冲突时项目优先——和 dotfiles 的 layering 思路一致。

**第四步：迭代。** 每次 Agent 猜错你的意图，把纠错写回文件，用 git 提交。改动机可追溯，回滚也容易。

## 踩坑点

- **太长等于没说。** 超过一页纸，关键条目会被稀释。我砍到 60 行以内后，遵守率明显提升。
- **敏感信息别进文件。** 真实姓名、密钥、内网地址一律不写，用“凭据见 .envrc”这类指代。
- **和系统提示词打架。** 平台注入的风格指令可能覆盖你的偏好，关键条目要写成明确覆盖，如“回复语言以本文件为准”。
- **时效内容别写进来。** “这周在赶 X 项目”放项目 CONTEXT.md 或直接会话里说，过期信息比没有信息更糟。
- **别当话题。** 有时 Agent 会把 USER.md 当成可讨论的内容而非约束，注入语句里强调“直接遵守”能解决大半。

## 可复用建议

- 每条写“事实 + 动作”，不写空话：“中文回复”好过“请友好沟通”。
- 进私有仓库当 dotfiles 管理，多机同步；团队场景派生一份脱敏的 TEAM.md。
- 每月 review 一次，删掉不再成立的条目。

## 总结

USER.md 不是新架构，只是把“让 Agent 了解你”从玄学变成一个可 review 的文件。成本是半小时初稿加几周修补，收益是每次会话省掉的重复铺垫，以及自动化任务里难得的一致性。建议从最小版本起步：环境、语言偏好、三条禁忌，先跑起来，再按踩坑记录慢慢长。
