## 背景

OpenClaw 这类常驻 Agent，体验的分水岭往往不在模型能力，而在上下文。`AGENTS.md` 解决的是"你怎么干活"，但一个更基础的问题长期被忽略：Agent 不知道"你在跟谁说话"。

## 问题

没有 USER.md 时的典型症状：

- 每个新会话都要重新交代：时区、语言习惯、技术栈、代码风格偏好
- Agent 自行假设，然后出错——默认写英文文档、用 npm 而你全套是 pnpm、在 macOS 环境里给 apt 命令
- 这些事实散落在历史对话里，清会话、换设备即丢失

本质是：关于用户的事实，缺少一份权威、持久、可注入的载体。

## 做法

1. **固定路径建文件**，如 `~/.openclaw/USER.md`，并在 AGENTS.md 中声明会话启动时读取。
2. **内容分两层**：
   - 静态层：称呼、时区、工作语言；OS、shell、编辑器、包管理器；稳定偏好与禁区
   - 动态层：当前项目、本周目标、正在回避的坑，每两周更新一次
3. **控制篇幅**：30–60 行为宜。它每轮都注入上下文，写得像简历只会稀释注意力。
4. **更新走显式指令**：说"把这个偏好记下来"，让 Agent 给出 diff 再确认，优于放任自动追加。

骨架示例：

```markdown
# USER.md
## 身份
- 称呼：老张；时区 Asia/Shanghai；工作语言中文
## 环境
- macOS 14 / zsh；编辑器 JetBrains；包管理 pnpm
- 主力 TypeScript、Go；部署 Docker + 自建 K8s
## 偏好
- 技术回复直接给结论和命令，少铺垫
- 文档一律中文；commit message 英文
## 当前
- 某项目插件化改造中，deadline 下月中
```

## 踩坑点

1. **写太长**。见过 200 行的 USER.md，Agent 每轮背着它，回复明显跑偏。超过一屏就该砍。
2. **信息过期**。三个月前的"当前在做"还留着，Agent 会一本正经引用已死的分支。
3. **塞敏感信息**。密钥、密码、证件号别放——这是明文，会随上下文发到模型服务端。
4. **与 AGENTS.md 职责混淆**。"回复要简洁"是行为规则，归 AGENTS.md；"我是后端工程师"是事实，归 USER.md。两边重复写，两边都会被削弱。
5. **只增不减**。记忆条目堆积后互相矛盾，删除和新增同样重要。

## 可复用建议

- 把 USER.md 当配置文件管理：进 dotfiles 仓库，走版本控制，改动可回溯
- 分层：全局一份 USER.md，项目细节留在各自的 AGENTS.md，别混
- 每月做一次 diff 审查，优先删过期项
- 验证注入生效的方法：偶尔问 Agent"你基于哪条信息做了这个判断"，能引用到 USER.md 条目，说明链路通了

## 总结

USER.md 是投入产出比最高的一类上下文工程：成本几十行文本，收益是省掉无数轮重复交代与错误假设。不必追求一次写全，从真实摩擦点出发——这次它猜错了什么，就把正确答案写进去。三个月后回头看，它大概率是你的 Agent 资产里最值钱的一小块。
