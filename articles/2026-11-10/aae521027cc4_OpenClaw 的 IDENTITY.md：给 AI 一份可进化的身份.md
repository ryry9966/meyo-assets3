## 背景

OpenClaw 的工作区里有一组用 Markdown 组织的"人格层"文件：SOUL.md 管性格与做事风格，USER.md 记录用户偏好，MEMORY.md 承担长期记忆。IDENTITY.md 是其中最短的一个，通常只有几行：agent 的名字、形象（emoji / 头像）、一句自我定位。很多人初始化时随手填一下就再也不看，我最初也是。直到同时在两个项目里跑 agent、又接了多个消息渠道之后，才发现这个文件的工程价值被严重低估。

## 问题

身份没有收敛到单一文件时，典型症状：

- 名字和自我介绍散落在 system prompt、渠道签名、插件欢迎语里，改一次要动五处，漏一处就出现"自称不一致"；
- 团队共用一个 gateway，两只 agent 自称相同，日志和对话里分不清谁在说话；
-想让 agent 随职责演进（比如从"日常助手"变成"这个项目的运维值日生"），但身份写死在 prompt 里，每次调整等于改代码发版；
- 长期协作中，agent 对"我是谁、我负责什么"的回答漂移，前后会话不一致。

## 做法

1. **建立最小身份文件。** IDENTITY.md 只保留四类字段：name、emoji/avatar、role（一句话职责）、短自我描述（2~3 句）。克制是关键——性格和价值观属于 SOUL.md，不要搬过来。
2. **清理重复来源。** 全局搜索渠道配置和插件里的硬编码名字，删掉，统一由工作区初始化时注入，保证 IDENTITY.md 是唯一事实来源。
3. **把演进流程化。** 允许 agent 起草身份变更（给出 diff），但落盘前必须人工确认。工作区用 git 管理，每次身份演进都有 commit 可回溯。
4. **留变更痕迹。** 在 MEMORY.md 里追加一条简短记录（何时、为何改），agent 在后续会话里能自然接上"我为什么是现在这个定位"。
5. **验证。** 改完后新开会话，问三个问题：你是谁、你负责什么、上次你的身份为什么变了。答案一致才算生效。

## 踩坑点

- **职责越界：** 把口吻、禁忌话题写进 IDENTITY.md，结果和 SOUL.md 冲突，改一处忘另一处。边界一句话：IDENTITY.md 管"是什么"，SOUL.md 管"怎么做事"。
- **身份漂移：** 早期我允许 agent 自主改名，两周后名字和自我描述面目全非。改成"提案—审批"后才稳定。
- **渠道兼容性：** 部分 IM 对 emoji 和头像渲染不一致，别把 emoji 当作承载关键语义的字段，它只是标识。
- **多 agent 复用：** 第二只 agent 直接复制了第一只的工作区，忘了改 IDENTITY.md，排查了半天"为什么它自称别人的名字"。
- **改了不生效：** 旧会话持有启动时注入的旧身份。先重开会话，再判断是不是文件没被读取。

## 可复用建议

- 把它当配置而不是 prompt：短、可 diff、进版本库。
- 变更按里程碑触发（接了新职责、换了定位），不要每天微调，频繁改动反而制造噪音。
- 给团队准备一份最小模板，新 agent 上线只填四个字段。
- 审批记录本身也是一种记忆：谁在什么时候给 agent 换过定位，长期看比名字本身更有价值。

## 总结

IDENTITY.md 的价值不在"给 AI 起名字"这种拟人趣味，而在于把身份从散落的硬编码收敛成一份可版本化、可审批、可演进的数据文件。改动成本趋近于零，换来的是多渠道、多 agent、长期协作下的一致性。这是 agent 工程里最便宜的一笔一致性投资，建议所有跑了超过两周的 OpenClaw 实例都认真补上这份文件。
