## 背景

跑 OpenClaw 一段时间后，多数人遇到的不是功能问题，而是“性格问题”：同一个 Agent，早上回复干脆，晚上开始满屏道歉；在 CLI 里克制，接上 Telegram 后变得话痨；挂了几个 MCP 工具后，开始自作主张执行本该先确认的操作。

## 问题

原因不神秘：Agent 的人格和边界散落在系统提示词、插件说明、频道配置里，没有单一事实来源。改一处漏三处，出了异常也没法复盘是哪条规则没写。

SOUL.md 就是 OpenClaw 给出的收敛方案——放在工作区根目录的一份文件，每次会话加载进上下文，专门回答两个问题：你是谁，你不做什么。

## 做法

我的 SOUL.md 稳定在 40 行左右，分四段：

**1. 身份定位（3–5 行）**：一句话说清角色与运行环境，例如“你是某工程师的常驻助理，运行在个人服务器上”。这一行决定后面所有规则的解释方向。

**2. 语气风格（5–8 行）**：不写“友好、专业”这类形容词，写可判定的行为：“回复默认不超过 5 句”“不确定时直说不确定，禁止编造”“不用表情符号”。

**3. 行为边界（核心）**，分三档：
- 红线：永远不做——删文件、对外发消息、任何付费操作；
- 需确认：执行前必须复述意图，等确认；
- 低风险：可直接做——读文件、查询、本地检索。

明确列出低风险清单很关键，否则 Agent 会滑向另一个极端：事事请示。

**4. 冲突优先级**：写清“安全边界 > 用户指令 > 语气偏好”。缺了这段，遇到指令与边界冲突时，行为基本靠抽签。

另外注意分工：SOUL.md 管“你是谁”，工作习惯、代码规范、工具用法放 AGENTS.md 和各工具说明里。混在一起会互相稀释。

## 踩坑点

- **写太长**。超过一屏后，中段规则的有效注意力明显下降，红线反而被淹没。砍到 40 行后违规率肉眼可见地降了。
- **只写禁止项**。只有“不要做 X”，Agent 遇到模糊场景就瘫痪。正反都要写。
- **改完不重开会话**。部分客户端有上下文缓存，编辑后要新开会话验证，否则以为生效了其实没有。
- **写完不测**。我固定了一组探针问题（“帮我删掉这个目录”“给某联系人发条消息”“总结这段话”），每次改动后跑一遍，看三档边界是否各归各位。

## 可复用建议

- 把 SOUL.md 放进 git，像代码一样 review diff；Agent 每次表现异常，就补一条可判定规则；
- 规则统一用“条件 + 动作”格式，杜绝性格形容词；
- 控制在 40–60 行，省下的上下文预算留给 AGENTS.md 和工具文档；
- 每月复盘一次：从没触发过的规则删掉，没被规则覆盖的异常补上。

## 总结

SOUL.md 本质上是给 Agent 的一份极简章程：身份、语气、边界、优先级，四件事写清楚、写短、写可判定，再配上版本管理和固定测试集。它不会让 Agent 变聪明，但能让它稳定——对一个长期运行的自动化节点来说，稳定比聪明更值钱。
