36kr 一篇实测把腾讯混元 Hy4 推上了热议，两个关键词被反复提起：**基模原生视觉**、**Agent 跨应用**。前者说的是模型"出厂自带眼睛"，后者说的是它能替你在多个 App 之间跑腿干活。这两件事单独看都不算新，凑在一起却指向同一个趋势——大模型竞争的主战场，正从"聊天谁更聪明"转向"任务谁能办成"。这篇文章拆三件事：原生视觉和"外挂视觉"差在哪、跨应用 Agent 的技术瓶颈在哪、以及"干活能力"到底该怎么客观评估。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/3d1a8e342f1a2ff7.png)

## 一、什么叫"基模有了视觉"：从外挂到原生

先说结论：原生视觉不是"给模型加个摄像头"，而是改了训练方式。

- **传统做法（外挂式）**：先训一个纯文本 LLM，再接一个视觉编码器（通常是 ViT/CLIP 这类），中间用 adapter 或投影层把图像特征"翻译"成文本 embedding。相当于两个系统后期缝合，像给电影配译制腔。
- **原生多模态**：预训练阶段就把图像 token 和文本 token 混在一起喂，模型从"识字"的第一天起就"看图"，视觉是母语不是配音。GPT-4o、Gemini 走的是这条路，国内 Qwen-VL、InternVL 系列也在快速跟进。

实测中能感知到的差异，主要落在三类场景：

1. **细粒度感知**：截图里的小字、密集表格、手写批注。外挂式容易"看不清就靠猜"，原生路线的字符级识别通常更稳。
2. **UI 理解**：按钮位置、输入框层级、图标语义——这些是 GUI Agent 的命根子，视觉底子不行，后面全白搭。
3. **推理路径更短**：外挂式要先"看图说话"再做文本推理，两次转换会丢信息；原生路线图文表征统一，图表题可以"直接看懂"而不是"转述"。

一句话总结：基模有视觉，本质上是在为第二件事——跨应用 Agent——铺路。

## 二、Agent 跨应用：听起来爽，难在哪

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/7e75600aa5a281e7.png)

跨应用 Agent 的定义很朴素：给它一个目标，比如"把这份会议纪要整理后发给项目群，再同步到日历"，它自己感知屏幕、规划步骤、点击输入、校验结果。技术链条是五段：

1. **感知**：读取截图或界面元素
2. **状态建模**：判断"我现在执行到哪一步"
3. **规划**：把目标拆成可执行的动作序列
4. **执行**：点击、输入、调用接口
5. **校验**：确认结果，失败则回滚或换路径

难点不在任何单一段，而在几组结构性矛盾：

- **误差累积**：单步准确率 95%，20 步任务的一次成功率只剩约 36%（0.95 的 20 次方）。写过长事务系统的人对此会心一笑——每一步都"大概率对"，整体就"大概率崩"。长程任务对每步可靠性的要求近乎苛刻。
- **UI 是活的**：弹窗、加载态、版本差异，都会让"背下来的操作路径"失效。模型必须真正"看懂"界面而不是死记坐标——这正是原生视觉的价值兑现点。
- **权限与安全边界**：跨应用意味着 Agent 可能触达支付、通讯、文件系统。授权粒度怎么设计、敏感操作要不要人工确认，是产品问题，更是工程问题。
- **评估难**：OSWorld、AndroidWorld 这类 GUI Agent 基准里，主流模型的任务完成率长期在爬坡，离"演示视频里的丝滑"还有距离。

所以看到"实测能跨应用"这类结论，重点不是问"能不能"，而是追问三个数：**一次成功率多少、平均几步、失败后能不能自己恢复**。

## 三、"干活能力"怎么测：别被跑分带节奏

媒体实测有真实价值，但要摆正位置——它是**参考点，不是基准线**。

- **Benchmark 在饱和**：MMLU 类知识问答普遍逼近天花板，还带数据污染嫌疑（训练语料可能见过原题），高分越来越难证明"会干活"。
- **更接近干活的指标**：代码看 SWE-bench（真实仓库改 bug），GUI 看端到端任务完成率，通用助手看 GAIA；再叠加工具调用准确率、JSON 结构化输出稳定性、长上下文多轮一致性。
- **别忘了成本**：MoE 架构下要看激活参数量而非总参数量。Agent 一跑几十步，单步延迟和 token 成本会被放大几十倍——"能干"和"干得起"是两回事。

36kr 这类实测样本量小、任务选择带主观性，适合当"场景样本"看，不适合当结论抄。真正的判断，得靠自己的任务清单。

## 四、往大里看：这一步棋在竞争什么

把镜头拉远，这两个特性反映的是行业共识的转移：

- **原生多模态是 Agent 的前置条件**，不是炫技。GUI Agent 拼的第一关就是感知，视觉底座不行，规划再聪明也抓不准那个按钮。
- **"模型—终端—应用"垂直整合**成为大厂打法：同时握着超级 App 和终端入口的玩家，Agent 可调用的应用多、授权深，生态优势会滚动放大。
- **API 形态在变**：从"对话补全"走向"任务委托"——给目标，返回结果。开发者接入的抽象层级在升高，竞争维度从模型分数转向任务完成率。

## 五、三条实用建议与冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/2ecc1982b7fcc72a.png)

1. **自己建一个 10 题任务清单**：挑真实工作里最高频的跨应用场景，记录一次成功率、平均步数、失败恢复情况。这比任何演示视频都诚实。
2. **敏感权限分级**：支付、发消息、删文件这类动作，先设只读模式或二次确认，让 Agent 当副驾而不是自动驾驶——至少现阶段如此。
3. **冷思考**：模型再强，天花板常常卡在任务定义不清。把目标、约束、验收标准说清楚，收益往往大于换更强的模型——对人如此，对 Agent 也一样。
