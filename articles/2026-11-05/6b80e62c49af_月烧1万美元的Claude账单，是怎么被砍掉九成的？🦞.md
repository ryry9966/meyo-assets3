最近技术圈热议一个案例：一家海外科技公司重度使用 Claude 做编程，每月账单约 1 万美元，痛感太强，干脆换了路线——改用智谱开源的 GLM 模型，自建 56 张 NVIDIA B200 组成的推理集群，扛住约 2000 名工程师的日常编码需求。据 36kr 报道，整体成本下降约 90%。这不是一个“薅羊毛”的故事，而是一道关于 AI 编程成本结构的算术题。把账拆开看，比只看结论有用得多。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/96a44787e293f281.png)

## 一、账单为什么失控：Agent 是台 token 碎钞机

- API 按 token 计费。以 Claude Sonnet 档为例，输入约 3 美元/百万 token、输出 15 美元/百万 token；Opus 档输出贵至 75 美元/百万 token。
- Agent 编程的工作模式是“循环”：读文件 → 写补丁 → 跑测试 → 看报错 → 再改，一个任务跑几十轮。每一轮都要把长上下文重新喂一遍，工具调用、报错日志这些中间产物全部计费。
- 举个具体例子：让 agent 修一个 bug，它可能先读 5 个文件（每次几万 token），改 3 版，每版都带着完整上下文重跑一遍——同一个任务重放 20 轮，实际消耗可能是“理想 token 数”的 10 倍以上。
- 实际感受：一个重度用户一天烧掉几千万 token 不稀奇，折算一人一月 300–500 美元很常见——“月烧一万美元”就是这么烧出来的；若放大到上千名工程师，就是每年数百万美元量级。
- 供应商也留了后门：prompt caching 能把命中的缓存输入打到约一折，batch API 半价。但 agent 每轮上下文都在变，缓存命中率天然不高——省钱空间有，救不了命。

## 二、九成折扣从哪来：租算力 vs 建算力

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/407b0fb69ec91fc6.png)

- 买 API，本质是按 token 租用别人的集群，价格里含研发摊销和利润；自建，是把变动成本换成固定成本：一次性买卡，之后只付电费、折旧和运维。
- 56 张 B200 的家底：单卡 192GB HBM3e 显存、约 8TB/s 带宽，合计超 10TB 显存。装下 GLM-4.6（355B 参数的 MoE，激活仅 32B）的权重绰绰有余，还能塞进海量 KV cache 扛高并发。
- MoE 是省钱的物理基础：推理算力跟着“激活参数”走，而不是“总参数”走。32B 的激活量只相当于一个中型稠密模型的开销，却保留了 355B 的知识容量——大，但不贵。
- 算账：B200 单价约 3 万美元上下，56 张光卡就接近两百万美元，加上整机与组网约 300 万美元量级；按三年折旧摊到每月约 8–9 万美元，再加电费和几名推理工程师的工资。
- 对面是多少？2000 名工程师按 300–500 美元/人/月的重度用法走 API，一个月 60 万–100 万美元。两相对照，“降九成”在数学上就成立了。
- 隐含前提：用量必须又大又稳。GPU 买来跑不满，就是机房里最贵的装饰品。

## 三、GLM 凭什么接得住 2000 名工程师

- 能力底座：GLM-4.6 在公开榜单 SWE-bench Verified 上约 68%，顶级闭源模型在 75%–80% 一档。差距存在，但没有代差；而编程是“可验证任务”——编译过没过、测试绿不绿，反馈信号清晰，开源模型在这类任务上追赶最快。
- 工程适配：200K 上下文、针对 agent 式工具调用做过专门训练，还提供与主流 agent 工具兼容的接口，把 Claude Code 的 base URL 改一下就能接入，迁移成本很低。
- 开源权重的隐性价值：权重可下载（宽松协议），意味着数据不出内网、没有限流、版本可锁定、还能微调。对大组织来说，确定性和合规有时比模型 IQ 更值钱。
- 补充路线：不买卡也行，直接用 GLM 的 API 或编程套餐，靠厂商补贴，入门价低到每月几十元人民币。中小团队走这条更合理；本案例选自建，纯粹因为规模大到“批发比零售便宜”。

## 四、新闻稿不会写的部分

- 人力成本：vLLM/SGLang 部署、吞吐调优、KV cache 管理、模型版本跟进，需要一个专职推理团队。自建不是凭空省钱，是把 OpEx 挪成了 CapEx 加人力。
- 质量长尾：最难的 10%–20% 任务，前沿闭源模型仍占优。全盘替换可能换来“平均便宜、尖峰变笨”，所以很多团队实际用混合路由：日常任务给 GLM，硬骨头留给 Claude。
- Jevons 效应：单价降 90%，人会自发用得更多——并行更多 agent、塞更长上下文、更大胆地试错。单位成本降九成 ≠ 总支出降九成，不少“省钱标杆”最后的真实结果是：产出翻了十倍，总账单只降了一半。未必是坏事，但要提前想清楚。

## 五、三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/ab517628be857ec8.png)

1. **先算盈亏平衡点，再谈自建。** 粗略公式：自建月成本 ≈ GPU 折旧 + 电费 + 运维人力；API 月成本 ≈ 单价 × 用量。前者是固定成本，后者是变动成本——用量小且波动大，API 永远赢；用量大且稳定，剪刀差才会打开。十人团队抄两千人团队的作业，多半是给自己挖坑。
2. **用“路由”替代“替换”。** 把任务分层：批量重构、样板代码、重复性修复交给便宜模型；架构设计、疑难 bug 交给前沿模型。再配合 prompt caching、batch、上下文裁剪，光靠工程手段就能先把 API 账单砍掉一半——很多人是账单爆炸之后才想起这些。
3. **把 token 当成本中心管。** 像管云账单一样管 AI 账单：统计每个任务、每个 PR 的 token 消耗，设预算和告警。这一轮降价潮的真正启示不是“换个便宜模型”，而是——token 的边际成本在塌方，agent 的用量在起飞，谁先建好成本观测体系，谁才敢真正放开手脚用。
