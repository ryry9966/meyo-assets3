最近互联网圈接连传来消息：字节的智能体开发平台“扣子”并入火山引擎、停止独立运营；腾讯的“元器”也启动业务调整，智能体迁移进腾讯云的智能体开发平台。两个上线一年出头、曾被寄予“下一个小程序生态”厚望的产品，几乎前后脚交卷。热搜把这概括为“大厂AI产品洗牌清退潮”，但只看热闹容易看偏——这两次下线更像一份公开的证伪报告：AI 中间层平台这条路，在大厂账本里暂时算不平。下面把逻辑一层层拆开。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/a9e56b11d4d93d17.png)

## 一、先对齐事实：下线的是什么，留下的又是什么

- **扣子（Coze）**：字节 2024 年 2 月在国内公测的低代码智能体平台，主打可视化 Workflow、插件、知识库，一度是 Bot 搭建圈的默认选项；2025 年年中前后团队与产品并入火山引擎，独立入口逐步收敛。
- **腾讯元器**：2024 年 5 月基于混元大模型发布的智能体平台，随后启动迁移，智能体承接方为腾讯云的智能体开发平台。
- 关键细节：两家的核心能力都没有“删库”，而是整体并入了自家云的 to B 产品线。死掉的不是技术，是“C 端平台生态梦”这个组织目标。
- 用工程师的话说：不是 `rm -rf`，而是一次 `git rebase`——代码还在，只是换到了另一条主干上。

## 二、三层拆解：智能体平台为什么撑不住

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/f17c6231f8fad22d.png)

1. **商业模式先天贫血。** 智能体平台是纯工具，付费意愿天然低；而用户每一次搭建和调用背后，都是实打实的推理算力成本——用量越大补贴越多，却不沉淀成壁垒。参照海外的 GPT Store：2024 年 1 月上线时被称作“AI 版 App Store”，预告过的创作者分成计划迟迟未兑现，第三方 GPT 热度一年内就凉了。连 OpenAI 都没把这笔账收平，何况后发者。
2. **分发故事没跑通。** 大厂做平台，图的是“开发者建站、平台收租”的小程序模式。但 AI 时代用户的心智是“直接问豆包/元宝”，而不是“去商店找一个问答机器人”。举个例子：智能体商店的热门榜上，长期霸屏的多是角色扮演类聊天机器人——这类需求用户一句 Prompt 就能让豆包自己演，何必先搭一个。没有分发，开发者赚不到钱；赚不到钱，就没人认真做内容，生态飞轮根本没转起来。
3. **技术范式半年一换代。** 2024 年那套“可视化编排 + 插件”的中间层，正被上下两股力量夹击：向下，基座模型原生支持 function calling，MCP 协议把工具接入标准化，“接线”成本骤降；向上，computer use 类通用 Agent 直接操作界面，连编排界面都绕开了。平台辛苦搭的脚手架，被模型每一次升级自动摊薄。
4. **组织账本不等人。** 降本增效周期里，AI 预算只向两个方向集中：旗舰入口（豆包、元宝）和云基建。一个增长平平、收入为零、还要跟主线抢模型资源的产品，排位必然靠后。

## 三、历史韵脚：入口确定之后，中间层总被收编

- 移动互联网时代的终局剧本：小程序平台最后是微信一家吃下绝大多数份额，其他大厂的同名产品大多沦为内部 KPI 项目，随后悄然降级。
- AI 时代正在重演：阿里把通义 App 并入夸克，to C 由夸克统一承接；月之暗面收缩投放；垂直小工具成批停服。行业收敛方向很清晰——少数超级入口 + 云端 to B 服务，中间层最受伤。
- 海外同步发生：OpenAI 的重心已从 GPT Store 转向 Operator、Agent mode 这类通用 Agent 能力。

## 四、资产去哪了：清退不等于归零

Agent 在工程上其实有两条路线：

- **自主规划型 Agent**：灵活，会自己拆任务，但路径不可控，出错难审计；
- **工作流编排**：死板，但每一步确定性高、可回溯、可审计。

企业生产环境要合规、要 SLA、要出事能查日志，天然偏爱后者。所以扣子的 Workflow、知识库资产搬进火山引擎后，服务的是愿意付钱的 B 端客户；元器并入腾讯云同理。同一套能力，从“冲 DAU 的生态项目”挪到“看营收的云产品线”，账本立刻就通了。

## 五、三条冷思考：在下一次洗牌前站稳

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/4876d4104accd305.png)

1. **押注平台前，先看它靠什么赚钱。** 回答不了“谁付钱、为什么付”的平台，生命周期按月计。选型时优先看它挂在母公司哪个 BU 的 KPI 下——挂 C 端增长线的工具平台，风险天然高于挂云营收线的。
2. **别把资产锁死在单一编排层。** Prompt 用纯文本存，知识库建在自己的数据库里，工具调用优先走 MCP 这类开放协议。平台可以下线，你的资产不该陪葬。
3. **中间层消失是常态，能力分层才是常态中的常态。** 基座模型每半年摊薄一次上层封装的价值，这不会停。对个人开发者，可迁移的长期能力——领域知识、数据资产、工作流设计——比绑定某个平台的操作技巧保值得多。

一句话收尾：平台会死，账本不会。看懂账本的人，才看得懂下一次洗牌的方向。
