最近工程师圈刷屏的 36kr 报道里有两个扎眼的细节：一边，有人每月在 Claude 上烧掉 1 万美元，直呼肉疼；另一边，据报道有公司干脆改用开源的 GLM，用 56 张 NVIDIA B200 自建推理集群，扛起 2000 名工程师的日常 AI 编程，成本直降约 90%。这条新闻真正值得聊的，不是“哪家便宜用哪家”，而是它把一个所有技术团队迟早要面对的问题摆上了桌面：**AI 编程的成本结构到底是怎么算的？省下来的 90%，又是从谁的口袋里省出来的？**

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/afed0b6885050b02.png)

## 一、账单是怎么烧起来的：Agent 是台 Token 碎钞机

先看钱花在哪。主流 AI 编程工具基本两种收费姿势：

- **订阅制**：Claude Pro $20/月，Max 档 $100–200/月，按席位收费；
- **API 按量计费**：以 Sonnet 档模型为例，输入约 $3/百万 token，输出约 $15/百万 token。

真正把账单推上去的，是 Agentic Coding（智能体编程）的工作方式：

1. 模型要反复读文件、跑命令、看报错、再修改，每次工具调用都会把上下文重新喂给模型；
2. 测试失败还会自动重试，一个看起来不大的改动，全程烧掉几百万 token 很正常；
3. 相比人类一问一答，Agent 模式下的 token 消耗高出 10–100 倍。

于是成本公式变得简单粗暴：**工程师人数 × 人均 token 消耗 × 单价**。几百个重度使用的工程师，每月一万美元只是起步价。

## 二、90% 的差额从哪来：租 API 与自建集群的两本账

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/95ad1a1618f38be2.png)

把两本账摊开算（数字为量级估算）：

**路线 A：继续租**（CapEx 转 OpEx）

- 2000 名工程师若都上 $200/月的 Max 订阅，月账单约 40 万美元；
- 好处是零运维、新模型即插即用；坏处是重度使用时边际成本极高，定价权在厂商手里。

**路线 B：自建**（OpEx 转 CapEx）

- 一张 B200（192GB HBM3e 显存、约 8TB/s 显存带宽）市价约 3–4 万美元，56 张约 200 万美元；
- 按 3 年折旧，每月约 5.5 万美元，加上电费（单卡功耗约 1kW）和运维人力，月成本约 7–8 万美元，还没算机房和网络；
- 摊到 2000 人头上，人均每月不到 40 美元。80%–90% 的降幅，账面口径下是算得出来的。

自建路线能成立，靠三个技术前提：

1. **MoE 架构**：GLM-4.6 这类 MoE（Mixture of Experts）模型总参数 355B 级，但每个 token 只激活约 32B，单 token 的推理算力需求大幅下降；
2. **推理框架成熟**：vLLM、SGLang 等支持 continuous batching 和 KV cache 复用，能把 B200 的利用率吃到很高；
3. **负载可预测**：工程师集中在工作时段使用，波峰波谷明显，便于容量规划和批处理。

一句话总结：open-weight 模型把“模型使用权”变成了“自有资产”，省掉的是厂商毛利、品牌溢价，以及重度使用的边际加价。

## 三、为什么开源模型这两年突然能打了

成本降 90% 的前提是质量“够用”。放在 2023 年，用二线模型换掉 Claude 是不可想象的；现在能成立，靠的是开源阵营的快速逼近：

- **基准成绩**：GLM-4.6 在 SWE-bench Verified 这类智能体编程基准上得分约 68%，头部闭源模型在 77%–82% 区间，差距存在，但已从“代差”缩小为“一档”；
- **长上下文**：200K 级窗口，装下一个中型代码仓库的关键文件够用；
- **开放协议**：GLM-4.5/4.6 以 MIT 协议开源，商用、微调、私有化部署无门槛；
- **同类竞品**：DeepSeek、Qwen3-Coder、Kimi K2 扎堆出现，形成了事实上的开源第一梯队。

背后还有一条更宏观的曲线：a16z 提出过"LLMflation"，同等能力的推理价格大约每年下降 10 倍。开源模型通常比闭源旗舰滞后半年到一年，但价格低一个数量级；对写单测、补全、小重构这类占日常 80% 的任务，这半年的代差不致命。

## 四、“便宜90%”的另一面：隐性成本清单

工程师的基本直觉：省下来的钱不会凭空消失，只是换了个地方付。自建路线的隐性成本至少有四项：

1. **运维人力**：GPU 监控、显存碎片、长尾请求、故障恢复，至少需要 1–2 名专职推理工程师；
2. **容量冗余**：2000 人早上十点同时开工的峰值，意味着平时利用率可能只有 30%–40%，闲置的 GPU 也是钱，只是不体现在模型账单上；
3. **质量长尾**：疑难 bug 定位、大型架构重构这类硬任务，闭源旗舰仍然占优——而这恰恰是资深工程师最需要 AI 的地方；
4. **迭代速度**：API 厂商几乎每周上新、修问题；自建集群的模型升级和量化调优节奏会慢一拍。

所以“成本降 90%”更准确的表述是：把一部分显性账单，转换成了隐性的人力与风险成本。规模够大、负载稳定的团队，这笔账划算；小团队照抄，大概率是给自己挖坑。

## 五、写在最后：三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/002c805f8573038e.png)

1. **先量化，再迁移。** 迁移前统计团队真实的人均 token 消耗和任务类型分布，用自家代码库做盲测对比，而不是只看榜单分数——榜单和你的业务代码之间，可能隔着一整个复杂度的鸿沟。
2. **混合路由往往是最优解。** 日常补全、小修小改走自建集群或低价方案（比如 GLM 的 Coding Plan，每月低至几美元）；硬骨头任务保留 frontier 模型。按任务分层，通常能拿到 80% 的成本节省和 95% 的质量。
3. **记住价格曲线的方向。** 推理价格还在快速下探，今天的重资产决策，半年后可能被更便宜、更强的 API 覆盖。买整机、签长约之前，给自己留一条退路，技术选型里最贵的错误从来不是选错，而是锁死。

AI 编程的竞争正在从“谁的模型更强”转向“谁的性价比曲线更陡”。对使用者来说这是好事：钱终于可以只花在刀刃上——剩下的，交给市场去卷。
