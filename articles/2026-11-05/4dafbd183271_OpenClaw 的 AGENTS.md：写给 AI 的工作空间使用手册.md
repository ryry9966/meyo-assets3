## 背景

OpenClaw 每次会话启动时都会读取 workspace 里的 `AGENTS.md` 并注入上下文。它不是普通文档，而是 agent 的"操作规程"——和管性格的 `SOUL.md`、管长期记忆的 `MEMORY.md` 并列。换句话说，你希望 agent 每次都遵守的规则，唯一可靠的落点就是这里。

## 问题

观察我自己和几个朋友的工作空间，常见三种状态：

1. 用默认模板跑了一个月，从没打开过；
2. 写了 400 行"项目百科"，agent 抓不住重点；
3. 规则和 SOUL.md 打架，agent 行为看运气。

外在表现很一致：同一个坑反复踩，每次都要口头纠正，换个 session 就忘。根源不是模型不行，而是"纠正"没有沉淀成"规程"。

## 做法

我的迭代流程，供参考：

1. **先采集再动笔**。翻最近两周和 agent 的对话，把所有"我又说了一遍"的纠正列出来。高频项就是手册正文，其余砍掉。
2. **按职责分区**。我分四块：运行环境（目录约定、常用命令）、工具约定（MCP server 的调用时机、插件的坑）、安全边界（删文件前确认、不碰 `.env`、不主动 `git push`）、输出偏好（回复长度、是否要小结）。
3. **控制篇幅**。目标 100 行以内，最重要的规则放最前面——上下文按顺序注入，靠后内容权重天然低。
4. **划清文件边界**。SOUL.md 只写性格语气，MEMORY.md 交给自动记忆，AGENTS.md 只写操作规程。一条规则只出现在一个文件里。
5. **纳入 git**。每次改完跑一个完整 session 验证行为变化，再提交。

## 踩坑点

- **与 SOUL.md 冲突**：两处都约束回复风格，agent 会随机偏向其一。冲突规则宁可删掉，也不要并存。
- **负面指令为主**：满篇"不要 XXX"效果很差，改成"遇到 X 时执行 Y"。
- **硬编码环境信息**：写死 `/Users/xxx/...` 换台机器就废，写相对路径和约定。
- **把密钥写进去**：AGENTS.md 全量进上下文，还可能被记忆工具读取，等于明文广播。密钥走环境变量，手册里只写"密钥在 .env，不要读"。
- **只加不删**：规则越积越多，注意力被稀释。每月删一次失效条目，比加新条目更重要。

## 可复用建议

把 AGENTS.md 当成"新同事入职第一天的 wiki"来写：假设读者能力很强，但对你的环境一无所知。三条经验：改 agent 行为，先改文档再堆提示词技巧；同一条口头纠正说过两次以上，就回写进手册；如果用了 subagent 或多 agent 协作，先确认子 agent 是否也读这份文件，必要时把通用规则拆成独立小节。

## 总结

AGENTS.md 的价值不在写得全，而在每条都被执行过、验证过。它是一个持续运营的活文档：踩坑 → 回写 → 验证 → 删旧。跑通这个循环，agent 稳定性的提升会比换任何提示词技巧都明显。
