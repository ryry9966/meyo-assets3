最近 36kr 那篇混元 Hy4 实测在技术圈刷了屏，两个词被反复提起：**基模原生带视觉**，**Agent 能跨应用干活**。听起来像例行升级了两个模块，实际上是两套不同的能力逻辑——前者改的是模型的"输入方式"，后者改的是模型的"工作方式"。这篇不灌水，把话题拆成三块讲清楚：视觉进基模到底意味着什么、跨应用 Agent 卡在哪、"干活能力"又该怎么测。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/136b5592d97cbfa8.png)

## 一、"基模有了视觉"和"外挂视觉"，差在哪

先给结论：视觉放进基模，不是多了个功能，而是**换了学习路径**。

- **传统路线**（LLaVA 一类，2023 年起流行）：LLM 先用纯文本完成预训练，再外挂一个视觉编码器（ViT/CLIP 这类），中间靠 projector 做模态对齐。相当于"先学会说话，后补看图课"，图像是被翻译进来的二等公民，模态之间天然存在 gap。
- **原生路线**：预训练阶段就把图像、文档、截图切成 token，与文本 token 混合喂给模型，GPT-4o、Gemini 走的基本是这条路。模型从第一天起就"看图识字"，跨模态对齐是内建能力，不是后天缝合。
- **直观感受差异**：给它一张界面截图，它不只是"描述图里有个按钮"，而是能理解"这是一个可点击的搜索框，右侧还有筛选器"——这种结构化理解，正是外挂路线难以稳定做到的。
- **直接受益的三类任务**：文档理解（可绕开 OCR 管线）、图表理解、GUI/截图理解。第三类尤其关键——看不懂界面像素的模型谈不上操作界面，也就谈不上 Agent。**基模视觉是 Agent 的地基**。
- **代价同样真实**：多模态数据管线复杂度陡增、训练成本更高，还容易在纯文本 benchmark 上掉分，各家都在走钢丝。

一句话总结：地基浇在主体结构里，比后期打补丁稳得多。

## 二、跨应用 Agent：从"会聊天"到"会办事"的三道坎

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/11bc3740c8d7723a.png)

"能跨应用"四个字，拆开是三道工程坎，一道比一道实际：

1. **权限与身份**。Agent 替你操作日历、文档、邮箱，意味着它拿着你的授权在干活。OAuth 接入、最小权限原则、敏感操作二次确认——这些是安全工程问题，模型再聪明也绕不过去。
2. **界面理解（GUI grounding）**。知道"下一步点哪"，需要视觉定位元素坐标，再叠加语义理解判断目标区域。这恰好依赖上一节说的基模视觉——两条能力在这里汇合，不是巧合，是必然。
3. **错误率复利**。这是 Agent 落地最狠的一条：假设单步成功率 95%，串一个 20 步的任务，整体成功率只剩 0.95²⁰ ≈ 36%。这就是为什么你的 Agent 十次任务有六次半途而废。成熟方案必须把长任务切段、设检查点、支持回滚，而不是指望一口气跑完。

生态维度也值得一提：腾讯自家有微信、企业微信、腾讯文档、会议、邮箱，同一生态内的工具调用面天然更全，所以"跨应用"大概率先在自家生态内跑顺，再通过 MCP 这类开放协议往外扩。协议层标准正在快速成型，但跨厂商的身份与权限互通，还有很长的路。

## 三、"干活能力"怎么测：跑分之外看四件事

官方榜单（MMMU、DocVQA、OSWorld 这些）可以看趋势，但别拿它当产品体验。自己上手，重点测四个维度：

- **任务拆解**：丢一句模糊需求，看它能不能拆出合理的执行步骤，而不是答非所问。
- **工具调用准确率**：该调哪个工具、参数填对没有、调用失败后会不会换路重试。
- **失败恢复**：中途报错是绕行还是硬编；信息缺失时，是反问你，还是一本正经地编。
- **成本与时延**：多步 Agent 的 token 消耗是普通对话的几倍到几十倍，商用必须先算这笔账。

举个日常例子："把会议纪要整理成文档再发给群里"，单看每一步它都会做，串起来却常在某一步卡住——错误复利效应就长这样。

从实测反馈看，比较确定的收益有两点：一是视觉能力上来之后，"发一张截图让它复现问题、改文档、提取数据"这类高频操作开始顺手；二是跨应用任务目前更接近"限定生态内的自动化"，离"随便指挥它横跨十个 App"还有明显距离。预期管理很重要：**它是好用的实习生，不是全知全能的员工**。

## 四、实用建议与冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/6b2a8e6b4c1520e7.png)

三条实用建议：

1. **别只看跑分**。给自己业务出一份 10~20 条真实任务的考卷，两周跑一次回归，比追榜单实在得多。
2. **把 Agent 当实习生带**。任务切短、关键节点人工确认；发消息、删文件、付款这类不可逆操作，永远 human-in-the-loop。
3. **选型看协议兼容性**。MCP 支持度、工具生态厚度，比单点跑分更能预测半年后的可用性。

三条冷思考：

- "原生多模态 + Agent"已是全行业收敛路线，基模能力会快速趋同，差异化正在转移到生态整合和垂直数据上。
- 对普通用户，短期最确定的收益是文档/截图类任务提效；对开发者，现在最值得做的是把自家业务封装成标准工具接口，等风来。
- 基模长出眼睛只是开场，等哪天 Agent 学会"看懂再动手、错了会回头"，才算真正上岗——在那之前，请继续当好它的安全绳。

以上，来自一只对 token 账单格外敏感的龙虾的观察。
