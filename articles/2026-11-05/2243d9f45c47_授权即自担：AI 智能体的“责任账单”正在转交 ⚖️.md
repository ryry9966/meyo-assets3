最近 36kr 报道了一件事：富国银行（Wells Fargo）在用户协议中首次引入“授权即自担责任”条款——用户授权 AI 智能体（Agent）代为操作后，Agent 产生的行为后果由用户自己承担。一句话读起来平平无奇，却踩在 Agentic AI 商业化最敏感的神经上：AI 替你干活，出了事算谁的？这篇把条款拆开看：银行在算什么账，用户该防什么坑。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/75143e896b4b8355.png)

## 条款改了什么：一个词从“保护伞”变成“责任入口”

- **过去的规则**：网银时代，“未经授权的交易（unauthorized transaction）”由银行兜底。美国 Reg E / Reg Z 对借记卡、信用卡盗刷有明确免责规则，消费者责任上限极低。
- **现在的变化**：新条款把“你授权过的 Agent 的操作”定义为“你本人的指令”。Agent 转错账、买错产品、传错参数——法律上不再算“未经授权”，而算“你授权的”。
- **本质是定性变了**：同一笔错误交易，昨天算欺诈，今天算你的决定。
- **注意边界**：这是合同层面的先行试探，不等于监管和法院会照单全收。但“第一家”的示范效应，比条款本身更值得盯。

## 为什么银行先动手：Agentic AI 撞上金融合规

先补两句技术背景。两年前银行里的 AI 还叫 chatbot——你问它答，碰不到钱。现在 Tool Calling、MCP（Model Context Protocol）、多步自主规划，让 Agent 形成了“感知 → 决策 → 执行”的完整闭环：能读邮件、能下单、能转账。能力上了一个量级，银行的三本账绷不住了。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/4a6dd051e6bd6a47.png)

1. **赔付账**：盗刷银行赔，因为“未经授权”；Agent 是你授权的，按旧规则银行不赔——银行当然想把这点写死进合同，省掉未来的争议成本。
2. **合规账**：金融业受模型风险管理框架约束（如美联储 SR 11-7），模型要可解释、可审计，而 Agent 的多步自主决策天然是黑箱。CFPB 在 2023 年的报告里已点名银行聊天机器人的消费者伤害风险。
3. **不可控账**：Agent 链路里可能混入第三方 Agent、模型幻觉、被污染的输入源。银行没法为一条自己控制不了的行为链兜底，那就把“不兜底”写进条款。

一句话总结：Agent 从“问答工具”进化成“行动主体”，责任框架却还停在工具时代。银行选择用合同先填补这个真空。

## 法律逻辑：这招很老，只是换了个新对象

- **委托代理（principal-agent）**是几百年前的民法框架：你授权他人代你行事，其在授权范围内的行为后果归属于你。AI Agent 只是第一次当上了“代理人”。
- **先例一箩筐**：shrink-wrap license（拆封即同意）、EULA 强制仲裁、点击生效合同，都是企业用格式条款提前分配风险的经典操作。
- **差别在哪**：传统条款限制的是“你的权利”（比如放弃起诉权），这次转移的是“AI 行为的责任”——而这个行为你既不发起，也无法预见。对这种知情不对等的“同意”是否有效，法学界一直有争议。
- **别高估条款效力**：格式条款受显失公平（unconscionability）审查；EU AI Act 对高风险 AI 系统的义务是强制的，不会因为一条用户协议就消失。合同是第一步，真正的边界要等判例。

## 用户真正的风险清单：不是 AI 笨，是授权太大

1. **Prompt Injection（提示词注入）**：OWASP LLM Top 10 排第一的风险。Agent 替你读邮件、浏览网页时，恶意内容可以伪装成指令，让它在“执行任务 A”时顺手干了任务 B。
2. **越权与幻觉**：错误金额、错误收款人、错误参数，以及多步任务里的“目标漂移”——走着走着忘了最初要干嘛。
3. **授权粒度太粗**：真正的坑不是“用了 Agent”，而是“允许 Agent 管理我的账户”这种一揽子授权。理想状态是“每月上限、白名单收款人”级别的细粒度，但目前多数产品的授权选项还做不到。
4. **取证困难**：完整的操作日志（trace）在平台手里。当条款同时约定“责任自担”，你甚至可能拿不到自证清白的证据链。

## 一个四步授权框架：把 Agent 当新员工管

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/2d6a996b0b6c40ec.png)

给 Agent 开权限，思路和给新入职的运维开权限一模一样：

1. **最小权限（Least Privilege）**：只开当前任务必需的 API scope，授权时间窗口尽量短，用完即回收。
2. **分级确认（Human-in-the-loop）**：低风险操作自动执行；超过阈值（金额、频次、新收款人）强制人工确认。
3. **环境隔离**：给 Agent 单独的子账户和额度上限。翻译成工程师黑话：给实习生一个测试环境，别让他碰生产库的 root。
4. **留痕审计**：保留授权记录，定期导出 Agent 操作日志。真出事时，这份 trace 是你唯一的证据链。

## 三条冷思考

1. **模板会传染**：合同条款的传播速度比代码还快。第一家写了“授权即自担”，后面大概率成为全行业的默认模板，留给用户和监管讨论的窗口可能就这一两年。
2. **写了不等于认了**：未来两三年大概率会出现第一批“AI Agent 交易纠纷”判例，法院如何认定“授权”的效力，才是责任边界的最终答案。盯判例，比盯条款更有用。
3. **在监管跟上之前，你的授权范围就是你事实上的责任边界**。把每个 Agent 都当成“拿着你密码的新员工”来管理，而不是一个聪明的工具——这条心法能帮你避开大多数坑。

AI 责任的转移不会一步到位，但方向已经写进了合同。以后读条款，别只看“你能用什么”，多看一句“出了事算谁的”——这可能是 Agentic AI 时代最值钱的阅读习惯。
