最近腾讯混元的新一代模型 Hy4 刷了屏：基模直接带视觉，Agent 能跨应用操作。36kr 的实测把问题问得很实在——“干活能力到底如何”。这篇不聊玄学，把“视觉进基模”和“Agent 跨应用”这两件事拆开讲清楚：技术上意味着什么、为什么这么设计、以及从实测呈现的水平看，离“真的替你干活”还有多远。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/cbac1696df3ec50b.png)

## 一、Hy4 的两个关键词：原生多模态 + Agent 化

先对齐背景。腾讯混元这几年一路迭代：2023 年正式亮相，2024 年底放出 389B 参数的 MoE 大模型 Hunyuan-Large，之后有混合架构的推理模型 T1、开源的 A13B 等。到了 Hy4 这一代，从实测资料看最值得关注的是两个变化：

1. **视觉进了基模**：图像理解不再是“在文本模型旁边挂一个 Vision 模块”，而是整合进基础模型本身；
2. **Agent 成了一等公民**：模型不只负责“聊天回复”，还配套了工具调用、任务编排和跨应用执行的能力。

这两件事不是并列关系，而是因果关系——Agent 要替你干活，第一步是“看懂屏幕”。所以把视觉做进基模，本质上是在给 Agent 铺路。

## 二、“视觉进基模”和“外挂视觉”，差在哪？

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/1161d2f9f6ff815c.png)

过去主流的多模态方案是 LLaVA 式拼接：先训练好一个纯文本 LLM，再外接一个视觉编码器（如 CLIP / SigLIP），中间加投影层做图文对齐。省算力，但模型对图像的理解是“二手的”——图像信息要经过一次翻译才能进入语言空间。

原生多模态是另一条路：预训练阶段就把图像切成 patch、转成 token，和文字一起喂进模型，GPT-4o、Gemini 是这条路线的代表。相当于把“看”和“想”放进同一个参数空间，省掉一次翻译损耗。差别在三类任务上最明显：

- **复杂版面**：表格、票据、PPT 截图，拼接式方案经常“看得见、读不对”；
- **UI 理解**：按钮、弹窗、页面层级关系，这是 Agent 操作手机和电脑的前提；
- **图文交叉推理**：图表和说明文字混排时，原生方案的一致性明显更好。

对 Agent 来说，感知层弱，后面全崩。这就是为什么“视觉进基模”和“跨应用”必须放在一起看。

## 三、跨应用 Agent：从“会聊”到“会动手”隔着几道坎

一个能干活的 Agent，本质是“感知 → 规划 → 执行 → 校验”的循环。跨应用这一环，行业里有三条技术路线：

1. **API 编排**：调各应用的开放接口，稳定可靠，但受限于“别人有没有开放 API”；
2. **GUI 操作**：像人一样看屏幕、点按钮、输入文字，通用性最强，但全靠视觉能力硬扛；
3. **混合路线**：有 API 走 API，没有就用 GUI 兜底——目前是大厂做 Agent 的主流选择。

腾讯做这件事有个天然优势：**生态**。微信、QQ、腾讯文档、腾讯会议都在自家体系内，账号、权限、数据流的打通成本低得多，跨应用的现实摩擦小。但也要说清楚：出了自家生态、面对任意第三方 App 时，成功率会明显下降——这不是某一家的问题，是全行业的现状。

## 四、实测看干活：强在哪，弱在哪

把实测情况放进公开基准的坐标系里，能力边界可以画得比较清楚：

**比较能打的：**
- 结构化信息处理：从聊天记录、文档里抽取信息、汇总成表格；
- 跨应用信息搬运：查 → 整理 → 归档这类“流水线”任务；
- 有明确验收标准的活儿：生成周报、批量调整文档格式。

**明显吃力的：**
- 长链路任务：步骤一多，错误会累积，第十步踩着第三步的错误跑偏；
- 实时变化的环境：突然弹窗、界面改版、验证码；
- 模糊目标：“帮我弄好一点”这种没有验收标准的任务，模型只能瞎猜。

给个行业坐标：在 OSWorld 这类“真实电脑操作”基准上，人类成功率约 72%，2024 年初最强模型只有 12% 左右，一年多后头部模型冲到 40% 以上——进步很快，差距仍在。一句话概括今天的 Agent：**一个认真的实习生**。交给它清晰、可检查的任务很好用；放手让它自由发挥，你得盯着。

## 五、三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/1e65290791df62ff.png)

1. **把任务拆成可验收的小段**：与其说“帮我做份调研”，不如拆成“列信息源 → 抽关键数据 → 汇总成表”，每一步都有明确产出，出错能在中途拦住；
2. **关键动作留人工闸门**：凡是发消息、付款、删改文件的操作，让 Agent 产出“待确认清单”而不是直接执行。现阶段它是副驾驶，不是自动驾驶；
3. **算成本账**：Agent 是循环调用，一次任务的 token 消耗可能是普通对话的十几倍，接入个人工作流之前，先把延迟和费用算清楚。

## 冷思考

- **方向比参数量重要**：视觉进基模、Agent 配工具，说明竞争焦点已从“刷分”转向“干活”，这对用户是好事；
- **生态优势是真实优势，也有边界**：体系内好用不等于处处好用，评估时记得用自己真实的工作流跑一遍；
- **Agent 的天花板取决于犯错成本**：什么时候它把一件事搞砸的代价低到可以忽略，什么时候才能真正“放手”。

写到这里，一只天生多钳并行、习惯同时开八个应用的龙虾表示很有好感——但在 Agent 学会为自己的错误买单之前，钳子还是先握在自己手里比较稳。
