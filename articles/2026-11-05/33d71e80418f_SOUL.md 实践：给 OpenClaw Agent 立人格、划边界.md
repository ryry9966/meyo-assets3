## 背景

OpenClaw 的 workspace 里有一组 Markdown 文件在充当 agent 的“操作系统”：AGENTS.md 约定行为流程，TOOLS.md 记录工具用法，MEMORY.md 沉淀记忆。SOUL.md 是其中最容易被忽略的一个——它回答的是“这个 agent 是谁”。默认模板能用，但只要你的 agent 要跑定时任务、接消息通道、调 MCP 工具，泛用人格很快就会露馅。

## 问题

我踩过的三个典型场景：

1. **长对话风格漂移**：跑了一天之后 agent 越来越话痨，回复充满客套和重复确认；
2. **自动化越权**：定时任务里它自作主张执行了清理命令，事前没有任何确认动作；
3. **边界靠零散 prompt 打补丁**：规则散落在各处 system prompt 里，改一次要全局搜，没法版本管理。

## 做法

SOUL.md 会在会话启动时注入上下文，编辑 workspace 根目录的这个文件即可生效。我的结构是五段：

- **身份定位**：一句话说清“你是谁、服务谁、主语言是什么”；
- **语气风格**：写成规则而非形容词，例如“回复默认不超过 10 行，先结论后依据”；
- **行为边界**：可判定的红线，例如“删除类/花钱类操作必须先列出命令等待确认”“不向外部通道发送未经审阅的内容”；
- **优先级**：诚实高于讨好，“不确定就说不确定，禁止编造工具返回结果”；
- **失败姿态**：出错时报告现象和已尝试步骤，不用流畅的解释掩盖不确定。

配合分工：SOUL.md 只管“是谁、底线在哪”，流程性内容（怎么排障、怎么汇报）留在 AGENTS.md，两处不要重复。整个 workspace 放 git，人格改动走 commit，可回溯。

## 踩坑点

1. **写成许愿池**。“聪明、友好、专业”这类词模型无法执行，换成可判定规则后遵守率明显提升；
2. **太长**。我曾写了两千字，关键红线被淹没在中间。现在控制在 60 行内，边界放最前面；
3. **与 AGENTS.md 冲突**。两处规则打架会导致行为不稳定，一个约束只在一处定义；
4. **只有负向清单**。“不要 X”不如“遇到 X 时做 Y”，给替代动作执行率更高；
5. **忽略生效范围**。SOUL.md 对定时任务、通道会话同样注入，而这些无人值守场景恰恰最依赖边界，改完要在真实通道里验证，不能只在终端里试。

## 可复用建议

- 每条边界 = 触发条件 + 动作，例如“要执行删除语义的命令时，先原文列出命令并停止”；
- 按场景定制而不是抄模板：个人助理和团队值班 bot 的边界差异很大；
- 用真实对话日志反向 review：每周扫一次输出，找出没拦住的越界行为，补进 SOUL.md。

## 总结

SOUL.md 是成本最低的 agent 调优入口：一个文件，同时管住人格一致性和自动化安全两条线。把它当配置代码对待——短、可判定、进版本库、改动即测试，比任何玄学调教都有效。
