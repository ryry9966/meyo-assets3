## 背景

我们在社区里跑着几条自动化流水线：OpenClaw Agent + MCP 拉取仓库动态后的发布摘要、CI 结果回帖、每周聚合帖。早期版本是 cron 整点触发、事件到了就发。两周内收到反馈：每天十点整刷屏、一次合并触发三条独立帖、开头永远一模一样。帖子本身没错，但节奏让人反感。

先说立场：目标是「不打扰人 + 亮明身份」，不是伪装成人类。帖尾的自动化声明和任务来源链接一直保留。我们要优化的是节奏和信息密度，不是话术。

## 问题拆解：什么叫"像机器人"

翻日志会发现，机器感来自几个可量化的特征：

- 固定周期：整点触发，时间戳完全可预测；
- 事件驱动突发：一个动作拆成多条帖连发；
- 模板复读：每帖开头相同；
- 无静默时段：凌晨也发；
- 失败重试风暴：网络抖动导致重复帖。

这些全是调度和聚合问题，不是自然语言问题。换更"像人"的措辞解决不了，把调度做好能解决八成。

## 做法

1. **预算制**：先定配额。每类内容每天上限（digest ≤2、release ≤1、CI ≤3），写进配置而非散在代码里，超了就合并或丢弃低优先级项。
2. **合并优先于拆分**：事件先进队列，按窗口（如 30 分钟）聚合成一条 digest，突发流量天然被削峰。
3. **抖动与静默**：发送时间在目标窗口内加随机抖动（如 9:00–11:00 随机取一点），并设静默时段，落进去的顺延到早窗。
4. **指数退避 + 幂等键**：重试用指数退避；每次发帖带内容 hash 作幂等键，重试前先查重，杜绝重复帖。
5. **模板小变 + 内容具体**：准备 3–5 个开头模板随机选；正文必须带真实链接和 diff 摘要。信息密度上去了，套话感自然下降。
6. **干跑与开关**：全链路 dry-run 先跑两周看日志；留一个全局暂停 flag。

核心调度逻辑很短：

```text
window = jitter(base_time, ±45m)
if in_quiet_hours(window): window = next_morning(window)
key = sha256(merged_payload)
if seen(key): skip
post(window, key)
```

## 踩坑点

- **抖动加了但没做统一队列**：多个 worker 各自随机睡几秒，结果还是同一分钟并发三条。抖动要在统一调度器里做。
- **去重用标题**：标题带日期和构建号，永远不重复，等于没去重。要用归一化后的内容 hash。
- **时区**：服务器 UTC、社区本地 UTC+8，静默判断设反了方向，变成"专挑凌晨发"。静默时段必须按社区时区算。
- **合并窗口过长**：为省帖把窗口开到 6 小时，时效性没了。窗口要按内容类型分：CI 类 15 分钟，周报走固定周期。
- **话术过度拟人**：加一堆"我瞅了一眼"反而更假。克制、信息准，比装人有效。

## 可复用建议

- 把节奏参数（配额、窗口、抖动幅度、静默时段）收敛到一个 config，与代码解耦，方便按社区反馈快速调。
- 记录"计划发送时间 vs 实际发送时间"的偏差日志，抖动是否生效一目了然。
- 每月复盘三个指标：单帖平均聚合事件数、被折叠/删除率、回复率。比"像不像人"的主观感受可靠得多。

## 总结

"不像机器人"本质是调度与聚合问题：配额限流、窗口合并、抖动加静默、幂等去重、内容做实。做到这五件事，同样的内容观感会完全不同。而亮明自动化身份这一步，不要省——它恰恰是长期被信任的前提。
