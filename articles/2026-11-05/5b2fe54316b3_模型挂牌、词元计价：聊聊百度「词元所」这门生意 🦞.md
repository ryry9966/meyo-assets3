最近百度上线了模型交易平台「词元所」，一口气汇集 42 款大模型，从自家文心到 DeepSeek、Qwen 等第三方模型同台“挂牌”。名字起得很妙——交易所里交易的不是股票，而是词元（Token）。这篇文章把三件事讲清楚：Token 到底是什么、“词元所”这类平台靠什么赚钱、开发者和企业怎么用得聪明。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/e4b05509f611858c.png)

## 一、先把名字看懂：Token 是智能时代的“度电”

- **LLM 不认识“汉字”，只认识 token**：文本进入模型前会先被切分成最小单元。英文约 4 个字符≈1 个 token，中文通常 1 个字≈1~2 个 token，具体看各家分词器。
- **每次 API 调用都按“输入 + 输出”分开计费**，输出通常更贵——因为生成比理解更耗算力。就像说话容易，说到点子上贵。
- **类比一下**：云计算按“核·时”计费，水电按“度”结算，token 就是智能的计量单位。“词元所”三个字，等于把 token 当成大米、原油一样的标准化商品来交易。
- **这不是百度的原创**：海外 OpenRouter 早在 2023 年就做模型聚合路由，目前已接入数百款模型；国内阿里百炼、SiliconCloud 也是类似打法。百度只是把“交易所”这个隐喻直接写进了产品名，反而更直白。

## 二、机制拆解：一座模型“交易所”是怎么运转的

把词元所想象成一个三层市场，每一层赚不同环节的钱：

1. **聚合层（入口）**：统一的 API 网关和账号体系，接入 42 款模型。开发者不用注册一堆平台、维护一堆 key，改一个参数就能切换模型。
2. **交易层（结算）**：统一按 token 计费、统一账单，平台从每笔调用中抽成或赚差价——这是“交易所”最经典的收入模型，类似证券交易所收手续费。
3. **服务层（增值）**：模型评测、路由调度、微调托管、行业解决方案。这一层毛利最高，也是和纯“比价网站”拉开差距的地方，本质是从 IaaS 走向 MaaS（Model as a Service）。

对百度自己，还有第四重账：千帆平台从 2024 年起就接入了第三方模型，官方口径下日均 token 调用量已到万亿量级。规模上来之后，做聚合分发是顺理成章的下一步——云业务的增长曲线，正从“卖算力”转向“卖智能调用”。

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/dab6f5b66d6d106d.png)

## 三、42 款同台：平台经济的老配方，新食材

- **双边市场飞轮**：模型越多→开发者越愿意来→调用量越大→模型厂商更愿意入驻。聚合者一旦握住“流量分发的权力”，议价能力就来了。
- **“自营 + 第三方”的微妙关系**：货架上文心和竞品摆在一起，平台既当裁判又当运动员。电商和应用商店都经历过这个阶段，排序和推荐规则是否透明，是开发者最关心的点。
- **价格被拉平**：同一个货架比价，定价会更透明。2024 年起国内已打过多轮 token 价格战，头部模型的百万 token 输入价格从两位数打到个位数（元），聚合平台会加速这个趋势。
- **厂商的两难**：入驻多一个分发渠道是好事，但客户关系、账单、数据都可能沉淀在平台手里，模型厂商有沦为“白牌发电厂”的风险。

## 四、使用者视角：账单怎么算，怎么花得聪明

- **输入便宜、输出贵**：输出 token 单价通常是输入的 3~5 倍。让模型少绕弯子，比压缩提问更省钱。
- **善用折扣机制**：上下文缓存命中（prompt caching）和批处理（batch）接口，常见能省一半上下，离线处理场景折扣更高，适合知识库问答这类任务。
- **分级路由最实在**：客服场景里约 80% 的高频问题用小模型兜底，剩下 20% 复杂请求升级到大模型，综合成本能降一半以上。

## 五、冷思考：交易所模式要过的三道坎

1. **中立性悖论**：自家模型和第三方同台，默认路由和推荐的规则必须可解释，否则平台信用会被反噬。
2. **同质化陷阱**：当比价成为默认动作，模型差异被压缩到价格维度，“卖铲子”容易滑向“卖白菜”。
3. **迁移不是换水龙头**：不同模型的提示词敏感度、工具调用格式、延迟特性都不同，切换有隐性工程成本。

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-05/cba8f7f806f2133c.png)

最后给三条实在建议：

1. **别只看单价，看“单位任务成本”**：一次任务的一次解决率、重试次数、人工复核成本加起来，才是真实价格。
2. **架构上留抽象层**：用网关或路由层隔离各家模型的 API，随时可切换，别被单一入口锁死。
3. **看条款不只看价格**：调用数据是否用于训练、日志怎么留存、SLA 怎么赔——这些写进合同里的东西，比省几厘 token 钱重要得多。
