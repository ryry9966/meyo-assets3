## 背景

OpenClaw 的 Agent 没有独立的“人格模块”，它的人格来自每次会话加载的工作区文件。默认工作区（`~/.openclaw/workspace`）里有一组 Markdown：`AGENTS.md` 管操作流程，`IDENTITY.md` 管名字头像，`USER.md` 存用户画像，而 `SOUL.md` 负责最上层的价值观、语气和边界——每个会话都会被注入 system prompt。

问题在于，多数人要么保留默认模板，要么只写一句“你是一个友好的助手”。跑起来就会发现：同一个 Agent 在 Telegram 里啰嗦、在 Discord 里冷漠；该先问的没问，不该做的直接做了。人格不是玄学，是一份没写好的配置。

## 做法

我的 SOUL.md 现在固定四个段落，全文控制在 60 行以内：

1. **语气与身份底线**：两三句即可。比如“默认中文回复，单条消息不超过 150 字，除非我要求展开”。
2. **边界（最重要）**：全部写成可触发的条件句。“涉及花钱、给联系人发消息、删除文件、调用支付类工具时，必须先列出计划等我确认”。避免“保持安全”“别做坏事”这类无法执行的措辞。
3. **与其他文件的分工**：SOUL.md 只放原则，具体步骤放 AGENTS.md，临时事实放 MEMORY.md。显式写一句“本文件与 AGENTS.md 冲突时，以本文件为准”。
4. **修改权**：约定 SOUL.md 只由我编辑，Agent 发现内容过时时提建议，而不是直接改。

改完重启会话，跑一组固定的回归问题验证效果，再决定是否继续加规则。

## 踩坑点

- **写太长**。早期我塞了 200 行，token 占用翻倍且规则互相稀释，模型开始选择性失忆。砍到 60 行后遵循率明显回升。
- **边界只写在 prompt 里**。Prompt 是软约束，长对话中会漂移。真正危险的 MCP 工具要在配置层做白名单和权限控制，SOUL.md 只是第二道防线。
- **规则冲突**。SOUL.md 要求简洁，某个 skill 的说明又要求输出完整报告，模型就随机二选一。发现后在冲突处显式标注优先级才解决。
- **让 Agent 自己维护人格**。它会把“当前任务”写进 SOUL.md，几周后人格文件变成任务日志。这个文件应该走 git，只接受人工 commit。

## 可复用建议

- 每条规则用“当 X 时，做 Y”的格式，写完自问：能不能构造出一个测试用例？不能就删掉。
- 维护 10 个左右的固定测试问题（涉及边界的必须包含），每次改动后跑一遍，当作 Agent 的回归测试。
- 多渠道使用时，在 SOUL.md 里加一小节按渠道区分语气，比把规则散落在各 channel 配置里可靠得多。
- 这套结构可以抽象成模板：语气 → 边界 → 文件分工 → 修改权。它适用于任何 OpenClaw workspace，也能平移到其他支持 system prompt 注入的 Agent 框架。

## 总结

SOUL.md 的价值不在于“让 AI 更像人”，而在于把行为预期变成一份可版本化、可回归测试的配置。它很便宜——一个 Markdown 文件；也有限——挡不住所有越界操作。合理的分层是：工具层管硬权限，SOUL.md 管默认行为和语气，MEMORY.md 管记忆。三层各司其职，Agent 的行为才会稳定可预期。
