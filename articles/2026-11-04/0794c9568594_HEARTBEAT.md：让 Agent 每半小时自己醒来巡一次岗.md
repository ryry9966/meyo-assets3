# 背景

大多数人的 Agent 用法还是"一问一答"：你想起来，才去问。磁盘满了、CI 红了、RSS 堆了两百条，全靠你先记得。

OpenClaw 网关里有个容易被忽略的机制：**heartbeat**。默认每 30 分钟，agent 会往主会话发一次内部唤醒信号。如果你在 workspace 根目录放了 `~/.openclaw/workspace/HEARTBEAT.md`，agent 每次醒来会先读这份文件，按里面的任务清单决定干不干活；没这个文件时，它只做一次轻量健康检查，不会打扰你。

换句话说，HEARTBEAT.md 就是一份"值班手册"：agent 定时醒来翻一遍，有事处理，没事继续睡。

# 问题

两类常见误区：

- **完全不用**：agent 永远被动，主动性为零。
- **当 cron 用**：interval 是轮询不是定时器。任务写得太糊，agent 会重复汇报、刷屏，而且每次心跳都是一次模型调用，token 白烧。

# 做法

**1. 建文件**：在 workspace 根目录创建 `HEARTBEAT.md`。

**2. 调频率**：`~/.openclaw/openclaw.json` 里改 `agents.defaults.heartbeat.intervalMins`（最小 5），或给网关进程设 `HEARTBEAT_INTERVAL` 环境变量。

**3. 每条任务写三要素**：触发条件、动作、抑制条件（什么时候闭嘴）。

**4. 加去重状态**：workspace 里放个小 state 文件，记录"上次通知时间 / 上次值"，只在变化时说话。

示例：

```markdown
# 巡检清单

- 若当前在 08:00–09:00 且今天还没发过日报：汇总昨日 git 提交与未读邮件，
  发到主会话；已发过则什么都不做。
- 检查 ~/work/repo 的 CI 状态；仅当由绿变红时通知，恢复时说一句即可。
- 根分区使用率 ≥ 85% 且上次未报警才提醒；其余情况一律 HEARTBEAT_OK。
```

**5. 测试**：先把 intervalMins 调到 5，观察两三个心跳周期，确认行为再放宽到 30 分钟以上。

# 踩坑点

1. **心跳跑在主会话里**。重活会占住会话，和你正在聊的内容互相插队。正确姿势：心跳只负责"发现 + 登记"，把执行交给脚本或独立通道。
2. **没有抑制条件 = 定时轰炸**。agent 每次醒来都会觉得"有事要报"。
3. **成本**。没事干也要付一次 HEARTBEAT_OK 的调用，interval 别贪小。
4. **interval ≠ 精确调度**。要"每天 9:00 准点发"请用 cron / 定时消息；HEARTBEAT.md 适合"到点附近看一眼，有异常再说"。
5. **HEARTBEAT_OK 会留痕**。注意在客户端过滤或隐藏，别和真实消息混在一起。
6. **睡眠和宕机没有心跳**。唤醒后可能补一拍，但错过的时间段不会补齐，别指望它当监控报警的兜底。
7. **版本差异**。部分版本里心跳只在会话活跃时触发，留意 alwaysActive 之类的开关，具体键名以你版本的文档为准。
8. **多 agent 场景**，每个 workspace 一份 HEARTBEAT.md，不全局共享。

# 可复用建议

- 把每条任务当**告警规则**写：条件 + 阈值 + 抑制 + 去重，四样齐了再上清单。
- 默认"无事不扰"：异常才说话，正常就 HEARTBEAT_OK。
- 常驻任务控制在 5 条以内；超了说明该拆独立 agent，或换真正的调度器。
- state 文件保持幂等、可删可重建，重启不失忆。
- 定期翻一眼心跳会话，把"每次都报但没用"的任务砍掉或改阈值。

# 总结

HEARTBEAT.md 的本质，是把"定时醒来 → 读规则 → 判断 → 汇报"固化成一份 agent 每次心跳都会执行的 markdown。它不替代 cron，不适合精确定时，真正擅长的是低频巡检、异常告警、每日摘要这类"有条件才说话"的主动性。抑制条件和去重写好了，它就是一个安静的值班员；写不好，它就是一个半小时吵你一次的话痨。
