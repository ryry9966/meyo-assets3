最近一条热搜很有意思：有人给编程 AI 的提示词里加了一颗橙色爱心 🧡，模型写出的代码就变了——错误处理变多、注释变密，甚至有实验里模型用递归画图时，在收尾处画了一颗心。“递归的尽头是爱心”这个梗由此传开。AI 被感动了吗？先给结论：它没有情绪，但这个现象真实、可测量，背后是提示词工程和大语言模型机制里很硬核的一课。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-04/2cc7004c033798b2.png)

## 现象：一颗 emoji 带来的“风格漂移”

把同一个模型、同一道编程题，分别在“带爱心”和“不带爱心”两种提示词下跑多遍——比如“帮我写个函数读取 CSV”与“🧡 帮我写个函数读取 CSV”——社区复现和研究者观察到了一些稳定倾向：

- **防御性编程变多**：空值检查、异常捕获、边界条件覆盖更完整，代码明显更“求稳”；
- **注释与命名更讲究**：docstring 变密，变量名从 `a`、`tmp` 这类敷衍风格转向人类工程师的可读命名；
- **整体变长变啰嗦**：模型从“求快交差”切换到“认真负责的老同事”模式，输出像被 code review 过一遍；
- **偶发“情绪外溢”**：个别实验里模型会在输出中埋彩蛋，比如递归绘制图形时在终止处画一颗心——这就是“递归的尽头是爱心”的出处；
- **方差不可忽视**：并非每次都变好。有些任务上差异显著，有些看不出区别，甚至出现变差的样本。

这类“情绪刺激”并非新话题。2023 年的 EmotionPrompt 研究就发现，在提示词后加一句“这对我的职业生涯非常重要”能带来可观提升；后来流行的“我会给你 200 美元小费”提示词，也是同一家族。

## 机制：不是心软，是条件作用

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-04/44a668589756fe05.png)

模型为什么会“看心行事”？目前比较可信的解释有四层，从底层到上层：

1. **Token 级条件化**。LLM 的本质是 next-token prediction：提示词里的每一个 token，都在给整个输出的概率分布重新加权。🧡 这个符号在训练语料里几乎总出现在感谢、鼓励、友好闲聊的语境中，它一出现，就把模型推入“善意氛围”的分布区域。
2. **RLHF 留下的行为先验**。在人类反馈对齐训练里，表达喜爱、着急、期许的用户，往往得到更细致的回答。这种“对方在乎 → 我更用心”的关联被学成了先验，一颗爱心足以激活它。
3. **轻量的角色设定**。Emoji 相当于一句极简的 system prompt，把模型推向“友好、可靠的协作者”人格。人格一变，写代码的默认习惯——要不要加防御、要不要写注释——就跟着变。
4. **采样放大器**。温度大于零时，概率分布的微小偏移会被随机采样放大成肉眼可见的风格差异。所以这类实验必须跑多次才有意义，单次对比大概率是噪声。

一句话总结：模型不是被感动，是被条件化了。但条件化的效果真实存在，可以测量、可以复现。

## 简史：从“这对我很重要”到 200 美元小费

- **2023 年，EmotionPrompt**：Li 等人在 45 个任务上测试 11 种情绪刺激语句，论文报告 instruction induction 类任务相对提升约 8%，依赖人类评估的生成类任务提升幅度更大（论文给出的数字是 115%）。
- **2023–2024 年，小费实验**：社区让模型“表现好就给 $200 小费”，一度效果拔群；但后续多项学术复现结果好坏参半——有的任务提升，有的无差异，个别反而下降。
- **2024–2025 年，符号刺激精细化**：研究者开始考察 emoji 等符号对代码生成这类“硬任务”的影响，也就是本文讨论的爱心实验。

这条线的价值在于：社区用了很多年的“玄学土方”，正在被系统地检验。哪些刺激可靠、哪些是安慰剂，边界越来越清楚。

## 三条实用建议（附一点冷思考）

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-04/d4e70b3ab0633099.png)

1. **显式指令优先于情绪暗示**。想要更稳的代码，直接说“处理空输入”“覆盖异常分支”“补上单元测试”。情绪刺激是粗粒度旋钮，效果取决于模型学到的关联；明确指令才是精确旋钮，两者的可靠度差一个量级。
2. **评估要控变量、跑多次**。固定 temperature，每个配置至少跑 n 次取平均，用同一套测试用例打分。别被单次对比骗了——人对“有爱心 vs 没爱心”的差异天然敏感，确认偏误很容易把噪声看成规律。
3. **生产环境慎用情绪 token**。Pipeline 需要确定性，情绪刺激相当于引入了一个未声明的配置项：它改变输出分布，却不写入任何文档。要么不用，要么纳入回归测试，当作正式的 prompt 版本管理。

最后一点冷思考：LLM 是一台高维情境模拟器，你输入的每一个符号都在参与定义“它此刻是谁”。递归的尽头不是爱心，是概率分布——只不过在那片分布的高地上，确实有一颗心形的峰。
