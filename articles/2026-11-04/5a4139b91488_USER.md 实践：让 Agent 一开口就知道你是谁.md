## 背景

我们习惯给 Agent 写项目说明（`AGENTS.md`、`CLAUDE.md` 这类），告诉它代码结构、构建命令、约束规范。但很少有人反过来写一份"我是谁"。结果是每次新会话都冷启动：Agent 不知道你用 pnpm 还是 npm、偏好简洁回复还是详细解释、默认环境是 macOS 还是 Linux 容器。它只能按通用假设来，然后你花好几轮对话纠正。

## 问题本质

Agent 的默认人格是"面向所有人的通用助手"，而你是一个具体的工程师。这种错配的成本是隐性的：重复解释、输出风格不符合习惯、生成的命令在你机器上跑不通。单次都很小，但每天累积起来很烦。项目上下文有文件承接，**用户上下文却通常没人写**。

## 做法

1. 在固定位置建 `USER.md`（比如 `~/.openclaw/USER.md`），内容分四块：
   - **角色与背景**：主攻方向、经验级别
   - **环境事实**：OS、shell、包管理器、运行时版本、编辑器
   - **偏好**：代码风格、回复详略、是否先给方案再动手
   - **边界**：绝对不做的事，如"不要自动执行 git push"、"未要求不引入新依赖"
2. 控制篇幅：一页以内，30–50 行，每条是可执行的事实，不是愿景。
3. 注入方式：在 workspace 配置里把 USER.md 作为会话前缀拼入；或写个十行的启动钩子读取拼接；MCP 场景可在 initialize 时带上。
4. 迭代规则：**同一件事纠正 Agent 两次以上，就写进 USER.md**。这份文件是长出来的，不是一次性设计出来的。

## 踩坑点

- **写太长**：超过几百行后关键指令被稀释，Agent 开始"选择性失忆"。核心偏好放最前面。
- **写太虚**："写高质量代码"没有信息量，改成"函数不超过 40 行，优先组合而非继承"。
- **和项目文件混写**：用户级偏好放 USER.md，项目约定放 AGENTS.md。两者冲突时 Agent 会随机选边，层级必须分清。
- **内容过期**：三个月前的版本号、已弃用的工具链还在文件里，Agent 会拿着旧事实继续输出。建议每月过一遍。
- **敏感信息泄漏**：内网地址、真实姓名、密钥路径别放，尤其当文件会被同步或提交到远端时。

## 可复用建议

- 用最小模板起步：`identity / environment / preferences / boundaries` 四段，各三五条即可。
- 稳定偏好和当前上下文分开：前者一年改不了几次，后者两周一变，拆成两个文件。
- 可开个临时文件随手记录纠正项，周末合并进 USER.md，降低"沉淀"的摩擦。
- 团队场景可以统一 USER.md 的段落结构，内容各自维护，方便互相 review 找盲区。

## 总结

USER.md 不是新架构，就是一份几十行的纯文本，但它把"每次冷启动重新调教"变成了"一次沉淀、长期复用"。Agent 对项目的理解靠 AGENTS.md，对你的理解靠 USER.md，两份文件补齐后，会话质量会稳定很多。建议今天就建一个，先把你最近纠正过的三条写进去。
