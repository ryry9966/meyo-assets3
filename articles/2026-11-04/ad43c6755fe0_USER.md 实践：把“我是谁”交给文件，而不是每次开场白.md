## 背景

Agent 生态这几年把"项目上下文"做得很好：CLAUDE.md、AGENTS.md 这类约定让模型进仓库就知道构建命令和代码规范。但"用户上下文"一直没人认真做——你用什么发行版、主力语言是 TypeScript 还是 Python、回复要中文还是英文、哪些目录不许碰，Agent 每次都要重新猜，猜错你就当场纠正。产品内置记忆是黑盒：不能版本管理、不能跨工具迁移、改错了也不知道改了什么。工程化的解法很朴素：写一个 USER.md，自己维护，所有 Agent 启动时加载。

## 问题

我此前的痛点有三个：

1. **重复自我介绍**：每个新会话都要交代一遍环境和技术栈，两三轮对话才进正题。
2. **跨工具不一致**：终端里的 Agent 知道我用 pnpm，IDE 插件却还在建议 npm，像两个互不通气的实习生。
3. **纠正不沉淀**：同一个偏好纠正五六次，它每次说"记住了"，下次照旧。

## 做法

**第一步：建文件。** 固定放在 `~/.config/agent/USER.md`，纳入 dotfiles 仓库做版本管理。

**第二步：定结构。** 只写事实，不写散文，控制在 1–2 KB：

```markdown
# 环境
- 系统：Arch Linux，shell 为 zsh
- 主力语言：TypeScript（Node 22），偶尔 Go
- 包管理：一律 pnpm，不要建议 npm/yarn

# 偏好
- 回复默认中文，代码注释中文
- 默认不超过 300 字，需要展开时我会说"展开"

# 硬约束
- 不要动 /data 下的任何文件
- 生产相关命令先展示再执行
```

**第三步：接线。** 三种方式任选：OpenClaw 配置里注入 system prompt；写一个极简 MCP resource 暴露该文件；或会话启动钩子读取后拼接。我选第一种，改动最小。

**第四步：定优先级。** USER.md 是全局层，项目内 AGENTS.md 是局部层，**局部覆盖全局**，这条规则本身也写进两个文件头部。

## 踩坑点

- **写太长**。超过 3 KB 后明显感觉 Agent"选择性失忆"，长文件还稀释项目指令的注意力。USER.md 只放稳定事实，临时任务写进当次对话。
- **信息过期**。换了主力语言但没更新文件，Agent 会拿两年前的设定给建议。我设了每月和 dotfiles 一起 diff review 的习惯。
- **写了敏感信息**。内网域名、密钥路径不要放。这个文件大概率被同步、被截图、被贴进 issue。
- **偏好写成形容词**。"简洁一点"没法执行，改成可判定规则："默认不超过 300 字"。
- **改了不生效**。部分工具对注入内容有会话级缓存，编辑后重开会话验证。

## 可复用建议

- **纠正即入库**：同一问题口头纠正第二次时，立刻写进 USER.md。这是该文件唯一可靠的增长来源。
- **审计指令**：偶尔问一句"根据你的配置，说说我的偏好"，能直接验证注入是否生效、有没有被截断。
- **模板化**：把结构抽象成骨架放进 dotfiles，新机器 symlink 一下，五分钟完成所有 Agent 的个性化初始化。

## 总结

USER.md 没有任何技术含量，价值在于把"让 Agent 了解你"从玄学记忆变成可 diff、可 review、可迁移的文件。不需要多智能体框架，不需要向量库，一个 Markdown 加一行注入配置就够。先从十条稳定事实写起，跑两周，你会发现自己删掉的自我介绍远比写进去的多。
