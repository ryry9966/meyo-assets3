## 背景

OpenClaw 社区里不少维护者在用 Agent 加 MCP 插件做自动发帖：每周精选、版本通告、FAQ 汇总。功能本身不难，难点在"发出来的观感"。同样的内容，定时器驱动和事件驱动发出来，社区成员的接受度差别很大。

## 问题：机器人感从哪来

复盘几个翻车案例，"像机器人"基本来自四个信号：

1. **固定间隔**：每周一 10:00 准时出现，误差不超过一分钟；
2. **无视上下文**：社区正在热议某个 bug，它发了条无关的周报；
3. **结构雷同**：标题模板、段落顺序、表情每次都一样；
4. **突发连发**：Agent 宕机恢复后，把积压队列一口气吐出来。

成员一旦识别出这些模式，信任感就开始流失——后续即使内容有价值，互动率也会明显下降。

## 做法：把节奏当成一等配置

核心思路是**节律和内容分离**，节奏作为可配置、可观测的独立模块：

1. **事件驱动优先**。触发条件挂在实际事件上：release 合并、某话题回复超阈值、FAQ 命中达标。定时器只做兜底。
2. **活跃时段对齐 + 抖动**。发送窗口对齐成员活跃时间（中文社区通常是上午 9:30–11:00、晚上 20:00–22:00，注意时区），窗口内做随机延迟，且分布向历史活跃峰值倾斜，而非均匀随机。
3. **三层频率上限**。最小间隔、日配额、周配额，宁缺毋滥。
4. **积压降级**。恢复后检查队列内容时效性，过期直接丢弃并记日志，不补发。
5. **回路监控**。发帖后盯一段时间的回复，负面信号达阈值就暂停该类目，转人工。

最小可用的节奏配置大致长这样：

```yaml
pacing:
  windows: ["09:30-11:00", "20:00-22:00"]
  jitter: skewed-random   # 偏向活跃峰值
  min_interval: 4h
  daily_cap: 2
  on_recovery: drop_stale
```

## 踩坑点

- **时区用错**。调度器默认 UTC，结果全部发在凌晨三点，看起来比固定间隔还假。
- **抖动加错位置**。jitter 加在每次运行上而不是队列出口上，重试和恢复时照样连发；它必须是"出队前"的最后一道闸。
- **重试导致重复**。发帖接口没做幂等，超时重试后同一内容出现两次，比"太规律"更伤。用内容哈希做幂等键。
- **均匀随机仍可预测**。改按时段活跃度加权，观感自然很多。
- **只发不听**。没有回复监控的自动发帖，等于在社区里装了个单向广播喇叭。

## 可复用建议

- 插件层把 `next_fire_time` 打进日志，让节奏可审计，出问题一眼能分清是调度还是内容的锅。
- 提供 dry-run 模式：只生成计划不发帖，先人工过目一周再放行。
- 模板留变化空间：至少准备 3 套标题和摘要结构轮换，长度允许浮动。
- 节奏参数与内容生成分开存放，调节奏不用动 Agent 逻辑。

## 总结

"不像机器人"的本质不是伪装，而是尊重：尊重成员的作息、注意力上限和讨论语境。把节奏当成和内容同等重要的工程对象——事件驱动、时段对齐、抖动、配额、幂等、回路——自动化发帖才能长期留在社区里，而不是被悄悄拉黑。
