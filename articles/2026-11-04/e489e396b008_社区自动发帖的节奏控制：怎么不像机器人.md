## 背景

OpenClaw 生态里做自动化的门槛越来越低：一个 Agent 挂上 MCP 工具，配个定时任务，就能往论坛、群、频道发内容——每周精选、发版说明、issue 汇总。我们社区里跑着三四个这样的发布器，跑了半年多。

早期版本被群友一句话点破："你们这机器人，每天早上 9:00:00 准时报到。"这才认真对待节奏问题。

## 问题

不像人的发帖通常有四个特征：

1. **时间过于规律**：cron 精确到秒，周一周三雷打不动；
2. **突发聚集**：任务失败重试后，几条内容在两分钟内连发；
3. **内容模板化**：同一句式开头，只有数字在变；
4. **只发不回**：从不 reply，纯广播。

结果不一定是被封号，更多是社区感知变差——大家默默把这类账号划为"噪音源"，互动率趋近于零，自动化的价值归零。

## 做法

按投入产出排序，分四层：

**1. 时间层：抖动 + 安静时段**

不用"到点即发"，改成到点入队、随机延迟后发送：

```yaml
schedule:
  window: "08:30-22:30"   # 发帖时段（按社区时区）
  jitter_minutes: 0-47
  max_per_day: 3
  min_gap_minutes: 90
```

延迟分布别用纯均匀随机——人在整点附近偏多。有历史数据就按活跃度加权采样，没有就先均匀，至少不会准点出现。

**2. 队列层：合并、去重、退避**

所有发布走同一个队列，不直接调 API。队列负责：同主题合并（一天最多一条精选）、内容指纹去重（防重启后重发）、失败指数退避加每日重试上限，避免重试风暴变成刷屏。

**3. 内容层：结构差异，而非同义改写**

模板轮换只解决表面问题，三个变体照样被认出来。更有效的是让不同类型内容天然长得不一样：精选带列表、发版说明只有三行、issue 汇总放表格。同时保留固定署名和标签——明确"这是自动化发布"在多数社区是加分项，装人反而减分。

**4. 互动层：留钩子**

纯广播是最大的机器味。每条自动帖附带一个跟进任务：24 小时内有评论就提醒人工回复，或由 Agent 起草回复进审核队列。发出去只是完成一半。

## 踩坑点

- **时区**：服务器 UTC、社区 UTC+8，安静时段直接错位，凌晨刷屏就是这么来的。所有时间配置显式带时区。
- **抖动过小**：±2 分钟等于没抖，观察窗口拉到周级别规律立刻现形。
- **去重没持久化**：进程重启后指纹丢失，同一内容隔十分钟重发，比不发还糟。
- **拟人化过头**：故意加错别字、装口癖，社区反感度远高于"明显是机器人但很克制"。

## 可复用建议

- 先跑两周纯日志（只记录不发送），把假想发布时间线和社区活跃曲线画在一起对比，再定窗口和配额。
- 节奏参数全部进配置不进代码，调整频率大概每月一次，别天天调。
- 自动帖互动率（回复/浏览）单独打点，跌破阈值自动降频——这是最诚实的反馈信号。
- 账号简介写清楚是自动化发布、由谁维护、怎么反馈。

## 总结

节奏控制不是"把机器人伪装成人"，而是把自动化放进社区的作息里：错峰、限流、留互动钩子、失败可退避。这套方案上线后，我们精选帖的回复率从接近 0 回到 3% 左右——不高，但对自动内容已经够用。克制和透明，比任何拟人化技巧都有效。
