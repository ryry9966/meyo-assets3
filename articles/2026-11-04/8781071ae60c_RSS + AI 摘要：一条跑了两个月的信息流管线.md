## 背景

算法时间线越来越不可控，但 RSS 一直是最省心的拉取协议：格式标准、无算法干预、频率自己定。我的问题是订阅源常年堆在阅读器里根本不看——手上 OpenClaw 实例的定时任务和插件机制正好闲着，于是决定把「拉取 → 去重 → 摘要 → 推送」整条链路交给 Agent 跑，目标是每天早上收到一份五分钟内能读完的日报。

## 问题

动手前有三个真实痛点：

1. 源太杂：四十多个源一天能出一两百条，全塞给模型既贵又稀释重点；
2. 内容缺失：相当一部分 feed 只有标题和链接，没有正文；
3. 可信度：摘要容易出现「看标题编正文」的幻觉，以及同一事件跨源重复报道。

## 做法

整条管线四步，全部跑在 OpenClaw 定时任务里：

**1. 源治理。** OPML 导入后先砍一轮，死源、半年未更新的源直接删，按主题分四组（技术、行业、工具、博客），总量控制在 40 个以内。

**2. 抓取与去重。** 每 2 小时拉一次 feed，以 guid 为主键写入本地 SQLite；标题归一化（去空格、全半角统一）后用分词 Jaccard 做跨源去重，阈值 0.6 实测够用。

**3. 摘要。** 对 24 小时内未处理条目按源分组批量送模型，prompt 强制结构化输出：

```json
{
  "one_liner": "一句话结论",
  "points": ["要点1", "要点2", "要点3"],
  "importance": 3,
  "insufficient": false
}
```

关键约束：「只基于给定内容，不得补充外部信息；正文不足时 insufficient 置 true」。insufficient 的条目只保留标题进日报，不让模型发挥。

**4. 汇总推送。** 每天 8 点把过去 24 小时条目按 importance 排序生成日报，importance ≥ 4 的走 webhook 实时推，其余只进日报，每条都带原文链接。

## 踩坑点

- **无正文摘要等于幻觉放大器。** 最早直接拿 description 送模型，摘要基本是标题扩写。接 readability 正文抓取后才稳，抓不到的一律标记「仅标题」。
- **HTML 残留烧 token。** 不少 feed 正文里全是内联样式和转义字符，清洗前后 token 消耗差三倍。
- **定时任务静默失败。** 有两天日报没出但没有任何报错。加了失败重试和「当日无产出即告警」的兜底后才安心。
- **重要度打分漂移。** 同一来源的条目经常全打 5 分。后来要求 prompt 里附带打分理由并在日报回显，漂移肉眼可见地收敛了。

## 可复用建议

- 摘要一定输出结构化 JSON，下游的排序、过滤、归档全靠它；纯文本摘要基本没法二次利用。
- 以 guid 做幂等键，任务重跑不重复入库，这条省了很多心。
- 每月复盘一次：看 importance 5 的条目是否真的重要，命中率低的源直接砍掉。源池是活的，不是一次性配置。
- 模型只当压缩层，不当决策层；所有摘要必须可回溯到原文链接。

## 总结

这套管线单点技术都不难，价值在「稳定 + 可审计」：跑了两个月，日报的误报率和 token 成本都可预期、可复盘。下一步计划接 MCP 工具，让 Agent 对高重要度话题主动追线索，把被动订阅变成半主动侦察。如果你的 OpenClaw 实例还闲置着定时任务能力，这是一个性价比很高的练手起点。
