最近 DeepSeek 网页版悄悄上线了"创造模式"（各家叫法不一，本质接近 Claude 的 Artifacts）：你在对话框里描述一个小工具，模型直接吐出一个能在页面里运行的单文件应用，改需求、加功能都在聊天里完成。36kr 那篇报道的标题很直白——"插件门槛被干碎了"。这句话一半是事实，一半是修辞。这篇把它拆开看：门槛原来是什么、碎掉的是哪一块、哪一块其实还硬着。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-04/108d634f2e13f49d.png)

## 「创造模式」是个啥：从“给你代码”到“生成即运行”

- 以前用大模型写代码的链路是：模型输出一段代码 → 你复制到本地 → 装环境 → 排错 → 跑起来。每一步都在劝退非程序员，很多人卡在"Node 版本不对"就放弃了。
- 创造模式的改动在于把**运行环境搬进了聊天窗口**：模型生成 HTML+CSS+JavaScript 的单文件应用，前端直接在沙箱 iframe 里渲染，右边预览、左边对话，说一句"把按钮改成蓝色"就热更新一版。比如你说"做一个番茄钟，带白噪音"，几十秒后你面对的就是一个带滑块和播放键、真能点的页面。
- 这个范式并非 DeepSeek 首创：2024 年 6 月 Claude 推出 Artifacts，随后 v0、bolt.new、Lovable 等一批"生成即运行"产品跟进。DeepSeek 的意义在于把它做成了免费、国内可直接访问的默认能力，叠加上亿用户基数，才让"普通人第一次亲手生成软件"成了大众事件。
- 背后是三个技术件：模型代码能力过线（R1 在 LiveCodeBench 等代码基准上已进第一梯队）；单文件产物设计（JS/CSS 全部内联，第三方库走 CDN，不依赖本地环境）；沙箱隔离（生成的代码跑在受控容器里，碰不到你的系统）。

## 插件门槛以前高在哪：解剖一条传统开发链路

以最典型的浏览器插件为例，从想法到能用，以前要走完这条流水线：

1. **学习成本**：HTML/CSS/JS 三件套只是入场券，还要读懂 manifest.json，理解 content script 和 background 之间的通信模型。
2. **工程成本**：本地调试、打包、多浏览器兼容——Chrome 和 Firefox 的 API 并不通用。
3. **分发成本**：Chrome Web Store 注册开发者账号、审核排队、隐私权限声明；小程序生态更重，注册、认证、审核一套流程走完，很多"我就想要个小工具"的冲动已经凉了，工具进了收藏夹吃灰。
4. **维护成本**：平台规则说改就改，Manifest V3 迁移就清退过一批老插件。

所以"门槛"从来不是一个东西，它是**一摞东西**：学习、工程、分发、维护。这摞东西客观上筛选了从业者，也把大量长尾需求挡在门外——很多小工具确实太小了，小到不配养一个完整开发流程。

## 大模型凭什么“干碎”它：三个变量叠在一起

- **代码生成能力过线**：长尾小工具大多是"输入 → 处理 → 展示"的薄逻辑，几百行 JS 就能写完，恰好落在当代大模型最擅长的区间。
- **运行环境标准化**：浏览器本身就是一台无处不在的虚拟机，单文件网页即开发、即分发、即运行，安装包和依赖管理这些传统摩擦直接归零。
- **反馈循环压缩**：需求描述、生成、预览、修改全收进一个对话框，迭代周期从"天"缩到"分钟"——这是体感变化最大的地方。
- 一个历史参照：ChatGPT 插件 2023 年 3 月上线，因为开发者太少、体验不稳，2024 年 4 月就下线，换成了 GPTs。这说明插件生态的瓶颈从来不是技术，而是"愿意为一个小功能写插件的开发者不够多"。当生成成本趋近于零，这个瓶颈就换了位置。

## 碎掉的是门槛，没碎的是边界

"干碎"有明确的适用半径，得泼几盆冷水：

- **多是前端薄应用**：没有真正的后端、数据库和用户系统，数据基本存不住（localStorage 除外），刷新即失。
- **调用外部 API 受限**：跨域、密钥管理（key 写在前端等于公开）、计费逻辑，沙箱里都解决不了。
- **质量与安全无背书**：生成的代码没有 code review、没有测试。凡是碰密码、支付、个人数据的工具，别用生成版本凑合。
- **维护是隐形成本**：demo 一小时，让它稳定跑一年是另一回事。浏览器 API 一变更、需求一膨胀，"顺手生成"的工具腐化得飞快。

一句话总结：碎掉的是"把想法变成能跑的 demo"这道墙，没碎的是"把 demo 变成可靠产品"那道墙——后者从来更厚，也一直更值钱。

## 三条实用建议与冷思考

1. **把创造模式当原型机，别当生产环境。** 验证想法、做团队内部小工具、给需求方演示，效率极高；一旦涉及账号、支付、他人数据，立刻回到正规开发流程，这条线不要模糊。
2. **值钱的能力在迁移。** 与其再背一个框架的 API，不如练"把需求说清楚"：输入是什么、输出长什么样、边界条件有哪些、出错怎么处理。会写需求的人，现在是真的能"白嫖"出一个工具。
3. **新的稀缺资源是分发和场景。** 当工具的生产成本趋近于零，"知道谁需要什么工具"反而成了护城河。对开发者，答案不是转行，而是把精力从"写工具"上移到"定义工具、并把工具送到对的人手里"。

技术的规律一贯如此：它不消灭一个工种，它消灭一道门槛，然后把门槛上原本站着的价值挤到别处去。看清价值被挤到哪儿去了，比争论"干没干碎"有用得多。
