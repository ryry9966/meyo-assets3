最近 36kr 一篇实测把“DeepSeek 创造模式”顶上了热议榜：不装任何插件，在对话框里说一句话，就能得到一个能跑、能点、能交互的小工具——日程整理页、数据转换器，甚至一个贪吃蛇小游戏。评论区最扎心的一句是：“我装了三年的浏览器插件，突然显得很多余。”这篇文章把这件事拆开看：创造模式到底是什么，插件门槛凭什么被“干碎”，以及哪些场景是真的回不去了。

## 一、“创造模式”到底是个什么模式

严格说，它不是设置菜单里的一个开关，而是社区对一类玩法的统称：让模型在对话里直接产出**可运行的产物（artifact）**，而不是一段需要你自己拷去 IDE 里跑的代码。

具体形态大概是三种：

1. **单文件 HTML 小工具**：HTML+CSS+JS 全部塞进一个文件，对话窗口内直接渲染，点开就能用；
2. **SVG/图形产物**：流程图、示意图、图标，让模型直接“画”出来，而不是用文字描述；
3. **可交互页面**：输入一堆乱糟糟的文本，输出一个排好版的日历页、看板或表单。

这条路最早由 Claude 的 Artifacts 跑通，2024 年中上线后验证了一个关键假设：模型的前端代码能力 + 对话内即时渲染，足以承载“现场造工具”的需求。DeepSeek 凭借 R1、V3 系列在代码基准上的表现，把这件事的成本打到了几乎可以忽略不计的程度。

## 二、插件门槛是怎么被“干碎”的



先看插件的本质：它是“某个特定场景的解决方案”+“一个分发渠道（应用商店/扩展市场）”的组合。过去满足一个需求的链路是这样的：

发现需求 → 搜插件 → 挑选比价 → 安装授权 → 忍受功能不对口 → 凑合用。

创造模式把这条链路压缩成两步：**描述需求 → 现场生成**。中间的搜索、安装、授权、付费环节全部消失。

支撑这个压缩的是三层技术变化：

- **代码能力越线**：主流旗舰模型在 HumanEval 这类代码基准上的通过率普遍超过 90%，写一个几百行的单页工具属于热身运动；
- **单文件自包含**：一个 HTML 文件自带样式与逻辑，不需要服务器、不需要部署，天然适合在对话里交付；
- **价格塌方**：DeepSeek 的 API 定价长期维持在每百万输入 token 一两元人民币的量级，2024 年甚至引发了一轮行业价格战。造一个工具的成本，从“工程师几天工资”降到“几分钱算力”。

经济学上讲，这是典型的边际成本坍塌：过去只有高频、大众化的需求才配得上一个插件；现在长尾的、一次性的、私人定制的小需求，也终于有了性价比。

## 三、实测：哪些插件场景可以退休了

把日常高频插件按场景过一遍，替换难度大致分三档：

**低难度（基本可以直接替换）：**
- 网页摘要、划词翻译类：把文本贴进去，让模型按结构输出要点，效果反而更可控；
- 格式转换类：CSV 转 Markdown 表格、JSON 格式化、时间戳换算，一句话的事；
- 小计算器类：房贷月供、汇率换算、周期倒计时页，现做现用。

**中等难度（能用，但要调教）：**
- 截图转表格：识别没问题，复杂合并单元格需要多轮修正；
- 数据可视化：让它生成带交互的图表页，默认颜值常胜过不少 BI 工具。

**高难度（暂时干不碎）：**
- 需要持久化数据的工具：AI 生成的页面关掉就没了，没有云同步；
- 需要系统权限的插件：读剪贴板历史、批量处理本地文件、跨网站自动化，浏览器沙箱外的活儿它够不着；
- 重度专业场景：剪辑、IDE、设计软件的深度工作流，不是一个对话框能替代的。

## 四、门槛下移 ≠ 专业工具消失

这里要泼一盆冷水：被干碎的是“门槛”，不是“专业工具”的价值。历史给过参照：

- 模板建站网站没有干掉开发者，只是让“做个官网”不再需要开公司；
- Excel 没有干掉数据库，只是让记个账不用请人写系统；
- 门槛下移的真正含义，是**需求的满足密度变高了**——过去九成的小需求因为不划算而默默消失，现在它们被现场满足。

另一个隐忧是维护：AI 现做的工具没有“作者”，出了 bug 找谁？答案还是找 AI 重新生成一版。这对一次性工具无所谓，对需要长期演进的系统就是灾难。未来更可能的格局是：高频通用需求继续由成熟插件和专业软件承接，长尾定制需求流向“对话即生成”，分发逻辑从“商店下载”部分转向“分享一个产物链接”。

## 五、给普通人的三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-04/af2459cbff95f067.png)

1. **把需求当产品文档写**。别只说“帮我做个日历”，而是说清输入是什么、输出长什么样、要哪些交互（比如“能勾选完成、按周切换”）。描述质量决定生成质量，这一条能拉开 80% 的差距。
2. **建立“个人工具仓库”**。好用的产物保存下来，遇到类似需求先改旧的不重写——改一版比从零生成更快，也更贴近你的使用习惯。
3. **敏感数据别往里贴**。生成的页面可能引用外部资源，公司内部数据、客户信息、隐私内容，生成前先想清楚它们会流到哪里。工具自由的前提，是数据自觉。

最后一句冷思考：插件时代教会我们“去商店找工具”，创造模式在教我们“把工具说出来”。真正的门槛从来不在软件市场里，而在你能不能把需求讲清楚——这件事，暂时还没被干碎。
