热搜说“Token与土豆齐飞”，主角是内蒙古乌兰察布，一个以马铃薯闻名的塞外城市，如今也是国内头部互联网公司扎堆建数据中心的地方，阿里、快手、优刻得、华为等厂商的机房都落在这儿。一边是地里长出来的土豆，一边是 AI 每秒吐出的海量 token，两者能凑进同一条产业链，靠的不是情怀，而是一套相当硬核的物理账和经济账。这篇就把这本账拆开算清楚。

## 先搞清楚：Token 是什么，凭什么这么费电

- **Token 是大模型的“计量单位”。** 模型不直接读汉字或单词，而是先用 tokenizer 把文本切成最小片段：一个英文单词约等于 1.3 个 token，一个汉字通常 1 个上下（不同 tokenizer 差别不小）。你在对话框里发一句话、收一段回答，后台对应的就是几百个 token 的输入输出计算与计费。
- **生成 token 的过程本身就是“算力燃烧”。** 大模型是自回归生成：一个 token 一个 token 往外蹦，每蹦一个，模型的千亿级参数都要在 GPU 里完整过一遍矩阵运算。写 1000 字回答，等于几千次全量计算接力。这就是为什么 GPU 一开就是上万张、功率按兆瓦计。
- **训练烧一次，推理天天烧。** 训练是集中式“大出血”——数千卡连续跑数周到数月；推理则是随用户量线性增长的“细水长流”。业界共识是：AI 应用铺开后，推理的总算力消耗会远超训练，而推理直接对应电费。

需求涨得有多快？国内头部大模型厂商披露的日均 token 调用量，一年内从千亿级冲到数万亿级；单次调用单价确实在降（一年降一个数量级很常见），但总消耗涨得更快——教科书级的杰文斯悖论（Jevons Paradox）：效率提升反而刺激总消耗暴增。有研究估算，一次 AI 对话的能耗约为传统搜索引擎查询的数倍到十倍。电，成了 AI 时代的第一原材料。

## 为什么是乌兰察布：算力选址的三道物理题

数据中心本质上是“把电变成热、顺便算个题”的工厂，选址就是解三道物理题。

1. **冷。** 服务器 7×24 发热，散热能占数据中心电费的 30% 以上。乌兰察布年均气温约 4.3℃，一年有五六个月可以直接抽室外冷空气给机房降温（free cooling）。当地新建集群的 PUE（电能利用效率，越接近 1 越好）能压到 1.2 以下，而全国平均水平还在 1.5 附近，别小看这 0.3 的差距，一个上万机柜的园区一年省下的就是上亿度电。
2. **电。** 内蒙古风电装机全国第一，风光资源富集，当地大工业电价长期在 0.3 元/度上下，比东部沿海低三成到一半。数据中心六成以上的运营成本是电费，电价差约等于利润差。
3. **近。** 乌兰察布到北京直线约 240 公里，光纤单向时延 5ms 左右，相当于把机房修到了北京隔壁。训练、离线批处理这类对延迟不敏感的负载整批西迁，北京本部机房留给时延最敏感的业务——分工干净利落。

天然空调 + 便宜电 + 靠近核心用户，三个条件能同时满足的城市屈指可数，乌兰察布算是教科书级答案。

## 东数西算：把算力当“电网”来调度

单点便宜还不够，2022 年 2 月全面启动的“东数西算”工程把这种格局制度化：全国规划 8 大算力枢纽、10 大数据中心集群，内蒙古枢纽下的和林格尔集群与集宁（乌兰察布）大数据产业园双双在列。

- **分层调度逻辑**：类似电网和物流网，按“延迟敏感度”给算力需求分层，模型训练、冷数据存储、离线渲染等可容忍几十毫秒延迟的任务西迁；实时推理、在线交易等留在用户密集的东部。
- **配套跟上**：集群之间目标时延 20ms 以内、集群内部 1ms 量级的直连网络，加上能耗指标倾斜与绿电供给，等于把“网络、土地、电”三个要素一次性打包。
- **对乌兰察布的升级**：从“招商招来的机房”变成国家级枢纽节点，网络优先级、项目来源、政策能级完全不是一个量级。

## 土豆与服务器共存：账本与隐忧

**账面上的收益：**
- 重资产投资落地，一个园区动辄几十亿，带来税收与建设、运维就业；
- 数据中心是不间断负荷，恰好能帮当地消纳波动大的风电光伏，绿电与算力在物理逻辑上是天生一对；
- 地方期待的升级路径：算力 → 数据服务 → AI 应用生态，从“卖机房”走向“卖智能”。

**但隐忧也得摆上桌：**
- **折旧曲线残酷**：通用服务器能跑 6~8 年，AI 服务器因算力迭代快，3~5 年就可能落伍，投资回收周期与硬件换代周期在赛跑；
- **电价依赖**：不少项目是被优惠电价吸引来的，长期竞争力要靠绿电交易和市场化电价机制兜底；
- **同质化竞争**：八大枢纽都在抢项目，最终拼的不只是电价，还有网络质量、运维人才和算力调度效率；
- **供需节奏风险**：AI 芯片两三年一代，若某阶段算力供给过剩，“空转的机房”是所有资产里最难看的一种。

## 冷思考：三条值得带走的判断

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/1227c279ca57e330.png)

1. **电价是地板，网络是天花板。** 无论评估算力供应商还是做基础设施规划，先看电价与 PUE（决定成本下限），再看时延与直连网络（决定业务上限），缺一不可。只谈电价的算力报价，多半不完整。
2. **把“分层思维”用到自己的业务里。** 对延迟不敏感的负载（训练、批处理、备份、渲染）大胆调度到便宜的地方，实时业务留在用户身边，这是乌兰察布模式最值得复用的部分，规模缩小到个人开发者选 API 部署区域时同样成立。
3. **盯“每 token 成本”，别只盯“每 GPU 小时价格”。** 真正的竞争力是端到端效率：硬件利用率、散热方案、电力成本要一起算。乌兰察布卖的不是机柜，而是“更便宜、更绿的 token”，理解了这一点，才算看懂热搜里土豆与 token 的合影。
