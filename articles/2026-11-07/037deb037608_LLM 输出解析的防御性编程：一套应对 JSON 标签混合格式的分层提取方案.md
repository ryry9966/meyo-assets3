## 背景

在 OpenClaw 的插件和自动化流程里，让 LLM 输出 JSON 是高频操作。常见约定是让模型用标签包裹结果，比如 `<json>{...}</json>`，或者直接包在 ` ```json ` 代码围栏里。问题在于：这套“契约”只在大多数时候成立。换模型、调温度、加长 prompt 之后，同一个系统拿到的输出会混合出现至少四种形态：纯标签包裹、代码围栏包裹、标签外面多了句“以下是结果：”、以及什么都不包的裸 JSON。

解析器按理想格式写，就会在真实流量里随机性挂掉。

## 问题

我最初的处理就是一个非贪婪正则提取标签内容再 `json.loads`，上线后失败率不高但稳定存在，而且失败样本五花八门：

- 模型用四个反引号的围栏包住三个反引号的代码块；
- 输出里出现两个 `<json>` 标签，一个是思考草稿，一个是答案；
- JSON 里的字符串值包含中文引号 `“ ”` 或全角逗号，直接炸掉 `loads`；
- `max_tokens` 截断，只剩前半个对象。

单独修每一个 case 都会变成打地鼠，最后我把它重构成一个分层提取管线。

## 做法

核心思路：**在调用 JSON 解析之前，先做格式归一化，且每一层都能独立失败降级。**

```python
def extract_json(raw: str) -> str:
    text = raw.strip().lstrip("\ufeff")

    # 第 1 层：剥代码围栏（只剥最外层，注意嵌套围栏用更长 fence）
    m = re.search(r"```[a-zA-Z]*\s*(.+?)```", text, re.S)
    if m:
        text = m.group(1).strip()

    # 第 2 层：剥标签，大小写不敏感，容忍标签内空白
    m = re.search(r"<\s*json\s*>(.*?)<\s*/\s*json\s*>", text, re.S | re.I)
    if m:
        text = m.group(1).strip()

    # 第 3 层：括号配对兜底——扫描第一个 '{'，
    # 计数时跳过字符串字面量内部的括号
    # 第 4 层：清洗——去尾逗号、替换中文引号为英文引号
    return text
```

关键点是**顺序**：先围栏再标签，因为标签经常出现在围栏里面；反过来会漏。括号配对作为兜底层，专门接住标签缺失的情况。清洗层只做可逆、无歧义的替换，不做“智能修复”。

解析失败后不立刻报错，而是把原始输出加解析错误回喂给模型，让它自修一次，仅限一轮。

## 踩坑点

1. **非贪婪正则跨段匹配**：`.*?` 在标签缺失闭合时会一路吃到文档末尾。标签层失败后应该放弃这一层，而不是返回一大段垃圾。
2. **括号计数不忽略字符串内部**：JSON 值里带代码片段时，`{}` 会配对错乱。计数前需要跳过被引号包裹的区域。
3. **多个标签实例**：不要取第一个，逐个尝试解析、取第一个能通过 schema 校验的，或者明确取最后一个。
4. **中文智能引号**是中文场景最高频的失败原因，值得单独一条清洗规则。
5. **流式输出**下标签未闭合就会触发解析，必须等终态事件再跑提取器。

## 可复用建议

- 把提取器做成独立模块，**用线上真实失败样本当测试 fixture**，比凭空写用例有效得多。
- 解析失败时把脱敏后的 raw 原文记进日志，失败模式是会随模型版本漂移的，需要语料才能发现。
- Prompt 侧同步收紧：“只输出标签内容，不要任何解释”，有条件就用 provider 的结构化输出模式，但别依赖它做唯一防线。
- 在插件的返回结构里保留 `parse_ok` 和 `raw` 字段，让上游流程能对失败分支做路由。

## 总结

LLM 输出解析失败不是模型的 bug，而是接口契约天然不稳定。防御性解析的本质是把格式归一化收敛到自己可控的边界层：分层提取、可降级、可观测、留语料。这套东西一次写好，后续换模型、改 prompt 都不用回头改解析逻辑，是插件工程里性价比最高的投入之一。
