过去两年，AI 的能力曲线从"能聊"爬到了"能干活"。2025 年 1 月，OpenAI 推出 Operator，能自己打开浏览器、移动光标、填表下单；4 月，Visa 与 Mastercard 相继发布面向 AI agent 的支付方案；5 月，Coinbase 推出 x402 协议，让机器与机器之间用稳定币直接结算。于是热议来了：AI 开始替我们花钱了。这句话背后不是噱头，而是"任务闭环"的最后一块拼图——支付——正在被打通。这篇把它怎么实现、凭什么被信任、还有哪些坑，一次拆开讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/2dd3221ca2f1b19e.png)

## 一、为什么支付是 Agent 的"最后一公里"

- 回看时间线：2022 年 ChatGPT 让模型能说；2023 年 function calling 让它能调用工具；2024 年多模态和长上下文让它能看、能读；2025 年 computer use / browser agent 让它能真正"动手"操作软件。
- 一个完整任务闭环是四步：规划 → 检索 → 操作 → 结算。前三步在数字世界里已经跑通，唯独结算卡住，因为支付天然涉及身份、授权、资金与追责，出错成本是所有环节里最高的。
- 所以 2025 年支付方集体下场，本质上不是"AI 想花钱"，而是商业闭环需要"AI 能付钱"。看一组节点：OpenAI Operator（1 月）、Visa Intelligent Commerce（4 月）、Mastercard Agent Pay（4 月）、Amazon"Buy for Me"代购功能（4 月）、Coinbase x402（5 月）、Google 联合数十家机构发布 Agent Payments Protocol（9 月）。半年之内协议、支付网络、产品三层同时启动，这个节奏在向来保守的支付行业相当罕见。

## 二、技术上怎么做到：三条主流路径

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/a4b6d5dd3425ccf3.png)

1. **浏览器操作型**：让模型像人一样"看屏幕、点按钮"。Operator 背后的 CUA（Computer-Using Agent）模型用视觉理解页面，再模拟鼠标键盘完成下单。优点是通用，理论上任何网站都能用；缺点是脆弱——验证码、弹窗、页面改版都会让它卡壳。
2. **API / 协议型**：绕开页面，让商家直接开放 agent 友好的接口。Stripe、PayPal 都发布了 agent 开发工具；Anthropic 的 MCP 把模型与外部服务的连接标准化；最有趣的是 Coinbase 的 x402——HTTP 协议里有个 402 状态码，1996 年在 RFC 1945 里就定义了，注释写着"为将来使用保留"，沉睡了近三十年。x402 把它激活：服务器返回 402，agent 自动用 USDC 稳定币完成微支付，全程无人工。一个 90 年代的占位符，在 2025 年成了机器支付的原语。
3. **支付网络改造型**：Visa / Mastercard 的思路是给 agent 发"代币化凭证"——每个 agent 一个独立虚拟卡号，绑定单一商户、单一场景和消费限额，商户端直接校验，真实卡号从头到尾不出现。

## 三、核心难题：怎么证明"是你让 AI 买的"

传统风控有个隐含假设：卡在谁手里，谁就是消费者。Agent 打破了这个假设，整个行业都在补一条认证链路：

- **授权委托（delegated authority）**：用户用 passkey 或生物识别确认一次"我授权这个 agent 在某类场景消费，上限 X 元"，生成可验证的授权凭证。Google 主导的 AP2 协议干的就是这件事的标准化。
- **凭证 tokenization**：agent 拿到的不是真卡号，而是限定商户、限定金额的虚拟号，即使泄露，损失边界也清晰可控。
- **human-in-the-loop**：超过阈值金额弹回人工确认。Amazon 的"Buy for Me"就是这个设计——agent 负责找货和填购物车，付款这一步由人亲手完成。
- **审计与追责**：每笔交易附带 agent 的决策上下文（为什么买、依据什么），事后可追溯、可仲裁。至于出问题算用户的、agent 平台的、支付网络的还是商户的，四方责任划分目前仍在博弈中。

## 四、已经落地的场景，和被重写的流量入口

- **机器对机器微支付**：agent 之间按次付费调用数据与 API，是 x402 的主战场。网页的"付费墙"可能演变成"每次抓取 0.01 美元"——爬虫经济被明码标价。
- **日常代购**：订餐、订机票酒店、日用品复购、订阅续费管理。这类"高频、低客单价、决策模式化"的支出最适合 agent 接管。
- **IoT 与车联网**：汽车自动支付充电费、停车费、过路费。其实机器钱包早有雏形——ETC 就是挂在你车上的一个支付 agent。
- **入口迁移**：如果购物决策和执行都交给 agent，搜索与推荐流量会被重新分配。"给 agent 看的商品页"会变成新的 SEO 战场，对电商和内容平台来说，结构性变化已经埋下伏笔。

## 五、风险清单：先别急着把主卡交出去

- **间接 prompt injection**：恶意页面在商品描述里藏指令，诱导 agent 做非预期操作（比如改地址、超额度下单）。这是当前 agent 支付最典型的攻击面，浏览器操作型路径尤其暴露。
- **能力幻觉**：买错、买重、买贵都会发生，而退款与争议流程目前是为"人"设计的，agent 交易的对账成本短期内会偏高。
- **隐私集中**：你的全部消费偏好汇聚到 agent 服务商手里，数据集中度比任何一家电商都高。谁来存、谁能用，取决于各家条款，值得逐条读一遍。

## 收尾：三条实用建议与一点冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/b9284796c0ad6d3f.png)

1. **最小授权原则**：给 agent 单独的支付凭证——虚拟卡或子账户，设月度限额，超过阈值必须人工确认。主卡永远不要直接挂上去。
2. **从低风险高频场景开始**：订阅续费、日用品复购、API 付费调用先交给它跑；高客单价决策保留人工，攒一段信任记录再逐步放权。
3. **商家与开发者的机会**：尽早准备结构化商品数据和 agent 可调用的下单接口，入口正在从"页面"迁往"协议"，晚一步就是别人的生态位。

冷思考一句话：谁掌握 agent，谁就掌握下一代钱包的入口。支付巨头半年内集体下场，抢的从来不是"帮用户花钱"这个动作本身，而是那个位置背后的门票。
