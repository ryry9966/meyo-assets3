过去两年，AI 在我们消费链路里的角色，完成了从“参谋”到“跑腿”的三级跳。以前它帮你总结测评、列比价表；现在 Perplexity 能在对话窗口里直接结算，ChatGPT 接入了 Instant Checkout，Google、Stripe、Coinbase 们密集发布支付协议。36kr 把这条线索概括成一句话：AI 开始替我们花钱了。这背后不是炫技，而是一条名为 Agentic Commerce（代理式商务）的新管道正在铺设。这篇文章把它拆开看：钱是怎么花出去的、为什么是现在、坑在哪里。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/1edc6a13018a8315.png)

## 从推荐到代购：AI 角色的三级跳

- **第一级：信息助手。** 搜索摘要、比价网站，AI 只负责“告诉你去哪买”，动手的仍然是你。
- **第二级：导购。** Amazon 的 Rufus、ChatGPT 的购物推荐开始回答“买哪个”，但点击、结账仍由用户完成。
- **第三级：代理。** OpenAI 的 Operator（2025 年初发布）能像人一样操作浏览器，走完整个下单流程；Perplexity 的 Buy with Pro 让用户在对话里一键付款；2025 年下半年，OpenAI 联合 Stripe 推出 Instant Checkout，商家把结算接口直接开进聊天窗口。

关键变化有两个：一是**决策权上移**——从“人逛、人选”变成“agent 逛、agent 选”；二是**入口位移**——流量分发从搜索引擎和购物 App，转向对话框。对商家来说，这意味着货架的位置彻底变了。

## 机制拆解：一笔 agent 订单是怎么完成的

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/8aa1bf6f006c6d56.png)

一次典型的 agent 下单，大致跑通五步：

1. **意图澄清**：你说“预算 300 内买双跑鞋”，agent 先确认需求边界，避免理解偏差。
2. **检索比价**：调用商品数据库与网络信息，生成候选清单。
3. **协议握手**：通过 MCP、A2A 这类工具协议调用商家接口，拿到结构化的商品与结算信息。
4. **支付执行**：这是最关键的一环，目前主流做法有三类——
   - **Tokenized 支付**：如 Stripe 支撑的 Instant Checkout，把真实卡信息换成一次性凭证，降低泄露风险；
   - **虚拟卡 / 单次卡**：限定商户、额度、时效，天然适合给 agent 用；
   - **标准化授权框架**：Google 牵头的 AP2（Agent Payments Protocol）提出 mandate 概念——用户用加密签名确认“我确实授权 AI 买这一单”，后续结算、退款、追责都以它为凭证；Coinbase 的 x402 则把微支付做成 HTTP 的原生扩展（复用了那个躺着多年的 402 状态码），面向 API 与内容付费。
5. **凭证回传**：订单、物流、售后信息回到对话流，agent 继续跟进履约。

打个比方：等于你给 AI 办了一张限额副卡，外加一份带签名的委托书。工程上的核心难题只有两个——怎么证明“授权是真的”，怎么保证“执行不跑偏”。

## 为什么是现在：三块地基同时打好

- **模型层**：function calling 足够稳定，长任务执行不再动辄“迷路”，这是过去一年最大的增量。
- **支付层**：tokenization、风控、拒付（chargeback）体系已经有十几年电商积累，agent 支付本质上是旧管线上接新阀门。
- **协议层**：巨头开始抢标准。逻辑和当年的 App Store、移动支付类似——谁定义了结账协议，谁就站在交易链路的收银台位置。

商家侧也有推力：搜索流量增长见顶，如果 agent 入口成为新的分发层，那 SEO 的下一步可能就是 GEO（生成式引擎优化）——让商品数据能被 agent 干净利落地读取、理解和调用。抢不到 agent 推荐位的商家，未来可能连“被比价”的资格都没有。

## 别急着放手：五个真实风险

- **间接注入（prompt injection）**：agent 替你浏览网页时，恶意页面可能在内容里夹带指令，诱导它买错商品、跳到假商户。这是整条链路里被安全社区点名最多的攻击面。
- **推荐不中立**：agent 可能优先展示“接入费/佣金”友好的商品，所谓比价未必是全市场比价。
- **事故归责**：买错了、重复扣款了，责任怎么分、退款怎么走，行业标准还在磨合期。
- **订阅失控**：agent 顺手订阅一串服务，月账单悄悄膨胀，人的感知反而变弱——自动化最隐蔽的成本是“无感”。
- **隐私**：消费记录是颗粒度最高的个人画像，交给谁、存在哪、训练不训练，值得较真。

## 三条实用建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/429f622d15f23b2f.png)

1. **权限画圈**：给 agent 单独开虚拟卡或子账户，设单笔与月度上限，超过阈值强制转人工确认。授权粒度越细，事故半径越小。
2. **看清利益链**：重要消费多问一句“这个推荐背后谁付费了”，再手动交叉验证一轮，别让“比价”退化成单源引用。
3. **留审计轨迹**：优先选带 mandate、订单日志的方案，每月复盘一次 AI 经手的账单。把“AI 替我花钱”当成雇了个实习生——授权要书面、额度要设限、定期要查岗。

管道正在铺，标准还在抢，各家协议的胜负几未分。等基础设施尘埃落定，真正决定钱往哪流的，不是模型能力，而是你把权限设计成什么样、以及你的消费习惯还剩多少定力。毕竟工具可以代理你的手指，但暂时代理不了你的判断。
