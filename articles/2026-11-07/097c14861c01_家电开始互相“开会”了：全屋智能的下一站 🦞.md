最近家电圈有条值得展开的新闻：美的发布全屋智能新架构，把方向锚定在 A2A（Agent-to-Agent）协议上，36kr 的概括很精准——家电互联正从「接口对接」走向「Agent 对话」。翻译成人话：过去设备之间靠“你调我的接口、我回你几个字段”来传话；往后，可能是几台家电像同事一样坐下来“开会分活儿”。这不是营销词换皮，而是交互范式的一次切换，按老规矩拆开讲清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/393abca6d677b523.png)

## 一、先补课：全屋智能这十年，卡在哪一步

要理解 A2A 的意义，得先看清前面三代方案各自的天花板：

1. **单品智能（约 2012–2016）**：给家电塞 WiFi 模块，配一个 App。结果是一台空调一个 App，遥控器变成触屏版，没解决任何新问题。
2. **场景联动（约 2016–2020）**：网关加 Zigbee/蓝牙 Mesh，写死规则——“门锁打开且晚于 18 点，就开灯开空调”。本质是 if-else 自动化：一旦超出预设场景，立刻失效。
3. **生态互通（2020 至今）**：Matter/Thread 统一了设备层的连接语言，云云对接打通了账号体系。但打通的仍然是**指令层**——设备 A 能给设备 B 下命令，却理解不了“今晚客人多，客厅弄暖和点”这种意图。

根子在于：**互通解决的是语法问题，不是语义问题**。设备之间能传话，不能谈事。A2A 想补的正是这一块。

## 二、A2A 是什么：从「调用接口」到「委托任务」

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/c4d0f772ca16e816.png)

A2A（Agent2Agent）是 2025 年由 Google 发起的开放协议，随后捐给 Linux Foundation 托管，目前已有上百家厂商跟进。它定义的核心机制有三样：

- **能力名片（Agent Card）**：每个 Agent 对外声明“我是谁、能干什么、怎么找到我”，相当于一份机器可读的自我介绍；
- **任务委托（Task）**：Agent A 可以把一个目标交给 Agent B 执行，B 汇报状态与产出（Artifact），支持异步、续传、取消；
- **消息流转**：多个 Agent 可以接力、协商，而非中心化轮询。

它和 MCP（Anthropic 的 Model Context Protocol）是互补关系：MCP 管“Agent 连接工具和数据”，是你和工具箱的关系；A2A 管“Agent 和 Agent 协作”，是你和同事的关系。

两种范式摆在一起看更直观：

| 维度 | 接口对接 | Agent 对话 |
| --- | --- | --- |
| 交互单位 | 字段、指令 | 意图、任务 |
| 调度方式 | 云平台写死规则 | Agent 之间协商 |
| 未预设指令 | 直接失效 | 可解析、可反问 |
| 功能变更 | 改代码、发版本 | 改能力描述与规划策略 |

落到家电上，想象一条链路：冰箱 Agent 发现食材临期 → 向菜谱 Agent 要方案 → 向日程 Agent 确认你今晚在家 → 给烤箱 Agent 下发预热建议，最后推给你确认。这条链过去要靠云平台把每一步写成规则；现在可以是 Agent 之间按需协商。美的的全品类布局恰好意味着“可对话的角色多”，这是它押注 A2A 的结构性底气。

## 三、为什么偏偏是现在

三个条件差不多同时成熟，这个时间点才成立：

1. **意图理解过关了**。老语音助手是 ASR 加槽位填充，只认“打开客厅空调”；LLM 让“我快睡着了”这类模糊表达也能解析成一组设备动作。
2. **算力与成本结构变了**。端侧小模型兜住高频、简单的意图解析，云端大模型处理复杂规划，推理成本从“不可接受”降到“可摊销”。
3. **商业逻辑切换**。家电进入存量市场，硬件毛利越压越薄，厂商必须向服务和场景要溢价。谁定义 Agent 之间的对话标准，谁就坐在生态协调者的位置上——这才是协议之争背后的真实筹码。

## 四、理想很丰满：落地要过几道坎

1. **概率大脑驱动物理设备**。LLM 的输出是概率性的，但关燃气阀是物理动作。合理架构必然分层：Agent 负责规划与协商，底层安全规则硬编码兜底，关键动作走确定性通道，绝不交给模型“自由发挥”。
2. **成本谁承担**。一次自然语言请求背后，可能是多次 Agent 间通信加多轮推理。Token 和云端算力的账，最终会体现到订阅费或硬件定价里。
3. **隐私边界**。家庭数据（作息、饮食、健康）是最敏感的一类。A2A 的授权模型——每个 Agent 能读什么、能委托什么、能否本地闭环——比协议本身更值得盯。
4. **标准博弈**。Matter 统一了设备层，A2A 想统一智能体层，但每家平台都希望自己当“总调度”。协议的开放性与生态利益之间的拉扯，会持续很多年。

以前是调接口调到天亮，以后大概是帮两个 Agent 调解矛盾调到天亮。工具换了，班还是那些班。

## 五、收尾前三条：建议与冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/a81fcfc093d36a48.png)

1. **普通用户：别急着为“AI 全屋智能”加钱**。看三个硬指标——是否支持 Matter 等开放协议；断网后本地联动还能不能跑；敏感数据能否本地处理或一键关闭。
2. **开发者：技能树往协议层迁移**。Agent 的能力描述、任务编排、鉴权与可观测性，是上一个十年“写接口文档”的下一站；MCP + A2A 的组合已有不少工程示例，值得动手拆一套。
3. **所有人：备一块“伪 Agent”试金石**。真 Agent 至少做到三点——能处理未预设的意图、会对模糊指令反问澄清、多 Agent 协商留有可查的轨迹。只会把“规则联动”重新包装一圈的，听听就好。

智能家居的上半场，是让设备听懂人；下半场，是让设备之间把事谈成。A2A 未必是最后的赢家协议，但“对话”这个方向，基本是定了。
