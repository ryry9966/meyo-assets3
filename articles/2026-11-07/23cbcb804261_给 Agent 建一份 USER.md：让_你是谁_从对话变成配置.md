# 背景：每次会话都在重新自我介绍

用 OpenClaw 一段时间后，你会遇到一个尴尬的模式：每次新会话，前几轮对话都花在重复交代上——"我主力用 Go，别给我生成 Python""我在东八区，别把定时任务排错""回复尽量短，不用客套"。项目层面有 CLAUDE.md / AGENTS.md 承载仓库约定，但"我是谁"这类跨项目、跨会话的个人上下文没有归属，只能在对话里反复投喂。

问题不只是重复。Agent 对你的默认假设往往和真实情况有偏差：给终端老手解释基础命令、在不该引框架的地方硬塞框架、时区算错导致自动化任务全歪。这些偏差每次都要靠对话纠正，而纠正本身也在消耗上下文窗口。

# 做法：一个文件，一行加载

思路很简单：建一份固定位置的 Markdown 文件，让 Agent 每次启动时加载。我放在 `~/.openclaw/USER.md`，在启动配置或 bootstrap 流程里加一条加载指令，也可以直接软链到工作区的 memory 目录。

内容分六块：

- **身份与角色**：一句话说清你是谁、主要产出什么
- **技术栈**：主力语言、框架、明确不用的东西
- **环境**：OS、时区、常用路径
- **沟通偏好**：回复长度、解释深度、"不要做什么"
- **当前关注**：最近两周在推进的事（滚动更新）
- **禁止项**：踩过的雷，比如"不要自动 commit"

核心原则：写陈述句和列表，不写散文；写可执行的偏好，不写"代码质量要好"这类空话。每一条都应该能让 Agent 产生可见的行为差异，否则删掉。

# 踩坑点

1. **写太长。** 我的第一版有 300 多行，结果 Agent 对中间内容基本无感——注意力被稀释，每个会话还在持续烧 token。现在控制在 60 行以内，效果反而更好。
2. **和项目级文件打架。** USER.md 说"用 pnpm"，项目 CLAUDE.md 说"本仓库必须用 npm"。要显式声明优先级：项目文件 > 用户文件 > 默认行为，并把这条规则写进 USER.md 本身。
3. **"当前关注"腐烂。** 三周前的关注点还留在文件里，Agent 就会按旧目标给建议。我设了每周检查一次，过期就删。
4. **塞敏感信息。** API key、手机号、内网地址一律不进 USER.md。这个文件很容易被同步或整段复制进对话，按"随时可能被第三方看到"的标准来写。
5. **写完不验证。** 加载配置未必真生效。最简单的验证方式：新开会话直接问"你对我的了解有哪些"，答不上来说明加载链路有问题。

# 可复用建议

- 把 USER.md 收进 dotfiles 仓库，像管 `.zshrc` 一样管它，跨机器保持一致。
- 让 Agent 参与维护：会话结束时问一句"根据这次对话，建议更新 USER.md 的哪些条目"，人工审核后合入。哪些纠正反复出现，它比你记得清楚。
- 分层存放：稳定偏好进 USER.md，项目约定进 CLAUDE.md，临时想法不进任何长期文件。
- 加一条减法规则：每次更新至少删一条。上下文文件只增不减，是熵增的开始。

# 总结

USER.md 本质上是件小事：一个 Markdown 文件加一行加载配置。但它把"让 Agent 了解你"从对话行为变成了配置行为——可版本控制、可审查、可迁移。实践下来，新会话的冷启动成本明显下降，Agent 输出的默认偏差少了大半。如果你已经在维护 CLAUDE.md，那就没有理由不给"你自己"也建一份。
