## 背景

用 OpenClaw 搭过几个常驻 Agent 之后，最直观的痛点不是模型能力，而是"失忆"：每次会话都要重新交代代码风格、部署习惯、沟通详略。上下文窗口再大，跨会话状态也是零。社区里常见的做法是把聊天记录往向量库里一塞，实际跑起来检索出的一半是噪声。这篇记录我们记忆模块从零到可用的取舍过程，全部基于 MCP 工具实现。

## 问题拆解

"记住偏好"其实是四个独立问题：

1. **存什么**：偏好 ≠ 对话记录
2. **什么时候写**：写入时机比存储选型更影响质量
3. **怎么读**：注入多少、什么时机注入
4. **怎么改**：偏好会变，冲突怎么办

## 做法

**第一步：先分类，别上来就建向量库。**

- 用户画像（稳定偏好）：代码风格、工具链、时区、沟通详略
- 情景记忆（任务级）：某项目的部署命令、上次报错与处理
- 工作记忆（会话内）：当前任务状态，不需要持久化

前两类分开存。画像用结构化 JSON + SQLite 就够，带 `source / created_at / last_used / confidence` 字段；情景记忆才值得上 embedding。纯向量检索对"不要用 Docker"这类否定句和具体 key 匹配很差，我们最终是结构化标签 + 向量的混合查询。

**第二步：写入走独立提取，不在对话中随手记。**

任务结束（或每 N 轮）触发一次提取 pass，标准写死在 prompt 里：只提取明确的、可复用的、用户主动表达的偏好；推断性内容标 `confidence=0.3` 单独存放。写入太勤是最常见的错误——"这个项目用 tab 缩进"被当成全局偏好，之后所有项目都被污染。

**第三步：读取定预算。**

会话启动注入画像 top-N（我们限制在 300 token 内），任务中途用 `memory_query` 做即时检索。实测注入超过 500 token 的记忆后，Agent 开始"过度自信"，把陈年偏好当成当前指令执行。

**第四步：冲突与遗忘。**

- 新记忆不覆盖旧记忆，而是 supersede：保留历史链，检索只取每条链末端
- 给 Agent 三个 MCP tool：`memory_store` / `memory_query` / `memory_forget`
- 给用户一个明文视图：直接看、改、删所有条目。这比任何算法优化都提升信任

## 踩坑点

- **embedding-only 检索**：否定语义丢失，"不要自动 commit"检回一堆自动 commit 教程
- **把对话日志当记忆存**：检索精度看着高，全是上下文碎片，注入后稀释指令
- **没有 last_used 和置信度**：没法衰减，半年前的废弃偏好永久霸占注入位
- **没有评测**：改一版提取 prompt，不知道变好还是变坏。后来固定 20 条偏好回放用例，每次改动跑一遍 diff
- **隐私**：记忆里常有 token、路径、人名，务必本地存储，`memory_forget` 必须真删而不是软删标记

## 可复用建议

1. 第一版就用一个带 schema 的 JSON 文件，别急着上基础设施
2. 写入保守、读取慷慨：宁少记，别记错
3. 条目五字段起步：`content / type / source / created_at / confidence`
4. 一切通过 MCP tool 暴露，Agent 自管记忆，用户可审计
5. 建 10–20 条回放用例做回归

## 总结

记忆系统本质是数据工程问题而不是模型问题：分类、写入时机、检索预算、冲突处理，四件事做对，一个几百行的 MCP server 就能让 Agent 表现出"记得你"的效果。先跑通最简闭环，再谈衰减和个性化排序。
