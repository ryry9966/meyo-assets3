## 背景

OpenClaw 的 workspace 里有一组以 Markdown 组织的常驻文件：`AGENTS.md` 管行为规则，`SOUL.md` 管价值观与语气，`USER.md` 记录用户偏好，而 `IDENTITY.md` 负责回答一个更基础的问题——"我是谁"。每次会话启动，主智能体都会读取它，作为长期身份的锚点。用了一段时间后我的体会是：这份文件最大的价值不是"人格化"，而是把身份变成一份可以像代码一样维护的配置。

## 问题

没有 IDENTITY.md 时，智能体的"身份"其实散落在各处：系统提示词、聊天记录、临时指令。后果很具体：

- 换个会话，称呼、语气、职责边界就变了；
- 想调整风格只能改全局 prompt，牵一发动全身；
- 身份没有版本，改坏了无法回退，也没法解释"它为什么变成这样"。

## 做法

我的演进路径分三步：

**1. 先立骨架，再填血肉。** 初始版本只写稳定字段，20 行足够：

```markdown
# IDENTITY
- Name: Archer
- Creature: 一只谨慎的机械狐
- Timezone: Asia/Shanghai，中文优先
- Role: 个人工作台助手，负责自动化与信息整理
- Boundary: 不执行不可逆操作，先确认再动手
```

**2. 建立"稳定区 / 实验区"两段结构。** 稳定区放长期不变的身份核心；实验区放正在试的表述（比如"汇报先给结论"），观察一两周，成立再转正，不成立直接删。

**3. 用 git 管理身份，并让智能体参与提案。** workspace 建议整体纳入 git。每周我会让 OpenClaw 基于最近几次不愉快的交互起草一版 IDENTITY.md 的 diff，人工 review 后再 merge。身份进化有据可查，也避免单方面自改导致的漂移。

## 踩坑点

- **身份与行为混写。** "语气要简洁"更像 SOUL.md 的职责；IDENTITY.md 写"我叫什么、我负责什么"就够了。混在一起，后期每次微调都在互相污染。
- **给它直接自改权限。** 我试过放开，结果一次长会话后它把角色边界悄悄改宽了。提案与审核必须分离。
- **写太长。** 超过一屏的身份文件，每次会话都在消耗注意力，字段间还容易互相矛盾。我压到了 35 行以内。
- **忘了其他会话也在读它。** cron 任务、子智能体读的是同一份文件，改身份前先确认没有自动化依赖旧表述。

## 可复用建议

- 把 IDENTITY.md 当 config-as-code：小步提交、附变更说明、可回滚。
- 每个字段问一句"三个月后还成立吗"，不确定的先进实验区。
- 多智能体场景给每个 agent 独立身份文件，不要共享，避免人格串台。
- 每月做一次"身份审计"：对照最近两周真实交互，删掉没兑现的描述。

## 总结

IDENTITY.md 的价值不在于让智能体"更像人"，而在于把身份从隐式状态变成显式、可版本化、可审查的配置。骨架先行、实验区隔离、提案审核分离——这三条能让身份随使用持续演进而不失控。身份是长期资产，值得像代码一样对待。
