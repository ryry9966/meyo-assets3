36 氪最近报道，美的把全屋智能的架构锚点押在了 A2A（Agent-to-Agent）上，家电互联的叙事从「接口对接」切换到「Agent 对话」。听起来像一句发布会口号，但拆开看，它指向一个实打实的架构问题：设备之间协作的底层逻辑，可能要换一套了。这篇把来龙去脉、技术原理和坑位一次讲清。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/be1fa13f31610f03.png)

## 一、现状：智能家居还停在「手牵手」时代

- 主流架构是设备 → 云 → App：设备联网上报状态，厂商云端收数据，手机 App 下发指令。跨品牌协作怎么办？签合作协议，然后逐个写 API 适配。
- 连接协议其实不缺：Wi-Fi、Zigbee、蓝牙 Mesh、Thread，再到 2022 年 Apple、Google、三星一起推的 Matter，解决的都是「连得上、控得了」。
- 但「连得上」不等于「听得懂」。接口对接的本质是静态契约：A 家要调 B 家的灯，得提前定义字段、取值范围、调用时序。B 家固件一升级改个字段，A 家的适配代码当场崩给你看，两边的工单系统同时亮红灯。
- 工程视角算笔账：N 个品牌 × M 类设备，worst case 要写 N×M 套适配。这就是为什么「人来灯亮」在同一生态里是广告、跨生态是玄学。

## 二、A2A 是什么：把「调接口」换成「开对话」

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/e4a596b23cb39aa0.png)

- A2A（Agent2Agent）是 Google 在 2025 年 4 月牵头发起的开放协议，首发就有 50 多家企业参与，随后捐给了 Linux 基金会。它不取代 Matter，也不取代 MCP，补的是「agent 与 agent 如何协作」这一层。
- 三个关键机制：
  1. **Agent Card（能力名片）**：每个 agent 挂一份 JSON 元数据，自我介绍「我是谁、会什么、怎么找我」。别的 agent 不用啃文档，直接发现能力。
  2. **任务生命周期**：协作以「任务」为单位，从下发、进行中到交付产物（artifacts）。A2A 还刻意设计了「不透明执行」——你只管提需求，我怎么干是我的黑盒。
  3. **长任务支持**：允许任务跑几十秒甚至更久，中途回报进度，适配真实世界的不确定性。
- 和 MCP 的分工一句话说清：MCP 管 agent ↔ 工具/数据的纵向接入，A2A 管 agent ↔ agent 的横向协作。类比一下：MCP 是 USB-C，A2A 是同事之间的群聊。
- 落到家里：每台家电理论上都变成一个 agent。空调会说「我能在 20 分钟内降到 26℃，但压缩机刚停机，需要 3 分钟重启保护」，中枢 agent 听完再做编排。设备不再是被调用的函数，而是会报价、会谈判、会说「不行」的协作者。

## 三、为什么是现在：三个条件刚好凑齐

1. **LLM 把「理解意图」的成本打了下来**。以前机器之间的对话要靠规则引擎写死，如今自然语言到结构化任务的转换已经接近 commodity。
2. **连接层的标准化铺垫完成**。Matter 生态起量后，底层管道不再是瓶颈，瓶颈上移到语义层——设备之间缺的是一套商量事情的语言。
3. **单品智能到头了**。全球智能家居设备年出货量早已是亿台级，但全屋智能的渗透率一直不温不火，行业需要从「能被 App 控制」升级到「能被一句话使唤」。美的手握国内最大的白电保有量之一，联网设备以千万计，有动机也有本钱推一个以家电为主体的 agent 生态——入口之争里，家电是它唯一的主场。

## 四、同一个晚归场景，两种架构差在哪

- **旧架构（接口对接 + 场景脚本）**：回家前在 App 预设「回家模式」，网关按 if-then 顺序执行：开门 → 灯亮 → 空调 26℃。逻辑全靠人提前写死，一旦出现预设外的情况——比如室内本来只有 22℃——照样把冷风吹满。
- **新架构（agent 对话）**：你说「到家了，有点热」。中枢 agent 拆解意图 → 空调 agent 回报能力与当前约束 → 判断「热」可能来自西晒，先让窗帘 agent 遮阳，空调再降两度 → 热水器 agent 插话：根据你的归家规律，已经提前加热完毕。
- 差别不在「更炫」，在扩展性：旧架构加一台新设备要再写一套场景规则；新架构理论上只要新设备把能力名片挂出来，就能被协商进任务，集成成本从 N×M 降到接近 N+M。
- 说句冷静的：agent 对话底下跑的仍然是 API。A2A 不消灭接口，它只是给接口包了一层「会说人话、会谈判」的壳，别理解成魔法。

## 五、四个待解难题：对话不等于万能

1. **时延与成本**：开个灯也要先让两个大模型对话一轮？token 要钱，秒级延迟要命。成熟方案必须有短路路径——高频简单指令走本地毫秒级直连，LLM 只做高层编排。
2. **确定性**：接口调用是确定性的，大模型是概率性的。家电里有热水器、燃气灶、门锁这类安全敏感角色，幻觉一次都不行。
3. **隐私边界**：家庭行为数据进入 agent 推理链路，在端侧跑还是云端跑？推理日志存在哪、谁能看？答案决定了用户敢不敢把家交给它。
4. **标准卡位战**：Matter（连接）、MCP（工具）、A2A（协作）、各家私有协议同时在场。协议从来不只是技术选型，更是生态卡位——谁的定义被广泛接受，谁就更接近「家庭操作系统」的位置。

## 六、三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/f8a9c4fe5a9fa9e3.png)

1. **看「短路路径」，别看 demo**。评估全屋智能方案先问一句：简单指令是否在本地毫秒级执行？如果关个灯都要先绕一遍云端大模型，架构不及格。
2. **关注能力开放的深度**。优先选支持 Matter、A2A 等开放协议的设备，能力名片越标准化，将来换品牌的迁移成本越低——全屋智能最大的隐性成本是生态锁定。
3. **给确定性留位置**。涉及水电燃气、门锁、老人看护的场景，必须有不经 LLM 的硬规则兜底。一句话总结这套架构的正确分工：agent 负责聪明，规则负责保命。
