最近36氪的一篇报道把一个技术名词推上了家电圈头条：美的全屋智能宣布技术路线锚定 A2A 协议，家电互联正从「接口对接」走向「Agent 对话」。翻译成人话：过去家电是等 App 派活的执行者，未来更像能自己开碰头会的同事。这不是换个营销词，底下是整套交互范式的迁移——连龙虾都知道，两只钳子得先商量好再夹，不然夹到的是自己。这篇文章把 A2A 讲透，顺便泼几瓢必要的冷水。

## 补课时间：A2A 到底是什么

- **出身**：A2A（Agent2Agent）协议由 Google 于 2025 年 4 月发布，同年 6 月捐赠给 Linux 基金会，转为中立开放标准。首批有五十多家科技公司站台，数月内成员扩展至上百家。它解决的问题很纯粹：让不同厂商做的 AI Agent 能互相发现、协商任务、交付结果。
- **三个核心机制**：
  1. Agent Card（能力名片）：每个 agent 公布一份机器可读的「自我介绍」——我能做什么、怎么调用，其他 agent 据此决定要不要找它合作；
  2. Task 生命周期：任务有 submitted → working → input-required → completed 的状态机，天然适合「洗一缸衣服」「除湿三小时」这类长流程；
  3. 不透明协作：agent 只暴露能力，不暴露内部实现，像黑箱对接，耦合度低。
- **工程细节**：A2A 没有发明新轮子，直接复用 HTTP、JSON-RPC、SSE 这些 Web 世界的老基建，接入成本可控。
- **和 MCP、Matter 的分工**：MCP（Anthropic 2024 年 11 月开源）管 agent 连接工具和数据；Matter 管 Wi-Fi/Thread 上的设备配网与基础控制；A2A 补上了最顶层的 agent 间对话。Google 的官方类比很形象：MCP 是给员工发工具，A2A 是让同事之间开会协作。

## 从「接口对接」到「Agent对话」，到底变了什么

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/ae456cbfdef78fa0.png)

**变化一：设备身份从「资源」变成「对等节点」。**
- 接口时代：空调是一组 REST API（`setTemperature(26)`），调用方把逻辑写死；
- Agent 时代：空调 agent 有自己的状态理解与决策权，能解释「为什么这么调」，必要时还会反问。

**变化二：自动化从「规则」变成「协商」。**
- 老式全屋智能的经典 bug：除湿机和空调打架——一个拼命加湿、一个拼命除湿，因为两条 if-then 规则互不知情；
- A2A 模式下，两个 agent 交换湿度状态和出力能力，协商出一份联合执行方案；
- 再举一例：洗衣机 agent 接到「高温洗四件套」的意图，先问热水器 agent 能否供应 60L、55℃ 热水，再问电价 agent 谷电几点开始，最后给出「23:30 启动」让你确认。

**变化三：集成成本从 N² 降下来。**
- 接口对接是点对点的：每接入一个新品牌，双方都要对着文档写适配、管版本兼容，设备越多复杂度平方级上涨；
- Agent 模式下，新设备挂上 Agent Card 即可被发现，协作像「拉新同事进群」，而不是「重新装修布线」。

## 为什么是美的，为什么是现在

- **品类优势**：全屋智能要「协商」，前提是屋里有足够多可协商的设备。美的覆盖空调、冰箱、洗衣机、厨电、小家电全品类，跨设备协同可以先在自家生态闭环，再谈跨品牌。
- **大模型成熟度到了**：美的 2024 年推出自研「美言」大模型。此前的智能语音本质是「高级遥控器」——识别命令但不懂意图；LLM 让设备具备了拆解模糊意图（「屋里太闷了」）并规划多步任务的能力，A2A 才有用武之地。
- **协议即生态位**：智能家居的历史就是一部协议史——Zigbee、Wi-Fi、蓝牙各自为战，直到 Matter 统一了连接层。连接层尘埃落定后，竞争焦点自然上移到「意图与协作层」。提前锚定协议，本质是抢座位：参与制定协议的一方，往往主导了生态里的话语权分配。

## 冷思考：Agent对话 ≠ 体验立马来个质变

- **确定性问题**：家电控制有硬约束——水温上限、童锁、功率保护。规则引擎是确定性的，LLM 是概率性的，让一个「可能幻觉」的 agent 直接控制热水器，不可接受。行业共识的架构是「agent 负责想，规则引擎负责守」：意图规划走大模型，安全边界走本地确定性逻辑。
- **延迟与成本**：每轮对话都是一次模型推理，云端往返数百毫秒起步；而烟机联动灶具这类安全联动需要毫秒级响应。分层架构（本地小模型做意图、云端大模型做规划）几乎是必然选择，这考验的是工程能力，不是发布会 PPT。
- **隐私与授权**：agent 能「自己行动」，权限模型就比一枚 API key 复杂得多——谁能授权空调 agent 把你的作息数据告诉电价服务？A2A 的不透明设计降低了耦合，但没有自动解决授权问题。
- **节奏要放平**：Matter 从 2019 年立项到 2022 年正式发版用了三年，生态渗透又花了几年。A2A 在家电侧的落地，同样是以年为单位的慢仗。

## 三条实用建议与一个判断框架

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/35672e25c3216694.png)

1. **给普通用户**：买「智能家电」先看协议再看功能。支持 Matter、明确表态兼容开放 agent 协议、API 文档公开的厂商，三年后大概率还能接入新生态；只在自己 App 里「智能」的封闭系统，贬值速度比冰箱里的菜快。
2. **给从业者**：架构设计要「可降级」。agent 不可用或超时，系统应自动退回传统规则引擎——体验的底线是「可靠」，「聪明」只是加分项，顺序不能反。
3. **给所有人的判断框架**：分辨真开放还是假开放，看三点——第三方 agent 能否自由接入？能力描述是否公开标准化？用户数据是否可迁移？三条全中，才算真的从「接口对接」走向了「Agent 对话」。

说到底，家电不必成为哲学家——能准时煮好饭、算准谷电、别把除湿机和空调放出去打架，就已经是模范 agent 了。
