最近开发者圈刷屏一条消息：DeepSeek 的 Agent 产品 Harness 日活达到 154 万，官方同时宣布开始给插件作者发放 Token 额度。两件事放在一起看，信号很明确——Agent 竞争的主战场，正在从“模型跑分”转向“生态建设”。这篇把 Harness 到底是什么、154 万日活的含金量在哪、发 Token 这步棋背后的经济学，一次讲透。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/cbf2cb1e458791f7.png)

## Harness 是什么：模型是引擎，它是底盘

- Harness 本是工程术语，指围绕大模型搭建的执行框架：工具调用、沙箱执行、上下文管理、重试纠错循环、权限控制。
- 一个类比：模型是发动机，Harness 是底盘 + 变速箱 + 方向盘。发动机再强，没有底盘也上不了路。Claude Code、Manus 这类产品，本质上都是“Harness + 模型”的架构。
- 走一遍完整流程：用户说“整理这份周报并发给团队”，Harness 负责拆解任务 → 调用文档工具 → 调用邮件工具 → 校验结果 → 汇报，中间任何一步出错还要回滚重试。这些“脏活”全在 Harness 层。
- 插件的角色，是扩展 Harness 的能力边界。官方插件再全，也覆盖不了长尾需求——企业内部系统、行业数据源、小众工具链，只能靠第三方开发者。这也是 MCP 这类协议存在的意义：一次开发，多个 Harness 都能跑，开发者不用被单平台锁死。

## 154 万日活，含金量在哪

- Agent 产品看 DAU 比看注册量诚实得多：用户是带着具体任务来的，能不能天天回来，取决于任务完成率，而不是首日的新鲜感。
- 横向对比，聊天类助手动辄上亿 DAU，154 万绝对值不算大。但 Agent 产品的价值单位是“完成的任务数”和“替代的人工时长”，不是闲聊轮次——单位经济模型完全不同。
- 结构比数字更重要：有插件生态的 Harness，能让用户在同一个产品里跑完整个工作流（取数 → 分析 → 出报告），而不是复制粘贴去别的工具。粘性来自“事情能办完”，不是“聊得开心”。
- 这也是飞轮的起点：日活涨了，插件才有曝光；插件多了，日活才留得住。官方此刻发 Token，卡的正是飞轮起步那一脚。

## 发 Token 的本质：补贴开发期的边际成本

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/09b4e86c7b44e319.png)

- 先算开发者的账。写一个插件要反复调试，每次调试都是真实的模型调用——长上下文加多轮工具循环，一次 debug 几毛到几块钱很正常，一个插件调上几百次，成本轻松上千。这笔钱如果全让开发者自掏腰包，生态必然长不大。
- 发 Token 的本质，是把开发期的边际算力成本降到接近零。这套打法有成熟先例：AWS 给初创公司送云资源额度、早期微信小程序给流量扶持。区别在于，App Store 类机制解决的是“收入侧”，Token 补贴解决的是“成本侧”。
- 但要分清：Token 不是现金。它覆盖算力开销，不覆盖人力投入。开发者真正的持续动力，最终要靠插件被大规模使用之后的分成或付费机制。
- 官方的账本也很清楚：补贴烧的是 GPU 时间，换的是生态内容供给。只要一个高质量插件带来的留存和任务量大于补贴成本，这笔买卖就成立。

## 冷启动的历史剧本，这次会不会重演

- 平台冷启动的通用剧本：早期补贴供给侧 → 供给吸引需求 → 需求反哺供给 → 飞轮转动。iOS App Store 靠分发让开发者赚到钱，VS Code 插件市场靠微软免费托管成就了编辑器的地位，Shopify 则直接分成，开发者拿真金白银。
- Agent 生态的特殊性有两条：
  1. 插件比 App 轻得多，本质是一层工具封装加 prompt 设计，迭代周期按天算，供给增长可以非常快；
  2. 也因此更容易被抄，护城河浅。激励设计和分发机制，比技术门槛更能决定生态走向。
- 对 DeepSeek 们的启示：协议越开放（比如兼容 MCP），开发者的迁移成本越低，反而会倒逼平台把补贴、曝光位和结算规则做得更有诚意——因为开发者随时可以用脚投票。

## 热闹之下的四个冷问题

1. **Token ≠ 收入**：补贴期结束后，开发者靠什么活着？没有清晰的分成路径，生态会长期停在 demo 阶段，看起来热闹，交付不了价值。
2. **安全面扩大**：插件能执行真实操作——读写文件、调用 API、甚至花钱。Prompt injection、权限滥用都成了真实攻击面，审核机制、沙箱隔离和权限粒度必须跟上补贴的速度。
3. **补贴的可持续性**：Token 烧的是真算力，政策需要设计“退出坡道”，比如按用量逐步过渡到分成结算，而不是长期无差别输血。
4. **马太效应**：头部插件拿走绝大多数用量和补贴，长尾无人问津。插件市场的发现与排序机制，决定这个生态最终是热带雨林，还是只有几棵大树。

## 三条冷思考：给开发者，也给观察者

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-07/386993397bfa6913.png)

1. **开发者：把插件当产品做，别当 demo 堆。** 上线前算清自己的 token 成本模型，设计好降级逻辑——接口挂了怎么办、上下文超长怎么办、工具返回脏数据怎么办。补贴是氧气，不是收入；按量分成、免费加高级订阅、给 B 端做定制，三条路至少提前想好一条。
2. **用户：评估生态别只数插件数量。** 更硬的三个指标：插件权限申请是否透明（它凭什么要读你全部数据）、任务完成率而非调用量、头部插件的质量分布。数量可以刷，完成率刷不了。
3. **观察者：盯补贴政策的“退出机制”。** 从纯补贴走向透明、可预期的分成结算，是生态成熟的标志。结算规则是否公开、是否稳定，比补贴力度大小更能说明平台是不是认真想做长期生态。

Agent 这场仗打到今天，模型层面的差距在收窄，真正拉开身位的是“谁能让开发者留下来”。发 Token 解决的是“愿不愿意来”；能不能留住，要看分成、要看工具链，以及那个最朴素的问题——跟着平台干活的人，到底能不能赚到钱。飞轮已经被推了一把，接下来看惯性够不够。
