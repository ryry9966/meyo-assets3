## 背景

多数人对 Agent 的用法是“拉”式的：你提问，它回答，会话结束。Agent 没有时间感，也没有待办概念——它不知道上周答应你的事还没做。

OpenClaw 提供了一个很轻的机制：HEARTBEAT.md。Agent 按固定间隔（默认约 30 分钟，可在配置中调整）醒来一次，读一遍 workspace 根目录下的 HEARTBEAT.md，有活干活，没活保持沉默。本质上是给 Agent 加了一个“值班巡检”循环。

## 问题

系统 cron 能定时，但不能判断；Agent 能判断，但不定时。比如“检查证书是否快过期，快过期就起草续期说明”——cron 写不了“如果”，Agent 不会自己醒来。这类低频、需要判断、需要汇报的事，正好落在两者的空档里。

另一个隐性问题：主动型 Agent 很容易变成噪音源。每 30 分钟发一条“一切正常”，三天后你只想关掉它。

## 做法

1. 在 workspace 根目录建 `~/.openclaw/workspace/HEARTBEAT.md`，空文件或删掉即等于关闭心跳。
2. 写成 markdown 清单，每条是可执行的祈使句：
   - `- 检查 ~/sync 有无未提交变更，有则 commit 并 push`
   - `- # 汇总今日日程，主动发消息给我`（`#` 开头的行表示需要主动汇报，其余默认静默执行）
3. 需要精细定时的任务别靠心跳猜时间：清单里只写“判断”和“动作”，准点触发交给系统 cron 调 agent CLI。
4. 在 HEARTBEAT.md 或 AGENTS.md 里写死一条静默规则：“若无待办或异常，回复 HEARTBEAT_OK，不给我发消息。”
5. 上线后观察两三天的 token 消耗和打扰频率，再回头调间隔和条目。

## 踩坑点

- **条目太模糊**。“帮我盯着服务器”会让模型每次心跳都编点东西来汇报。任务必须有明确触发条件、明确动作、明确“无事则沉默”。
- **把心跳当 cron 用**。心跳间隔不保证精确，±几分钟很正常。要准点的任务（备份、定时推送）走系统 cron。
- **清单膨胀**。每次心跳都是一次完整的模型调用，二十条任务的 HEARTBEAT.md 一天烧掉的 token 很可观。把重逻辑下沉到脚本，清单只写“跑 xx.sh，异常则通知我”。
- **权限放太大**。心跳是无人值守执行的，别放 rm、force push 这类动作。危险操作改成“先起草，等我确认”。
- **静默规则没生效**。不同模型对“沉默”的服从度不同，需要迭代措辞，把“无事不发消息”写成硬性指令而非建议。

## 可复用建议

- 分层设计：cron 管准点，脚本管逻辑，HEARTBEAT.md 管判断和汇报。它是“判断调度器”，不是 cron 替代品。
- 清单控制在 5–8 条，每周 review 一次，做完的归档删掉。
- 高风险动作一律“草稿先行”：写 draft 文件或发一条待确认消息，人不点头就不执行。
- 配合 quiet hours：在 AGENTS.md 里写明深夜时段只处理标了 `#` 的紧急项，打扰会明显下降。

## 总结

HEARTBEAT.md 本身只是一张 markdown 清单，价值不在文件而在两件事：把任务写成可验证的祈使句，以及把“刻意沉默”当成一等公民。做好这两点，Agent 才真正从“问答机”变成常驻的值班员——大部分时间安静，出事时才说话。
