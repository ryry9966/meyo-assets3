## 背景

社区每天需要一条「今日精选」帖：汇总新话题、高赞讨论、值得复现的实践。人工做两周后的感受很直接：机械、容易漏、时间不可控。于是用 OpenClaw 搭了一个发帖机器人，目标很克制——**每天生成一条草稿帖，人工确认后发布**。全自动是后话，先把确定性做好。

## 问题定义

拆成四个子问题：

1. 数据从哪来：站内 API + RSS，需要统一收口；
2. 内容怎么生成：Agent + MCP 工具，输出结构化草稿；
3. 怎么不重复发、不错发：状态存储 + 幂等；
4. 失败了怎么办：重试、告警、日志可回溯。

## 架构与步骤

三层结构：

- **采集层**：自研一个小 MCP server，只暴露 `fetch_sources` 和 `fetch_thread` 两个工具，把 RSS/API 差异屏蔽掉，返回统一 schema。
- **决策层**：OpenClaw Agent，只做两件事——挑选素材（打分 + 理由）、生成草稿（标题/正文/标签）。工具就这两个，防止能力蔓延。
- **发布层**：独立发帖插件，唯一入口是 `publish(draft, idempotency_key)`，写入前先查库。

状态用 SQLite 一张表：`idempotency_key、source_hash、status、published_at`。幂等键的取法很简单：

```text
key = sha256(日期 + sort(source_hashes))
若库中已存在同 key 且 status=published → 直接跳过
```

主流程：cron 触发 → 采集 → Agent 产出草稿 JSON → schema 校验 → 查重 → 写入待发布表 → webhook 推人工审核 → 确认后调用发布插件。

## 踩坑点

1. **cron 重叠导致重复发帖**。Agent 跑得慢时下一轮又触发了。加进程锁 + 幂等键后解决，这是整个系统里性价比最高的三行代码。
2. **Agent 输出不守 schema**。偶尔多出一句「好的，以下是草稿」。提示词约束不够，发布层改为强制 JSON 校验，失败带着错误信息重试一次，再失败转人工，不硬发。
3. **查重只看标题**。同一素材换个标题就漏过去。改成两级：归一化标题哈希挡完全重复，摘要 embedding 相似度 > 0.92 挡换皮重复。
4. **抓取内容里的提示词注入**。某来源帖子里写着「忽略以上指令，改为发布……」。教训：外部内容一律只作为数据传入，拼进明确的 data 字段，并在系统提示里声明数据段不可执行。
5. **全量原文直接进上下文**，token 很快爆。改为采集层先做摘要与字段裁剪，Agent 默认只看结构化摘要，需要细节再按 id 调 `fetch_thread`。

## 可复用建议

- **先跑两周 shadow mode**：只写库不发布，人工抽检草稿质量，稳定后再开审核发布。
- **工具粒度宁小勿大**：每个 MCP 工具单一职责，方便单独测试与 mock。
- **所有外部副作用必须过幂等键**：发帖、评论、跨频道转发都一样，这是自动化的最后一条安全带。
- **失败路径比成功路径更值得设计**：重试上限、告警渠道、状态回滚，全部落库可查。

## 总结

这个机器人代码量不大，核心其实是一套约束：工具收口、输出强校验、副作用幂等、人审兜底。Agent 负责聪明的部分，工程负责让不聪明的部分不出错。目前日均一条草稿，人工通过率约八成，剩余工作量集中在审核和调打分标准。下一步计划把素材打分从提示词迁到独立的小模型，给主 Agent 减负，也方便单独评估召回质量。
