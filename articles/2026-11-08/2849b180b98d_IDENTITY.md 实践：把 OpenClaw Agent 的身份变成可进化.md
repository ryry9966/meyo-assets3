## 背景

OpenClaw 的工作区里有几个约定俗成的 Markdown 文件：`AGENTS.md` 管行为规则，`SOUL.md` 管性格底色，而 `IDENTITY.md` 管的是最基础的一层——“我是谁”：名字、emoji、一句话设定、如何称呼用户。

很多人装完就沿用默认身份，或者把一大段角色扮演 prompt 堆进系统提示。短期没问题，跑两周就会暴露短板。

## 问题

身份不落文件，通常会遇到三种典型症状：

1. **跨会话漂移**：今天自称 A、语气冷峻，明天自称 B、开始卖萌，新会话每次“抽卡”；
2. **不可版本化**：身份藏在 prompt 字符串里，改坏了没法 diff、没法回滚；
3. **不可协作**：身份不是文件，团队成员无法评审、无法沉淀各自的用语习惯。

## 做法

1. **最小化字段起步**。在 `~/.openclaw/workspace/IDENTITY.md` 写第一版，建议只保留：`name`、`emoji`、一句话 `vibe`、称呼用户的口径。核心内容控制在 10 行以内。
2. **只写可验证的描述**。“你是一个乐于助人的助手”这类话没有约束力；“回复默认口语化，不使用感叹号连用，称呼用户为『老板』”这种才有执行标准。
3. **纳入 git 管理**。和 `AGENTS.md`、`SOUL.md` 一起提交，每次改动写清动机，方便回溯“从哪个版本开始变味”。
4. **让 Agent 自己读**。OpenClaw 在会话启动时会加载 workspace 文件，确认新会话拿到的是最新版即可，不需要在 channel 配置里重复写身份。
5. **建立进化闭环**。每两周把不满意的对话摘录丢给 Agent，让它对照 IDENTITY.md 提出修改建议，人工审核后小步合入。这就是“可进化”的核心：身份由真实交互反馈驱动，而不是一次性写死。

## 踩坑点

- **写太长**：身份文件超过一屏，Agent 开始“表演人格”而不是干活。细节放到 `SOUL.md`，硬规则放 `AGENTS.md`。
- **身份和规则混写**：改语气时误伤工具调用约束，是最高频的事故。职责分离：IDENTITY 管“是谁”，AGENTS 管“怎么做”。
- **大改不灰度**：一次性重写身份，老会话上下文会和新身份冲突。小步提交，观察两三个会话再继续。
- **多实例共用身份**：跑了多个 workspace 时，软链同一个文件还指望差异化，必然翻车，各写各的。
- **别忽略 emoji 和称呼**：这类“小事”出现在每次对话开头，恰恰是最容易漂移的地方，值得显式写死。

## 可复用建议

- 把 IDENTITY.md 当代码：小 commit、写清动机、能回滚。
- 每次觉得“说话不像我想要的”，先改文件再调模型参数——绝大多数语气问题根源在身份描述模糊。
- 团队场景下把身份文件纳入 code review，新成员的协作习惯可以自然沉淀进 Agent。

## 总结

IDENTITY.md 的价值不在于“让 Agent 更像人”，而在于把身份从一段不可控的 prompt 字符串，变成可版本化、可评审、可迭代的工程资产。身份是会过期的，与其追求一次写对，不如搭好“交互反馈 → 修改提案 → 人工合入”的小闭环。文件很小，但它决定了你每天对话的基调。
