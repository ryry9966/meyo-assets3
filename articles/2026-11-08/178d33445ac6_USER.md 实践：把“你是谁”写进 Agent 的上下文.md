## 背景

OpenClaw 的 workspace 里有几个约定俗成的文件：`SOUL.md` 管人格，`MEMORY.md` 管记忆，`USER.md` 管"坐在对面的这个人是谁"。多数人的上手顺序是反的：先花一晚上调 `SOUL.md` 的语气，`USER.md` 留空。结果就是 agent 对你一无所知——时区、主力语言、当前在做什么，全靠每次对话临时补。

## 问题

没有 USER.md 时，几个典型症状：

- **重复自我介绍**。同一个偏好（"回复短一点""不要加表情符号"）在不同会话里纠正了 N 遍。
- **输出风格漂移**。今天结论先行，明天又开始铺垫三段。
- **上下文错位**。agent 拿通用假设回答你：默认你用 macOS、默认你在做 Web 项目，而实际你在维护一套自建 K8s。

根因是：模型每次会话都是冷启动，而你脑子里的隐式上下文从来没被显式化。

## 做法

在 workspace（默认 `~/.openclaw/workspace/`）新建 `USER.md`，控制在 50 行以内，分区写：

```markdown
# USER.md

## 基本信息
- 称呼：老周
- 时区：Asia/Shanghai
- 语言：中文为主，技术术语保留英文

## 技术栈
- 主力：Python / Go，编辑器 Neovim
- 部署：自建 K8s

## 当前项目
- openclaw 日志聚合插件，目标两个月内出 v0.1

## 沟通偏好
- 结论先行，最多 3 条要点
- 代码示例可直接运行，不要伪代码
- 不要主动建议换语言或大重构

## 禁区
- 不在回复里加表情符号
```

三条写法原则：

1. **写事实，不写愿望**。"我希望回答高质量"是废话；"结论先行，最多 3 条要点"才是可执行规则。
2. **只写长期稳定的信息**。临时任务放对话里，滚动事件放 `MEMORY.md`，`USER.md` 只放三个月后依然成立的东西。
3. **和 `SOUL.md` 分工**。语气、人设归 `SOUL.md`；你是谁、你的环境归 `USER.md`，别混着写。

维护节奏：每当你第二次纠正 agent 同一个问题，就顺手把这条规则沉淀进去；每个项目节点做一次 diff 式更新，只改变化的部分，不重写。

## 踩坑点

- **写太长**。两三千字的档案每次会话都吃 token，关键信息还会被稀释，一屏以内是硬约束。
- **敏感信息入库**。真实姓名 + 公司 + 服务器地址全写上，一旦对话被截图或共享就是事故。用代称，密钥信息永远不进文件。
- **写完不更新**。项目换了两轮，档案还停在三个月前，agent 拿旧上下文回答，比没有档案更误导。
- **规则互相冲突**。一边写"回复要短"，一边写"给我完整代码示例"，agent 只能随机选一个。写完通读一遍，消掉矛盾。

## 可复用建议

- 把"第二次纠正"当信号：同一件事说第二遍，就该进 `USER.md`。
- 团队场景可以拆分：个人偏好留 `USER.md`，项目级约定派生一份 `PROJECT.md`，避免互相污染。
- 直接对 agent 说"把这条规则沉淀进 USER.md"，让它自己改自己，你只做 review。
- 写档案的过程本身就是收益：很多人写到"沟通偏好"一栏才发现，自己从没想清楚要什么样的回复。

## 总结

`USER.md` 是 OpenClaw 里成本最低、收益最直接的个性化手段：一个几十行的文件，换来的是不用每次重新介绍自己。它的本质不是"配置"，而是把你脑子里的隐式上下文显式化、可版本化。先写 20 行，用一周，再回头改——比一开始就追求完美档案有用得多。
