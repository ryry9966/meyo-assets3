最近 36kr 报道了一个耐人寻味的事实：Anthropic 团队在公开分享中透露，Claude Code 这个 AI 编程工具自己的代码库，约九成代码就是 Claude 写的。AI 写代码不稀奇，稀奇的是"AI 写的工具自己也在被 AI 写"。真正的问题随之浮出水面：当生成端几乎不设上限，审查端就成了整个软件工程最脆弱的一环。Claude Code 团队给出的答案是六道关卡——把质量控制从"事后人工把关"改成"流水线纵深防御"。这篇文章把它拆开看清楚。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-08/9cac21eacbfa7f74.png)

## 一、生成不再稀缺，审查成了新瓶颈

先看底层逻辑的变化：

- **代码生成的边际成本趋近于零**。过去一个工程师一天产出几百行已算高产，现在一个会话就能铺开上千行 diff。
- **但人的审查带宽没变**。Code Review 本质上是人类串行处理的环节，一个 reviewer 一天能认真消化的 diff 有限，超过三四百行，审查质量就肉眼可见地滑坡，"LGTM 但没细看"成了普遍现象。
- **数据也在敲警钟**。GitClear 基于数亿行代码的追踪分析显示，AI 助手普及后，复制粘贴型代码首次超过了重构搬移型代码，重复代码块明显增多——生成快了，但"债"在同比扩张。
- Google Cloud 的 DORA 2024 报告给出更直接的量化：AI 采用率每提升 25%，交付吞吐量估计下降约 1.5%，交付稳定性下降约 7.2%。

结论很朴素：产出速度翻倍而审查带宽不扩，堵点只会从"写"平移到"审"。

## 二、六道关卡：把质量做成流水线，而不是事后补救

Claude Code 的思路不是"再加一个人肉审查者"，而是在从生成到合并的路径上布设多层防线，人工只守最后一关：

1. **事前约束**：把架构约定、代码风格、禁用依赖写进项目上下文（类似 CLAUDE.md 的规范文件），让模型生成时就不越界。事前一行规范，省掉事后十轮返工。
2. **静态检查**：lint、format、类型检查在 CI 里强制卡点，机器规则不讲情面，不合格直接打回。
3. **自动化测试**：要求 AI 同时产出测试，但测试必须与实现**分开审**——这是防"自证测试"的关键，下一节细说。
4. **安全扫描**：密钥泄漏检测、SAST 静态漏洞扫描、依赖审计。AI 特别爱"发明"不存在的包名，幻觉包名被攻击者抢注的 slopsquatting，已经是被系统研究过的真实供应链威胁。
5. **AI 交叉审查**：用一个上下文独立、最好不同模型的审查实例重读 diff，相当于"第二双没有先入为主的眼睛"。
6. **人工终审**：人不逐行抠语法，而是聚焦机器管不了的三件事——架构是否合理、边界条件是否完整、业务语义是否真的对。

注意这里的分工逻辑：**确定性越高的问题（格式、类型、已知漏洞）越靠前的机器关卡处理；模糊性越高的问题（设计、语义）才留给人和 AI 交叉判断。**

## 三、AI 审 AI，为什么不能只靠它

- **同源盲区**：同一模型家族在训练数据和知识偏置上高度相似，生成者看不出的问题，审查者大概率也看不出。人类交叉审查的价值在于"错误不相关"，而同款 AI 审 AI 的错误是相关的——两道防线可能漏在同一个洞上。
- **自证测试**：让写实现的 AI 顺手写测试，测试很容易"顺着 bug 走"——它验证的是"代码现在做了什么"，而不是"需求本来要什么"。这是 AI 时代测试质量退化最隐蔽的方式。
- **幻觉包的供应链风险**：已有安全研究统计发现，AI 幻觉出的包名有相当比例会跨会话重复出现，攻击者可以批量抢注这些名字，蹲守哪个倒霉项目执行 install 时上钩。

所以第五、第六道关卡不能省：AI 交叉审查负责扩大覆盖面，人负责守住"意图层"。机器证明代码"能跑"，人决定代码"该不该这么跑"。

## 四、没有 Anthropic 的资源，普通团队怎么落地

这六道关卡不需要大厂基建，按优先级排：

1. **先把机器卡点上齐**：CI 里的 lint、类型检查、测试、安全扫描是底线。没有这些，AI 产出等于裸奔。
2. **立 diff 纪律**：AI 产出的改动必须小步提交，单次 PR 控制在两三百行以内。大爆炸式 diff 是审查质量的头号杀手，对人和对 AI 审查都一样。
3. **测试与实现分开审**：测试可以由 AI 生成，但审查时先回到需求，独立判断用例是否覆盖了"应该发生什么"，而不是"实际发生了什么"。
4. **人工火力集中**：把资深工程师的时间投向错一次代价大的区域——权限控制、并发与事务、数据一致性、对外接口。CRUD 和胶水代码，放心交给机器关卡。
5. **沉淀回归集**：每修掉一个 bug，就固化成一个测试用例。回归集是团队对"AI 常犯什么错"的集体记忆，也是终审的底气。

## 五、三条冷思考

1. **审查带宽决定 AI 生产力的上限**。工具链扩产容易，审查扩容难；不解决审查，提速只是把排队换个地方。
2. **责任无法外包**。AI 可以承担工作量，不能承担责任。合并权限、上线签字、事故追责，最后都落到人头上——这决定了人必须保留对"意图层"的最终判断权。
3. **度量指标该换了**。代码行数在 AI 时代是成本而非产出，别再用它考核任何人或模型。更值得盯的是缺陷逃逸率、变更失败率、审查耗时这些"质量带宽"指标。

最后一句实话：六道关卡的核心不是技术堆叠，而是一种态度转变——把 AI 当成一个产出极快、经验丰富、但需要严格监督的初级同事。你不会让这样的同事直接改生产库，对吧？
