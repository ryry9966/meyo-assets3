## 背景

用 Agent 做日常自动化的人大概率遇到过这种场景：上周明明说过"commit message 用中文、别自动 push"，这周它又全英文提交还顺手推了远端。根源很朴素——LLM 本身无状态，上下文窗口不是记忆。把偏好硬编码进 system prompt 只能撑住几条，条数一多就开始互相挤压、失效。

## 问题

我踩过的三种典型失败：

1. **全塞 prompt**：偏好超过 20 条后 token 爆炸，模型开始漏看；
2. **"都记下来"式日志**：每次对话 append 一条，三个月后 400 条记录，检索出来的全是噪音；
3. **只写不删**：偏好变了（比如从 pnpm 换到 npm），旧记忆还在，新会话里两条冲突记忆同时命中，模型随机站队。

本质问题是把记忆当成了存储问题，它其实是写、读、更新三个环节的系统设计。

## 做法

我的方案四步走，在 OpenClaw 里用一个 MCP tool 加一个 JSONL 文件就能落地。

**1. 分层**。只存三类：profile（稳定偏好，如代码风格、回复语气）、episode（项目级事实，如"A 服务跑在 8080"）、working（当前任务上下文，会话结束即弃）。对话历史不等于记忆。

**2. 定义写入触发**。三个来源：显式指令（"记住……"）直接写；纠正时刻（"不对，我要的是 X"）价值最高，优先写；会话末用便宜模型异步抽取候选记忆，先进 staging 区，置信度过线才转正。每条带字段：`type / content / tags / confidence / created_at / last_hit`。

**3. 检索注入**。会话启动时按任务关键词 + embedding 混合检索 top 5～8 条，压缩成一行一条注入 prompt，附时间戳。个人规模（几百条）grep 足够，别急着上向量库。

**4. 更新与遗忘**。新偏好与旧记忆冲突时用 supersede 语义：旧条标记 `superseded_by`，保留但不再命中。每周 cron 合并去重，`last_hit` 超 90 天且置信度低的移入归档。再给 Agent 一个 `memory_forget` tool，你说"忘掉这条"它能自己调。

## 踩坑点

- **写得太勤**：不设门槛，Agent 连"今天天气不错"都存。纠正类直写，其余必须过置信度门槛；
- **注入不压缩**：原文注入很快吃掉上下文预算，一行一条 + 截断是必须的；
- **静默改写**：别让模型直接改记忆文件，所有写入走 tool 调用并留 diff 日志，否则排查"它为什么这么理解我"会非常痛苦；
- **检索词不匹配**：你问"构建太慢"，它检索不到"pnpm 缓存配置"，混合检索 + 打 tag 能大幅缓解；
- **隐私**：记忆文件天然聚集敏感信息，放本地，别同步云盘，定期人工过一遍。

## 可复用建议

- 先用 markdown/JSONL 起步，个人规模 grep + embedding 混合检索足够；
- 记忆保持人类可读、可手改——你直接编辑它，比任何自动清理都可靠；
- 写个验收脚本：开全新会话问 5 个偏好相关问题，统计命中率，每次改动后跑回归；
- 每月人工 review 一次。记忆是资产，需要 curate。

## 总结

让 Agent 记住你，核心不是"存得多"，而是写入有门槛、检索有预算、更新有语义、遗忘有机制。把它当成一个有生命周期的小型数据系统来设计，Agent 才会从"每次重新教"变成"越用越顺手"。
