## 背景

OpenClaw 社区里最高频的行为是“贴日志求救”：agent 行为异常，截一段会话、丢一份 config、发一张终端截图。这套习惯在纯本地玩具阶段没什么问题，但一旦你的 agent 接了公司内网、真实客户数据或内部 SOP，社区就成了泄露面最大的出口。多数泄露不是被攻击，而是自己贴出来的。

## 问题：三类东西最容易跟着贴出去

1. **凭证类**：`.env` 内容、config 里的 token、MCP 服务器地址后带的签名参数。
2. **拓扑类**：内网域名、服务名、目录结构、工具清单——单独看无害，拼起来就是你们的架构图和工作流。
3. **历史类**：session 导出和 workspace 里的 memory 文件，包含完整的工具输出、聊天上下文，甚至客户对话。

第三类最常被忽略：很多人知道删 key，但不知道 OpenClaw 的会话记录里，工具返回值是全量落盘的。

## 做法：把脱敏做成确定性流程

**一、密钥一律外置。** token 只放 `.env` 或密钥管理，绝不写进 `SOUL.md`、`AGENTS.md` 或任何 workspace 文件——这些文件最容易被整份复制分享。

**二、维护一份“公开模板”。** 平时备两份 config：真实版自用，脱敏版（域名换 `example.internal`、token 换占位符）随时可贴。求助时直接给脱敏版，省掉临场判断。

**三、日志过脚本再贴。** 人眼不可靠，用确定性正则过滤，例如：

```bash
grep -Ev 'sk-[A-Za-z0-9]{8,}|Bearer |192\.168\.|10\.[0-9]+\.' full.log > share.log
```

正则清单按自己的环境维护：密钥前缀、内网网段、内部域名。更简单的原则：贴最小复现片段，不贴全量。

**四、会话文件默认不外发。** 有人让你“发下 session 看看”时，先导出文本、审查工具输出段落，或只贴复现问题的那几轮。memory 文件同理。

**五、给 agent 立规矩，但别指望它。** 系统提示里可以写“不透露内部工作流细节”，这只能降概率——模型不是访问控制系统。工具侧同步做最小权限：MCP 按需开启、只读优先，别把内部知识库全量挂给常驻 agent。

## 踩坑点

- **“删了 key 再贴”不等于安全**：日志里往往还留着内网域名、用户 ID、路径结构，足够拼出内部拓扑。
- **让 agent 自己脱敏**：模型会漏，脱敏必须是脚本，不是提示词。
- **`.gitignore` 漏了 memory**：开源示例仓库把 workspace 的记忆文件推上远端，比贴在社区还难撤回。
- **分享技能包带私货**：插件目录里遗留的 `.env` 和硬编码的测试 token。
- **贴过的 key 一律视为已泄露**：不管删得多快，先 rotate 再排查。

## 可复用建议

- 贴出前过五项 checklist：凭证、内网标识、客户数据、会话历史、业务 SOP。
- 团队内约定“求助只贴片段”的默认文化，帮别人看分享时也按这五项扫一眼。
- 疑似泄露后的动作固定化：作废凭证 → 查访问记录 → 再评估泄露范围，顺序别乱。

## 总结

Agent 时代的信息泄露，大多是流程问题而不是模型问题。密钥外置、模板分离、脚本脱敏、会话审查——这四件事固化成习惯后，社区求助的成本几乎不变，泄露面会小一个量级。红线不是不许求助，而是求助前先过一遍确定性流程。
