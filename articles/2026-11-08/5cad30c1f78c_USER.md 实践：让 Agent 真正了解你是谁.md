## 背景

OpenClaw 的 workspace 有一组约定文件：AGENTS.md 管行为规范，SOUL.md 管人格设定，MEMORY.md 存动态记忆。但很多人漏掉了 USER.md——一份描述“使用者本人”的静态档案。它解决的问题很朴素：Agent 每次会话冷启动时，对你一无所知。

## 问题

没有用户档案时，常见三种重复成本：

1. **环境解释**：每次都要说明“我在 UTC+8，主力机是 Linux，Python 用 uv 管理”；
2. **风格纠正**：你偏好先给结论、控制在三百字内，Agent 默认输出长篇解释；
3. **边界重申**：比如“不要动 /etc 下的配置”“凌晨别触发通知”。

这些信息高度稳定，却靠对话反复注入。把稳定偏好塞进 MEMORY.md，会导致记忆膨胀、难以审计——动态记忆和静态档案应该分开。

## 做法

在 workspace 根目录（通常是 `~/.openclaw/workspace/USER.md`）建文件，控制在 50 行 / 1k token 以内，因为它每个会话都会被注入上下文。结构分四段：

- **基本事实**：时区、语言、设备环境、活跃时段；
- **技术栈**：主力语言、包管理器、编辑器、关键版本约束；
- **协作偏好**：回答风格（先结论后细节）、注释密度、是否需要主动给替代方案；
- **红线与边界**：隐私要求（不记录家庭信息）、操作禁区（不自动 `git push`）。

写法上遵循“事实优先”：用 bullet 不用叙述；写可度量的约束，不写愿望——“回复先给一行结论”比“希望简洁一点”有效得多。

分层原则：只放跨项目稳定的个人信息；项目相关的放项目级 AGENTS.md；会话中学到的放 MEMORY.md。

写完先验证注入链路：直接问 Agent “我的时区和包管理器是什么”。答不上来说明加载路径有问题，别急着改内容。

## 踩坑点

- **写成简历**：几百行人生经历只会稀释关键信息，Agent 的注意力是有限资源；
- **混入易变状态**：“当前在做 X 项目”两周就过期，过期事实比没有事实更危险；
- **放敏感信息**：USER.md 会随上下文发给模型 API，密钥、住址、证件号绝不进这个文件；
- **与 SOUL.md 冲突**：两边对回复风格定义不一致，Agent 行为会摇摆，风格规则只在一处声明；
- **规则过载**：超过二十条“总是/绝不”，Agent 开始顾此失彼。

## 可复用建议

- 把 USER.md 纳入 dotfiles 仓库做版本管理，改动可回溯、可同步多机；
- 每月让 Agent 自己审一遍：“读 USER.md，列出已过期或可合并的条目”——删减比增补重要；
- 多设备场景区分“全局共识”和“本机事实”，后者放设备级文件；
- 用模板冷启动可以，但跑两周后按实际对话痛感裁剪，没被用到的条目就删。

## 总结

USER.md 是一份配置，不是记忆。它的价值在于用极小的 token 成本，把高频重复的用户上下文固定下来。评价标准不是“内容多全”，而是三个月后重新打开，里面没有一句需要解释的过期话。建议先从时区、技术栈、回复风格三件事写起，跑一周看效果，再决定加什么。
