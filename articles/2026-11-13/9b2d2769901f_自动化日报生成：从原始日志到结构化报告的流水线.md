## 背景

团队每天要写日报，素材散落在各处：CI 构建记录、服务错误日志、git 提交、告警历史。人工翻日志费时还容易漏。我们的思路是：读日志交给脚本，归纳交给 agent，排版交给模板，串成一条每天定时跑一次的流水线。

## 问题

直接让 agent"看日志写日报"有几个坑：日志量大塞不进上下文；输出格式每天不一样；关键数字偶尔被"编"出来；失败重跑会重复推送。所以核心不是能不能生成，而是如何让输出稳定、可信、可重跑。

## 做法

整条链路分五步，每步一个独立脚本，agent 只出现在第三步：

1. **采集**：按日期拉取各来源日志，落到 `reports/raw/YYYY-MM-DD/`，只取最近 24 小时，边界用统一时区截断。
2. **归一化**：日志转成 JSONL（时间戳、来源、级别、关键字段），多行堆栈按规则合并成单条事件；然后聚合——按错误类型计数、取 topN、提取 commit 摘要。这一步纯代码，不进模型。
3. **归纳**：调用 agent，输入是聚合后的 JSONL 和固定 prompt，要求只输出符合预定义 JSON schema 的结果：summary、incidents（含计数和证据行号）、changes、risks、todos。temperature 调低，数字必须来自输入。
4. **渲染**：用固定 Markdown 模板把 JSON 填进去。排版永远由模板控制，模型不直接产出最终日报。
5. **推送**：OpenClaw 定时任务每天早上触发整条流水线，产物写入归档目录，摘要推到群频道，正文附原始数据路径备查。

## 踩坑点

- **多行堆栈拆散**：异常栈被逐行解析，错误计数翻了几倍。按缩进和 `at` 前缀规则先合并。
- **时区混杂**：来源里 UTC 和本地时间并存，日报边界差了 8 小时。统一时区后再截断。
- **模型改数字**：早期版本会"凑整"。改成归纳层禁止生成任何数字，数字一律由模板从 JSON 注入。
- **JSON 输出偶发不合法**：加 schema 校验，失败自动重试一次，仍失败则降级推"纯统计版"，保证当天不空发。
- **重跑重复推送**：推送前检查当天是否已有成功归档，重跑只覆盖归档、不重复推送，需要时手动加 `--force`。
- **敏感信息**：内网 IP、用户标识在归一化层统一脱敏后再进模型。

## 可复用建议

- 确定性环节全部交给代码，agent 只做归纳。其余步骤可测试、可回放，出问题能定位到具体一层。
- 报告 schema 固定下来，周报、看板可以直接复用同一份 JSON。
- 上线前先跑一周影子模式：每天生成但不推送，和人工日报对比覆盖面，确认没大遗漏再挂定时任务。
- 归档中间产物（JSONL、JSON），排障时能逐步回放，比只留最终报告有用得多。

## 总结

日报自动化的价值不在"替人写报告"，而在把数据管道和语言归纳分开：确定的事交给代码，模糊归纳才交给 agent。管道稳定之后，同一套采集和 schema 还能扩展周报、值班交接和异常复盘。目前这条流水线每天跑一次、归纳层只调一次 agent，成本可控，比早期"一把梭"的方案稳得多。
