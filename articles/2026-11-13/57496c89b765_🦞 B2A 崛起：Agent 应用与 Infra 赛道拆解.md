互联网的流量入口换过好几茬：PC 时代拼搜索框，移动时代拼 App 图标，现在轮到一个新角色上岗——AI Agent。36kr 把这个变化浓缩成一个词：B2A（Business to Agent），意思是企业要服务的"用户"不再只是人和公司，还包括替人干活的智能体；文章顺势梳理了 14 条 Agent 应用赛道和背后的 Infra 底座。这篇把它拆开揉碎：B2A 到底改变了什么、赛道怎么分、钱从哪来、坑在哪。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-13/41f6ad6e69807465.png)

## 一、B2A 的本质：流量入口的第三次迁移

- **B2C 时代**，平台竞争的是人的注意力：界面要好看、推荐要精准，SEO 和应用商店是分发主战场。
- **B2B 时代**，SaaS 竞争的是流程席位：按人头付费，CRM、ERP 把企业流程搬上线。
- **B2A 时代**，"用户"变成了 Agent：它不看你的 UI 多漂亮，它读 API 文档、结构化数据和权限协议，替主人比价、下单、订机票、填表单。

举个例子：人订酒店要打开三个 App 比价三轮；Agent 直接调用三家平台的接口，拿到结构化报价，几十秒完成决策并下单。"首页转化率"这类指标失效了，取而代之的是：接口稳不稳定、数据能不能被机器读懂、授权流程顺不顺畅。

这也是为什么 Anthropic 在 2024 年底开源 MCP（Model Context Protocol）之后，OpenAI、Google 在 2025 年相继跟进——大家抢的是"Agent 连接世界的 USB 接口"这个位置。SEO 之后，一门新手艺出现了：让 Agent 找得到你、读得懂你、信得过你，业内叫 AEO/GEO。

## 二、14 条赛道，剥开壳其实就五类肉

14 条赛道名字各异，按"Agent 替人干什么"归拢，大致五类：

1. **生产型**：写代码是跑得最快的——Cursor、GitHub Copilot、Devin、Claude Code 都属于这类。据公开报道，Cursor 的年经常性收入（ARR）在 2025 年已到数亿美元量级，是 Agent 商业化最快的样本。
2. **交互型**：浏览器操作、电脑操作（Computer Use）、语音外呼。Operator、Claude 的 computer use 都在这一档，本质是给 Agent 装上"手和眼"。
3. **流程型**：客服、销售 SDR、招聘初筛、财务对账。任务可量化、可闭环，比如客服 Agent 按问题解决量收费（Sierra 的模式），天然适合"按结果付费"。
4. **知识型**：Deep Research、法律检索（Harvey）、投研与医疗辅助。核心壁垒是领域数据和评测集，不是模型本身。
5. **协调型**：多 Agent 编排平台，让一群专家 Agent 开"项目会"：派活、校验、汇总、互相挑错。

一条规律浮出来：**任务越可结构化、验收越客观，Agent 渗透越快**。写代码有编译器和测试兜底，客服有解决率兜底；"创意"和"拍板"类任务，暂时还得人机协作。

## 三、Infra 底座：真正卡脖子的地方

应用层热闹，利润和壁垒往往在底座。沿调用链自下而上数一遍：

1. **模型层**：长上下文、工具调用可靠性、推理成本。Agent 是长链路任务，一次活要几十上百次调用——模型成本降一个量级，商业模式就成立一截。
2. **上下文与记忆层**：向量数据库、RAG 管道、长期记忆（Mem0、Letta 等）。Agent 一干活就是几小时，没记忆等于失忆的实习生。
3. **工具连接层**：MCP、function calling、API 市场，决定 Agent 能"摸到"多少真实世界。
4. **执行环境层**：沙箱、云浏览器、代码运行容器（E2B、Browserbase）。Agent 要跑代码、开网页，就得有安全隔离的"工位"。
5. **评测与可观测层**：LangSmith、Langfuse 这类工具。市场研究机构 Gartner 预测，到 2027 年约 40% 的 Agentic AI 项目会被砍掉——多数死因不是模型不行，而是没有评测体系，错误定位不了。这一层是隐形的续命药。
6. **身份与支付层**：Agent 用谁的身份登录？谁授权它付款？支付公司正在设计 Agent 原生支付协议，这是 B2A 真正"过手钱"的一层。

## 四、商业逻辑：钱怎么分，护城河在哪

- **计价方式变了**：按席位收费的逻辑会松动——一个 Agent 干十个人的活，谁还买十个席位？行业在试按任务、按结果收费（per-outcome），客服场景已先跑通。
- **毛利要重新算**：推理成本、失败重试成本、评测运维成本三笔账叠加，Agent 产品的毛利模型与传统 SaaS 不同；定价盖不住 token 账单的产品，规模越大亏得越多。
- **分发权在转移**：B2C 流量由应用商店和搜索框决定；B2A 流量由 API 目录与对话入口决定。被 Agent 选中的供应商拿走订单，没被选中的连曝光机会都没有——平台规则问题会原样重现，只是裁判换了人。
- **壁垒三件套**：领域数据与评测集、深度工作流集成、信任与合规（审计日志、权限体系）。只套壳一个模型的应用层，窗口期最短。

## 五、冷思考：三件事想清楚再上船

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-13/945b209d761fa0e7.png)

1. **先算错误成本，再谈自动化**。写错一封邮件和写错一笔转账指令，是两个世界。错误不可逆、责任难界定的环节，先做"人审闭环"，别追求全自动的爽感。
2. **成本按"任务"算，不要按"对话"算**。Agent 的长链路调用加上重试，真实成本常是单次对话的十倍以上；把 token、重试、评测运维三笔账都列进预算模型，再决定商业模型成立不成立。
3. **把产品做成机器可读的**。API 文档、结构化 schema、MCP server、清晰的权限与计费接口——未来三年，"Agent 用你的产品顺不顺"会像当年的"移动端体验"一样，直接决定生死。

一句话收尾：B2A 不是"把人换成机器人"这么简单，而是整个互联网的服务界面从"给人看"到"给机器用"的一次重写。写代码赛道已经证明这条路能跑通；下一个是谁，取决于谁的任务最可结构化，以及谁的 Infra 最先不卡脖子。
