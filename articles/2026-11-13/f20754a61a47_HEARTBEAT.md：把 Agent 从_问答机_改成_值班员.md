## 背景

多数人用 Agent 还是"一问一答"：你想起来才问，它才动。但 OpenClaw 这类常驻本机、带网关的 Agent 有个被低估的机制——心跳（heartbeat）。它每隔一段时间自动唤醒一次，如果工作区根目录存在 `HEARTBEAT.md`，Agent 会读取并执行里面的任务，再把结果推到指定会话。这个文件，就是你声明"主动性"的地方。

## 问题

被动模式下，人成了调度器：每天自己去问"CI 过了没""有没有新邮件""日报写了没"。这类事低频、琐碎、规则明确，最适合交给机器。而用 cron + 脚本写又太重：要维护代码、处理鉴权、拼通知。我们缺的是介于"纯对话"和"写自动化脚本"之间的中间层——纯声明式、可版本化、零代码。HEARTBEAT.md 正好填这个位置。

## 做法

1. 在 Agent 工作区根目录新建 `HEARTBEAT.md`。
2. 用 Markdown checklist 写任务，每项只做一件事，写清"查什么源、判定条件、结果发到哪"。
3. 配置里设心跳间隔，分钟级即可，别低于 15 分钟。
4. 每次心跳，Agent 读取该文件，调用已有工具链（MCP server、插件、exec）逐项执行。
5. 关键一步：给每类任务写"静默规则"——无事可报就不发消息，只返回轻量 ack。

一个能跑的最小模板：

```markdown
# 心跳任务
- [ ] 检查 repo-a 的 CI，仅失败时通知（附失败 job 名）
- [ ] 扫描 ~/downloads 超 7 天的文件，只列出，不删除
- 静默规则：全部正常时不发送任何消息
```

## 踩坑点

- **任务含糊**：写"帮我关注项目动态"，Agent 每次心跳都做一轮昂贵检索，token 账单很难看。任务必须收敛为可判定的条件。
- **没写静默规则**：每 30 分钟收到一条"无事发生"，三天后你自己就会把心跳关掉。
- **耗时任务**：上一个没跑完下一个又触发，产生重入冲突。任务保持秒级完成，或用锁文件防重入。
- **明文风险**：文件是明文，别写 API key，凭据走 MCP 配置。
- **精度误解**：心跳不是精确调度器，"9 点整提醒开会"这类需求请用 cron。
- **工具缺位**：Agent 缺少某任务所需工具时会硬编或静默失败，上线前手动跑通一轮链路。

## 可复用建议

- **当代码管**：进 git、走 PR review，改任务 = 改配置，可回滚可审计。
- **固定四段结构**：目标 / 检查项 / 通知规则 / 静默条件，团队里任何人接手零成本。
- **小步起步**：先放 2-3 个任务跑稳一周，再逐步加。高频信息类任务改成"每次心跳累积、每日汇总发一次"。
- **数据源走 MCP**：别让 Agent 自由发挥抓数据，固定工具输出才稳定可比。

## 总结

HEARTBEAT.md 的价值在于把"主动性"从对话里的口头约定，变成一个声明式文件：零代码、可版本化、成本可见。它不是完整自治系统的替代品，但对监控、汇总、巡检这类规则明确的低频任务，是投入产出比最高的一步。一条经验：任务越小、静默规则越严，这套机制就活得越久。
