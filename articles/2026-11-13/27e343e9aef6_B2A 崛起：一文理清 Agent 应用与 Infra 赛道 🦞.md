过去二十年，互联网生意的基本盘是“服务人”：B2C 把产品卖给消费者，B2B 把方案卖给企业。从 2024 年起，一个新变量开始改写规则，AI Agent 正在成为独立的行为主体，它会自己检索、比价、调用工具、执行任务。于是 B2A（Business to Agent）被推上桌面：企业的产品不仅要让人用得爽，还要让 Agent 用得顺。36kr 这篇热文把 14 条 Agent 应用赛道与 Infra 版图做了全景梳理，本文把它拆开，讲清三件事：B2A 到底变了什么、钱在哪些赛道流动、普通人和企业该怎么跟进。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-13/e379e7e59ab422a2.png)

## 一、B2A 变的不是名词，是商业的“接口”

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-13/c1a3ad7a7f010a5e.png)

B2C 时代的核心资源是流量，流量背后是人的注意力：竞价排名、信息流广告、直播带货，本质上都在争夺“人看什么”。到了 B2A，做“看、比、选”这个动作的换成了 Agent，商业接口随之重写。具体变化有三层：

1. **交互层**：网页让位于结构化接口。Anthropic 开源的 MCP（Model Context Protocol）让模型能标准化接入外部工具与数据；Google 力推的 llms.txt 让网站可以主动告诉来访的模型“我是谁、怎么调用我”。这些动作的共同点是：给 Agent 修门，而不是修橱窗。
2. **决策层**：人购物是“浏览—收藏—下单”，Agent 是“检索—评估—执行”。当比价与参数分析交给模型，品牌溢价可能被“参数忠诚度”稀释，谁能进入 Agent 的候选池，谁才有资格谈转化。
3. **计费层**：按人头订阅（seat-based）开始松动。Agent 干活按任务、按调用计费（usage-based）更自然，部分 SaaS 厂商已在试验“按完成的结果付费”。这不是定价技巧的微调，而是收入模型的底层更换。

## 二、应用层 14 条赛道：可以归进四个筐

36kr 列出的 14 条应用赛道，按商业成熟度大致能装进四个筐：

- **生产力硬通货（已跑通闭环）**：编程 Agent（Cursor、Claude Code、Devin 一类）、客服与销售 Agent、深度研究与数据分析 Agent。共性是结果可验证、ROI 好算：代码能跑通就是跑通，客服解决率直接进报表。编程 Agent 最先规模化并非偶然——代码有编译器和测试当裁判，天然适合 Agent 迭代。
- **垂直行业 Agent（慢生意、高壁垒）**：法律、医疗、金融合规、招聘等。护城河不在模型，在行业 know-how、数据合规与客户信任。这类公司的目标通常不是“更通用”，而是“在很窄的领域比人稳定”。
- **操作执行类（最难啃）**：浏览器操作、computer use、办公自动化、RPA 与 Agent 融合。让模型像人一样点网页、填表单，痛点是成功率与容错，在生产环境里，一次误操作的成本足以否掉整个方案。
- **平台编排类（应用层里的卖铲人）**：多 Agent 编排、企业级 Agent 平台、工作流引擎。前三类要组合作战，都绕不开它们。

## 三、Infra 层：Agent 的“水电煤”

应用层迭代快、死亡率高，但只要 Agent 数量在涨，底下这些“必选项”的收入就相对稳定。Infra 赛道大致七块：

1. **模型层**：闭源与开源并存，长上下文与工具调用能力是军备竞赛的核心指标。
2. **框架编排**：LangChain、LlamaIndex、CrewAI 等，解决“模型、工具、记忆怎么串起来”。
3. **记忆与检索**：向量数据库与长期记忆管理，决定 Agent 是金鱼脑，还是能积累经验的同事。
4. **沙箱算力**：Agent 执行代码需要隔离环境，安全沙箱是刚需而非可选项。
5. **评测与可观测**：Agent 输出不确定，“这次调用有没有干对活”需要专门的 Eval 工具度量，这是从 A/B 测试传统里长出来的新赛道。
6. **协议生态**：MCP、A2A（Agent-to-Agent）之于 Agent 世界，相当于 HTTP 之于网页，协议即生态。
7. **安全合规**：权限管控、防 prompt injection、审计日志。Agent 一旦能“动手”，安全就从加分项变成准入项。

这层的商业逻辑与云计算一致：不赌哪匹马赢，收所有赛马的场地费。

## 四、为什么是现在：三个底层变量

- **能力跨阈值**：2023–2025 年，工具调用、长上下文、多步推理快速成熟，Agent 从发布会演示变成可交付产品。
- **协议标准化**：MCP 于 2024 年底开源后迅速被主流厂商跟进，工具接入从“每个应用各写一遍胶水代码”变成“实现一次、处处可用”，生态飞轮开始转动。
- **推理成本陡降**：同等能力模型的价格一年内降了约一个数量级，“高频调用”的商业模式在财务上第一次成立。成本曲线，往往比产品曲线更能决定赛道生死。

## 五、三条冷思考

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-13/69c4c07f387d5ea3.png)

1. **警惕 Agent 万能论**。当前执行类 Agent 的可靠率离生产环境仍有距离。落地顺序建议倒着排：先做错误成本低的场景（内容生成、代码、内部分析），再碰错误成本高的场景（直接动钱、动生产系统）。
2. **对开发者：找缺的工具，别挤应用的红海**。一个稳定的 MCP server、一份清洗好的垂直数据源、一个好用的评测工具，都可能成为 B2A 时代的卖水生意。应用层比拼产品感，工具层比拼可靠性，后者对个人和小团队更友好。
3. **对企业：现在就做 Agent 友好化**。把文档结构化、开放 API、部署 MCP 接口，成本并不高。未来流量分发权可能从搜索引擎逐步转移到 Agent 平台，接口早一天可用，就早一天进入 Agent 的候选池。

B2A 不是新造的营销词，而是“谁来使用软件”这个问题的答案发生了迁移。上一个十年，得流量者得天下；这一个十年，得调用者得天下。
