## 背景

我们习惯把 Agent 当"问答机"：不发消息它就不动。但真实使用中有一类事务天然是周期性的——收件箱梳理、服务巡检、仓库整理、每日摘要。这些事你不去问，它就永远不发生，最后你还是那个人肉 cron。

OpenClaw 的 heartbeat 机制就是给 Agent 装一个"值班闹钟"：网关每隔一段时间（默认 30 分钟）唤醒一次 Agent，让它读取工作区里的 `HEARTBEAT.md`，按里面的指令决定这一轮做什么。文件存在且非空，Agent 就照办；为空或缺失则直接静默跳过。

## 怎么做

**1. 找到文件。** 默认在 `~/.openclaw/workspace/HEARTBEAT.md`。多 agent 场景可在配置里用 `target` 指定由谁值班。

**2. 写"值班手册"，不是愿望清单。** 每条任务写清：做什么、什么条件下才通知你、最多多久提醒一次。例如：

```markdown
# Heartbeat
- 检查收件箱：只有需要我决策的邮件才发消息，
  其余汇总一行写入 inbox-digest.md，保持静默。
- 磁盘水位超过 80% 才提醒，每小时最多提醒一次。
- 没有可执行事项时静默结束，不要编造汇报。
- 不要修改本文件。
```

**3. 调整间隔。** 在配置中把 `heartbeat.every` 设为如 `"15m"`，改完重启网关生效。

**4. 观察前几轮。** 看日志确认它真的在读文件、真的在按条件沉默，而不是每轮都找借口说话。

## 踩坑点

- **文件越长，账单越贵。** 每次心跳都会把 HEARTBEAT.md 全文塞进上下文，一天几十轮乘下来，长文件就是持续烧钱。控制在几十行内，细节交给 MCP 工具或脚本。
- **没有条件的主动性等于通知轰炸。** 每条任务都要加 "Only if…" 和冷却规则，这是低噪声主动的关键。
- **心跳不是 cron。** 它是"松间隔巡检"；精确到每天 9:00 的任务请用真正的定时任务，别拿心跳硬凑。
- **别写密钥。** 这个文件会被反复读入上下文，任何敏感信息都等于定时泄露。
- **防止自我漂移。** 模型可能顺手"优化"自己的值班手册，明确写上禁止修改，并把它放进 git。

## 可复用建议

把 HEARTBEAT.md 当 SOP 管理：入库做版本控制；每条任务用统一模板——目的 / 动作 / 触发条件 / 输出方式 / 冷却时间；先从一两个高频低风险任务起步（比如收件箱摘要），跑稳一两周再追加。搭配 MCP 工具时，让心跳只负责"决定要不要做"，具体动作全部落到工具调用上，方便审计和限流。

## 总结

HEARTBEAT.md 的价值不是"让 Agent 更主动"，而是"让 Agent 更克制地主动"。一份短小、有条件、有冷却的值班手册，加上合适的间隔与真 cron 的分工，才能做到：该出手时出手，其余时间安静。
