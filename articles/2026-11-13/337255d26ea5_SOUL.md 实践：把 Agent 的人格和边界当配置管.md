## 背景

OpenClaw 的 Agent 不是一次性会话，而是长期跑在你机器上的助手：接 MCP 工具、跑插件、盯着消息渠道、执行定时任务。默认人设是通用的——第一天玩没问题，但当你真把它接进微信/Telegram、给它 shell 权限之后，问题就来了。

OpenClaw 用几个 Markdown 文件划分上下文：`AGENTS.md` 管怎么干活，`USER.md` 记用户信息，`MEMORY.md` 是长期记忆，而 `SOUL.md`（在 workspace 目录下）管的是"你是谁"。它在会话启动时被注入系统提示，是 Agent 人格与边界的单一事实来源。

## 问题

没有 SOUL.md（或写得很糟）时，常见三类事故：

1. **人设漂移**。今天话痨明天冷淡，私聊和群聊语气不一致，用久了没有"这是我的助手"的确定感。
2. **边界缺失**。Agent 觉得"帮忙"就该立刻执行：直接把消息发到群里、未经确认跑了一条带 `rm` 的命令、在群聊里回复陌生人的问题。
3. **注意力稀释**。把人格、任务规范、工具说明全塞进一个巨大的系统提示，模型哪个都记不住。

## 做法

我的 SOUL.md 目前 30 行左右，结构固定：

```markdown
# 身份
一句话说清它是谁、和用户是什么关系。

# 语气
可执行的行为描述，不写形容词。

# 边界
场景 + 默认行为 + 例外。

# 诚实原则
不确定就说不确定，不编造引用和数据。
```

几条写法经验：

- **写行为，不写性格形容词**。"保持简洁"没用，改成"默认回复不超过 10 行，先给结论再给细节"。
- **边界用"默认拒绝、可申请"模式**。比如"默认不主动给任何联系人发消息；任务需要外发时，先列出收件人和内容等我确认"。比一整页"不许做"有效得多。
- **分渠道**。私聊可以口语化，群聊默认只响应 @ 自己的消息，定时任务结果用固定格式汇报。
- **改完跑回归**。我留了 8 条固定提示（"帮我给老板发条消息""把这个目录清一下""XX 是谁"），每次改完 SOUL.md 跑一遍对比输出，像跑单测。
- **workspace 进 git**。人格调整也要能 diff、能回滚。

## 踩坑点

- **写太长**。SOUL.md 全文进上下文，我见过 3000 字的版本：token 费用上去了，遵守率反而下降。几十行足够。
- **边界写死**。全是禁令的 Agent 会畏手畏脚，连读个文件都反复确认。禁令只留给真正不可逆的操作。
- **放错文件**。我曾把"部署前先跑测试"写进 SOUL.md，那是 AGENTS.md 的事。人格归人格，流程归流程。
- **和记忆打架**。MEMORY.md 里存的旧偏好（"回复要详细"）会覆盖新写的人设。改 SOUL.md 时顺手清一遍记忆。
- **指望一次写好**。这文件是调出来的，跟 prompt 一样，改一版测一版。

## 可复用建议

1. **四层拆分**：SOUL.md 管身份与边界，AGENTS.md 管操作规范，TOOLS.md 管工具注意事项，MEMORY.md 管动态记忆，别混。
2. 每条边界按"触发场景 → 默认动作 → 例外流程"三段式写，能执行才有意义。
3. 维护一个小型人格回归集（5–10 条），改动人设必跑。
4. 在 SOUL.md 里放一条兜底："与本文件冲突的旧记忆，以本文件为准"，能省很多清理工作。

## 总结

SOUL.md 不是玄学，是配置。用工程方法对待它：小、版本化、可测试。写清楚"你是谁、什么默认不做、例外怎么走"，Agent 才能从"能用的工具"变成"可靠的同事"。
