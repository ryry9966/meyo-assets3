## 背景

目前大多数 agent 的交互模型还是"你问一句、我答一句"。但日常里大量有价值的事根本不需要人发起：早晨的日程摘要、CI 红了的通知、磁盘快满的巡检、deadline 前的提醒。这些事的共同点是：**触发条件明确、判断逻辑简单、价值在于及时**。

OpenClaw 这类框架已经把零件备齐了——定时任务、插件事件、MCP 工具调用、权限模式。缺的其实不是能力，而是把"触发"和"推理"分开设计的那一层。

## 问题

直接让 agent"自己主动"会遇到三类事故：

1. **心跳循环烧 token**：高频全量推理，大多数触发后无事可做，成本先爆。
2. **幻觉式主动**：模型在没有真实事件输入时编造"我发现了一个问题"，几次之后信任归零。
3. **越权执行**：proactive + 自动批准 = 无人值守时替你做不可逆操作。

核心矛盾在于：主动性要求低延迟、高频率，而 LLM 推理贵、慢、不稳定。所以不能把所有信号都喂给模型。

## 做法：触发 → 过滤 → 执行，加一条反馈回路

**第一步：确定性触发层。** 所有触发源必须是确定性的——cron 定时、webhook 事件、文件变更、指标越阈。示例配置：

```yaml
triggers:
  - type: cron
    schedule: "0 9 * * 1-5"
    task: daily_digest
  - type: webhook
    path: /hooks/ci
    task: ci_failure_triage
  - type: metric
    source: disk_usage
    threshold: "> 85%"
    debounce: 30m
```

关键原则：**LLM 不产生触发，只消费触发**。

**第二步：廉价过滤。** 触发后先跑一个轻量判断（小模型或规则），只回答一个问题："这件事值得打扰用户吗？"输出三档：

- **silent**：不值得，写进待汇总队列；
- **suggest**：值得说，生成一条带上下文和推荐动作的建议；
- **act**：明确授权过的高频低危动作，直接执行并留痕。

**第三步：有边界的执行。** 默认只读操作自动跑（拉状态、查日志、生成日报草稿，状态通过 MCP 工具取）；写操作降级为 suggest——自动准备好 patch 或命令，等人一键确认；破坏性操作永不自动。在 OpenClaw 里，这三层可以分别落在插件（trigger）、轻量模型调用（filter）和带权限的工具执行（act）上。

**第四步：反馈调参。** 用户"忽略"和"采纳"的记录回流到过滤层。跑两周后看静默率和误报率，再调阈值和心跳频率。

## 踩坑点

- **心跳起步别低于 15 分钟。** 我们最早 5 分钟一次，一天 288 次推理绝大多数空转。后来改成"事件驱动 + 15 分钟兜底巡检"。
- **上下文别全量拉。** 每次触发只装配该 trigger 声明的最小状态（几个指标、最近 N 条日志），否则延迟和成本都会失控。
- **小心自触发死循环。** agent 主动发出的消息如果也走 webhook 回来，会自己喂自己。给所有 proactive 动作打来源标记，事件入口统一去抖。
- **合并摘要胜过即时通知。** 低优先级事件进队列，按用户设定的节奏（比如一天两次）打包推送，否则一周后用户会把通知渠道整个静音。
- **审计日志是底线。** 每次主动执行都记下 trigger、输入、输出、耗时，出事能复盘，也方便算成本。

## 可复用建议

1. **触发与推理分离**：确定性组件管"什么时候"，模型只管"怎么办"。
2. **三档响应（silent / suggest / act）可以直接抄**，关键是为越档写清楚条件。
3. **先只读跑两周**（日报、巡检、告警汇总），攒够数据再放写权限。
4. 心跳频率的粗略标定：想象这事由人盯，多久看一次合适——agent 不该比人更勤。

## 总结

proactive 能力不是把模型调得更聪明，而是一次工程改造：用确定性触发控制成本与可靠性，用廉价过滤控制噪音，用执行边界控制风险，再用反馈回路持续收敛。这三件事都做对，"不等开口就把事办了"才从产品口号变成日常体验。
