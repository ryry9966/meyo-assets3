最近在跑多 Agent 并行任务时踩了不少坑，把 session 隔离这套做法整理成帖，供参考。

## 背景

OpenClaw 里主 Agent 常需要派生子 Agent 处理重活：批量工具调用、长耗时检索、并行试错。理想状态是主会话只保留"控制面"——下发任务、回收结果、记录决策。但实际跑起来，子 Agent 的工具轨迹和中间输出经常顺着会话流回主上下文，几个任务下来主会话膨胀、注意力被噪声稀释，记忆库里还混进一堆过程性内容。

## 问题：污染的三条路径

实践中观察到三条典型路径：

1. **上下文回灌**：某些 spawn 方式默认复用父会话 ID，子 Agent 每次 tool call 都追加进主会话历史。
2. **记忆越界**：子 Agent 写 memory 或配置文件时没有命名空间，主会话后续检索命中一堆无关的中间结论。
3. **资源隐式耦合**：MCP server 实例、临时目录、环境变量被父子共用，子 Agent 的失败状态影响后续任务。

## 做法

方案分五步，均可复现：

1. **独立 session ID**：派生时显式指定新 `session_id`（或 `isolate: true`），禁止子 Agent 写回主会话文件。先在配置里确认默认行为，别假设默认就是隔离。
2. **约定返回契约**：子 Agent 只回传结构化摘要——`{result, artifacts, errors, cost}` 四个字段；完整 transcript 归档到独立存储，主会话只摄入摘要。
3. **工作区隔离**：每个子 Agent 分配独立临时目录，路径作为参数显式传入，任务结束后由父 Agent 统一清理或归档。
4. **记忆命名空间**：写入限制在 `sub/<task_id>/` 前缀下，主 Agent 检索默认排除该前缀，需要时按 ID 精确拉取。
5. **MCP 按会话隔离**：工具 server 按 session 打标签或用独立实例，避免缓存和文件句柄跨会话串。

## 踩坑点

- **默认值陷阱**：部分版本里同步 spawn 共享会话、异步才隔离，升级后行为可能变化，靠测试确认而非文档记忆。
- **摘要带噪声**：父 Agent 把整段历史塞给子 Agent，回传摘要里夹着无关引用，等于二次污染。下发时只给任务必需的上下文。
- **并发写坏文件**：多个子 Agent 并发 append 同一 session 文件会导致行损坏。要么独立文件，要么加锁。
- **孤儿会话**：异步派生后忘记收集结果，session 在后台跑完无人消费，磁盘和费用都受影响。
- **临时目录复用**：上次失败留下的半成品文件被下次任务误读，务必在任务入口做清理。

## 可复用建议

- 封装一个 `spawn_isolated()` 包装函数，把五步固化，团队统一入口。
- 主会话做"瘦身自检"：任务前后对比 token 数与会话文件大小，异常增长即报警。
- 把返回契约写进子 Agent 的 system prompt 模板，而不是靠口头约定。
- 定期跑审计脚本：扫描主会话里是否出现子 Agent 专属工具名，出现即说明隔离失效。

## 总结

Session 隔离的本质不是某个开关，而是四条边界：独立会话 ID、独立工作区、命名空间化的记忆、结构化的返回契约。主会话保持控制面定位，过程细节留在子 Agent 自己的会话里，需要时按 ID 回溯。边界清晰之后，并行派生和多级任务才敢放心上生产。
