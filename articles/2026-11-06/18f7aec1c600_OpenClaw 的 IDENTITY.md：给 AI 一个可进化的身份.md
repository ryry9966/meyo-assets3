## 背景

OpenClaw 的 agent workspace 里有一组以 Markdown 为载体的"人格文件"：`AGENTS.md` 管行为规则，`SOUL.md` 管价值观和语气，`MEMORY.md` 管长期记忆，而 `IDENTITY.md` 回答的是最基础的问题——"我是谁"。它通常只有十几行：名字、头像 emoji、一句话自我定位、语气倾向、几条边界。每次新会话启动时，这份文件会被注入 system context。

听起来很小，但它是所有 prompt 里复用率最高的一份：写一次，影响每一次会话。

## 问题

默认的 IDENTITY.md 有两个毛病。一是"出厂人格"过于通用，助手说话像客服，缺乏稳定的个性锚点，长期使用中行为会漂移——今天话多，明天冷淡。二是多数人把它当成一次性配置：写完就再也不看，三个月后 agent 的实际表现和文件描述早已对不上，身份变成了一份失效文档。

多 agent 场景下问题更明显：几个工作区里的 IDENTITY.md 互相复制粘贴，最后所有 agent 用同一种腔调说话，分不清谁是谁。

## 做法

我的做法分三步，核心思路是：把身份当成代码来维护。

**第一步：重写一份最小骨架。** 控制在 25 行以内，只留四个字段：名字与 emoji、一句定位（比如"偏好直接给结论、先答后解释的终端助手"）、两三条语气规则、一两条明确不做的事。用第一人称陈述句，短句优先。

**第二步：纳入 git 管理。** workspace 本来就该在版本控制里，IDENTITY.md 每次修改都提交，commit message 写清动机（如"回复太啰嗦，加入'不重复用户已知信息'"）。身份变更从此有历史、可回滚。

**第三步：建立进化回路。** 两种信号触发修改：一是日常使用中捕捉"身份摩擦"——agent 说了不符合定位的话，当场在 MEMORY 里记一行，攒够三条就改 IDENTITY.md；二是每月做一次漂移审计，直接问它"用三句话介绍你自己"，把回答和文件 diff。不一致说明注入的身份已被会话习惯覆盖，要么改文件，要么在 SOUL.md 里补约束。

## 踩坑点

- **写太长。** 超过 40 行后，关键身份描述会被淹没，agent 表现反而更随机。身份文件靠精准，不靠全面。
- **和 SOUL.md 抢地盘。** 价值观、安全边界放 SOUL.md，IDENTITY.md 只回答"我是谁、什么腔调"。两边重复且措辞不一致时，agent 行为会来回摇摆。
- **改了不生效。** 身份在会话启动时注入，改完文件要开新会话才生效，别在旧会话里反复质问它"你怎么还没变"。
- **写成营销文案。** "你是无所不能的超级助手"这类描述只会让输出浮夸。具体、可观察的行为描述（"先给结论""不用感叹号"）远比抽象头衔有用。

## 可复用建议

- 25 行以内、四个字段、第一人称短句，是一份够用的起点。
- 每次修改走 git，一个 commit 只改一个身份特征。
- 每月一次"自我介绍审计"，拿三句话回答和文件做 diff。
- 多 agent 场景给每个 agent 至少一个可区分的语气特征，而不是只改名字。
- 稳定内容放文件头部，实验性改动放末尾并标注日期，验证有效再合并。

## 总结

IDENTITY.md 的价值不在初始配置，而在持续维护。它很小，十分钟就能重写；它又很大，大到决定每一次会话的基调。把"我是谁"当成一份活的文档——有版本、有变更理由、有定期审计——agent 才不会在长期使用中漂成一个你不认识的陌生人。
