36kr 那篇《一文讲透AI产品经理》在朋友圈刷屏，说明一件事：AI 产品经理已经从“风口新词”变成了很多 PM 认真规划中的下一站。ChatGPT 上线两个月用户破亿到现在不过两年多，大模型调用价格却已降了一个数量级——能力在涨、成本在降，应用层自然爆发，岗位需求跟着水涨船高。但热闹背后，多数讨论停留在“要懂大模型”这种正确废话上。这篇文章把岗位地图、底层机制和转型路径一次性摊开，讲透。

## 一、AI PM 和传统 PM，差在哪

转型前先认清差异，不然就是拿着旧地图找新大陆。核心有四点：

1. **确定性 → 概率性**。传统功能是“点了按钮一定跳转”；大模型产品同一个问题问两遍，答案可能不一样。产品目标从“实现功能”变成“把输出分布调到够好”，接受 95 分而非 100 分。
2. **需求边界由模型决定**。传统 PM 的天花板是想象力加排期；AI PM 的天花板是模型能力加成本。模型会什么、一次调用多少钱，直接决定功能怎么设计。
3. **交付物变了**。PRD 之外，多了评测集（eval set）、bad case 库、prompt 规范、知识库与工具调用设计。其中评测集是新的“需求文档”——它把“什么叫好”写成了可执行的判断标准。
4. **指标体系变了**。留存、转化照旧，但新增幻觉率、任务完成率、token 成本、首 token 延迟（TTFT）这些“模型原生指标”。

## 二、六大方向：一张岗位地图

市面上的“AI 产品经理”其实是六种差异很大的工种：

1. **模型与基础平台方向**：贴近模型侧，做 Agent 平台、推理服务、模型 API 的产品化。要懂推理成本和调用链路，用户是开发者。
2. **C 端应用方向**：AI 陪伴、AI 搜索、创作工具。核心是在对话、生成这些新交互范式下找场景，赛道最拥挤，也最吃增长直觉。
3. **B 端应用与行业解决方案方向**：Copilot、行业 SaaS 加 AI。核心是把 AI 嵌进既有工作流、算清 ROI，是传统行业 PM 迁移最顺的路。
4. **数据与训练侧方向**：数据集构建、标注体系、SFT/RLHF 数据策略。模型的上限很大程度由数据决定，这个方向离本质最近。
5. **评测与安全合规方向**：评测基准、红队测试、内容安全。随着生成内容标识等合规要求落地，这个方向正从“配角”变“刚需”。
6. **AI Infra / 中台方向**：MLOps、RAG 平台、模型网关、多模型调度，本质是“把模型当算力卖”的工具层。

## 三、机制篇：一个 AI 功能从输入到上线走了哪几步

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-06/c81e72795902bba5.png)

理解这条链路，是和算法同学对话的最低门槛：

1. **请求编排**：用户输入进来，先拼 prompt、检索知识库（RAG，即检索增强生成——先查资料再回答，用来对冲模型知识过时和幻觉）。
2. **模型推理**：token 一个个生成，温度参数控制随机度；Agent 模式下还会通过 function calling 调用外部工具。
3. **后处理与安全**：格式解析、敏感内容过滤、引用标注。
4. **评测与回流**：线上 bad case 被捞出来进评测集，驱动下一轮迭代。

为什么会有幻觉？因为大模型本质是“预测下一个 token 的概率”，它不是在查资料，而是在补全“最像答案的文本”。幻觉不是 bug，是机制的副产品——产品的职责是用 RAG、引用标注和交互设计，把错误圈在用户可容忍的范围内。PM 不需要会训模型，但必须能把这条链路讲清楚，否则立项会上连“这个 bad case 该修模型还是修数据”都判不了。

## 四、转型三步走：别裸跳

1. **第一步：补最小知识集（2~4 周）**。上下文窗口、温度参数、RAG、微调与 prompt 的区别、function calling、多模态基础。目标不是会训模型，是开会不懵。
2. **第二步：做一个拿得出手的作品**。用现成 API 做个小工具，重点不是功能多炫，而是附一份评测报告：定义 20 个测试用例，跑分，逐条分析 bad case。这份文档比简历上写“熟悉 prompt 工程”有说服力十倍。
3. **第三步：找迁移支点**。在你熟悉的行业里找 AI 切入点——做电商的看导购和客服，做教育的看批改和陪练。B 端经验加垂直场景理解，是当下招聘市场最认的组合。很多岗位要求“有 AI 项目经验”，用 side project 破掉“要经验才有项目、有项目才有经验”的死循环。

## 五、避坑指南与判断框架

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-06/8d70000ff620cc95.png)

- **坑一：把“套壳”当贬义**。应用层的价值在场景、私有数据和分发渠道。模型能力会被平权，这些壁垒不会。
- **坑二：Demo 驱动开发**。Demo 里 90% 准确率，长尾场景可能掉到 60%。上线前先建评测集，用数据说话，不用感动自己。
- **坑三：不算成本账**。token 成本乘以调用量，高频低价场景很容易烧穿毛利。先算单位经济模型，再谈体验升级。
- **坑四：无脑追新**。Agent、多模态、新范式一个季度一个样，但“帮用户把事办成”这个需求十年没变。

判断一个 AI 功能值不值得做，问三个问题就够：

1. 用户对错误的容忍度有多高？（写初稿容忍度高，法律文书容忍度低）
2. 关键数据在不在你手里？（RAG 没有好数据就是空转）
3. 被替代方案的现状成本是多少？（人工或规则引擎现在花多少钱，AI 真能省出多少）

## 收尾：三条冷思考

1. **AI PM 的稀缺能力不是“会用 AI”，而是“定义什么叫好”**。评测体系的设计能力，才是这个岗位真正的护城河。
2. **行业知识比模型知识更保值**。模型能力每半年就被拉平一次，但对某个行业工作流的深度理解需要数年积累。
3. **转型前先看目标岗位的真实日常**：是写 prompt 调评测，还是陪客户定方案？方向不同，能力模型完全不同。别为转型而转型，别用焦虑替代理性。

潮水方向确实变了，但游过去的最好是学会换气的鱼，而不是光着膀子硬跳的……龙虾。共勉。
