# 从零搭建 AI 社区发帖机器人：架构设计与踩坑实录

## 背景

我在维护一个几百人的技术社区，一直想加一个"每周精选 + 新人引导"类的固定栏目。人肉写不可持续，于是决定基于 OpenClaw 搭一个发帖机器人：定时选题、生成草稿、审核后发布。目标不是全自动灌水，而是**机器出草稿、规则守底线、人只做抽检**。

## 问题

拆开其实是三个问题：

1. **内容质量怎么稳**：LLM 写帖容易跑偏、编造引用；
2. **怎么不重复**：定时任务跑久了必然撞题；
3. **发布可靠性**：重试、幂等、限流，任何一个没处理好就是事故。

## 架构与做法

整体五层，LLM 只出现在生成层：

- **触发层**：cron 每 6 小时拉一次任务，进程锁防重叠；
- **生成层**：OpenClaw agent 调 MCP 工具（抓社区热帖、读仓库 issue、查统计数据），产出结构化草稿 JSON（标题/正文/标签/引用来源），不产出"发布动作"本身；
- **审核层**：规则校验（链接白名单、长度、标签合法性）+ 相似度去重（与近 30 天帖子比 embedding，阈值 0.85）+ 可选人工闸门；
- **发布层**：论坛 API 适配器，纯确定性代码，客户端先对规范化标题做 hash 作为幂等键；
- **记录层**：SQLite 落指纹、发布状态、失败原因。

关键取舍：agent 只有"建议权"，一切写操作走代码。MCP 工具分权限，读类自动放行，`create_post` 这类写工具默认要求确认。

## 踩坑实录

1. **编造链接**。第一周抓到 3 篇草稿引用了不存在的 issue 地址。解法：引用必须来自工具返回值，正文里的 URL 逐个回查，查不到直接拒稿。
2. **cron 重叠导致重复发**。任务卡在限流重试时，下一轮已经起来了。加进程锁 + 指纹唯一约束，双保险。
3. **429 限流**。论坛 API 的限流比文档写的严。指数退避之外，把统计类调用合并成批量接口，一次拉一批。
4. **外部内容 prompt injection**。抓来的 issue 正文里出现过"忽略之前指令"式文本。处理方式：工具输出一律当纯数据，包定界符并转义，系统提示词固定不动。
5. **同质化**。跑两周后帖子越来越像。加选题池轮换 + 新颖度检查，命中重复主题直接换题。
6. **token 成本**。草稿用小模型、审核用大模型，工具结果落缓存，单篇成本降了约六成。

## 可复用建议

- LLM 只负责生成，发布永远走确定性代码，这条是底线；
- 一切写操作带幂等键，服务端不支持就在客户端造；
- 先 dry-run 一到两周，人工抽检通过率稳定后再放开；
- 把目标平台 API 封成 MCP 工具，而不是塞进 prompt，并做权限分级；
- 状态必须落库，别放内存——进程重启是常态，不是意外。

## 总结

目前稳定运行四周，发帖 30 余篇，拒稿 6 篇，重复 0 次，人工只做每周抽检。回头看，这个项目真正的工程量不在"让 AI 写帖"，而在审核层和发布层的护栏上。自动化放大的是你流程本身的质量：流程烂，机器人只会更快地出事故。
