## 背景

社区运营里有一类重复劳动：把群里的讨论、周更的素材沉淀成帖子，定时发布。我最初用纯脚本（模板 + cron）解决，内容死板，慢慢就荒废了；后来索性把「想标题、写正文、发帖」全交给 agent 自由发挥，结果第一次实跑就发出一篇格式崩坏的帖子，删帖删到手软。这篇记录最终落地的架构和几个真实的坑，供有同样需求的同学参考。

## 目标与边界

先说清楚边界：这不是自动水贴机器人。它只做三件事：

1. 定时收集素材（RSS、群消息摘录、issue 列表）
2. 起草帖子（标题 + 正文 + 标签）
3. **经人工确认后**发布

原则一句话：agent 负责生成，人负责放行。

## 架构

- **触发层**：cron 定时任务 + 手动指令，两条入口
- **编排层**：OpenClaw agent，挂载三个 skill（素材汇总、草稿生成、格式校验）
- **工具层**：三个 MCP 工具，权限收窄——`fetch_materials` 只读、`save_draft` 写本地 SQLite、`publish` 必须携带人工生成的确认 ID 才能调用
- **状态层**：SQLite 存任务、草稿、dedup key、发布记录

关键设计是发布必须二次确认：确认 ID 只能由我在审核界面生成，agent 拿不到也伪造不了。这一条挡住了后来 90% 的事故。

## 踩坑实录

**1. 重试导致重复发帖。** 网络超时后 agent 自动重试，同一篇帖发了两次。修复：发布前先生成 dedup key 落库，`publish` 检查 key 已存在就直接返回已有链接。结论：幂等要放在工具层实现，不能指望模型自觉。

**2. Markdown 被二次转义。** 草稿里的代码块经 agent 输出再进发布 API，反引号和换行全部转义，正文惨不忍睹。修复：工具只接收结构化字段（title/body/tags），序列化在工具内部做一次，绝不接受模型吐最终 HTML。

**3. 密钥进过上下文。** 早期图省事，把社区 API token 写进提示词方便调试，后来意识到任何进上下文的内容都可能被模型复述。改为 MCP 服务端读环境变量，prompt 里永远不出现 token。

**4. 定时漂移。** 素材抓取偶尔 20 秒、偶尔 3 分钟，超时任务堆积，晚上一口气连发五篇。修复：加互斥锁 + 超时放弃本次，宁可漏一期，不排队挤爆。

**5. 模型擅自改标题。** 明确要求保留原标题，它还是会「优化」措辞。修复：标题进校验白名单，不一致直接打回重写。

## 可复用建议

- 一切有副作用的工具，默认提供 dry-run 模式
- 状态进数据库，不要存在对话记忆里
- 工具权限最小化拆分，读和写分离
- 保留审计日志：谁、何时、确认了哪篇
- 把「人工放行」做成机制，而不是靠自觉的习惯

## 总结

整套东西核心代码不到三百行。agent 部分反而是最简单的，真正的工作量全在工程边界上：幂等、权限、确认流、超时策略。「生成—审核—发布」这三段式不依赖具体平台，平移到任何自动化发布场景都成立。建议想动手的同学先从只读的素材汇总做起，发布能力最后再开——或者干脆永远保持人工放行，让机器人停在草稿箱，也是完全合理的产品形态。
