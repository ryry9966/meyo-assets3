# 背景

OpenClaw 接上定时任务之后，很多人做的第一件事就是自动发帖：cron 触发 → agent 生成内容 → 走 MCP 工具发到论坛或群。跑起来很快，但跑不到一周就会被看出来——整点发帖、间隔一致、句式雷同。轻则被折叠限流，重则被管理员当成营销号处理。

# 问题：机器感从哪来

被识别为机器人，通常不是内容质量的问题，而是这几个信号：

- **时间规律**：固定间隔、整点触发、秒数永远是 00；
- **内容同质**：同一套模板、长度方差极小、标点和 emoji 习惯完全一致；
- **行为单一**：只发不读，从不引用上下文，响应速度不符合人的节奏；
- **频率失配**：新账号一上来就高频输出。

# 做法

1. **调度层加抖动**。不要裸用 cron，基础间隔乘一个 0.7–1.3 的随机系数，秒级也要随机，避免固定“每天 9:00”。
2. **跟随社区活跃曲线**。统计目标社区的历史发帖时间分布，让 agent 的活跃时段与之对齐；深夜、节假日静默或大幅降频。注意时区——服务器大多是 UTC，社区是东八区，不校准就会出现“凌晨三点活跃”。
3. **频率硬约束**。全局由一个队列单点控制：每日上限、相邻两帖最小间隔、同版块冷却时间。参数全部抽进配置文件，别写死在代码里。
4. **先读后写**。发帖前用工具拉最近 N 条帖子做去重和上下文检查；读写比保持在 1:10 左右，偶尔只评论不发帖。
5. **内容去模板化**。长度刻意拉开方差，开头句式轮换，尽量回应当下的讨论，而不是空降话题。
6. **人工兜底**。agent 产出先进草稿队列，人工一键放行。初期 100% 审核，跑稳后再降低比例。
7. **失败退避**。遇到限流（429）做指数退避，恢复后按正常节奏补发，绝不能把积压任务一次性倾泻。

# 踩坑点

- 抖动只加在分钟级，秒数永远是 00，照样一眼假；
- 时间像人了，内容还是同一个模板，等于白调；
- 重试堆积后集中补发，一波突发比不发更刺眼；
- 节假日“早报”照发——节假日是社区里最强的异常信号；
- 多个插件各自调度，单看每个都克制，合起来就是刷屏。

# 可复用建议

- 节奏参数做成一份配置（`min_interval`、`jitter_ratio`、`daily_cap`、`quiet_hours`、`cooldown_per_channel`），换社区只换配置；
- 每周把发帖时间戳画个直方图，肉眼扫一眼是否像人的分布；
- 宁可少发。“偶尔出现、每次有用”比“时刻在线”安全得多；
- 所有发帖收敛到一个调度器，节奏只能有一个控制点。

# 总结

不像机器人的核心不是伪装，而是克制：低频、有上下文、有静默期、有人工兜底。把节奏当成一等公民来设计，你的 agent 才能在社区里长期存活。
