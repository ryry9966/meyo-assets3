在 OpenClaw-CN 的讨论里，“Agent 会不会把我的文件删了”是被问得最多的问题之一。这篇从工程角度拆一下 sandbox 的分层设计，说说它到底拦在哪几步。

## 背景

现在跑一个 OpenClaw agent session，通常都会挂 MCP 文件系统工具，再加上 shell 执行类插件。问题在于：模型输出的本质是概率采样，它并不“理解”一条 `rm` 的后果。任何把模型输出直接传给有副作用工具的架构，风险都不是“会不会出错”，而是“错得多快”。

## 问题

社区里真实出现过的场景：让 Agent“清理临时文件”，glob 少写一个边界，把 dotfile 一并扫了进去；workspace 里有个指向外部的 symlink，相对路径一解析，删到了 workspace 之外；还有 cwd 和预期不一致，批量操作落在错误的目录。共同根因只有一个：**把模型输出当成了可信输入**。

## OpenClaw 的做法：四层防线

1. **会话级权限声明。** 每个 session 启动时绑定一份 capability profile，声明可用工具、可写路径前缀、网络开关。未声明的调用在网关层直接拒绝，模型连结果都拿不到，不会进入“试错循环”。

2. **路径守卫。** 所有文件工具参数先做规范化：解析 `..`、解析 symlink 到最终真实路径、再判断是否落在 workspace 根内。符号链接逃逸是最常见的绕过手段，守卫对解析后的 inode 所在位置做判断，而不是看参数字符串长什么样。

3. **危险操作降级。** 写/删类操作不直接生效。执行器把“计划”和“落盘”拆开：先校验，再对 workspace 打快照（默认 git-backed），删除类默认进回收目录而不是 unlink。出错时回滚，而不是道歉。

4. **命令白名单。** shell 插件不依赖黑名单——黑名单永远追不完。按 profile 放行命令模板，解析阶段就拦掉带 `rm` 或向 workspace 外重定向的请求。

## 踩坑点

- **TOCTOU**：校验和执行之间路径被替换。OpenClaw 内部用 openat 风格的相对 fd 操作缓解；如果你自己写插件，拿字符串路径再 open 一次，就绕过了守卫。
- **symlink 嵌套**：workspace 内的链接指向 `/etc`，必须解析到最终位置再判断，只看一层不够。
- **平台差异**：Windows 的 `\` 分隔符和大小写不敏感文件系统，测试别只跑 Linux。
- **profile 太宽**：图省事把整个 HOME 设成可写，等于没沙箱。
- **轻信 MCP server 自述**：server 声称“只读”不等于只读，权限以网关实际校验为准。

## 可复用建议

1. 最小权限**按会话发，不按 agent 发**，不同任务用不同 profile。
2. 有副作用的工具先 dry-run 输出计划，人确认后再放行。
3. 批量写操作前强制快照——回滚永远比道歉便宜。
4. 审计日志记“参数原文 + 规范化路径 + 决策结果”，排障时这一条最有用。
5. 用假 workspace 做破坏性测试：故意放 symlink、`.` 开头文件、带空格的文件名，看守卫拦不拦得住。

## 总结

Agent 不会“意识到”自己在删文件，所以安全必须来自结构，而不是模型自觉。OpenClaw 的思路可以浓缩成一句话：把每次工具调用当成不可信输入——声明、校验、降级、留痕。模型可以犯错，但错误被限制在快照可回滚的范围之内。这才是“为什么不会误删”的完整答案。
