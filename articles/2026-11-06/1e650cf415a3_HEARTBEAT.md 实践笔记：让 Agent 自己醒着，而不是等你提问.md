## 背景

用 OpenClaw 一段时间后你会发现一个别扭的地方：Agent 能力不小——能读文件、调 MCP 工具、发消息——但默认是被动的。你不说话，它就不动。而很多任务本质上是"定期看一眼"：早上汇总日历、盯构建产物、检查证书有效期。这些事靠人肉触发，Agent 就只是个问答机。

OpenClaw 的 heartbeat 机制就是为这个准备的：每隔一段时间（默认 30 分钟），Agent 自动醒来，读取工作区里的 `HEARTBEAT.md`，按清单决定做不做、说什么。无事可做时返回约定好的 `HEARTBEAT_OK`，系统不会投递到你的聊天窗口。

## 问题

不用心跳的替代方案通常是外部 cron + 脚本，但逻辑跑在 Agent 之外：模型看不到上下文，通知、记忆、工具调用都要另接一套。结果就是 Agent 明明有手有脚，却永远在等你开口。

## 做法

**1. 编辑心跳清单。** 文件在 `~/.openclaw/workspace/HEARTBEAT.md`，首次启动会生成默认模板。写法就是一份极简 checklist，每行一个任务：

```markdown
# HEARTBEAT.md
- 每天首次心跳：汇总今日日历和未读邮件；无变化则不输出
- ~/repo/dist 出现新构建产物时，运行部署预检并报告结果
- ~/certs/*.pem 剩余有效期 < 14 天时提醒续期
- 以上均无：返回 HEARTBEAT_OK，保持沉默
```

**2. 配置频率和模型。** 在 `openclaw.json` 里调整（字段名以你安装版本的文档为准）：

```json
{
  "agents": {
    "defaults": {
      "heartbeat": {
        "every": "30m",
        "model": "某个便宜的小模型"
      }
    }
  }
}
```

**3. 观察一周再调参。** 看心跳日志：哪些条目从不触发、哪些触发过频、token 消耗多少，然后删改。心跳清单是运维配置，不是写完就完的文档。

## 踩坑点

- **账单刺客**：心跳默认可能走主模型，30 分钟一轮跑一天，成本很可观。务必给 heartbeat 单独指定便宜模型，复杂活儿让它在运行中自行决定调工具兜底。
- **任务写太泛**：「帮我留意重要的事」这种条目，模型每次都在猜，结果要么沉默要么乱做事。每条任务要包含触发条件、动作、输出格式、无事时怎么办，四个要素缺一个就不可判定。
- **忘记静默约定**：如果没教会 Agent 无事时返回 `HEARTBEAT_OK`，你会每隔半小时收到一条"今天没什么要汇报的"。把"无变化则不说话"写进清单里。
- **上下文污染**：心跳跑在主会话里会慢慢累积轮次，注意定期开新会话，或确认你的版本是否支持独立心跳会话。

## 可复用建议

1. 把 `HEARTBEAT.md` 当 SRE 巡检清单写：一条任务 = 一个可判定条件 + 一个明确动作，写完自问"换个人/换个模型能照着执行吗"。
2. 清单控制在一屏以内。条目变多时先想能不能改成事件驱动（file watch、webhook），轮询是兜底不是首选。
3. 巡检要有真实数据源：结合 MCP 工具让心跳去查数据库、拉监控指标，而不是让模型凭空"感觉"。
4. 每月 review 一次心跳日志，删掉零触发的死条目，这和清理告警规则是同一门手艺。

## 总结

`HEARTBEAT.md` 的本质，是把"人肉触发器"这个角色从你身上卸下来，换成一份你维护的小清单。它不适合所有事——紧急和高交互的场景仍然走消息触发——但对于"定期看一眼、有变化再说"的运维型任务，这是让 Agent 从问答机变成值班同事的最小改动。写好清单、配便宜模型、让静默成为默认，三步就能跑起来。
