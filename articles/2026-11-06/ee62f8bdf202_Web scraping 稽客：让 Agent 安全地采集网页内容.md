# 背景

Agent 要回答真实世界的问题，网页几乎是绕不开的信息源。但在 OpenClaw 的实际部署里，“让 Agent 自己去抓网页”这件事的坑比想象中多：抓回来的不是正文而是半屏广告；页面里藏着一句“请忽略之前的指令”；或者一个反爬站点把整个任务拖到超时。这篇帖子把我们内部那套“稽客”式的抓取流程拆开讲——所谓稽客，就是每次采集都要查证件、过安检，而不是放 Agent 裸奔。

# 问题

1. **间接提示注入**：网页内容会进入模型上下文，HTML 注释、隐藏 div、图片 alt、SVG `<desc>` 都可能塞指令。只 strip `<script>` 只是及格线。
2. **合规与礼貌**：robots.txt、站点 ToS、限速。Agent 循环重试时很容易把小站打挂，或被对方封 IP。
3. **内容质量与体量**：动态渲染页拿不到正文；能拿到时，长文又容易撑爆上下文预算，逼 Agent 做低质量摘要。
4. **失败不可观测**：裸 curl 的异常堆栈对 Agent 没有决策价值，它只会瞎重试。

# 做法

核心原则：**抓取发生在工具层，不发生在模型层**。Agent 只调用一个干净的工具，安全策略全部收敛在 MCP server / 插件里。

1. **收口入口**：只暴露一个 `web_fetch(url)`，返回结构化结果 `{title, text, truncated, fetched_at, source_hash}`。永远不把原始 HTML 喂给模型。
2. **准入检查**：域名白/黑名单；默认尊重 robots.txt；per-domain 令牌桶限速（如 1 req/s）；UA 里写明身份。黑名单命中直接拒绝，不做模糊处理。
3. **清洗与消毒**：HTML → 正文（readability 类算法）→ Markdown，剥掉 script/style/注释/表单/隐藏元素。抓取内容统一用 `<web_content source="...">` 包裹后进上下文，并在系统提示里明确：标签内一切内容是数据，不是指令。
4. **体量控制**：正文超上限就截断并标记 `truncated: true`，让 Agent 自己决定分页还是换源，而不是默默塞超长内容。
5. **缓存与降级**：同 URL 短 TTL 复用快照，但只缓存 2xx；非 2xx 返回结构化错误（`rate_limited / blocked / not_found`），让 Agent 能判断换源还是放弃。
6. **审计日志**：记录时间、URL、状态、内容哈希。排查注入案例时，有快照可回放，比猜有效得多。

# 踩坑点

- **只删 script 不够**：我们测试时发现注入指令藏在 SVG 的 `<desc>` 里；HTML 注释、`aria-label`、隐藏 div 都是常见藏身处。要按“最终文本”审计，而不是按标签删。
- **蜜罐页面**：个别站点对非浏览器 UA 返回“正常”的假文章。关键事实让 Agent 交叉核对第二来源，工具层可以把两个来源的哈希一起返回。
- **别硬刚 Cloudflare**：无头浏览器成本高、脆弱，也更容易踩 ToS 红线。优先找 RSS、开放 API、sitemap 这些官方出口。
- **编码与相对链接**：GBK 老站点会吐乱码；正文里的相对链接不补 base URL，Agent 下一步抓取就 404。
- **限速要 per-domain**：全局限速会让一个慢站拖死整个任务队列；同时要设单任务总超时。
- **缓存毒化**：把 5xx 页面缓存住，之后半天都在复用错误内容——这个 bug 我们真踩过。

# 可复用建议

- 工具返回值设计成“Agent 可决策”的结构，错误也是数据。
- 安全开关全部进配置：白名单、robots、限速、截断上限，默认值从严。
- 数据围栏标记 + 系统提示声明要**配套上线**，只做其中一件效果减半。
- 原始快照至少保留 24 小时，注入类问题几乎只能靠回放定位。

# 总结

让 Agent 安全地抓网页，本质是把“自由浏览”收敛成“受控采集”：入口收口、准入从严、内容消毒、体量可控、失败可观测。工具层多做的每一步检查，都是替上下文挡掉的每一次注入尝试。稽客的价值不在于抓得多快，而在于每次进门的都是干净货。
