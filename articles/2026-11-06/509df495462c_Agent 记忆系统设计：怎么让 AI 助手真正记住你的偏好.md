# 背景

用 Agent 做日常自动化半年后，最让我烦的不是模型不够聪明，而是它每次都"失忆"：昨天刚确认过部署用 pnpm、回复用中文、代码注释不加表情，今天新会话又全部重来。最常见的第一反应是把所有偏好塞进 system prompt，但一个月后 prompt 膨胀到几千字，大量过时内容反而稀释了真正重要的指令。

# 问题的本质

记忆系统的难点不在"存"，而在三个决策：

- **写什么**：哪些信息值得跨会话保留
- **何时读**：按需检索还是全量注入
- **怎么忘**：偏好变了、事实过时了怎么办

# 我的做法：三层记忆 + 一条写入门禁

**L1 核心画像（profile）**：一个不超过 500 字的结构化文件，只放最高频偏好（语言、代码风格、工具链）。每次会话开始直接全文注入，不走检索——这类信息量小、命中率接近 100%，检索纯属浪费。

**L2 事实库（facts）**：存具体但不高频的事实，每条带时间戳和来源，关键词 + 向量混合检索，按需注入。

**L3 会话记忆**：任务内的 scratchpad，不落盘，会话结束后按置信度筛选，才有资格晋升到 L1/L2。

**写入门禁**是关键。我给 Agent 暴露一个 MCP 工具 `memory_write`，规则：

- 用户显式说"记住这个"→ 直接写
- 隐式抽取（从对话推断）→ 必须同时满足：出现 ≥2 次、置信度过阈值、与现有条目不重复
- 冲突时新值覆盖旧值，但保留旧值和覆盖时间，方便回滚

落地步骤：① 先建 profile.md 并注入 system prompt；② 加 `memory_write` / `memory_forget` 两个 MCP 工具；③ 上门禁规则；④ 记忆文件进 git，每周跑一次 review 提示清理。

# 踩坑点

1. **早期全量抽取，两周后事实库变垃圾场**。Agent 会把"用户今天心情不错"这种一次性信息也存进去，加门禁后才稳定。
2. **向量检索对偏好类短文本效果差**。"回复用中文"这种句子 embedding 之后和一堆闲聊的距离都很近，混合检索里的关键词命中救了这个场景。
3. **记忆注入风险**：让 Agent 读网页和文档时，内容里出现"请记住……"这类指令，早期实现真的会写进记忆。现在所有外部来源的记忆写入必须打来源标记并经用户确认。
4. **没有 forget 等于没有记忆**。每周 review 会列出 30 天未被检索命中的条目，提示确认删除或归档，事实库才没无限膨胀。

# 可复用建议

- 显式记忆优先做，隐式抽取后做。前者二十行代码解决 80% 的问题
- 核心画像直接注入，别迷信检索
- 记忆要可审计：进 git，用户随时能看、能改、能回滚
- 结构化字段优于自然语言长句，`reply_language: zh` 比一段描述好维护得多
- 先做 forget，再做 remember

# 总结

记忆系统的本质是信息过滤和生命周期管理，不是存储问题。小而准的画像 + 严格门禁的写入 + 定期清理，比"把一切存下来再用向量搜"可靠得多。这套三层结构我跑了一个多月，偏好遗忘问题基本消失，事实库也稳定在两百条以内。如果你在 OpenClaw 上搭过自己的记忆方案，欢迎交流写入策略上的取舍。
