# Agent 记忆系统设计：怎么让 AI 助手真正记住你的偏好

## 背景

大模型本身是无状态的。每次会话开始，Agent 都是“失忆”的——你得重新交代一遍：项目用什么包管理器、代码风格偏好、时区、部署流程。OpenClaw 的 Agent 场景里，很多人接完 MCP 工具后第一件事就是想让助手“记住我”，但大多数实现停在“把聊天记录塞进向量库”，效果往往一言难尽。

## 问题

三种常见失败模式：

1. **全量塞 prompt**：把历史对话拼进上下文，token 爆炸，噪声还会稀释真正关键的偏好。
2. **只存向量**：语义检索能召回“大概相关”的内容，但“用户用 pnpm 不用 npm”这类精确事实靠相似度召回既不稳定，还会和当前指令打架。
3. **只加不改**：记忆只追加不更新，用户早换了工具链，Agent 还按三个月前的偏好干活，而且你无法审计它到底记住了什么。

## 做法

我们踩过坑之后，收敛成三层结构 + 受控读写：

**1. 分层存储**

- **核心画像**：结构化小文件，控制在 300 token 以内，每次会话启动直接注入 system prompt。只放高频、稳定的事实：语言偏好、代码风格、时区、禁忌操作。
- **情景记忆**：会话结束后由模型抽取候选事实，写入本地向量库（sqlite-vec 就够用），带 topic 标签和时间戳，按需检索 top-3。
- **工作记忆**：会话内 scratchpad，会话结束即丢弃，不落盘。

**2. 受控写路径**

不要让 Agent 隐式“随手记”。提供显式的 `save_memory(type, content, tags)` 工具加会话结束自动抽取，写入前过两道闸门：相似度去重（阈值 0.85 以上视为重复）、重要性打分（寒暄和琐碎过程直接丢弃）。

**3. 可更新的读路径**

画像用“键值覆盖”更新：用户说“改用 npm 了”，就更新对应字段并记录 `updated_at`，而不是追加一条新记录，冲突时取最新。同时提供 `forget(key)` 工具——能忘和能记一样重要。

**4. 人类可审计**

画像落成纯文本 `MEMORY.md`，进版本控制，用户随时可以打开看、手动改。这一条比任何算法都重要。

## 踩坑点

- **记忆污染**：早期不设写入门槛，一周后库里全是“用户今天问了个好”。重要性门槛必须有。
- **注入风险**：记忆内容本质是不可信数据，拼进 prompt 时要包裹并标注来源，防止历史内容里藏指令。
- **陈旧记忆压过当前指令**：检索结果与当轮指令冲突时，永远让当前指令优先，检索分数乘一个时间衰减因子。
- **抽取过猛**：自动抽取时模型倾向于什么都记。抽取 prompt 里要给明确的“不记”清单：临时调试信息、一次性路径、未确认的猜测。

## 可复用建议

- 先做最小闭环：一个 `MEMORY.md` + 一个检索工具，跑两周再考虑向量库。
- 区分三类记忆：关于用户的事实 / 项目约定 / 一次性上下文，存储和生命周期都不同。
- 用“重放测试”验证记忆质量：同一个任务隔一周跑两遍，看第二遍是否减少了重复交代。
- 写操作留日志，让用户能看到 Agent 记了什么、什么时候记的。

## 总结

Agent 记忆不是“接个向量库”就完事，核心是四个工程问题：**写入要有门槛、存储要分层、更新要有冲突策略、内容要可审计**。从一个人能看懂的记忆文件开始，比从复杂的检索管线开始，更容易活下来。
