## 背景

用 OpenClaw 这类常驻 Agent 一段时间后，最大的噪音往往不是模型不够聪明，而是它每次都把你当陌生人：重新解释一遍操作系统、主力语言、"给可运行代码别给伪代码"，回答永远是一种面向"平均水平用户"的通用腔。自动记忆（MEMORY.md 那类流水账）能存事实，但长期偏好和一次性任务混在一起，信噪比低。我的做法是把"用户是谁"单独抽成一个静态文件 USER.md，随会话注入。

## 问题

具体痛三个点：

1. **重复劳动**。每个新会话都要自报家门，时区、环境、风格偏好全靠现场口述。
2. **记忆污染**。Agent 自动写入的长期事实和短期事件混放，还会互相覆盖。
3. **行为不一致**。手机上问和桌面上问，语言、单位、时区都可能不一样。

## 做法

USER.md 本质上是一份随上下文注入的声明式配置，三步：

1. 在工作区根目录建 `USER.md`（如 `~/.openclaw/workspace/USER.md`），并在 AGENTS.md 里声明：USER.md 是用户长期画像，优先级高于自动记忆，冲突时以它为准。
2. 按固定分区写，高信号放前面：
   - **环境**：系统、时区、语言偏好
   - **偏好**：技术栈、代码风格、回复结构
   - **禁项**：明确不许 Agent 主动做的事
   - **长期目标**：一两行，写当前季度最重要的事
3. 像维护代码一样维护：进 git，每季度删一次过期条目。

模板控制在 40 行内：

```markdown
# USER
## 环境
- macOS + Linux 服务器，时区 Asia/Shanghai
## 偏好
- 中文回复，技术名词和命令保留英文
- 先结论后过程；代码要可直接运行，不要伪代码
## 禁项
- 不自动 git push，不改 CI 配置除非明确要求
- 删除、支付、外发类操作必须先确认
## 长期目标
- （一两行）
```

## 踩坑点

- **写成简历**。我第一版写了 120 行，上下文被稀释，Agent 反而抓错重点。压到 40 行内后明显变准。
- **双写冲突**。同一事实既在 USER.md 又在自动记忆里且不一致，Agent 会摇摆。定规则：长期事实只进 USER.md，记忆只做流水账，值得沉淀的条目手工搬。
- **敏感信息入库**。这个文件每次都会进模型上下文，API key、具体住址绝对不要写。
- **偏好写得绝对**。"永远不要用 Python"这种写法，真需要脚本时它会硬憋别的方案。写成"默认 X，除非 Y"。
- **共享实例**。同一个网关服务全家或团队时，单份 USER.md 就是错的，要按人拆分并在路由层区分。

## 可复用建议

- 当 config 文件写：声明式、短行、重要条目放最前——越靠前越不容易被长上下文稀释。
- 验证很简单：新会话直接问"你现在知道我哪些长期偏好"，复述不准就是注入没生效或文件太长。
- 禁项区收益最高，先写这个再写偏好。
- 定期"反向提炼"：翻一遍自动记忆，把重复出现三次以上的事实固化进 USER.md，然后删掉记忆里的对应条目。

## 总结

USER.md 解决的不是模型能力问题，而是上下文供给问题：把"你是谁"从反复口述变成一份版本化、可审计的静态配置。40 行以内、分区清晰、只放长期事实、绝不放敏感信息——做到这四点，Agent 的输出会从"通用助手腔"明显转向"了解你的同事"。成本半小时，值得。
