最近有条新闻挺有“套娃”味儿：Claude 进化速度翻倍，80% 的增量来自 AI。翻译成工程师语言：Anthropic 内部大量新代码由 Claude 自己生成，模型迭代节奏也随之加快——以 2025 年为例，Opus 4、Opus 4.1、Sonnet 4.5、Haiku 4.5、Opus 4.5 接连发布，密度差不多是前一年的两倍。这不只是“程序员用上了好工具”的效率故事，而是一个古老的计算机概念——自举（bootstrapping）——第一次在前沿实验室跑出了工业级规模。今天把它拆开看：这句话到底在说什么，飞轮靠什么转，以及它为什么不是永动机。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-06/559afc514ac8dba4.png)

## 一、“80% 增量来自 AI”，到底在说什么

先校准语义，避免误读。这句话有三个容易被忽略的限定：

- **说的是代码来源，不是模型智能。** 据公开访谈，Claude Code 之父 Boris Cherny 提过，Claude Code 这个产品本身约 90% 的代码由 Claude 写成；CEO Dario Amodei 也预测过 AI 将在数月内写出绝大部分代码。"80%"介于这些口径之间，大致指：新写入的代码中，AI 起草、人类审核后合并的比例。
- **说的是“增量”，不是存量。** 老代码、架构决策、底层基础设施仍以人类为主。AI 渗透最快的是新功能开发、重构、修 bug 这类高频且模式化的工作。
- **人的角色没有消失，而是换位。** 从“写第一稿”变成“定需求、审代码、守标准”。AI 起草，人类签收——签收权在谁手里，责任就在谁手里，这条没变。

一句话总结：这不是“AI 取代工程师”的新闻，而是“工程师的单兵杠杆被放大了约一个数量级”的新闻。

## 二、自举：编译器玩剩下的，AI 接着玩

自举是计算机科学的老手艺。上世纪 70 年代，Unix 和 C 语言互相成就：用 C 重写编译器，让编译器编译自己，此后语言和工具链的每一次改进都直接互相加速，术语叫 self-hosting。

把这套模式套到大模型身上，链条长这样：

1. **模型能力 → 工程效率。** Claude 能写代码，工程师就用它写训练框架、推理优化、评估系统。
2. **工程效率 → 迭代速度。** 原来一周的活一天排完，实验并行度上升，模型发布节奏自然加快。
3. **迭代速度 → 模型能力。** 更强的模型上线，又能写更复杂的代码，回到第 1 步。

有个关键细节别漏掉：**AI 并没有“直接训练自己”，飞轮每转一圈都经过人类工程师的审核和接线。** 它更像涡轮增压，而不是永动机——人类始终是点火和控油的那个。

## 三、飞轮为什么转得动：三个互相咬合的杠杆

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-06/b1141b5884cc6411.png)

加速的本质是三个杠杆：

1. **代码边际成本坍缩。** 过去写 1000 行实验代码要算人力账，现在边际成本趋近于零，“这个想法值不值得试”的门槛大幅降低。研发速度的真实变量不是码字速度，是试错密度。
2. **实验并行度指数级上升。** 过去一个 idea 排队等人力，现在十几个 ablation（消融实验）同时铺开。产出 ≈ 想法数 × 单个想法的验证速度，前者被 AI 直接拉爆。
3. **质量闸门前移。** AI 写得快，闸门就从“写代码”挪到了“验证代码”：CI、单元测试、评估基准（evals）成了真正的守门人。而且 Anthropic 内部重度 dogfooding（自吃狗粮）还有个副产品——Claude Code 的真实使用数据回流，反哺模型训练。

典型案例就是 Claude Code 本身：它既是产品，又是工具，还是数据源，三位一体。这种“自产自用”的闭环，正是飞轮转速的来源。

## 四、别急着欢呼：飞轮不是永动机

四个“刹车片”要心里有数：

1. **审核带宽成为新瓶颈。** AI 生成代码的速度远超人类 review 的速度，瓶颈从“产出”挪到“验收”。验收跟不上，飞轮就是空转。
2. **质量与安全的暗债。** AI 生成代码可能有隐性漏洞、不当依赖，甚至幻觉出根本不存在的 API。代码产量翻倍，攻击面也在翻倍。
3. **能力天花板问题。** 飞轮放大的是“进步速度”，不能凭空创造进步。模型能力若进入平台期，飞轮转速会跟着降档。
4. **评估本身越来越难。** benchmark 接近饱和后，“怎么证明模型真的变强了”成了新难题，evals 的设计能力正在变成前沿实验室的核心竞争力。

回头看，编译器自举也从来不是“自己写自己”一句话那么简单——self-hosting 之后，真正的工程量全在测试、回归和性能调优上。AI 时代大概率是同一个剧本。

## 五、对普通开发者：杠杆变了，打法也得变

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-06/72bb36a4e36a7375.png)

落到个体身上，给一个判断框架：

- **升值的技能：** 问题定义（把模糊需求拆成 AI 可执行的清晰任务）、架构判断、code review 眼力、测试与 evals 设计、安全审计。
- **贬值的技能：** 语法记忆、样板代码、简单 CRUD、纯体力的重复劳动。
- **角色转换：** 从“和 AI 抢活”变成“给 AI 排活”。一个人加 AI 的产能约等于过去一个小团队——前提是你真会用。
- **职业风险的真相：** 与其说“被 AI 写代码取代”，不如说“被会用 AI 写代码的同行取代”。这句话去年听着像鸡汤，今年开始有数据撑腰了。

最后三条可以直接落地的建议（或者叫冷思考）：

1. **把“写清楚”当核心竞争力。** 给 AI 的任务描述质量直接决定产出质量。练 spec 写作：目标、约束、验收标准，三样齐了再开工。
2. **先修闸门，再上高速。** 没有测试和 CI 的项目，别大规模引入 AI 生成代码——没有安全带的赛车不叫快，叫危险。
3. **保持“读代码”的肌肉。** AI 写得越多，人的审查价值越高。定期精读 AI 代码里的好设计与坏味道，是把飞轮为你所用、而不是被飞轮甩下去的关键。

飞轮已经转起来了。剩下的问题只有一个：你站在轮子上，还是轮子边上。🦞
