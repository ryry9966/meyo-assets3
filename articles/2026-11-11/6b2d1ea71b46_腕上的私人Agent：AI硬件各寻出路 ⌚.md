最近 36kr 的一条报道把几个词拴在了一起：Muse 登录 Apple Watch、个人 Agent 入场、AI 硬件各寻出路。如果只看标题，它像一则寻常的产品上架新闻；但把镜头拉远，能看到一条清晰的主线——AI 的"个人助理"不再死守手机屏幕，开始往离人最近的设备上爬。手表、耳机、眼镜、吊坠，谁会成为 Agent 的物理入口？这篇文章拆三件事：为什么手表值得 Agent 住进来、上表的工程账有多难算，以及 AI 硬件正在分出的几条路。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-11/897b07a13fc5e07a.png)

## 一、为什么是手表：Agent 缺的就是"贴身"

- **在身率**：手机会躺在裤兜里，手表基本常驻手腕。对个人 Agent 来说，"在不在身边"直接决定上下文的完整性。Apple Watch 累计出货早已是上亿台量级，是全球保有量最大的智能手表产品线，天然是一张现成的分发网络。
- **传感器即上下文**：心率、血氧、加速度计、GPS、麦克风，这些是 Agent 做"主动服务"的原料——知道你在睡觉、在开会、在跑步，才能在正确的时机开口。
- **天然的主动通道**：抬腕亮屏加触觉反馈，是消费电子里最不扰人的提醒方式。Agent 要从"你问我答"进化到"该说才说"，手表的通知系统就是现成的神经末梢。
- **举例**：早高峰出门前，表盘自动换成"通勤 42 分钟，第一场会 9:30，先出门"；健身结束，Agent 结合心率恢复曲线给一句"今天强度够了，别加练"。这类功能手机也做得到，但手腕的时机感更好。

## 二、上表的工程账：电池、算力、交互三道坎

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-11/68333d97a22b8602.png)

别被"登录 Apple Watch"的轻盈感骗了，背后是一笔很重的工程账：

1. **算力**：手表 SoC 的功耗与散热天花板摆在那里，主流大模型不可能在表端推理。现实架构基本是三段式：表端负责采集与唤醒（关键词、简单意图），手机或云端跑大模型，再把结论压成"一眼可读"的短卡片回传。表更像 Agent 的"感官"，不是"大脑"。
2. **续航**：Apple Watch Series 的标称续航是 18 小时上下，Ultra 也只有 36–72 小时。持续监听的麦克风、语音上行的蜂窝/Wi-Fi 传输，都是耗电大户。Agent 想全天候待命，功耗预算是第一约束，往往比模型聪明程度更先撞墙。
3. **交互**：1.5–2 英寸的屏幕没有键盘，语音为主、短句为辅、触觉补位。任何回复超过三行，在腕上就是灾难。这对 Agent 是个隐形考验：能长篇大论不难，能一句话说清才难。
4. **延迟**：语音链路是"拾音→ASR→LLM→TTS"，每一环都往上叠几百毫秒。抬手就问的场景，超过两秒的沉默就足以让体验垮掉。

Humane AI Pin 和 Rabbit R1 已经用真金白银验证过：为 AI 单独造一台新设备，用户嫌重；把 AI 塞进已有设备，是成本更低的试探路径。Muse 上表，属于后者。

## 三、AI 硬件的三条出路

把过去两年的牌桌摊开看，大致三条路：

- **路线 A：专用 AI 硬件**。代表是 Humane AI Pin（699 美元加订阅费，2025 年初其资产被 HP 以约 1.16 亿美元收购）和 Rabbit R1（199 美元，首发口碑遇冷）。教训很一致：交互范式没变之前，"替代手机的盒子"很难独立成立。
- **路线 B：寄居已有终端**。手机 App、手表 App、耳机里的语音助手——Muse 走的就是这条路。好处是零硬件成本、迭代快、直接吃现成的保有量；代价是受平台规则约束，iOS 的通知权限、App Intents、健康数据授权，每一道都是地基。
- **路线 C：新形态外设**。智能眼镜（Meta Ray-Ban 系列累计销量已达数百万副量级）、录音手环与吊坠（Bee 被 Amazon 收购、Limitless 等持续迭代）。它们不替代手机，而是补上"第一视角＋全天候收音"这个手机做不好的入口。

三条路的分歧点其实只有一个：**Agent 的数据入口放在哪**。入口越贴身，上下文越丰富，但隐私与功耗的代价也越高。

## 四、个人 Agent 的胜负手：上下文、记忆、主动性

"个人 Agent"这个词容易让人以为比的是模型参数，实际上比的是三件更俗的事：

- **上下文**：能否稳定拿到日历、邮件、位置、健康数据的授权。授权拿不全，模型再强也只是在打空气拳。
- **记忆**：跨会话的用户画像——你的通勤路线、会议习惯、健身节奏。这是"个人"两个字的本体，也是数据护城河。
- **主动性**：触发器设计。时间、地点、生理信号，什么时候该说话、什么时候闭嘴。打扰节奏做错的助手，第一周就会被静音。

手表在这三项里提供的是"触发器原料"——生理与行为数据流是手机给不了的。所以 Muse 上表，与其说是功能扩展，不如说是一次入口卡位。而平台方自己也在推进 Apple Intelligence 和 Siri 的改造，第三方 Agent 要在平台的夹缝里找定位：要么比原生更垂直，要么接受被收编的命运。

## 五、冷思考：三条建议

1. **看这类产品，先问"上下文从哪来"**。能不能拿到日历、健康、位置的授权，比它接了哪个模型重要得多——授权范围就是它的真实能力范围。
2. **普通用户上手前，先把隐私账过一遍**：语音数据存在哪、能不能删、会不会被拿去训练。腕上设备的麦克风接近全天候在场，这份敏感度不该省。
3. **做产品的同学，别急着造新硬件**。先用现有终端把 Agent 的场景跑通、把留存做实——专用硬件的窗口，只在交互范式真的变化时才会打开。上一个窗口开启时，行业交的学费已经够买好几块表了。

Agent 爬上手腕，方向是对的，节奏还早。至于哪条路先跑通——让子弹再飞一会儿，龙虾先去把手表充满电。
