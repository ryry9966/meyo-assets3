## 背景

用 OpenClaw 搭自动化的人，迟早会做同一件事：让 agent 定时往社区发东西——日报摘要、changelog、监控告警、抓取信息的聚合。跑起来的第一周很爽，第二周群里就有人抱怨“又在刷屏”。我这边几条跑了几个月的发布管道，踩过不少节奏上的坑，整理一下。

## 问题

默认的定时任务有几个典型特征，凑在一起就是一股“机器味”：

- cron 整点触发，每天 09:00:00 准时出现，秒级不差；
- 没有内容门控，今天没有值得发的东西也硬发一条“今日无更新”；
- 频率只增不减，告警、日报、聚合各自独立触发，高峰期连发三四条；
- 失败重试不设上限，接口一抖动就爆出重复帖。

注意一点：很多人第一反应是“把文案改得更像人写的”，这个方向偏了。社区反感的从来不是某个句式，而是节奏和密度。文笔再自然，一天五条整点推送照样被折叠。

## 做法

无论发帖这一步是走 MCP 工具、插件 webhook 还是直接调 API，节奏控制都应该独立成一层，而不是散落在各个触发点里。我的做法是把“采集”和“发布”拆成两个循环，中间加一道门控和一层节奏策略：

1. **值发布门控**。攒一批条目先打分：有效条目低于阈值（比如 3 条有意义的内容）就静默丢弃，不发“空日报”。这一条对观感的改善最大。
2. **基础间隔 + 抖动**。不用固定 cron，用“基准间隔 ± 随机偏移”调度，比如 6h ± 25min，秒数也随机。整点整分是机器人最明显的指纹。
3. **静默时段**。按社区所在时区设安静时间（我们定 23:00–08:30），非高优告警一律顺延。时区的坑后面单说。
4. **合并与去重**。小事件进队列按 digest 发布；内容做哈希，48h 窗口内重复的直接丢；发布带幂等键，重试不会产生第二条。
5. **熔断**。连续若干条零互动、或收到管理员任何提醒，自动暂停并转人工审核。宁可少发，不能惹人烦。
6. **标注身份**。按社区规则在帖尾挂自动化标识和联系人。这条不是可选项——“不像机器人”的意思是不像刷屏的机器人，不是伪装成人类。

一份够用的配置大概长这样：

```yaml
publish:
  base_interval: 6h
  jitter: 25m
  quiet_hours: "23:00-08:30"   # 社区所在时区
  daily_cap: 4
  min_items: 3                 # 低于则静默跳过
  dedup_window: 48h
  breaker: 连续3条零互动 → 暂停转人工
```

## 踩坑点

- **时区**：服务器是 UTC，社区在国内，静默时段一开始差了八小时，凌晨五点连发三天才被发现。调度一律用社区时区算。
- **心跳和发布耦合**：最初 5 分钟一次的 agent 心跳顺手就触发发帖判断，等于没有节奏控制。采集循环随便跑，发布必须独立节流。
- **只调文案不调频率**：改了三版措辞观感毫无变化，把 daily_cap 从 8 降到 4，当天就没人抱怨了。
- **抖动当万能药**：只加随机间隔不做门控，等于把规律垃圾变成不规律垃圾。

## 可复用建议

- 先影子运行两周：发布模块 dry-run，只写日志不真发，人工过一遍“本应发出”的内容，再放开。
- 把每天实际发布时间记下来，和群活跃时段对齐，比任何“拟人文案”都管用。
- 三个数字记住就够：daily_cap、min_items、quiet_hours，其他都是锦上添花。

## 总结

所谓“不像机器人”，本质是节制：该发的少而准，不该发的忍住不发，出问题能自己停下来。节奏控制是发布管道的工程问题，不是文案问题。先把门控、抖动、静默时段这三件事做对，再谈别的——并且永远亮明自动化身份，这是这类自动化的底线。
