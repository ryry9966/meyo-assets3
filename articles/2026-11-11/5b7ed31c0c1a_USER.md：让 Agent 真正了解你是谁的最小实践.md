## 背景

用 OpenClaw 这类常驻 Agent 一段时间后，你会发现一个反复出现的摩擦：每开一个新会话，Agent 对你一无所知。它不知道你主用 TypeScript 还是 Python，不知道你偏好简短直接的回复，也不知道你的服务器在哪个时区。自动记忆功能能缓解一部分，但它是黑盒——记了什么、何时记的、怎么被检索，很难审计，甚至会记错。

USER.md 是社区里逐渐形成的约定：在工作区放一个纯文本文件，用声明式的方式告诉 Agent「我是谁、我怎么工作」。会话启动时注入上下文，你拥有全部编辑权。

## 问题

本质是上下文供给的问题：

1. **重复自我介绍**：同样的偏好，一周纠正 Agent 三次；
2. **记忆不可控**：自动抓取的内容不一定是你想强调的，错误记忆还会被反复引用；
3. **多端不一致**：手机上聊到一半的约定，回到桌面端 Agent 又问一遍。

## 做法

我的 USER.md 目前 40 行左右，放在 `~/.openclaw/workspace/` 下，分五段：基本情况（时区、作息约束）、技术栈（语言、版本、部署形态）、沟通偏好（先结论后细节、方案给取舍）、在进行的事（只写稳定事实）、禁止事项（红线类指令）。

```markdown
# USER.md
## 基本情况
- 时区 UTC+8；深夜消息只标记，不执行
## 技术栈
- 主力 TypeScript / Node 22；全部自部署，无 Serverless
## 沟通偏好
- 默认中文；先结论后细节；方案要给取舍，不只给一个选项
## 禁止事项
- 未经确认不执行删除类命令、不重启生产服务
```

两个提效技巧：一是**让 Agent 自己起草**——对它说「根据我们最近的对话，起草一份 USER.md」，你只做删改，比从零写快得多；二是**纳入 git**，每次改动可回溯，也方便跨设备同步。

## 踩坑点

- **写太长**。早期我写了 200 多行，Agent 开始忽略后半段，而且每次会话都在烧 token。压缩到 50 行内后遵循度明显变好。
- **放易变信息**。任务清单、临时安排写进去，三天就过期——过期信息比没有信息更糟，Agent 会拿旧事实当依据。易变内容放日历或项目文件。
- **指令冲突**。写了「始终用中文回复」，某次让它翻译英文文档就打架了。偏好写成「默认……除非我另有要求」。
- **敏感信息**。API key、详细住址不要写，文件可能随工作区被同步、被插件读取。

## 可复用建议

- **判断标准**：同一件事对 Agent 说过两次以上，就值得进 USER.md。
- **分层管理**：USER.md 管「你是谁」（稳定），项目级 NOTES.md 管「在做什么」（中期），会话内上下文管「当前任务」（易变）。
- **每月回顾**一次，删掉不再成立的内容；给段落标更新日期，方便判断新鲜度。
- 团队场景可沉淀一份脱敏的 TEAM.md，统一编码规范和回复口径。

## 总结

USER.md 的价值不在「记忆」，而在「声明」：用几十行文本，把隐性的个人上下文显式化、可审计、可版本化。它不智能，但可靠——这恰恰是工程上最该先做的一步。从 20 行写起，等你发现自己又在向 Agent 解释自己时，再往里加一行。
