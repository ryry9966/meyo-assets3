## 背景

我们在社区里跑了一个 OpenClaw agent，负责三类自动化发帖：每周精选摘要、版本发布说明、常见问题汇总。链路很标准：定时触发 → agent 拉数据源 → LLM 整理 → 通过 MCP 插件调论坛 API 发布。

第一版上线两周就收到反馈："这号一看就是机器人。"复盘下来，问题不在内容质量，而在节奏：每天 10:00:00 整点发帖、间隔恒定 24 小时、句式模板雷同、被吐槽后照发不误。行为模式太规整，反而成了最大的破绽。

## 问题：机器感从哪来

拆下来主要是五点：

1. 时间戳精确到秒，永远整点
2. 频率恒定，没有工作日/周末差异
3. 模板句式固定，换数据也像一个模子
4. 出错重试导致同一内容连发
5. 对社区反馈零响应，被屏蔽了还继续发

## 做法

我们把节奏控制做成独立的调度层，发帖前必须过五道闸：

**1. 时间窗 + 抖动。** 废弃整点 cron，改成"目标窗口内随机落点"，比如工作日 09:40–10:30，周末干脆不发。抖动别用均匀分布——均匀随机仍然可预测，间隔的统计特征太规整，换成偏态分布后观感明显改善。

**2. 频率预算。** 每个渠道设周配额（论坛 ≤3、群 ≤2），并做全局共享预算。这是后来补的：最初各渠道独立限额，叠加起来一天五条，直接被当 spam。

**3. 冷却与去重。** 同话题 72 小时冷却；发布前对最近 N 条历史帖算 embedding 相似度，阈值以上直接打回。踩过坑：阈值太松时重复内容漏过去了，太紧又把两条角度不同但用词接近的帖子误杀，最后改成"相似度超标 + 人工确认"双条件。

**4. 质量门槛分级。** 低风险类（FAQ 汇总）直接发；高风险类（公告、口径敏感内容）先进草稿队列，人工点确认才发。LLM 的口径问题没法全自动兜底，这一步不能省。

**5. 反馈回路。** 监听屏蔽、举报、负面回复，单日负面信号超阈值自动暂停并通知维护者。API 报错走指数退避，重试前先查重，杜绝连发。

还有一条容易被忽略：**明示机器人身份**。签名写清楚"由 agent 自动整理，有问题联系维护者"。实测下来，透明反而降低了反感——大家烦的不是自动化，是不受控的自动化。

## 踩坑点

- 重试逻辑没做幂等，一次网络抖动连发三条，比不抖动更像机器人
- 模板句式没轮换，时间随机了但开头永远是同一句，一眼假
- 忘了设安静时段，凌晨三点发摘要，被截图挂出来
- 节奏参数写死在 agent prompt 里，改一次频率要重新调试整个链路

## 可复用建议

- 调度层和生成层分开，节奏参数全部配置化
- 先用"草稿队列 + 人工确认"跑两周，积累负面信号基线，再逐步放开自动发布
- 定一条硬规则：任何自动化动作，必须能在一分钟内一键停止
- 定期抽查发帖历史的间隔分布——人眼能看出的规律，别指望用户发现不了

## 总结

节奏控制本质上是给自动化加"礼貌约束"：少发、慎发、可停、可查。目标不是把机器人伪装成人，而是让它像人类运营者一样克制。这套调整上线后，我们的 agent 稳定运行三个月，零投诉。一句话总结：自动化的体感质量，来自约束的密度，不来自生成能力。
