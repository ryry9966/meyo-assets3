## 背景

社区里不少人用 OpenClaw agent 加 cron 做自动发帖：每日精选、周报、工具速递。管线本身不难，难的是"像人"。我最早的每日摘要固定每天 9:00 发，模板固定，跑了三周就有熟人私信问"你那个是脚本吧"。更尴尬的是有一条凌晨 3 点整点发出去，观感直接崩了。

## 问题

机械节奏有三个可量化的特征：

1. 发帖间隔方差为零或接近零（精确 24h）；
2. 内容骨架固定，只有变量替换；
3. 完全不看频道上下文——冷场时发、和真人讨论撞车时也发。

这不一定是"作弊"，但会让读者下意识给内容降权，也更容易触发平台频控。

## 做法：把节奏做成独立的调度层

我在内容管线和发布 API 之间加了一层 scheduler shim，核心四件事：

**1. 活动加权的抖动（jitter）**
发布时间不写死，在目标窗口（如 9:00–11:30）内按历史活跃分布加权采样，而不是均匀随机：

```python
slot = weighted_sample(heat_map, window="09:00-11:30")
fire_at = today + slot + tiny_jitter(minutes=5)
```

**2. 频率硬约束**
每日上限、最小间隔、连续发布冷却。这些是硬规则，优先级高于任何排程，专防 agent 落后之后一口气补发五条的"突发脉冲"。

**3. 发布前上下文检查**
发之前拉一次频道状态：最近 N 条消息有没有同主题讨论？过去 24h 有没有语义相近的内容？命中就 defer 或合并进下一次 digest，决策写日志。

**4. 内容层去模式化**
模板池至少三套轮换，开头句、长度、列表项数量允许波动。注意：只抖时间、内容固定，依然像机器人，两件事必须一起做。

## 踩坑点

- **均匀随机比固定时间更假**。凌晨 3:47 发"早安资讯"比每天 9:00 准时更刺眼。抖动要在"像人的分布"里抖，不是纯随机。
- **重试导致双发**。网络超时后重试，同一内容发两遍。给每次发布加 idempotency key，服务端去重。
- **时区**。调度器跑 UTC，社区按本地时间活跃，窗口判断错了整个方案白搭。配置里显式声明时区并补测试。
- **去重靠字符串比对会漏**。生成内容每次措辞不同，应按实体/关键词集合做相似度，或对抽取的要点列表做 hash。
- **把 defer 决策埋掉**。跳过的帖子不留痕，你永远不知道 agent 欠了多少债。所有 defer/skip 落日志，定期人工过一遍。

## 可复用建议

- 节奏配置与内容管线分离：一份 `cadence.yaml`（窗口、上限、冷却、去重阈值），换社区只改配置。
- 先灰度：新节奏在低风险频道跑两周，看间隔分布直方图，方差拉起来、没有脉冲再推广。
- 高风险频道留人工确认队列：agent 出草稿，人点发送。半自动不丢人。
- 判断别靠感觉，算两个指标：发帖间隔的变异系数（CV）衡量节奏；"发布后 1 小时内人工补发同主题"的次数衡量撞车。

## 总结

节奏控制不是伪装术，而是让自动化尊重社区作息的工程问题。加权抖动、硬性频率约束、发布前上下文检查、内容去模式化——四件事都不复杂，但应该做成发布链路上的固定一层，而不是散落在脚本里。目标也不是"看起来是人"，而是一个行为可预期、不打扰讨论、内容稳定的 bot。这种 bot，大家其实是欢迎的。
