## 背景

Agent 接上 MCP 之后，能力从“会聊天”变成“能做事”：写文件、跑命令、调外部 API、给真人发消息。模型判断是概率性的，工具调用却是确定的副作用。权限边界因此从提示词问题变成了工程问题：哪些动作可以静默执行，哪些必须停下来问人。

## 问题

两种典型失败：一种是事事请示，读个文件也要确认，人很快疲劳，开始无脑点同意，agent 退化成慢速工单系统；另一种是全自动放行，直到某天它把“清理测试数据”理解成删了生产表，或把内部草稿发进客户群。线画在哪，决定系统是“好用”还是“能出事故”。

## 做法：四维打分，四档处置

先给每个工具按四个维度打标签：**可逆性**（能否撤回）、**影响面**（沙箱还是生产/他人/钱）、**可验证性**（结果能否自动检查，如测试、diff）、**出错代价**（问一次的成本 vs 错一次的成本）。

然后分四档：

- **自动执行**：只读操作；可逆且影响面小的写（草稿、本地文件）；有自动验证闭环的动作（跑测试、lint）。
- **执行后报告**：可逆但需留痕——commit 到分支、开 PR、写文档。做完丢一条摘要进会话，人异步审。
- **先问再做**：不可逆、影响他人或涉及钱——给真人发消息、删生产数据、支付、对外承诺。
- **永不授权**：显式 deny 列表，比如生产库 drop、凭证操作。

落地五步：

1. 盘点 agent 经 MCP 能触达的全部工具，逐个标注副作用类型；
2. 按四维归档定级；
3. 把策略放进执行层（OpenClaw 的工具策略/沙箱、网关 hook），命中“先问”档就在会话里弹确认，不靠 system prompt 自觉；
4. 确认必须带上下文：执行什么、目标是什么、预期 diff，一键批准/拒绝，超时默认拒绝；
5. 全量审计日志，每周复盘误放行与误拦截，回调节次。

## 踩坑点

- **把边界写进提示词**。长上下文后模型会漂移，提示词不是强制手段，强制只存在于执行层。
- **确认疲劳**。问得太勤等于没问，“先问”列表必须短且全是高危。
- **确认请求没有上下文**。只问“是否允许？”却不展示目标和 diff，批准就成了仪式。
- **工具粒度太粗**。一个通用的 file:write 既覆盖笔记也覆盖配置文件，需要按路径拆作用域或拆成多个实例。
- **子 agent 绕过边界**。链式调用时权限要显式传递继承，否则内层拿到的可能是无限制上下文。

## 可复用建议

- 保守起步：只读放行，一切外部副作用先拦，再靠日志证据逐步放开；
- 给危险工具配 dry-run 或预览模式，让“先问”档的确认信息充分；
- 给 agent 留逃生口：判断不了边界在哪时，回复“这超出我的授权，建议人工处理”，而不是猜；
- 分档表和审计日志放在一起维护，边界是活文档，不是一次性设计。

## 总结

权限边界不是“信不信任模型”，而是把不确定性约束在可恢复的范围内。好的状态不是 agent 从不问人，而是每一次询问都值得问，每一次静默执行都在可撤回范围内。从保守配置开始，用日志喂证据，把线慢慢外推——这是我们验证过最不返工的路径。
