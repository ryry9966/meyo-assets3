## 背景

大部分 Agent 的交互模型是“你问它答”：不发消息，它就不存在。但一个真正常驻的助理应该有自己的节奏——早上主动给你日程摘要、磁盘快满时提前报警、周五下午把本周事务整理成周报。这些事共同的特点是：**没有一个“提问”动作去触发它们**。

OpenClaw 为此内置了心跳机制：Agent 按固定间隔被自动唤醒一次（默认约 30 分钟，可在配置里调整），唤醒后读取工作区根目录的 `HEARTBEAT.md`，根据内容自行判断要不要做事、要不要说话。这个文件，就是你的 Agent 从“应答机”变成“值班员”的开关。

## 问题：被动模式下的三个盲区

1. **时效性任务靠人记**。你不问，它就不汇报日程和待办。
2. **巡检类工作没有触发点**。磁盘、邮件、订阅源这类检查，天然缺少“用户发起”这个环节。
3. **上下文断裂**。每次都由你重新发起，Agent 没有自己的巡值节奏和记录。

## 怎么做

**1. 建文件。** 在 Agent 工作区根目录创建 `HEARTBEAT.md`。文件不存在时心跳基本是空转，写了才开始生效。

**2. 第一条写“沉默条款”。** 明确告诉它：没有异常或到期任务时直接保持沉默（按约定回复 `HEARTBEAT_OK` 跳过），禁止输出“一切正常”之类的客套汇报。没有这一条，你会在两小时内被刷屏劝退。

**3. 分三层写检查项。** 控制在 10–20 行内，参考结构：

```markdown
# HEARTBEAT.md

总则：无事保持沉默（回复 HEARTBEAT_OK），不要输出"一切正常"。

## 每次心跳
- 检查 todo.md 是否有到期未完成任务，有则提醒

## 时间触发
- 每天 08:30（Asia/Shanghai）：汇总今日日程 + 昨日未完成项，发私聊
- 每周五 17:00：整理本周处理记录，写入 weekly.md

## 条件触发
- 磁盘占用 > 85%：报警并列出可清理目录
- 出现标记为重要的未读邮件：只发标题与发件人摘要
```

**4. 写清输出动作和时区。** 指定结果写到哪个文件、发到哪个会话；时间条件注明时区，别让模型自己猜。

**5. 短间隔测试，再调回。** 测试期把心跳间隔压到 5 分钟验证行为，确认无误后改回 30 分钟或更长。

## 踩坑点

- **把 HEARTBEAT.md 写成任务大杂烩**。每次心跳，整个文件都会进入上下文。30 条检查项意味着每 30 分钟烧一遍 token，而且注意力被稀释，反而漏事。
- **漏了沉默条款**。Agent 每轮都礼貌回复“检查过了，没问题”，心跳就成了骚扰源。
- **时间条件不写时区**。“早上 8 点”可能在半夜触发。
- **重活塞进心跳**。心跳是巡检不是批处理。耗时任务让它先写入队列文件，由你确认后再执行。
- **心跳输出进了群聊**。把心跳投递目标配到独立会话，群聊侧建议直接关掉，避免刷屏。
- **忽略成本**。哪怕沉默，每次心跳也是一次模型调用。间隔 5 分钟和 30 分钟，月成本差一个量级。

## 可复用建议

- 把 HEARTBEAT.md 当**值班手册**而不是任务列表：写检查项、阈值、输出渠道，不写一次性任务。
- 让 Agent 维护一个 `heartbeat-log.md`，每次动作追加一行，方便审计和调频率。
- 与 AGENTS.md 分工：AGENTS.md 管“怎么做事”（规范与偏好），HEARTBEAT.md 管“什么时候主动做事”。
- 定期清理。心跳项和真实需求会漂移，每季度删掉不再需要的检查项。

## 总结

HEARTBEAT.md 的本质，是把一份“值班表”外化成模型可读的文件：调度靠 OpenClaw 的心跳机制，判断靠文件里的规则，克制靠你自己写下的沉默条款。搭建成本极低——一个十几行的 markdown 文件——但它决定了你的 Agent 是个等你提问的应答机，还是会自己巡值的常驻助理。建议从最小的一个心跳项开始（比如每天早上一条日程摘要），跑一周，再逐步加。
