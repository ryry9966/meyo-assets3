## 背景

大多数助手默认是“被动应答”：你不说话，它不动。真正的价值缺口在主动侧——晨间简报、异常提醒、待办跟进。OpenClaw 这类常驻 agent 天然具备常驻运行、多渠道触达、MCP 工具调用的基础，缺的不是能力，而是把“何时出手”做成可维护的工程结构。

## 问题

直接让模型“自己决定什么时候主动”，几乎必踩三个坑：

1. **噪音**：每隔几分钟汇报一次“一切正常”，一周后用户开始屏蔽它；
2. **成本**：心跳轮询每个 tick 都调 LLM，token 账单失控；
3. **失控**：agent 自己发出的消息又触发监听器，形成自循环；或拿着过期状态去执行写操作。

根因是把“触发时机”也交给了概率模型。**主动性应该是确定性系统，判断才是模型的事。**

## 做法：拆成三层

**1. 触发层（确定性，不碰 LLM）**
- cron：固定节奏（晨报、周报）；
- webhook / 文件监听：事件驱动（CI 失败、日历变更）；
- 心跳预检：高频但廉价的条件检查，用脚本或规则实现。

**2. 预检层（纯规则）**

触发后先过门槛：去重 key、冷却时间、重要度打分、静默时段。不达标直接丢弃，根本不进模型。

**3. 行动层（LLM + 工具）**

只有通过预检才调 LLM，payload 只注入本次触发相关的最小上下文，而不是整份记忆。动作分两档：

- 低风险（汇总、草稿、提醒）→ 直接发；
- 高风险（删改、对外发送）→ 产出 draft，等人确认。

一个极简的配置示意（结构自定，关键是有这三段）：

```yaml
trigger:
  type: cron            # 或 webhook / heartbeat
  schedule: "0 9 * * 1-5"
preflight:
  dedup_key: "morning_brief"
  quiet_hours: "22:00-08:00"
action:
  mode: draft           # 先草稿，跑稳两周再放开
  tools: [calendar.read, mail.read]
```

## 踩坑点

- **自触发循环**：agent 发的消息又回到自己的 inbox，触发新一轮。给主动动作打上 actor 标记，监听层直接跳过。
- **状态过期**：触发时缓存已失效，基于旧数据执行写操作比不执行更糟。行动前重新拉取关键状态。
- **心跳频率**：tick 里只跑规则判断，LLM 调用必须在预检通过之后。
- **时区**：cron 默认 UTC，晨报发在半夜的教训人人都有过。
- **权限差异**：无人值守的主动会话，工具权限要比交互会话更紧，只读优先。

## 可复用建议

- **触发写配置、动作用代码、判断交给模型**——三层各自可测试、可回滚。
- 先让主动 agent 只产出**一周草稿**，再逐项放开写权限。信任是渐进的，不是一次授权。
- 每次主动触发都记录 reason，出问题时能回溯“它当时为什么出手”。
- 频率上限和静默时段是底线配置，写死在预检层，不要指望模型自觉。

## 总结

Proactive 不是让 agent 更聪明，而是让它更守规矩：确定性的触发、廉价的预检、收敛的行动。做到这三层，“不等你开口”才不会变成“你让它闭嘴”。
