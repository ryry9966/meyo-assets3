最近 36kr 一篇报道在技术圈刷了屏：DeepSeek 的原生 Agent 还没官宣，硅谷的华人工程师已经把“下一代 Agent Harness”做出了声量。很多人第一次看到 Harness 这个词会愣一下，它不是新模型，也不是聊天产品，而是包在模型外面、真正让 AI 动手干活的那套工程系统。这篇文章讲清三件事：Harness 到底是什么，为什么它突然成了胜负手，以及这波“抢跑”到底在抢什么。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-09/e0c78a56e77adc08.png)

## 一、Harness 是什么：给发动机装上底盘

- Harness 本意是“挽具”：把马的力气变成拉车动力的那套皮带和轭。软件工程里早有 test harness 的说法，指包裹被测系统的脚手架。到了 AI 语境，它指包裹在大模型外围的一整套工程层。
- 常见类比有两种：模型是发动机，Harness 是底盘、变速箱和方向盘；或者模型是马，Harness 是缰绳和车轭。
- 一个典型的 Agent Harness 至少包含五层：
  1. **Agent Loop**：ReAct 式循环，思考、调工具、观察结果、再思考，直到任务结束；
  2. **工具层**：shell 终端、文件读写、浏览器、代码执行沙箱；Anthropic 2024 年底开源的 MCP 协议，正在成为工具接入的事实标准；
  3. **上下文工程**：历史压缩、记忆文件、检索增强，决定模型每一步能“看见”什么；
  4. **错误恢复**：重试、回滚、输出校验；
  5. **权限与沙箱**：让模型敢动手，又不至于拆家。

## 二、为什么 Harness 是胜负手

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-09/eb01d49ea06cf9d4.png)

- 普林斯顿 SWE-agent 团队 2024 年提出 Agent-Computer Interface（ACI）概念：同一个模型，只改变它操作终端和文件的方式，在 SWE-bench 上自动修 bug 的成功率就能差出数倍。一句话总结：模型能力是上限，Harness 决定你离上限有多远。
- 从概率看更直白。Agent 任务动辄几十步，整体成功率约等于单步成功率的 N 次方：单步 95% 可靠，20 步任务整体只剩约 36%；把单步提到 99%，整体回升到约 82%。Harness 的核心工作，就是把每一步的失败率往下压。
- 从上下文看：模型只有上下文窗口这一块“工作记忆”。任务越长，中间信息越容易丢——研究里叫 context rot、lost in the middle——工具返回的大段日志还会污染窗口。压缩、记忆外置、子代理拆任务，本质上都是 Harness 在替模型打扫房间。
- 这也解释了一个日常体感：同一个模型，套在打磨过的编程 Harness 里像资深工程师，裸调 API 却像第一天上班的实习生。差距不在模型，在挽具。

## 三、华人团队抢跑了什么

- 引爆点很清晰。2025 年 3 月 Manus 刷屏，核心思路正是用云端沙箱加精心打磨的 Harness 驱动现有模型；开源社区几个小时就复刻出最小可用的 OpenManus，背后是 MetaGPT 系的华人研究者。
- 更早的 OpenHands（前身 OpenDevin）由 CMU 等校的华人研究者主导，长期在 SWE-bench 上与商业系统同台比拼，是目前最活跃的开源 Agent 平台之一。
- “抢跑 DeepSeek”的真实含义：不是比谁模型更强，而是不等模型厂发布原生 Agent，先用 Harness 把 DeepSeek-V3/R1、Qwen 这些现成开源模型改造成能干活的智能体。谁先把引擎装进底盘，谁先上路。
- 争议也在这里。一派认为薄薄的 Harness 只是过渡方案，等模型原生支持工具调用和长任务就会被碾过；另一派认为评测体系、领域数据、生态集成才是长期资产。目前两条路线实际并行：模型厂把能力“内化”，应用层把工程“外化”。

## 四、冷思考：模型变强后，Harness 会变薄吗

- Sutton 的 Bitter Lesson 早就说过：通用方法加算力，长期赢过手工技巧。Harness 有一部分注定被模型“吃掉”——早年手写的解析器和 few-shot 模板，如今已经是原生的 function calling。
- 但反例同样存在。Claude Code 出现在模型已经很强的年代，Harness 反而越做越厚：上下文压缩、子代理、钩子、记忆管理。合理的解释是：模型变强后，人们会把任务推向更难的边界，Harness 的价值随之转移到新边界，而不是消失。
- 一个可操作的判断标准：会被吃掉的，是绕开模型短板的补丁，雕花 prompt、临时 glue 脚本；会留下的，是模型本身做不了的事，沙箱安全、权限审计、评测基准、领域工具和数据。

## 五、给想下场的人三条建议

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-09/ce8e66795ce4ead1.png)

1. **先搭最小可用的循环，再谈花活。** 带重试和输出校验的 Agent Loop，胜过十页雕花 prompt。先把“调工具→看结果→修正”跑通，再往上加记忆和子代理。
2. **把预算花在评测和上下文工程上。** 攒一小套真实任务集，分别量单步成功率和端到端成功率；上线后盯两条曲线，上下文长度和错误累积速度。没有评测的 Harness，等于盲改。
3. **把会被吃掉的部分写薄，吃不掉的部分写厚。** prompt 层保持轻，随时可换模型；沙箱、权限、日志、领域工具和评测数据做扎实——这些才是模型换代时带得走的资产。

“抢跑”这个词火药味不轻，但这场竞争的本质其实是分工：模型厂负责让发动机马力更大，工程师负责造出足够好的底盘。DeepSeek 什么时候下场还没有准信，可以确定的是——无论哪家的模型跑在前面，都得先套上挽具，才能拉车。
