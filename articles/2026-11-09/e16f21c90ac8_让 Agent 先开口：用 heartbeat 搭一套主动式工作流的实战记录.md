## 背景

多数 Agent 交互是"你问它答"。但真正省时间的场景往往相反：任务在后台被察觉、被处理，人只在需要决策时出现。OpenClaw 提供了两类原始能力支撑这种模式——heartbeat（定时唤醒 agent 自查）和 cron（定点触发），配合 MCP 工具和频道推送，可以搭出一套"不等你开口"的主动式工作流。下面是我跑了两个月的方案。

## 问题

主动 ≠ 多说话。实践中最大的矛盾是：唤醒太频繁，token 烧得快、通知变成噪音；太保守，又退化回被动问答。其次，主动执行写操作（发消息、改文件、调外部 API）的授权边界必须比被动模式更严格——没人希望半夜被 agent 替你"顺手"发一条没核对的消息。

## 做法

我的骨架是"观察便宜、行动贵"的三层结构：

1. **状态文件做事实源**。在 workspace 放 `state.md`，列出每次心跳要检查的事项：某目录有没有未处理的 PR、日历 MCP 今天有没有冲突、监控脚本输出是否过阈值。数据由普通脚本写入，agent 只读不猜。
2. **心跳配置成"默认沉默"**。心跳 prompt 里明确写：一切正常就保持安静，不输出任何内容；只有命中 `state.md` 里的触发条件才行动。这一句是整个系统的开关。
3. **三级响应分级**：
   - L0 静默：把发现追加到 `log.md`，不打扰人；
   - L1 记忆：写入 `inbox.md`，下次打开会话自然带上上下文；
   - L2 推送：调频道工具主动发消息，只留给"不处理会有损失"的事。
4. **写操作一律二次确认**。L2 行动若涉及对外发送或删除，先回一句"我准备做 X，确认后执行"，把不可逆动作交还给人。

## 踩坑点

- **心跳间隔别贪快**。从 10 分钟调到 30 分钟，成本降了三分之二，漏掉的事为零——多数检查项不需要分钟级敏感。
- **agent 总能"找到事说"**。没有显式的"沉默是正确答案"约束，它每次心跳都会汇报点东西刷存在感。prompt 里必须写明，并给一两个反例。
- **重复通知**。同一问题每次心跳都推。解法是在 `state.md` 加"已通知"标记位，处理完才清除。
- **cron 时区**。定点任务默认走了 UTC，凌晨四点触发一轮全量检查，白烧一晚 token。定点任务一律显式声明时区。
- **状态文件竞争**。脚本写和 agent 读撞过一次车，改成先写临时文件再原子 rename，之后没再出现。

## 可复用建议

- 先只做只读主动（观察、汇总、提醒），跑稳两周再放开写操作。
- 每次主动决策（说/不说/做了什么）都落日志，一周后回看，能准确校准心跳频率和分级阈值。
- 触发条件写成结构化清单而非自然语言长段落，agent 判断稳定得多。
- 主动能力的本质是把人的注意力当预算花：每次加新触发项前先问，这件事值得打断我吗？

## 总结

OpenClaw 的主动式能力不神秘，核心就三件事：一个廉价规律的唤醒机制、一份结构化的事实源、一条"沉默是默认、行动需分级"的纪律。把观察和行动拆开、把不可逆动作交还给人，agent 就能从问答机变成真正省心的后台同事。建议从一两个只读触发项起步，让它先学会安静，再学会主动。
