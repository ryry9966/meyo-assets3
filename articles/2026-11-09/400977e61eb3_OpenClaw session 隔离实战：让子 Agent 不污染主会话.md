## 背景

OpenClaw 的主会话承载着任务上下文、用户偏好和长期记忆的写入入口。当我们把一个多步骤任务——批量排查日志、跑一轮数据抓取、调用一组 MCP 工具做验证——交给子 Agent 执行时，最容易忽略的问题是：子 Agent 的中间过程去了哪里。

## 问题

早期我们的做法是直接在主会话里让模型"自己搞定"，结果是：

- 几十次工具调用的返回值全部堆进主会话上下文，几轮之后 token 膨胀，模型开始忘记最初的任务边界；
- 子 Agent 中途的失败重试、报错信息混进对话历史，主 Agent 后续决策被这些噪音带偏；
- 子 Agent 写长期记忆时没有命名空间，把临时结论当成持久事实存了进去。

本质上这不是 prompt 写得好不好的问题，而是 session 边界没有画出来。

## 做法与步骤

1. **子 Agent 用独立 session 启动**。给每个子任务分配独立的 session id，上下文从零开始，只注入完成该任务必需的最小背景，不继承主会话历史。
2. **定义返回契约**。子 Agent 结束时只返回结构化摘要：结论、关键数据、失败原因，禁止回传完整 transcript。在 spawn 参数里显式限制返回长度。
3. **工具权限收窄**。子 Agent 的 tool allowlist 单独配置。主会话里能写记忆、能改全局配置的工具，默认不给子 Agent。
4. **工作区隔离**。子 Agent 的中间文件写到按任务 id 命名的 scratch 目录，任务结束统一清理，避免覆盖主 workspace 里的同名文件。
5. **记忆写入走命名空间**。如果确实需要子 Agent 沉淀经验，让它写到以任务名为前缀的命名空间，由主会话审核后再合并进长期记忆。

## 踩坑点

- **返回契约没写死**。prompt 里一句"汇报一下过程"，子 Agent 就会把整段执行流水贴回来，隔离等于白做。返回格式必须在 spawn 时约束，不能靠事后提醒。
- **环境变量泄漏**。子 Agent 继承了主会话的全部环境变量，导致它"以为"自己知道一些上游状态。需要显式剔除无关变量。
- **scratch 目录没清理**。连续跑多次同类任务后，旧中间文件会干扰新任务的判断——子 Agent 读到了上一次的残留输出，还当成本次结果。
- **记忆命名空间形同虚设**。只加前缀不做审核，垃圾结论照样进长期记忆。主会话审核合并这一步不能省。

## 可复用建议

- 把"子 Agent 返回什么"当成接口设计，固化成模板，而不是每次临时想；
- 采用默认拒绝式授权：权限宁可少给，出问题再补，不要反过来；
- 任务结束做一次 session diff：主会话里多了什么？如果出现大段原始工具输出，说明隔离有漏洞，先堵边界再谈优化。

## 总结

Session 隔离的核心不是"把子 Agent 藏起来"，而是控制信息回流的方向和体积：过程留在子 session 里消化，只有结论以受控格式流回主会话。把返回契约、工具权限、工作区、记忆命名空间这四条边界显式画出来，主会话才能在长任务链里保持干净、决策不漂移。
