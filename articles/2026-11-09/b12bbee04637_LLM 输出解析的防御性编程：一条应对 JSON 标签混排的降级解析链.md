## 背景

在 OpenClaw 里写 skill、插件或自动化流水线时，让模型输出一段 JSON 来驱动后续工具调用或 MCP 请求，是很常见的做法。理想情况是拿到一段能直接 `json.loads` 的文本，但只要模型、版本、温度稍有差异，输出格式就会漂移。提示词约束和 response_format 能降低脏输出概率，却没法归零——尤其是流水线里混用多个模型、或输出经过 agent 转写之后，格式更不可控。

## 问题

把我们社区成员线上攒到的失败样本归类，典型的“脏输出”有这几种：

- ` ```json ``` ` 围栏包裹，有时只有尾部的 ` ``` `；
- `<json>`、`<answer>` 之类自定义标签，不同模型习惯不同；
- JSON 前后各带一句说明文字；
- 输出两个 JSON 块（一段分析 + 一段结论）；
- 字符串值里嵌套代码围栏；
- 尾逗号、单引号、`True/False/None`、中文引号；
- `max_tokens` 截断，只给你半截。

裸 `json.loads` 在以上任何一种情况下都会抛异常，然后整条链路中断。

## 做法：降级解析链

核心思路是承认格式不可控，把解析做成一条**有序降级链**，每层记录命中策略，而不是赌某一个正则：

1. **原样 parse**，最理想路径；
2. **剥围栏**：按行匹配围栏起止，不要全局替换，避免误伤字符串值里嵌的围栏；
3. **剥标签 / 括号配平**：先提取已知标签；没有标签时用括号配平扫描找首个完整对象——逐字符跟踪引号状态和花括号深度，字符串内部的 `{` `}` 不计数。不要用贪婪的 `\{.*\}`，遇到多 JSON 或值里带 `}` 必翻车；
4. **修复常见语法**：尾逗号、单引号、`True/None`、中文引号，修复动作要记日志；
5. **schema 校验**：parse 成功但字段缺失或类型不对，同样判失败；
6. **兜底**：抛结构化错误并把原始输出落盘，必要时带纠错提示重试一次。

```python
def extract_json(raw: str) -> tuple[dict, dict]:
    # 候选顺序：原样 -> 剥围栏 -> 剥标签 -> 括号配平
    for strategy, text in candidates(raw):
        try:
            data = json.loads(repair(text))
            if schema_ok(data):
                return data, {"strategy": strategy}
        except json.JSONDecodeError:
            continue
    raise ParseError(raw=raw)
```

## 踩坑点

- **全局剥围栏会误伤嵌套围栏**：字符串值里存着一段代码时，粗暴的字符串替换会把内容截断；
- **静默修复掩盖模型质量问题**：统计面板上要能看到“哪层策略命中、改了什么”，否则你不会发现某个模型的输出质量在退化；
- **截断输出别盲修**：括号碰巧配平不等于内容完整，先看 `finish_reason` 或长度异常再决定是否进入修复层；
- **多 JSON 块的取舍规则要写死并进测试**：我们的经验是取最后一个通常是最终答案，但必须验证而不是猜；
- **不可见字符**：`\ufeff` BOM、全角引号，报错信息和肉眼看到的内容对不上时，优先怀疑它们。

## 可复用建议

- 解析器收敛为一个公共模块，skill、插件、MCP 工具共用，别各抄一份；
- 返回 `(data, meta)`，meta 带命中策略，方便观测和失败回放；
- 建一个坏输出语料库：线上每次解析失败就归档原始输出，沉淀成单测用例；解析链每次改动跑一遍全量回归；
- 提取、修复、校验分层实现，别糅在一个函数里；
- 提示词约束照常写，它是第一道防线，但只当概率手段，不当唯一防线。

## 总结

防御性解析不是把解析器写复杂，而是把“输出格式不可控”这个事实工程化：有序降级、命中可观测、失败可回放、用例可回归。它不能让脏输出消失，但能让脏输出不再打断你的流水线。欢迎在社区帖子里贴你收集到的失败样本，语料库越全，这条链越稳。
