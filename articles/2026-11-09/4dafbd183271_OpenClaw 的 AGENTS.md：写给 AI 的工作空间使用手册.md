## 背景

OpenClaw 的 agent 每次会话启动，都会从工作空间读取一组上下文文件。其中 `AGENTS.md` 最关键：它会被注入系统提示词，相当于 agent 在这个工作空间里的"常驻操作规程"。不管是交互会话还是定时心跳任务，读到的都是同一份。三个文件分工大致是：SOUL.md 管它是谁，IDENTITY.md 管怎么自称，AGENTS.md 管"在这里怎么干活"。

## 没有它会怎样

装了再多 MCP 工具和 skill，agent 不知道什么时候用、按什么规矩用，等于白装。实际踩过的坑：

- **猜路径**：把临时脚本写到项目根目录，污染 git 状态
- **跨环境出错**：在 Windows 上用 bash 语法，或者默认 npm 而团队用的是 pnpm
- **越权**：直接 `git push`、批量删文件、对外发消息，事先不确认
- **重复教学**：每个新会话都要重新交代一遍项目约定

这些多半不是模型能力问题，而是上下文缺失。

## 我的结构：四段式

不追求大而全，每条都是祈使句、具体可判定：

```markdown
# 环境事实
- macOS / zsh；包管理用 pnpm，禁止 npm
- 工作空间根目录：~/openclaw-workspace

# 目录约定
- projects/ 下各项目，改动前先看 git status
- archive/ 只读，不要做清理

# 安全边界
- git push、rm -rf、对外发消息：必须先问我
- 涉及密钥与付费的操作：拒绝执行并提醒

# 工具用法
- 查资料先搜索，抓正文用浏览器工具
- 批量改文件写脚本跑，不要逐个编辑
```

## 踩坑点

1. **写太长**。它占上下文预算，超过两屏 agent 就开始漏看。细节下沉到 TOOLS.md，或做成独立 skill。
2. **写成散文**。"小心一点""注意安全"没有可执行性。规则要具体到 agent 能自我检查的程度。
3. **和别的文件抢戏**。人格、语气放 SOUL.md，AGENTS.md 只放工作规程，混写会导致行为漂移。
4. **存敏感信息**。它会被读进上下文，可能随日志落盘。密钥放环境变量。
5. **一次性工程**。写完不管，三个月后全是过期信息，比不写更糟。

## 可复用做法

- **纠错沉淀**：每次手动纠正 agent 后问自己一句——这条要不要变成 AGENTS.md 里的一行？能沉淀就沉淀。
- **进 git**：文件本身版本化，行为退化时可以 diff 出是哪次改动引入的。
- **改完开新会话验证**。旧会话的残留上下文会掩盖问题，测不出真实效果。
- **一行一条，动词开头**。方便扫读，也方便日后删改。

## 总结

AGENTS.md 是 OpenClaw 里成本最低、收益最直接的一个杠杆：不用写代码，不用动配置，几次会话的纠错就能积累出一套贴合自己工作空间的规程。把它当成工程卫生而不是玄学——小步迭代、进版本库、定期修剪，agent 行为的稳定性会有肉眼可见的改善。
