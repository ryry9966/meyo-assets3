## 背景

OpenClaw 每次会话启动时会读取工作区里的几个固定文件：`SOUL.md` 管人设，`USER.md` 管你是谁，`MEMORY.md` 管动态记忆，而 `AGENTS.md` 是唯一一份**每次都加载**的操作手册——它决定了 agent 在你的机器上如何干活。`AGENTS.md` 本身是一个跨工具的开放约定，OpenClaw 把它作为工作区的常驻说明书来用。

## 问题

没有 AGENTS.md 时，agent 的行为完全依赖模型先验和你当次的零散指令。实际用下来有三个典型症状：

1. **行为漂移**：上周纠正过“别往工作群发长语音”，这周又犯；
2. **边界不清**：agent 自作主张执行清理命令、在错误的渠道用错误的语气回复；
3. **换模型后行为不一致**：所有约定都停留在聊天记录里，没有落盘，换一个模型全部归零。

## 做法

我的 AGENTS.md 迭代了三个月，现在的结构是五段：

1. **环境声明**：主机、时区、默认语言、软件源偏好；
2. **渠道约定**：Telegram、WhatsApp、Discord 等入口分别对应什么工作语境和回复风格；
3. **安全红线**：删除类操作必须确认；涉及付款、给第三人发消息需要显式批准；
4. **工具偏好**：优先用哪个浏览器、什么时候该读文件而不是凭记忆回答；
5. **消息风格**：默认回复长度、什么情况用列表、什么时候直接说“不知道”。

写法上有三条纪律：

- **两次纠正法则**：同一件事口头纠正到第二次时，立刻写进 AGENTS.md。把它当成事故复盘，而不是聊天；
- **每条一行、可验证**：“回复默认不超过 200 字”比“回复要简洁”有用得多；
- **控制体积**：这份文件每次会话都进上下文，我目前压在 60 行以内，长内容挪到 `TOOLS.md` 或单独文档，这里只留路径引用。

最后用 git 管起来，每次改动可 diff、可回滚。

## 踩坑点

- **改完不生效**：AGENTS.md 在会话启动时加载，正在跑的会话不会热更新。改完要么开新会话，要么让 agent 重新读一遍文件；
- **职责混写**：把人设写进 AGENTS.md，又把操作规则写进 SOUL.md，两份文件互相打架。明确分工：SOUL 管性格，USER 管用户画像，AGENTS 管操作规程；
- **塞任务状态**：临时 todo、当前任务不该放这里，那是 MEMORY.md 和 `memory/` 日志的职责；
- **过度约束**：堆太多“永远不要”，agent 会畏手畏脚，什么都来问你。红线只留真正不可接受的几条。

## 可复用建议

- 新装机先用 20 行骨架跑起来，别追求一次写完美；
- 每月 `git log` 回看一次，删掉过时规则——手册也会腐烂；
- 多工作区/多 agent 场景下，每个工作区一份 AGENTS.md，共性约定用软链共享一份公共文件；
- 每次改动后做固定测试：让 agent 复述它理解到的规则，确认加载生效。

## 总结

AGENTS.md 本质上是“配置即文档”：你希望一个新同事上手时知道的所有事，都值得写进去。它的价值不在于一次写多全，而在于持续迭代、版本可控。手册写得越好，你纠正 agent 的次数就越少——这才是自动化该有的样子。
