## 背景

OpenClaw 的 Agent 在每台机器上拿到的是同一套 skills、MCP 配置和系统提示，但真正执行命令的环境差异很大：macOS 和 Linux 的路径习惯不同，Python 可能在 pyenv、conda 或系统里，代理开不开、Docker 是本地还是远程 context、本机启用了哪些 MCP server——这些都不会自动进入模型上下文。

## 问题

常见两种错误姿势。一是每次新会话口头交代一遍环境，漏说一条就翻车一次，而且无法复用；二是把机器细节硬编码进 skills 或提示词，换台机器全部失效。结果是 Agent 反复试错：猜路径、装错版本的包、在错误目录里执行破坏性命令。

## 做法

1. 在 workspace 根目录维护 `tools.md`，定位是"本机操作手册"，Agent 启动时会读取它。
2. 推荐结构，保持条目化：
   - **机器档案**：OS、shell、包管理器、运行时版本与安装位置
   - **网络**：代理、镜像源、VPN 触发条件
   - **项目布局**：代码根目录、数据目录、常用入口命令
   - **任务配方**：构建 / 测试 / 部署的标准命令序列
   - **MCP 与插件**：本机启用了哪些 server、stdio 启动命令、端口、已知启动失败原因
   - **禁区**：不允许动的目录、禁止 sudo 的场景
3. 用事实而不是指令来写：写"python3 在 ~/.pyenv，版本 3.12"，而不是"请使用 Python"。
4. 环境变了立即更新。把它当成有 owner 的文档，而不是一次性配置。

## 踩坑点

- **别放 secrets。** `tools.md` 全文会进模型上下文，token 写进去就是扩大泄露面。只写指针："密钥在 ~/.env 或密钥管理器"。
- **别写成散文。** 长段落模型会选择性忽略，表格和短条目最稳定。
- **别和 skills 重复。** 同一件事两处说法冲突时，Agent 不知道信谁。原则：`tools.md` 管环境事实，skills 管操作流程。
- **别忽略时效。** 升级后路径变了，Agent 会围绕过期文档一本正经地幻觉。关键条目标注"上次验证时间"。
- **别同步绝对路径。** 多机共用一份文件时，用 `$CODE_ROOT` 这类约定变量代替 `/Users/xxx`，跨系统同步注意换行符差异。

## 可复用建议

- 固定一个模板，每台机器只填差异块，共同块保持一致，方便 diff 和迁移。
- 写个十行的校验脚本：遍历 `tools.md` 声明的命令，逐个 `which` 一遍，跑一次就知道文档漂移了多少。
- 让 Agent 参与维护：它执行中发现新事实（新装的 CLI、变更的路径、跑挂的命令）时，要求它提议更新 `tools.md`，而不是靠人记。
- 敏感信息走 `.env` 或密钥管理器，`tools.md` 永远只存引用。

## 总结

`tools.md` 的价值不在文件本身，而在把环境知识从"对话记忆"变成可版本化、可校验、可迁移的一等资产。原则就三条：写短、写真、写事实。配合定期校验脚本，Agent 在任何一台新机器上都能少猜一半、少错一半。
