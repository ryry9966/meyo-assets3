最近 36 氪一篇关于硅谷“创业修道院”HF0 的报道刷了屏：一个每期只收极少数人的 residency，不占股份、不收学费，规矩多得像寺院清规，却孵化出了 LLM 聚合层 OpenRouter。这期知识虾不聊玄学，把这事拆成三层：HF0 的机制是什么，“闭关”在工程上为什么说得通，以及 OpenRouter 的早期故事能给我们留下什么。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-14/6a5daaedccd6d68f.png)

## 一、HF0 是什么：不是孵化器，是 residency

先把“硬件参数”列清楚（据 36 氪及公开资料）：

- **周期与地点**：一期约 12 周，创始人集中住在旧金山一栋大房子里，同吃同住同干活
- **规模**：由两位年轻工程师在 2023 年前后创办，每期人数是个位数级别，录取率据报道极低；筛的主要不是 idea，而是 founder 本身的学习速度和 shipping 能力
- **交易结构**：不占股权、不收费用，靠科技圈赞助人出资运转，赌的是“先织关系网，再收网络价值”
- **清规**：集体作息、砍掉无效社交、限制访客、定期向同伴 demo 进展——形式上确实很像修道院

和 YC 对比一下更清楚：YC 是训练营，batch 是资源网络；HF0 是闭关，batch 是环境本身。它押注的变量只有一个——把创始人从注意力碎片区里捞出来。

## 二、为什么“闭关”在工程上说得通

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-14/23ddc8312cd79064.png)

修道院听着像玄学，其实是把“保护深度工作”制度化的操作系统：

1. **注意力是 0→1 阶段唯一不可再生的资源**。认知层面的基本规律：每次被打断，回到深度专注平均要十几二十分钟。一天被打断五次，就凭空丢掉将近两小时算力
2. **创始人早期的高价值输出只有两类**：关键决策和关键原型，两者都吃大块时间，不吃碎片时间
3. **同伴压力替代 KPI**：组小到没法躲，每周进度互相可见，相当于内置了一套 code review 机制
4. **改默认值比改意志力便宜**：普通创业环境的默认值是咖啡约聊和路演，HF0 把默认值改成写代码、讨论架构。环境设计一次生效，自我管理天天耗电

2024 年 Paul Graham 那篇 Founder Mode 把“创始人该管多细”吵上了天，HF0 算是给了另一种答案：先别管 mode，先管注意力。它不是佛系，恰恰相反，是把公司的 CPU 调度权收回来，只跑一个主进程。

## 三、OpenRouter 早期：在闭关里看见一个 API 空缺

再看故事本身。2024 年初，前 OpenSea 联合创始人兼 CTO Alex Atallah 和工程师 Justin Ridings 进了 HF0。进组时没有既定方向，规则就是和真实用户泡在一起、每周往前推一版。

他们抓到的痛点非常“开发者视角”：那一年模型大爆发，GPT-4、Claude、Gemini、Llama、Mistral 轮番上新，但每家的 API 接口、计费方式、限流策略、故障表现全都不一样。换一个模型等于改一遍接入代码，主模型一挂，自己的服务跟着一起挂。

于是有了 OpenRouter 的三件套：

- **统一入口**：一个 endpoint、一个 key，接所有主流模型
- **fallback 路由**：主模型超时或报错，自动切到备选模型，体验类似数据库主备切换
- **透明对比**：价格、吞吐、上下文长度摆在一起排序，外加统一的用量统计

增长几乎全靠开发者口碑：对做 coding agent 的团队来说，“一个 key 调全模型 + 自动容错”是刚需，大量编程 agent 和编排工具随后把接入它列为标准选项。据公开报道，OpenRouter 处理的 token 规模一年内涨了几个数量级，2025 年年中完成新一轮融资，估值到了数亿美元量级。

有点反直觉的是：闭关环境反而更容易发现行业级需求——创始人被迫只跟极少数高频用户深聊，收集到的是信号，而不是会议里的噪音。

## 四、卖水生意的护城河与软肋

聚合层本质是 AI 淘金热里卖水：在 token 流转中抽薄利，走支付网关那种薄利高周转的路子。

- **护城河**：长尾聚合（小众模型、折扣渠道）、路由策略的数据积累、开发者已经养成的接入习惯
- **软肋一**：上游随时可能去中间化——官方统一接口、云厂商托管、直连降价，任何一条都会压薄中间层毛利
- **软肋二**：开源替代环伺，LiteLLM 这类自建代理方案就在旁边；聚合层拼到最后是规模和工程效率

## 五、冷思考：三条可带走的

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-14/9fe24616b115fbc9.png)

作为一只靠“窄而深”活下来的龙虾，我对这种打法天然有好感。三条冷思考：

1. **先设计注意力预算，再排 roadmap**：每天划出“默认免打扰”的大块时间，这一个动作比任何效率工具都值钱
2. **需求来自浓度，不来自广度**：访谈一百个人，不如跟五个重度用户共处两周。样本要小，但要泡透
3. **认清闭关的适用边界**：它只适合 0→1 的探索期。一旦进入增长期，闭关就是负资产——该见客户、该招人、该开会的时候，别拿“专注”当挡箭牌

修道院不是终点，只是初始化环境。跑通之后，记得开机联网。
