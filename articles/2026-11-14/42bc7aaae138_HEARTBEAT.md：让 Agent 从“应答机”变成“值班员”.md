## 背景

用 OpenClaw 一段时间后，大多数人会停在同一个模式：Agent 很聪明，但永远被动——你不问，它不动。真正让它像“助理”而不是“聊天窗口”的分水岭，是 `HEARTBEAT.md`：一份放在工作区里的普通 Markdown 文件。Agent 每次心跳唤醒（默认约 30 分钟，视版本可配）时读一遍，按里面的指令自查并执行。

## 问题

被动模式有三个真实痛点：

1. 周期性事务全靠人记：盯日志、查磁盘、提醒待办，忘了就出事。
2. cron 能定时，但没有上下文：它不知道“上次检查结果是什么”，只能无脑执行。
3. 你希望 Agent 在合适的时机“多说一句”，而不是每次都等你想起。

心跳机制补的就是这个空档：轻量、带会话上下文、能写判断逻辑。

## 做法

三步跑起来：

**1. 建文件。** 在工作区根目录新建 `HEARTBEAT.md`，把它当成写给 Agent 的值班手册。推荐结构：

```markdown
## 每次心跳执行
- 检查 ~/logs/app.log 最后 50 行，ERROR 连续出现 3 次才汇报
- 磁盘占用超 85% 时提醒，并附占用最大的 3 个目录
- 今日待办未完成且已过 18:00，汇总发我

## 汇报纪律
- 无异常时只回复 HEARTBEAT_OK，不要发消息
```

**2. 配节奏。** 在网关配置里调整心跳间隔（如临时调成 1 分钟做验证）。多 Agent 场景下，各 agent 的 heartbeat 段可以指定各自的文件和间隔。

**3. 验证。** 短间隔跑半小时，确认三条路径都符合预期：触发、执行、静默，然后调回正式值。

关键机制：Agent 心跳执行后如果判断“无事发生”，回复 `HEARTBEAT_OK` 即可被网关吞掉，不推送到你的聊天渠道。这是心跳不变成骚扰的关键开关。

## 踩坑点

- **文件越长，每次心跳 token 开销越大。** 控制在 30 行内，重任务交给 cron 或 skill。
- **别把耗时任务塞进心跳。** 心跳是“巡检”，不是任务队列，跑十分钟的任务会把整个节奏拖垮。
- **指令模糊 = 要么天天误报，要么永远静默。** “看看系统正不正常”这种写法没用，条件必须可判定：阈值、次数、时间点。
- **精确定时别用心跳。** “每天 9:00 整发日报”用 cron；心跳间隔有漂移，卡点场景不可靠。
- **心跳插入可能打断你正在进行的对话。** 频繁的渠道可以把心跳汇报路由到独立 session。

## 可复用建议

- 把 `HEARTBEAT.md` 当“值班交接文档”维护：每月删一次失效项，新增项先观察一周。
- 固定四段式模板：检查项 / 触发条件 / 执行动作 / 汇报格式。
- 让心跳把关键动作追加写入 workspace 下的 `heartbeat-log.md`，方便事后审计它到底“主动”干了什么。
- 心跳管“模糊的周期性”，cron 管“精确的时间点”，两者配合覆盖大部分自动化需求。

## 总结

HEARTBEAT.md 的价值不在功能多强，而在它把“主动性”变成了一份可以版本管理、可以持续调优的纯文本配置。写好这一个文件，Agent 才真正从应答机变成值班员：大事主动开口，小事保持安静。
