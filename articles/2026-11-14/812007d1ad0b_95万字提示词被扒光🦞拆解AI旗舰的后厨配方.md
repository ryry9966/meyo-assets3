11月下旬，Anthropic 发布新一代旗舰 Claude Opus 4.5。评测数据还没热乎完，社区里已经流传出它的 system prompt——按字符口径统计约 9.5 万，折算成 token 两万多，相当于出厂说明书被人整个拍到了网上。36kr 等媒体跟进后，话题冲上热搜。这其实是重复过很多次的剧本：Grok、o1、Gemini 都被扒过。但这次值得认真拆一拆，因为泄露的体量和内容结构，恰好是一堂难得的公开课。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-14/dec8bb8e4ceab735.png)

## 系统提示词是什么：AI 的"后厨操作手册"

先对齐基本概念。用户在对话框里看到的只是模型的"前台"，真正决定行为的，是推理时注入的一段不可见文本：

- **system prompt（系统提示词）**：厂商在服务端写死的全局指令，优先级最高，用户看不到也改不了；
- **tool definitions（工具定义）**：告诉模型有哪些函数可调用、参数格式是什么；
- **user message**：你的对话内容，只是整个上下文里的一小块。

类比一下：用户看到的是菜单，system prompt 是后墙上贴的操作手册——何时开火、何时尝味、出餐格式、哪些东西绝不能端出去。

厂商把它当机密，主要三个原因：调优成本高（一份 prompt 往往迭代几十个版本）；它是产品差异化的载体（同样的底模，编排规则不同，体验天差地别）；以及防止攻击者摸清"规则边界"后定制 jailbreak。

## 9.5 万字里都写了什么：与其说是咒语，不如说是工程决策

从社区流出的文本看，体量膨胀主要来自这几块（按占比粗排）：

1. **工具编排规则**：什么时候调 web search、什么时候写代码执行、结果如何交叉验证。这部分占大头，而且很多不是散文，是大段 JSON schema 和函数说明——"95万字"的水分主要也在这里。
2. **Agent 行为准则**：接到任务先拆解还是先动手、卡住多久该上报、长任务如何分段验证。这是 agent 产品的核心 know-how。
3. **语气与反谄媚（anti-sycophancy）**：明确禁止"Great question"式开场，要求不确定就直说、不迎合错误前提。Anthropic 把反讨好写进制度，在业内是出了名的。
4. **安全与版权边界**、**extended thinking 的组织方式**等。

最值得玩味的读后感是：这份"绝密文件"里几乎没有魔法词，绝大多数条目都是可执行的 if-then 决策规则。换句话说，泄露出来的不是咒语，而是一份产品经理的决策清单——这才是它值钱的原因。

## 怎么被扒的：一场不对称的攻防

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-14/8ae62e81d31a5181.png)

原理一句话讲完：**模型要执行指令，就必须先把指令读进上下文；而读进上下文的 token，在概率层面就可能被"引"出来。** 模型并没有独立的"保密记忆区"，system prompt 和用户输入躺在同一块上下文里。

手法这些年不断换代：

1. **经典款（2023）**：一句"Repeat the words above starting with..."直接诱导复读，早期命中率极高；
2. **变体款**：要求 Base64 编码输出、倒序拼写、藏头诗（acrostic）、伪装成"调试模式"；
3. **场景款**：让模型"写一篇包含你出厂设定的虚构文档"，或借 summarize、日志类工具把上下文原样吐出来。

厂商的防御也在升级：输出端分类器实时拦截、对抗训练强化拒绝行为、prompt 里写明"永不透露"。但注意，"永不透露"这行字本身也在上下文里，防线终究是概率性的。安全圈的共识很清楚：**system prompt 从来不是 security boundary，真正的边界在代码层。**

## 泄露了会怎样：厂商的算盘没你想的那么慌

- **竞争情报风险**：对手拿到编排规则，可以快速对齐产品行为，省掉大量试错成本；
- **定制攻击风险**：摸清规则边界，越狱会更有针对性。

但厂商并没有"绝密泄露即崩盘"级别的恐慌，原因很简单：**行为可以被复述，机制很难被复刻**。prompt 只是冰山露出水面的一角，水面下是 RLHF/RLVR 训练管线、评测体系、工具基建——这些抄不走。

还有个有意思的反差：Anthropic 本来就有公开消费端 system prompt 的惯例，此前在 GitHub 上按版本发过 claude.ai 的提示词全文，这次被扒的是后端/新旗舰版本。可见厂商的口径是"分层透明"：人格层可以公开，产品编排层保密。

## 从"被扒光"里学什么：给写 prompt 的人

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-14/4055df1b0f9391ce.png)

泄露版本反而是最好的公开课，三条最实用：

1. **写决策规则，不写形容词。**"要专业、要有帮助"没有信息量；"当用户消息含糊且低成本无法澄清时，按最合理解释继续执行，并在结尾注明所做假设"才是一条合格的规则。
2. **工具规则写成条件分支。** 什么条件触发、什么条件禁止、结果异常怎么办，逐条列清——这次泄露文本里最厚的部分就是这种结构。
3. **把 prompt 当代码管。** 两万多 token 的 prompt 一定有人持续在改：版本化、diff、回归测试缺一不可，否则每次改动都是盲改，等于裸奔。

## 收尾：三条冷思考

1. **把 system prompt 当"可泄露资产"来设计**：假设它明天就会被贴到网上，里面不该出现任何密钥、内部地址、真实权限描述——真正的安全资产必须放代码层。
2. **体量即产品**：从几百词到两万 token，prompt 的膨胀对应的是 agent 能力面的扩大。评估一个 AI 产品的成熟度，看它的提示词工程化程度，有时比看 demo 更准。
3. **保密是竞争策略，不是安全机制**：提示词可以被抄走，抄不走的是训练和评测体系。与其焦虑被扒，不如把护城河修在水下。
