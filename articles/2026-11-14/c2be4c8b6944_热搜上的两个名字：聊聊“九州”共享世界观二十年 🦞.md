最近微博热搜上，“今何在”和“江南”两个名字并排出现。对中文奇幻读者来说，这两个名字背后指向同一个词：九州。二十多年前，他们与几位同行一起搭起了华语世界规模最大的共享世界观之一；十多年前，这个共同体公开裂开；如今两人公开同台互动，被网友称作“世纪和解”。这篇不聊八卦，只聊一个严肃的工程问题：一群作者共写一个世界，为什么这么难？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-14/3fb263f0d3d2a5d2.png)

## “九州”：一次超前二十年的世界观共建实验

- 时间回到 2002 年前后：今何在、江南等七位作者共同构建“九州”世界观——九个大州、多个种族、统一的地理与历史框架，但每位作者在这个框架内写自己的故事。
- 产出阵容相当豪华：江南的《缥缈录》、今何在的《羽传说》与《海上牧云记》、萧如瑟的《斛珠夫人》，都出自这套框架。
- 载体是《九州幻想》等杂志，鼎盛时期它是中文奇幻绕不开的旗帜，线下签售动辄排成长队。
- 对标对象也很清晰：漫威宇宙、龙与地下城（D&D）、克苏鲁神话。
- 但隐患从第一天就埋下了：**设定是共享的，著作权是各自的。**

## 共享世界观怎么运转：像开源项目，也像 git 分支

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-14/1a4f38e00b2bdf30.png)

把“共写一个世界”翻译成工程师的语言，结构立刻清晰：

- 世界观设定文档 ≈ 技术规范 / API：地图、纪年、种族、规则，所有人调用同一套接口。
- 正史（canon）≈ 主干分支 main：哪场战争发生过、哪个角色活着，必须有唯一裁决，否则下游全乱。
- 每位作者的故事 ≈ fork 出来的 feature branch：可以自由发挥，但要考虑将来合并回主干时的兼容性。
- 矛盾集中在 merge 环节：两本书对同一段历史的写法冲突了，听谁的？谁持有主干的管理员权限？

历史上出现过三种治理模式，各有代价：

1. **克苏鲁神话模式**：早期几乎没有版权约束，人人可写。世界繁荣，但设定互相打架、质量参差，至今仍是一锅“野生开源”大杂烩。
2. **漫威模式**：IP 归公司所有，编剧是雇佣兵，canon 由编辑部统一裁决。权责清晰，但创作者没有产权，谈不上共建感。
3. **九州模式**：作者各自持有版权 + 松散联盟，没有统一编辑部。自由度最高，治理成本也最高——这为后来的裂痕写好了伏笔。

## 三个结构性矛盾：为什么共写世界的团队总在散伙

1. **产权分散**。设定集、单部作品、影视改编权散落在不同作者与公司手里。影视方想买“九州”，得凑齐多个版权方，谈判成本指数级上升——好比把单体应用拆成了微服务，结果发现没人有整套系统的 admin 权限。
2. **话语权之争**。没有漫威式编辑部的九州，canon 裁决权实际上跟着人气走：读者默认只认销量最高的几位作者写的算数，其余参与者渐渐沦为“贡献设定的人”。分配感一旦失衡，合作就只剩体面。
3. **激励不对齐**。共享设定是公共品：每个作者都得往里投入精力，但卖书收入归自己。教科书级的 free-rider（搭便车）问题——世界被用得越多，公共部分越没人维护，最后逐渐荒废。

2013 年那场公开争执，本质上就是这三条线同时短路：设定归属、改编权、话语权。此后两位作者各自深耕：江南做出《龙族》，今何在把《海上牧云记》搬上屏幕。单打独斗都算成功，但“九州”这个公共项目，停更了很多年。

## 各自成王之后：为什么“世界观”反而更稀缺

- 二十年过去，两人各自验证了个人 IP 的商业价值：小说改编影视、动画、游戏，链条已经跑通。
- 但市场慢慢看明白一件事：**一部作品是一个 App，一个世界观是一个操作系统。** App 会过时，生态却能持续接入新故事、新作者、新改编。
- 国际市场的同款规律：星球大战靠世界观授权运转了近五十年，D&D 的设定集养活了一整代桌游厂商。
- 所以这次同台之所以值得讨论，不只是情怀：它意味着“九州”这套操作系统，理论上重新有了合并回主干的可能性。至于是否重启、怎么重启，公开信息还没给出答案，不妨保持观望。

## 冷思考：从“九州”二十年里能带走什么

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-14/d17ad2e20fc05a0b.png)

1. **先写 CONTRIBUTING.md，再写第一行代码。** 共创之前先定规则：谁拥有什么、canon 谁裁决、收益怎么分、fork 的边界在哪。规则成本前移一分，后期的撕裂就少一分。
2. **把世界观当基础设施维护，而不是当背景板。** 设定文档要标准化、版本化、可检索——地图、时间线、术语表，像维护一份公共 API 文档那样持续投入，协作成本才能真正降下来。
3. **别用感情代替合同。** 熟人合作最大的坑，是把“关系好”当成“不用谈”。IP 合作里，友情能加速启动，但只有清晰的协议扛得住利益变大之后的风浪。

一句话收尾：共享世界观是浪漫的工程——浪漫负责让人开始，工程负责让人走完。🦞
