## 背景

用 OpenClaw Agent 配 MCP 工具做社区自动化已经很普遍：定时发周报摘要、版本发布通知、每日问答精选。跑通链路不难，难的是发出去之后"像不像人"。我们把几个自动发帖账号的发布记录拉出来对过时间分布，机械感的来源其实非常集中，不是玄学。

## 问题：机械感从哪来

- **调度指纹**：cron 固定整点触发，9:00:00 精确发布，间隔方差接近零。
- **爆发式发布**：一次生成五篇，三分钟内连发，然后十小时静默。
- **内容指纹**：模板不变、开头句不变、段落数和 emoji 不变。
- **多 Agent 撞车**：三个 Agent 各带调度器，谁也不知道对方刚发过。

读者侧的感受是刷屏和疲劳，平台侧则是误伤限流，两边都不划算。

## 做法：四层节奏控制

**1. 调度层：高斯抖动 + 活跃时段曲线**
把固定 cron 改成"基准间隔 + 正态抖动"，sigma 取基准值的 25% 左右，偶尔留一段长空档。发布时刻不是均匀铺满 24 小时，而是从历史消息量统计出活跃时段分布，让发帖密度跟着社区作息走。

**2. 队列层：单一出口**
所有发帖收敛到一条队列、一个 dispatcher，出队时检查与上一条的最小间隔。多 Agent 场景用 Redis 锁或统一的 MCP 网关收敛，宁可排队也不并发。

**3. 内容层：模板池 + 相似度门槛**
准备至少三套结构模板轮换，发布前对最近十篇做 n-gram 重合率检查，超阈值就换模板或重写开头。别每篇都是同一个开场。

**4. 反馈层：dry-run 和退避**
先开 dry-run 跑一周，日志记录"本应发布"的内容和时间，人工审完再放开。被删帖或被举报触发指数退避：1h → 4h → 12h。

## 踩坑记录

1. **均匀随机抖动照样露馅**。大家都用 ±30min 均匀分布，这本身成了新指纹。改高斯，加长尾。
2. **抖过头伤体验**。周报类内容用户有预期（周一早上看），别乱抖。时间敏感型和内容型帖子要分开策略。
3. **重试风暴比机器人感更致命**。失败后无幂等重试，同一篇发两次。每个帖子生成 idempotency key。
4. **时区**。服务器 UTC、社区本地时区，凌晨三点发帖是最明显的机器痕迹，没有之一。
5. **只调节奏不调内容没用**。间隔再自然，二十篇开头一模一样照样一眼假。

## 可复用建议

```yaml
schedule:
  base_interval_min: 180
  jitter: gaussian          # sigma ≈ base * 0.25
  quiet_hours: ["01:00", "08:00"]
  min_gap_min: 40
  max_daily: 6
content:
  template_pool: 3
  similarity_threshold: 0.6 # 与最近 10 篇比较
backoff:
  on_flagged: exponential   # 1h → 4h → 12h
```

盯三个指标就够：发帖间隔分布直方图、相邻内容相似度、删帖/举报率。先保守——少发、发好，数据看起来自然了再逐步放开。

## 总结

节奏控制的本质不是伪装，而是让自动化尊重社区的活动节律和读者的注意力。把机器的输出分布向人的行为分布靠拢，一半是工程问题（队列、抖动、幂等），一半是产品判断（什么时间发什么）。顺序别反：先 dry-run，再小流量，最后全量。
