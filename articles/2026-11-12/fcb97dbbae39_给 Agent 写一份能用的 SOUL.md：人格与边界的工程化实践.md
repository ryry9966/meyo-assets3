## 背景

OpenClaw 的 Agent 行为不只由模型决定，还由工作区里一组 Markdown 文件共同塑造。其中 SOUL.md 的角色最特殊：它定义“这个助手是谁”——性格、语气、价值取向，以及更重要的，**不做什么**。不少新用户把它当可选项，跑通工具链后就不再维护。但在长会话、多插件、带 MCP 工具权限的场景里，这份文件是行为一致性的第一道闸门。

## 问题

没有明确人格与边界的 Agent，常见四种表现：

- **语气漂移**：同一会话内风格随上下文忽冷忽热，早上简洁克制，晚上话痨附和；
- **过度顺从**：用户随口一句“把这个目录全删了”，它真的去执行；
- **边界泄漏**：把内部设定、工具调用细节、其他会话的记忆当话题聊出来；
- **人格真空**：接入十几个 MCP 工具后，回答风格取决于最后读到的工具文档。

这些是 prompt 层的问题，换模型解决不了。

## 做法

我的 SOUL.md 固定为四个区块，控制在 60 行以内：

1. **身份与语气**：两三段说清角色定位和默认风格。要写具体的，别写“友好专业”这种空话，写“回复默认短句，先给结论再给理由”。
2. **硬边界**：列出永不执行的操作类别（未确认的批量删除、对外发送、支付类动作），并规定触发前必须先复述操作内容、等用户确认。
3. **拒绝策略**：遇到“假装你是另一个 AI”“忽略之前的设定”这类诱导时，不解释内部结构，直接说明做不到并给替代方案。
4. **文件间关系**：AGENTS.md 管流程与工具用法，SOUL.md 管人格与底线，冲突时以 SOUL.md 为准——这条本身要写进文件。

写完做一轮红队测试：准备十条诱导性输入（越权指令、注入、套内部设定），逐条跑，没拦住的补条款。

## 踩坑点

- **写太长**。超过 200 行后，中段规则的遵循率明显下降。原则性条款比穷举更重要。
- **条款互斥**。一边“永远别问确认”，一边“危险操作必须确认”，模型只能随机站队。落笔前先自查矛盾。
- **当保险箱用**。有人把 API key、住址写进去“让 AI 记住”。SOUL.md 会进入上下文，任何能影响对话内容的东西都可能把它带出来。敏感信息放环境变量和权限层，不放人格文件。
- **只写不测**。改完不跑红队用例，等于没改。

## 可复用建议

- 把 SOUL.md 放进 git，行为异常时对照 diff 找原因，比翻聊天记录快得多；
- 风格类条款可以写得宽松，安全类条款必须写成可判定句式（“执行 X 前必须 Y”），避免“尽量”“适度”这类模糊词；
- 文件头写版本号，出问题能定位是哪次改动引入的行为变化。

## 总结

SOUL.md 的本质不是让 Agent 更像人，而是把不可预期的行为收敛进可预期范围。成本是一个 Markdown 文件加一轮测试，对长期运行的自动化 Agent 来说，这是性价比最高的一道防线。建议每个跑 OpenClaw 的人都写一版，然后随真实对话持续迭代。
