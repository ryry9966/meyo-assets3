## 背景

信息源越加越多，真正读完的越来越少。RSS 其实没死，它只是缺一层过滤。我的目标是：每天早上收到一条消息——今天值得看的十条，每条一句话摘要加原文链接，由 OpenClaw 定时任务自动跑完，人只负责读。

## 问题

- 订阅源太杂，重复率高，同一个事件三五个源都在报；
- 不少源只输出摘要不给全文，AI 摘要容易变成"摘要的摘要"；
- 把所有条目一股脑扔给 LLM，token 成本和噪声都不可控；
- 管线跑三天就静默挂掉，没有任何告警。

## 做法

**1. 收敛订阅源。** 从 80+ 砍到 20 个左右，按"必读 / 可扫 / 归档"分级。只给必读源上 LLM 摘要，其余只做标题聚合。这一步比任何 prompt 调优都省 token。

**2. 抓取层。** cron 或 OpenClaw 定时任务触发，RSS 请求带 ETag / Last-Modified，命中 304 直接跳过。对只给 summary 的源，补一步网页抓取加正文抽取（readability 类库），失败就退回用原始摘要，不要硬重试。

**3. 去重与状态。** SQLite 存三样：URL hash、标题 simhash、发布时间。同源重复靠 URL hash；跨源同事件靠标题相似度聚簇（阈值 0.85 左右，宁多留勿误杀）。已推送条目打标记，重跑不重发。

**4. 摘要层，分两段。**
- 粗筛：用便宜模型对每条打相关性分，输出 JSON，砍掉 60–70%；
- 精摘：留下的条目用结构化输出生成"一句话摘要 + 为什么值得看"，链接只允许来自输入，由代码回填，禁止模型补全；
- 日报合成：精选条目再压成 200 字导语置顶。

**5. 投递与兜底。** 推送到 Telegram 或邮件。每次跑完写一条心跳记录，超过 24 小时没心跳就给自己发告警。

## 踩坑点

- **格式地狱**：RSS 2.0 / Atom / RDF 混着来，日期格式五花八门，解析用宽容的现成库，别自己写正则；
- **全文抓取被反爬**：单源间隔 2–5 秒，失败时缓存上次成功内容并标记"可能过期"；
- **模型幻觉链接**：prompt 里只喂纯文本加条目 ID，模型只负责文字，链接永远由代码拼回；
- **成本失控**：先粗筛再精摘，比一把梭便宜一个数量级；
- **静默失败**：某 feed 连续 7 天零条目要告警，多半是源挂了或改版了。

## 可复用建议

- 抓取、去重、摘要、投递四层解耦，中间状态落库，任何一层都能单独重跑；
- 摘要输出一律过 JSON schema 校验，不合规丢弃重试一次，再失败就降级为只推标题；
- 每周抽 10 条人工对一下摘要与原文，发现漂移再调 prompt，别凭感觉；
- 把 rss-fetch、readability、push 包装成 MCP 工具，调度交给 cron，摘要策略留给 agent 决策——工具做确定性的事，agent 做判断性的事。

## 总结

这条管线没有任何黑科技，价值全在"收敛、分层、兜底"六个字。LLM 只做它擅长的压缩和相关性判断，工程问题交给工程手段。跑稳之后，每天的信息摄入从"刷两小时"变成"读三分钟"，这才是自动化的意义。欢迎在评论区交流你们的信息流方案。
