## 背景

OpenClaw 的 workspace 约定里有几个关键文件：AGENTS.md 定义 agent 怎么干活，MEMORY.md 存过程记忆，而 USER.md 用来描述"你是谁"。实际观察下来，大多数人把精力花在 AGENTS.md 和工具链调优上，USER.md 要么空着，要么写了两行就再没动过。

## 问题

后果非常具体：

- 每个新会话都要重新交代一遍"用 pnpm 别用 npm""回复用中文""不要加 emoji"；
- agent 靠聊天记忆猜你的环境，猜错就一路错下去，时区、操作系统、部署方式全凭运气；
- 记忆是慢慢攒的，而你的偏好早就定型了，中间的落差全变成重复纠错成本。

本质上，个性化不该靠对话"聊"出来，它是一份配置。

## 做法

在 workspace（通常是 `~/.openclaw/workspace/`）里建 USER.md，建议按五段组织：

```markdown
# About me
## 基本环境
- 时区 Asia/Shanghai，macOS + Linux 服务器
- 主力 Python / TypeScript，包管理 pnpm、uv
## 沟通偏好
- 默认中文回复，代码与注释用英文
- 先给结论再给过程，不要铺垫
## 边界
- 不确定先问，不要替我做产品决策
- 不输出 emoji 和客套话
## 当前焦点（每月更新）
- 在做 MCP 工具鉴权相关插件
```

三条原则：

1. **写事实和指令，不写散文**。agent 无法执行"我是一个追求极致的人"这种句子，"回复用中文"它可以。
2. **控制体积**。USER.md 每个会话都会注入上下文，压在 1–2KB、几十行以内，越靠前权重越高。
3. **分清归属**。"我是谁"进 USER.md，"你该怎么干活"进 AGENTS.md，重复和冲突都会让模型摇摆。

之后把它当成 bug 修复流程：agent 又问了一遍你已经回答过的问题？别在聊天里争，往 USER.md 加一行，下个会话验证。

## 踩坑点

- **写成简历或随笔**：形容词多、事实少，等于没写；
- **信息过期**：换了技术栈、换了项目，旧条目还在持续误导模型，建议给"当前焦点"标注日期，定期清理；
- **塞敏感信息**：住址、密钥、证件号不要进 workspace，它可能被同步和备份，也会随上下文发给模型；
- **越写越长**：超过一屏后，后面的行基本被忽略，优先级排进前 20 行；
- **多工具各写一份**：我把同一份 USER.md 软链到其他 agent 的配置目录，改一处全局生效，避免两套"人设"互相打架。

## 可复用建议

- workspace 纳入 git，diff 记录就是你偏好的演化史，改坏了能回滚；
- 每季度像维护 dotfiles 一样审一遍，删掉不再成立的条目；
- 自动化和 cron 任务同样会注入 USER.md，这比依赖聊天记忆可靠得多，headless 场景尤其值；
- 验收标准很朴素：同一个问题 agent 不再问第二遍，就算生效。

## 总结

USER.md 是投入产出比最高的一份配置：几十行、一两 KB，换来的是每个会话省掉的开场白和纠错轮次。把"让 AI 了解你"从玄学变成工程，方法就是把它写成文件、纳入版本管理、定期维护。今天就可以花十分钟写下第一版。
