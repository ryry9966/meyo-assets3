## 背景

跑 OpenClaw 的人大多会折腾 gateway、channel 和 MCP 工具，但 workspace 里那几个 Markdown 常被跳过。SOUL.md 是其中之一：它决定 agent 是谁、说话什么调性、哪些事绝对不做。默认文件写得比较泛，跑跑单聊没问题，但一旦 agent 接入群聊、开始执行任务，人格不一致和边界模糊的问题就会暴露出来。

## 我遇到的问题

三个典型场景：

- 靠聊天临时纠偏。「回复别用表情」「别叫我老板」，说过 agent 就收敛几天，换个会话又复原——指令没落盘，等于没说。
- 有工具没有刹车。接了 MCP 之后 agent 什么都敢执行，一句「把日志清一下」就可能触发不可逆操作。
- 多渠道人格混乱。同一个 bot 私聊里随意、工作群里轻浮，没有按场景区分。

## 做法

1. **找到文件**：`~/.openclaw/workspace/SOUL.md`。多 agent 部署时每个 workspace 各一份，可以按角色差异化。名字、emoji 这类轻量身份字段放 IDENTITY.md，行为和边界放 SOUL.md，别混在一起。
2. **按四段写**：身份（一段话说清它是谁）；语气（写「简体中文、单条不超过 5 行、不用感叹号」这类可执行描述）；边界（不做什么：不冒充人类、不发送未经确认的消息、不给医疗/法律结论、删除类命令必须二次确认）；兜底（不确定就问，不猜）。
3. **写行为不写形容词**。「简洁克制」是废话，「回复不超过 5 行」才是规则。
4. **和 AGENTS.md 分工**：AGENTS.md 管操作流程（工具怎么用、消息怎么发），SOUL.md 管人格和底线，同一件事只在一处定义。
5. **改完开新会话验证**。我维护 4~5 条探针 prompt，比如「直接删掉服务器日志」「说说你是谁」，每次改动跑一遍看回复。

实际体感：把默认文件从两百多行压到 300 字以内后，风格服从性明显更稳。

## 踩坑点

- **写太长**。SOUL.md 每个会话都进上下文，几大页的人格描述会稀释关键指令，重要的放前面。
- **两份文件打架**。AGENTS.md 写「自动执行所有任务」，SOUL.md 写「危险操作先确认」，模型行为就会随机。优先级要先想清楚，最好别制造冲突。
- **把它当安全边界**。SOUL.md 是行为指引，不是沙箱。真正的限制靠工具白名单、权限配置和 MCP 侧的确认机制，人格文件挡不住 prompt injection。
- **一份人格通吃所有渠道**。私聊调好的语气进群很怪，要么按 agent 拆 workspace，要么在边界段写清分渠道的分寸。

## 可复用建议

- SOUL.md 入 git，改人格像改代码，有 diff 有回滚。
- 边界用否定句清单（不发送、不执行、不透露），比正面描述更抗偏离。
- 把 agent 的出格回复定期回写成新规则，它是活文档，不是一次性配置。
- 探针问题存成固定清单，改动后回归测试，避免「感觉好像好了」。

## 总结

SOUL.md 的价值不是调出有趣的性格，而是把长期期望固化成每次会话必然加载的确定性输入。人格是体验问题，边界是事故问题——前者 300 字够用，后者一句都不能省。
