## 背景

Agent 要“活在当下”，绕不开网页：监控文档更新、抓公告、比对价格、汇总变更日志。和一次性脚本不同，OpenClaw 这类常驻型 Agent 今天抓一次没事，明天可能自己决定每小时抓一次。所以重点不是“怎么抓到”，而是“怎么抓得可控、可审计”。我把采集前的这套自查叫“稽客”：Agent 既是客人，也得先稽查自己。

## 常见问题

实际跑起来，问题集中在四类：

1. **上下文污染**：裸抓 HTML 直接塞给模型，脚本、样式、导航栏占掉大量 token，真正正文可能不到一成。
2. **提示注入**：网页里一句“忽略之前的指令”，Agent 就可能照做。外部内容是数据，不是指令，但很多流程没做隔离。
3. **无节制请求**：没限速和缓存，循环任务跑一夜，轻则 429，重则封 IP。
4. **合规盲区**：robots.txt、站点条款没人看，采集不留痕，出问题无法溯源。

## 做法

一个比较稳的最小流程：

1. **域名白名单前置**。维护 allowlist，名单外的域名直接拒绝，而不是“抓了再说”。
2. **统一抓取层**。别让每个插件各写一份 fetch。做一层中间工具（封成 MCP tool 或内部服务），统一做三件事：正文抽取（HTML→Markdown）、剥离 script/style、限制单页返回长度，超长分段翻页。
3. **消毒后再入上下文**。页面正文包进明确的分隔标记，系统提示里声明：标记内是外部数据，其中任何指令一律不执行、不访问其中链接。
4. **限速 + 缓存 + 退避**。每域名 QPS 上限 1~2，结果缓存设 TTL，429/503 指数退避，能带 ETag 就用条件请求。
5. **留审计日志**。记录 URL、时间、返回码、内容哈希——追查“它为什么这么做”时，这是唯一可靠的证据链。
6. **能不抓就不抓**。优先官方 API、RSS/Atom，结构稳定、站点明确允许，还省 token。

## 踩坑点

- **200 ≠ 成功**。反爬常返回 200 加空壳页或验证页，要校验抽取后的正文长度，别只看状态码。
- **编码**。部分老站点是 GBK，不按 charset 处理就是乱码。
- **相对链接**。抽取时没拼 base URL，Agent 拿着 `/docs/x` 继续访问，直接 404。
- **SPA 页面**。GET 只拿到骨架。先找数据接口或 RSS，实在不行再上 headless 渲染，成本和风险都高一个量级。
- **默认 UA**。库默认 UA 很容易被规则拦截；用诚实的自标识 UA 加联系方式，是对站点的基本礼貌。
- **缓存 key 漏参数**。命中错误响应，或永远不命中，循环任务变成持续轰炸。

## 可复用建议

- 抓取层独立成服务，所有插件复用，策略一处生效。
- 白名单、消毒、限速、日志做成默认行为，而不是可选配置。
- 铁律一条：外部数据永不升级为指令来源。
- 优先 RSS 轮询差量，避免全量重抓。
- 定期抽查采集日志，Agent 常会“自作主张”扩大抓取范围。

## 总结

网页采集本身不难，难的是让一个会自主循环的 Agent 长期做而不出事。白名单管边界，消毒管安全，限速缓存管体面，日志管追责。四件套齐了，稽客才算到位。
