36kr 给 Grok 这次大升级配了一句很扎心的副标题——"AI 同事开始抢活干"。情绪先放一边，这件事值得用工程视角拆开看：升级到底动了什么？"抢活"的技术和经济前提是什么？哪些活会先被抢、哪些抢不走？这篇文章按机制 → 成本 → 范围 → 短板四层往下讲，结尾给三条能落地的建议。

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-12/5a347a93e1a1d76e.png)

## 一、机制：AI 从"有嘴"到"有手"

上一代聊天机器人本质是"文本进、文本出"：你问一句它答一句，活儿还是你自己干。这次 Grok 升级的关键不是跑分多涨了几个点，而是模型拿到了三样东西：

1. **工具调用（tool use / function calling）**：模型可以主动搜索、抓网页、跑代码、调 API，而不是只在参数里"背答案"；
2. **多步规划（ReAct 范式）**：把"帮我调研并写份报告"拆成搜索 → 筛选 → 交叉验证 → 写作 → 自查一条链跑完，中途还能根据结果改计划；
3. **长上下文与记忆**：挂载几十万 token 的资料，任务做到一半不会"失忆"。

举个直观对比：以前让 AI 分析竞品，你得自己复制粘贴二十篇网页喂给它；现在的 agent 自己去搜、自己抽数据、跑段 Python 算出市场份额、直接交付图表和结论。行话叫从 Chatbot 到 Agent——前者是顾问，后者是实习生，区别在于你不用全程盯手。

## 二、成本账：为什么偏偏是现在

Agent 的雏形两年前就能拼出来，一直没大规模上岗，卡点在**单位任务的推理价格**。过去两年，同等能力的推理成本降了一个数量级（头部模型 API 从每百万 token 几十美元级降到几美元级），再叠加量化、蒸馏、前缀缓存这些工程优化，"跑一个 agent 完成一项任务"的边际成本，第一次压到了雇人做的最低成本之下。

经济学逻辑很朴素：**当外包给 AI 的价格 < 人工价格 × 沟通成本，替代就发生**。所以纯跟文本、代码、表格打交道的活首当其冲；大量依赖物理世界的岗位暂时安全。历史上有个参照：ATM 普及后，美国银行柜员数量在头二十年不降反升——机器接管了点钞，人被挪去做销售和复杂咨询。但要清醒：这轮替代的是**认知型任务**，和以往任何一次自动化都不一样。

## 三、范围：哪些活先被抢，一条风险光谱

按任务特征排序，越靠前越危险：

1. **结构化 + 可验证 + 重复**：数据清洗、周报、客服工单、测试用例生成、初稿文案——输入输出清晰、对错能自动校验，agent 最擅长；
2. **结构化但需要判断**：财务分析初稿、竞品调研、简历初筛——AI 出一版人改一版，效率翻倍，但也意味着同样的产出只需要一半的人；
3. **强依赖隐性上下文**：跨部门推进、客户关系、拍板担责——AI 没有你脑子里的组织记忆，也签不了字、背不了锅。

关键区分在这里：**被抢的是任务（task），不是岗位（job）**。岗位是任务的集合，AI 吃掉其中六成，剩下四成重新组合，"岗位形态改变"会比"岗位消失"更早到来。

## 四、短板：为什么暂时抢不干净

1. **幻觉**：95% 正确率和"可以放心用"之间，隔着人工验收这道坎，越关键的数据越不敢裸用；
2. **上下文盲区**：它不知道你们去年那个项目为什么黄了、哪个供应商不能碰——没写下来的隐性知识，它学不到；
3. **责任归属**：代码它写，事故谁背？签字权、审计链、法律主体，这些制度问题技术解决不了；
4. **长程漂移**：任务一长（几十步以上），agent 会中途"忘掉初心"，需要人盯着纠偏。

所以现阶段的真实分工是：**AI 干活，人做验收、提示和兜底**。这不是安慰剂——验收能力正在变成新的稀缺技能。毕竟它不交社保、不摸鱼、7×24 在线，硬拼时长属于下策。

## 五、三条建议：跟不领工资的同事共处

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-12/e800513b550eb5a2.png)

1. **主动拆解自己的工作**：把每周做的事列成任务清单，标出哪些"可 agent 化"，重复的部分主动让出去，省下的时间拿去做判断和验证——被动"被抢"和主动"让活"，半年后的处境差很远；
2. **练验收，别只练提示**：会写 prompt 的人会越来越多，能快速判断 AI 产出对错的人才是瓶颈。建立抽查习惯：每天抽几条 AI 结论人工核实，对自己的误差率心里有数；
3. **沉淀私有上下文**：把团队的隐性知识写成文档、整理成结构化数据。看着像"给 AI 打工"，实际是让自己成为组织里唯一持有关键上下文的人——上下文就是新的护城河。

最后一句实话：每次工具进化，标题都爱写"抢活"，工程视角看到的其实是"任务重组"。焦虑不解决问题，盘点你自己的任务清单才算数。
