「3 天撬开 20 年护城河」——36kr 这条标题最近刷屏。源头是 TechCrunch 曝光的 Anthropic 融资路演材料：一名工程师借助 Claude Code，几天内把 CUDA kernel 移植到 Triton，据称性能与 NVIDIA 手工优化版本持平甚至快出 10%~20%，而传统人力做这件事通常要数周到数月。同期，Anthropic 刚以 1830 亿美元估值融资 130 亿美元，又宣布了规模数百亿美元的谷歌 TPU 合作。技术叙事叠加资本动作，才有「芯片变局」一说。这篇拆开来看：CUDA 护城河究竟是什么？3 天移植到底移了什么？哪些是真变局，哪些是路演修辞？

![cover](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-12/0a498edbaec3661f.png)

## 先搞懂：CUDA 的护城河不是代码，是「生态复利」

CUDA 是 NVIDIA 2006 年推出的 GPU 通用计算平台，至今约 20 年。它的壁垒从来不是「一套开发工具」，而是层层复利：

- **软件栈**：cuBLAS（矩阵运算）、cuDNN（深度学习原语）、TensorRT（推理优化）、NCCL（多卡通信）、CUTLASS（算子模板），每一个都历经十几年打磨和多代硬件适配；
- **工具链**：编译器、Nsight 性能分析、调试器、驱动，形成完整闭环；
- **人才社区**：全球数百万开发者，教程、问答、现成代码取之不尽，招人即用；
- **框架绑定**：PyTorch、JAX 的 GPU 后端长期以 CUDA 为第一公民，上层用户甚至感知不到它的存在；
- **硬软协同**：每代新卡发布当天配套软件基本就绪——这是竞争对手最难追的一环。

护城河的本质：**换硬件的成本，被摊进每一个工程师、每一行代码、每一次招聘里**。跨越它，缺的从来不是某几个天才 kernel。

## 「3 天移植」到底移了什么

![img1](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-12/d80e3f20b2c2160f.png)

先补两个概念：

1. **kernel**：GPU 上真正干计算活的最小函数，比如一次大矩阵乘法，其性能直接决定训练与推理效率；
2. **Triton**：OpenAI 开源的 GPU 编程语言（2021 年开源），语法接近 Python，把内存排布、线程调度这些 CUDA 里最繁琐的部分交给编译器自动处理；PyTorch 2.0 的 torch.compile 默认就用它生成 kernel。关键在于：Triton 还有 AMD 等多硬件后端，一份代码理论上可以喂给不同厂商的芯片。

按曝光材料的说法，工程师用 Claude Code 跑通了「生成代码 → 编译 → 测基准 → 改进」的自动循环，几天完成移植。这恰好是 LLM 的优势场景：

- **语料充足**：GitHub 上有海量公开 kernel 实现，模式高度重复；
- **闭环可验证**：写完立刻编译、测速、比对数值精度，模型可以自动迭代，不用等人评审；
- **稀缺经验被摊平**：业内估计全球真正精通 CUDA 底层优化的工程师仅数千人，LLM 相当于把这份 expertise 变成了 API。

但要记住：**这是一批 kernel 的移植，不是一整套软件栈的迁移**。「3 天」是单点案例，「撬开护城河」更多是叙事修辞。

## NVIDIA 为什么不必太慌：剩下的 80% 在哪

NVIDIA 的回应大意是：单个 kernel 的移植成果，低估了 CUDA 生态二十年的深度与广度。这话有依据——训练一个前沿大模型，kernel 只是冰山一角，水面之下还有：

- **数值库覆盖**：数百个算子都要有等价实现，缺一个就卡住整条 pipeline；
- **多机通信**：万卡集群的效率大头在 NCCL 这类集合通信库里，是独立于 kernel 的另一座山；
- **生产级稳定性**：数值精度一致性、跨硬件回归测试、驱动兼容，这些没有捷径；
- **新特性适配**：每代新卡的新指令、新精度格式，底层库必须第一时间吃透；
- **一个微妙事实**：Triton 在 NVIDIA GPU 上最终仍编译成 PTX（NVIDIA 的中间表示），跑在 NVIDIA 硅片上——它削弱的是 CUDA C++ 这层「语言锁定」，而非硬件本身。

结论：这个案例证明的是「迁移成本在快速下降」，不证明「护城河已平」。

## 真正的变局：从技术壁垒到定价权之争

商业逻辑才是这条热搜的底层。有个经典框架叫 **commoditize your complement（让互补品商品化）**：对 Anthropic 来说，GPU 算力是「模型」的互补品，互补品越便宜、可选供应商越多，自己的议价力越强。看它近期的动作：

- 与谷歌合作最高 **100 万颗 TPU、超 1GW 算力**，2026 年起陆续上线；
- 与 AWS 的 Project Rainier 集群投入约 **50 万颗 Trainium2**；
- 130 亿美元新融资，几乎全部投向算力开支。

多供应商策略成立的前提，是**迁移软件栈的成本足够低**——这正是「Claude 移植 kernel」叙事在商业上的真实作用：向投资人证明，摆脱单一供应商在工程上是可行的。

对行业更结构性的影响是：过去造一颗 AI 芯片，最难的往往不是硬件，而是「没有 CUDA 等价物」；当 LLM 能批量翻译、生成、调优 kernel，AMD、TPU 与各类自研 ASIC 补齐软件短板就多了一条低成本路径。NVIDIA 未必丢份额，但**独占性定价权**会慢慢被稀释。

## 冷思考：三个判断标准

![img2](https://cdn.jsdelivr.net/gh/ryry9966/meyo-assets3@main/images/2026-11-12/38c3d3c528aab79a.png)

1. **看端到端，不看单点跑分**：移植一个 attention kernel 快 20% ≠ 训练快 20%；关键指标是集群整体 MFU（算力利用率）与训练吞吐能否被非 NVIDIA 后端稳定支撑。再看到「X 天超越 CUDA」式说法，先问覆盖了多少算子；
2. **看生态数据，不看发布会**：Triton、ROCm、MLIR 的版本迭代速度、CI 测试覆盖、PyTorch 官方对非 CUDA 后端的维护投入——GitHub 上的公开数据比任何演讲都诚实；
3. **押注框架层抽象，别焊死底层**：业务代码尽量停在 torch.compile / JAX / XLA 这一层，让「换后端」变成一行配置而非一次重写——无论这场变局走向哪边，你都是受益方。

护城河没有被一夜填平，但「三天填一格」这件事本身，比任何一次填格都重要。
