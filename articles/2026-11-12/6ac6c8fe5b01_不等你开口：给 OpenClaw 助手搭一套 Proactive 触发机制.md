## 背景

大多数助手默认是“被动应答机”：你不发消息，它一辈子不动。但跑在 OpenClaw 上的个人 Agent 天然具备常驻条件——有持续进程、有会话状态、接了 MCP、有推送通道。缺的不是能力，而是把“被动等输入”改成“主动找事做”的一层触发设计。

## 问题

主动 ≠ 定时群发。工程上真正要解决三件事：

1. **什么时候触发**：时间驱动、事件驱动，还是自检驱动；
2. **触发了要不要打扰你**：需要一个“值得打断”的判断阈值；
3. **主动之后能做什么**：只读汇报，还是直接执行写操作。

这三个问题没想清楚，做出来的就是每半小时问一句“有什么需要我做的吗”的骚扰机器。

## 做法

我把它拆成三层，逐层加：

**第一层：时间驱动。** 最简单，cron 直接调 agent 跑固定任务，比如每天早八点生成日报、列出待跟进事项发到群。没有智能判断，胜在确定性强。

**第二层：heartbeat 自检。** 给 agent 配周期性自检 prompt：每 2 小时醒来，只做三件事——检查待办、用只读 MCP 工具看外部状态（仓库新 issue、监控异常）、判断有没有值得打断用户的事。判断标准写进 prompt：只有“需要在 X 小时内响应”或“影响已有决策”才输出，否则静默记日志。

**第三层：事件驱动。** webhook → 轻量 MCP server → 推事件给 agent，比如 CI 失败、PR 被评论。关键是 pre-filter：事件先进规则层（来源/关键词/严重级），过滤后才唤醒 agent，避免每次提交都烧一遍 token。

外面包一层全局策略：静默时段（23:00–8:00 只入队不推送）、每日主动推送上限 3 条、写操作一律降级为“提议 + 等确认”。

## 踩坑点

- **打扰预算失控。** 初期 heartbeat 每次“都觉得有事要说”，第三天我就开始无脑忽略推送——狼来了。修复：判断标准从“有没有事”改成“拖到下次心跳会不会变糟”，每日上限写死在策略层，不依赖模型自觉。
- **心跳烧 token。** 2 小时全量检查一轮，啥也没有也跑工具调用。改成心跳先跑无工具的轻量检查（只读本地状态文件），有疑似异常才升级全量。
- **会话污染。** 心跳跑在主会话里，几天后上下文全是自言自语。改为单独 session，结束只把“需要用户知道的结论”写回共享状态文件。
- **自触发循环。** 主动消息发到群，被 webhook 再次捕获，agent 自己回复自己。给主动输出打标记，事件层见标记直接丢弃。
- **时区。** cron 用了 UTC，静默时段实际错位 8 小时，半夜被吵醒过一次。

## 可复用建议

- **先只读，后写。** 前三周主动层只做汇报，写操作全部转确认，观察误报率再逐步放开。
- **分级通道**：静默日志 → 日报聚合 → 即时推送，让“主动”有档位。
- **决策留痕**：所有主动判断写日志，每周回看——N 条推送里有几条真有用，低于一半就收紧阈值。
- 判断标准用否定句式写给模型（“除非……否则不要打扰”），比正向描述有效得多。

## 总结

Proactive 能力不是“加个定时任务”，而是**触发设计 × 打断阈值 × 通道分级**三件事的组合。先让 agent 学会闭嘴，再让它学会开口——顺序反了，用户就会替你把它关掉。
