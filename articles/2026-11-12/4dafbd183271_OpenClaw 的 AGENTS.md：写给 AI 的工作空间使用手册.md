## 背景

OpenClaw 的 agent 每次会话启动时会读取工作空间里的 AGENTS.md。如果说 SOUL.md 定义"我是谁"，那 AGENTS.md 定义的是"在这个工作空间里怎么干活"——它本质上是一份写给 AI 的使用手册，相当于新人入职第一天拿到的那份上手文档。

## 问题

没有这份文档时，常见的低效模式有三个：

1. 每次会话重复交代同样的规则："回复别太长""跑任务前先确认""别动那个目录"；
2. 多 agent 或多人协作时行为不一致，产出质量取决于运气和聊天记录；
3. MCP 工具和插件装了一堆，agent 却不知道在当前工作空间里"什么时候该用哪个"。

约定只存在于人的脑子里，AGENTS.md 就是把它显式化的地方。

## 做法

默认工作空间在 `~/.openclaw/workspace`。我们按下面的骨架维护 AGENTS.md，控制在几十行：

- **工作空间说明**：一句话讲清这里是干什么的、边界在哪；
- **环境与命令**：构建/测试/lint 的确切命令，可直接复制执行；
- **协作礼仪**：回复长度偏好、哪些频道保持安静、何时该主动确认而不是自作主张；
- **硬性禁令**：不改锁文件、不碰 CI 配置、引入新依赖必须先问；
- **工具调度**：如"日程操作优先走 xxx MCP 工具，别手拼请求"；
- **完成标准**：声明"完成"之前必须通过哪些验证。

多 agent 场景下每个 agent 有独立工作空间，各自维护一份 AGENTS.md，是隔离行为最便宜的手段。

## 踩坑点

- **写太长**。它每次会话都进上下文，几百行的文件会稀释关键规则，信噪比比全面性重要；
- **指令太虚**。"写好代码"没有约束力，"提交前执行 `pnpm lint && pnpm test`"才有；
- **文档腐烂**。命令变了文档没更新，agent 会忠实执行过时规则。把它当代码：进版本库、随变更改；
- **与 SOUL.md 抢戏**。身份和偏好写进 SOUL.md，操作规则留在 AGENTS.md，两边重复会互相干扰；
- **塞敏感信息**。它会被每次会话读入上下文，不要放 token 和密钥。

## 可复用建议

1. 把 AGENTS.md 当作"给 AI 的 onboarding 文档"来写，而不是一份普通配置文件；
2. agent 犯了同类错误两次以上，优先改文档，而不是继续口头纠正输出；
3. 定期开一个全新会话做验证：让它独立完成一个常规任务，观察它是否真的遵守了规则；
4. 子目录有特殊约定（比如 docs 格式）就下沉到子目录的 AGENTS.md，别都堆在根上。

## 总结

AGENTS.md 是 OpenClaw 工作流里性价比最高的一类基础设施：成本是几十行 Markdown，收益是行为一致性、可交接性和协作确定性。原则就三条：短、真、常更新。
