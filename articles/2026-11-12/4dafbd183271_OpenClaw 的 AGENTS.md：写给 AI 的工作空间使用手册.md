## 背景

OpenClaw 的 agent 每次会话启动时，会把工作区根目录（默认 `~/.openclaw/workspace`）下的 AGENTS.md 注入上下文。它是唯一一份"每次都在场"的持久指令——相当于给 AI 同事准备的岗位手册。README 写给人看，AGENTS.md 写给模型看，两者的写法完全是两回事。

## 问题

没有这份手册，或写法不对，典型症状有三种：

- 每个新会话都要重新交代一遍目录结构、测试命令、部署流程；
- 工具选择混乱：明明本地脚本一秒能查的事，偏要走 MCP 远程接口绕一圈；
- 上周纠正过的错误这周原样再犯——会话上下文不跨期，长期行为全靠这份文件兜底。

## 做法

1. **位置与加载**：工作区根目录放一份，多项目就每个仓库各放一份，跨项目的通用约定做成模板复制。
2. **固定结构**：建议按这几段组织——身份与职责边界 / 环境说明（目录、运行时、依赖）/ 常用命令（构建、测试、部署的确切命令）/ 代码与提交约定 / 工具优先级（何时用 MCP、何时用本地脚本、何事必须先问人）/ 红线（禁止未确认直接 push、禁止动生产配置等）。
3. **用祈使句写**："测试命令是 `pnpm test --filter core`" 比 "本项目使用 pnpm 作为包管理器" 有用十倍。agent 需要可执行的指令，不需要介绍性文字。
4. **控制篇幅**：全文 150 行以内。它每轮会话都占上下文，长文稀释注意力还烧 token。
5. **迭代维护**：把它当代码管。agent 犯错、你纠正之后，立刻让它"把这条写进 AGENTS.md"，一条规则一个 commit，改命令和改文档放同一个 PR。

## 踩坑点

- **写成 README**：塞满项目背景和发展历程，模型每轮都要读一遍却用不上。
- **规则互相矛盾**："始终先跑 lint" 和 "小改动可跳过 lint" 同时存在，agent 每次随机执行一条。矛盾不如不写，先自己裁决再落笔。
- **内容过期**：命令改了文档没更，agent 会坚信文件而不信现实。过期指令比没有指令更危险。
- **存敏感信息**：密钥、token 绝对不能写进去——文件内容会进入模型上下文，等于明文外发。
- **当日记本用**：它是约束，不是记忆。流水账交给 memory 目录，AGENTS.md 只放"每次都必须成立"的规则。

## 可复用建议

- 接手新工作区时，先让 agent 读一遍 AGENTS.md 并复述关键约定，确认加载和理解都正常，再开始干活。
- 团队场景把它纳入版本库，规则变更走 review，避免某个人单方面"调教"出只适合自己的 agent。
- 同时使用多个 agent 工具的话，AGENTS.md 正在成为跨工具的通用约定，一份文件多处生效，不必为每个工具维护副本。

## 总结

AGENTS.md 是工作区里杠杆最高的一份配置：写清楚一次，之后所有会话都受益。它不需要华丽，需要的是准确、简短、持续维护。把它当成给 AI 同事的运维文档来经营，回报非常直接。
